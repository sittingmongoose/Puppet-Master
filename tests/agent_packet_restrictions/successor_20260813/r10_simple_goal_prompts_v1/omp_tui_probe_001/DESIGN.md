# R10 OMP TUI zero-model transport probe 001

This is a one-use, zero-model Windows transport probe. It tests only the corrected boundary that a later OMP canary would use:

1. one no-restart, `IgnoreNew` scheduled task runs the driver under the logged-in user's interactive token with a two-minute service ceiling;
2. the Session-4 PowerShell 7 driver launches Windows Terminal with discrete `ProcessStartInfo.ArgumentList` tokens;
3. Windows Terminal launches one wrapper file with no prompt or task argument;
4. the wrapper asserts that it received zero arguments, then invokes an inert PowerShell receiver through a native argument array shaped like the future OMP option array;
5. the receiver proves exact element-for-element argv delivery;
6. the driver binds one newly observed exact live-title HWND through Windows Terminal, wrapper, and receiver ancestry, activates that title, rechecks the foreground HWND immediately before and after one `SendInput` call, and sends one frozen inert line plus Return;
7. the receiver records the exact line and exits; the original HWND and both recorded child PIDs must then disappear.

The reviewed probe scripts contain no direct invocation of `omp.exe`, a provider, a model, Goal Mode, `/goal`, a PuppetMaster subject, or any source/tool workflow. They sample the `omp.exe` endpoint before and after the input interval; they do not prove that an unrelated transient process or network operation could not occur between samples. The probe grants zero empirical or qualification credit. The fixed host, user SID, PowerShell/.NET runtime, nonce, title, window id, paths, argv, inert input, scheduler policy, and ceilings are in `probe_contract.json`; `bundle_manifest.json` freezes the five runtime files.

The earlier defect used POSIX single quotes inside `cmd /k`; `cmd.exe` treated the quotes literally and OMP received `'--profile'` as prompt text. This probe forbids `cmd.exe`, constructed `pwsh -Command` strings, and `Start-Process -ArgumentList`. The future OMP wrapper may inherit this probe's launch mechanics only after this first attempt passes and fresh frozen review binds a real profile/model/thinking tuple.

Attempt reservation is the driver's first state change. Every later detected or caught preflight/runtime failure attempts to publish the immutable terminal failure before optional residual observation; any existing attempt/evidence root is an unmodified hard stop. Receipts publish through flushed temporary files and atomic rename. Forced host or Scheduled Task termination, an uncancelled blocking call, or terminal-publication failure can leave no terminal receipt and is a nonpassing lost-evidence outcome, never a pass or authority to retry. Acceptance is exact and fail-closed: frozen host/user/runtime, active console Session 4, endpoint `omp.exe` count zero at both samples, no pre-existing exact title or evidence directory, exact wrapper/receiver argv and identity joins, one newly observed visible exact-title Windows Terminal HWND, exact ancestry and foreground rechecks, one complete `SendInput` call, one exact receiver line, destroyed original HWND, exited wrapper/receiver PIDs, no retry, and no cleanup signal. Focus denial, partial input, title ambiguity, timeout, residual process/window, malformed receipt, or missing terminal evidence permanently fails this probe.

Named residuals remain: the scheduler, Windows host, and staged bytes are unsigned; an unavoidable global `SendInput` focus race remains after the last check; endpoint samples do not prove interval-wide OMP/network absence; one receiver `ReadLine` does not independently prove that no second line remained queued; `SendInput` success is not evidence of OMP consumption; the future effective OMP identity surface is unresolved; and a passing inert receiver does not prove native Goal activation or terminal lifecycle.
