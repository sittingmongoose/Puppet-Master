# Storage-plan full pre-WorkNode sandbox

This experiment tests the simplified bounded-context architecture on one already-standardized large canonical plan. It reads `Plans/storage-plan.md` but writes only under this sandbox. It does not edit Plans, ledgers, Spec Lock, shards, evidence governance, or the planning index, and it never creates a NodeSeed, WorkNode, executable queue, final node manifest, implementation file, runtime launch, or production build task.

## Pipeline boundary

The deterministic host performs the complete document-scoped path:

1. bind the exact source, canonical parser, current indexed comparison rows, global PlanUnit ID registry, and completed migration coverage;
2. extract every PlanUnit fence from the full 974,842-byte document with the canonical `pm-plan-index.py` parser;
3. generate every acceptance unit and the document card;
4. classify every dependency edge as internal, external-known, or missing against the frozen existing registry;
5. compare all extracted PlanUnit and acceptance rows to the already-generated canonical subset;
6. carry forward the honest global validation and PNC-019 runtime-certification blockers; and
7. emit a node-readiness disposition that explicitly stops before WorkNode creation.

The subject model does not receive the plan body, global index, history, migration files, hidden oracle, or host implementation. It receives only one bounded PromptCapsule containing the small phase receipts required to report the final pre-WorkNode gate.

V2 made every scored value and type either a same-named typed admitted fact or the explicitly supplied result schema ID. Its first Ox subject completed native Goal and produced the exact semantic result, but the frozen rendered-TUI evidence projection false-negatived wrapped bytes. V2 remains a permanent zero-credit failure. V3 preserved those subject bytes and added strict persistent-session verification, but its first Ox prompt and carriage return were coalesced into one PTY write: OMP retained the prompt as a composer draft and never created a user message, Goal state, or model result. V3 remains a permanent zero-credit transport failure. V5 changes only that closed evidence invariant and fresh identities. It validates one active-context record per native inference separately from zero-or-one exact continuation records. This experiment qualifies bounded typed-receipt assembly, not an independent semantic audit.

## Native Goal surfaces

- OMP receives exactly one external interactive TUI submission beginning `/goal `. Both `advisor.enabled` and `task.agentAdvisor` must be off immediately before launch. A row-bound receipt captures the exact OMP binary/profile/version and raw outputs of every frozen effective-config query; its hash is joined through the launch receipt and ordinal launch journal. No ordinary tools, skills, or rules are needed. Each row uses a fresh `--session-dir`. Transport is exactly two low-level writes: the unchanged prompt bytes without a carriage return, then one standalone carriage return only after a prompt-specific composer card is observed. A pre-prompt snapshot must lack that card, the composer snapshot must extend it, and the resulting session prefix must independently prove a fresh header, the selected model/effort, native Goal active state, an initial hidden `goal-mode-context` byte-equal to OMP 18.0.4's rendered active template, and one exact user objective within 90 seconds. These are two input events for one external task submission, not a second task prompt or lifecycle instruction. The fixed title slot plus append-only v3 JSONL must then prove one linear session, native Goal active/complete state, one matched `goal({op:"complete"})` call/result, one terminal assistant result, no ordinary tools, and normal session exit. If OMP itself schedules its one native hidden automatic continuation after a text-only stop, it must prepend exactly one additional active-context record for that inference; only the distinct adjacent `goal-continuation` record counts toward the extra assistant turn. Both records must byte-equal their frozen templates rendered from the same objective and latest monotonic Goal accounting state. Neither hidden platform record is a controller follow-up or second external submission. The rendered TUI can corroborate activation, completion, and visible result only; it cannot supply authoritative prompt or answer bytes.
- Codex receives one app task prompt beginning naturally `Create a goal that `. Native Goal activation and completion are qualified from the raw rollout, not from `read_thread` summaries.
- No subject receives controller-authored lifecycle choreography, a second external submission, a retry, answer repair, or a replacement. The verifier accepts only the direct native Goal path or OMP's single exact native hidden continuation path.

The isolated OMP profile currently reports an unrelated `wirekitty` MCP HTTP 404 during startup. V5 does not hide or reinterpret it: the lossless TUI transcript is retained, readiness waits until OMP emits its aggregate `MCP finished` state, and no claim of clean MCP startup is made. The observed failure did not prevent the native Goal routes used in earlier diagnostics, but it remains a named runtime residual rather than qualification evidence.

The two passes use unchanged source, parser, registry, migration inputs, capsule bytes, output contract, oracle, route configuration, and scorer. Each row has a fresh task/session/cwd identity and no retry or retro-credit. OMP Ox Alpha/free runs first, Cursor second, and Qwen last. Cursor and all paid/Codex/Qwen routes remain frozen until the free Ox evidence harness passes exactly; Cursor must then pass before the remaining matrix is spent. A model-specific failure is preserved and fail-stops the frozen suffix.

## Expected honest disposition

Storage extraction and comparison are expected to pass. Pre-WorkNode readiness is expected to remain blocked because:

1. the pre-existing canonical global validation reports a stale `node_readiness_report.json`; and
2. PNC-019 executable runtime certification is incomplete.

The typed result must therefore report structural success, `canonical_node_readiness_artifact_stale`, `pnc019_runtime_certification_incomplete`, and `no_worknodes_created=true`. This is architecture qualification evidence only, not product readiness, safety certification, canonical Plan completion, or authority to create work nodes.
