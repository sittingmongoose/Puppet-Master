# Composer, Spellcheck, and Thread State

## Spellcheck

Behavior:

- subtle underline;
- right-click or keyboard suggestions;
- Replace once;
- Ignore once;
- Ignore for this draft;
- Add to personal dictionary;
- Add to project dictionary when permitted.

No automatic replacement. No permanent Chat toolbar button.

Skip:

```text
Code blocks
Inline code
URLs
Paths
Shell commands
Hashes
Identifiers
Structured data
Known provider/model/Persona/tool names
Literal text
```

Thread overflow may include a quiet `Disable spell check in this thread`.

Production uses a cross-platform spell service:

```text
Automatic — OS then PM local
System dictionaries only
PM local dictionaries only
```

Grammar/style is separate, opt-in, and provider/Usage/privacy-aware.


## Thread-local override presentation

Model, Persona, effort, speed, access, BSD, Crew, and worktree selectors must communicate the current scope without crowding the composer.

Changing one thread does not alter siblings.

A broader action requires explicit language and confirmation, for example:

> Apply Deep Researcher to all threads in this PlanningRun?

## Full Access terminology

Use `Full Access`, never `Yolo`, in visible UI and impact records.

## Plan/Review tools

Do not display Plan or Review as blind modes. Their effective tool availability may include browser/research/testing/diagnostics while write/network/external side effects remain policy-controlled.
