# 5.6 Sol Assistant Chat Creative Bakeoff — Start Here

## Purpose

This packet gives **one new creative director, 5.6 Sol**, the complete behavioral and integration envelope for an original Puppet Master Assistant Chat concept system.

It is not a correction pass over another agent's concepts. It is a fresh independent bakeoff entry.

## Core assignment

Create:

- eight Chat-window concepts;
- eight Chat-thread concepts;
- one interactive comparison workspace in which any of the eight thread concepts can mount inside any of the eight window concepts;
- docked and pop-out forms using the same semantic state;
- all eight Puppet Master themes;
- continuous width testing from 520 to 1200 px;
- realistic, deeply interactive demo content;
- film-level authored motion and a complete reduced-motion mode;
- functional tests, visual evidence, and traceable Plan/Command/Wiring/DRY impact records.

The 64 same-model combinations must work. They do not need to be 64 manually designed pages.

## Independence rule

The agent must **not open, inspect, render, copy, compare against, or derive ideas from any other model's Assistant Chat concept folder**.

Allowed sources:

- the current `PMConcept7` as functional and shell evidence;
- current live Plans and owner contracts;
- the ConceptHub starter/framework;
- this packet;
- the supplied four videos and screenshots;
- neutral external product and motion research.

Other agents' concepts are excluded even as inspiration.

## Source priority

When material conflicts, use this order:

1. The current user instructions and creative brief in this packet.
2. `02_FIXED_PRODUCT_BEHAVIOR.md` and `03_CUMULATIVE_THREAD_DECISIONS.md`.
3. The machine-readable decision and requirement registers.
4. Current live canonical Plans and current owner handoffs in the repository.
5. Current PMConcept7 behavior and shell geometry.
6. Original packet material as source history.
7. External products and videos as functional or motion inspiration only.

Old Plan/Build prompts are not authority. This packet's `IMPLEMENTATION_PROMPT.md` is the one implementation Goal. `AUDIT_PROMPT.md` is the one later read-only audit Goal.

## Read strategy

Do not load the entire packet into every model context.

A good first pass is:

1. Main agent reads this file and `01_CREATIVE_DIRECTOR_BRIEF.md`.
2. A bounded read-only subagent inventories original fixed behavior from `02_FIXED_PRODUCT_BEHAVIOR.md` and `machine/original_requirements.json`.
3. A second subagent inventories cumulative decisions from `03_CUMULATIVE_THREAD_DECISIONS.md` and `machine/final_chat_decision_coverage.json`.
4. A third analyzes the four video references and motion obligations.
5. A fourth inventories Commands/Wiring/DRY/Plan/test implications.
6. The main agent synthesizes a short design constitution before proposing the plan.

Subagents provide evidence and inventories. The 5.6 Sol parent remains the only creative director and writer.

## Creative versus fixed

Fixed:

- product behavior;
- state ownership and security boundaries;
- data truthfulness;
- required scenarios and tests;
- shell, theme, width, mount, and portability constraints;
- no canonical edits during concept work.

Open:

- visual language;
- hierarchy;
- spatial architecture;
- message treatment;
- history treatment;
- activity compression;
- artifact presentation;
- questionnaire composition;
- motion choreography;
- how each concept yields space under pressure;
- how the eight windows and eight threads differ.

Cards, panels, rails, layers, sheets, canvases, timelines, or entirely new metaphors are allowed. The packet does not prescribe a preferred component grammar.
