## Task 5 — Fix run-gates hanging/ignoring timeout (P2 → reliability)

**Root cause (confirmed):** Every run-gates subprocess gate calls `subprocess.run` without process-group isolation. When a child (or its grandchild, e.g. a spawned tool) holds the stdout/stderr pipe open, the parent's `TimeoutExpired` fires but `Popen`'s internal `communicate()`-to-reap hangs on the open pipe → run-gates never returns. `cmd_validate_gui_asset_policy` (`pm-plans-verify.py:3004`) is the **only** gate that also lacks a `timeout=` entirely. The `run_named_check` SIGALRM wrapper (line 169) raises `SubcheckTimeout` in the parent but does not kill the child tree.

**Fix (per user's chosen approach — shared helper, all run-gates subprocess gates):**

Add `run_validator_subprocess(check_name, argv, *, timeout_seconds, report_label, extra_failure_fields=None)` to `scripts/pm-plans-verify.py`:
- `subprocess.Popen(..., start_new_session=True, stdout=PIPE, stderr=PIPE, text=True, cwd=ROOT)`.
- Poll with `proc.communicate(timeout=timeout_seconds if timeout_seconds>0 else None)`.
- On `TimeoutExpired`: kill the whole process group — `os.killpg(os.getpgid(proc.pid), signal.SIGKILL)` inside try/except; fall back to `proc.kill()` if `os.getpgid`/`killpg` raises (POSIX-only / no-process-group). Then `communicate()` again (bounded) to reap and drain pipes so no child holds them.
- Always return a **structured** report: on timeout → `report_status(report_label, [{"error":"subprocess_timeout","timeout_seconds":...,"process_group_killed": bool,"stdout_excerpt": tail[:4000],"stderr_excerpt": tail[:4000], **extra}])`. On success → parse JSON stdout; on non-JSON → structured `validator_output_not_json` failure with bounded stdout/stderr/returncode. Normalize nonzero-exit-with-pass-status like the existing gates do.
- Never raise; always returns a dict so run-gates/audit-governance get a structured pass/fail/timeout.

**Route these 7 gates through the helper** (both `cmd_run_gates` and `cmd_audit_governance` check_specs call them, so the helper is reached from both paths):
1. `cmd_check_shards` (line 895)
2. `cmd_validate_gui_asset_policy` (line 3004) — **also gains a `timeout=` path it previously lacked**
3. `cmd_validate_prd_planning_runtime_contracts` (line 5160)
4. `cmd_validate_implementation_readiness` (line 5212)
5. `cmd_validate_plan_migration` (line 5267)
6. `cmd_validate_audit_status_index` (line 5321)
7. `cmd_validate_audit_closure` (line 5376)

Leave `cmd_validate_bootstrap_ledgers` (line 5098, not in run-gates/audit-governance) and `iter_repo_files` `git ls-files` (line 305, repo inventory) untouched per user instruction.

**Tests — new file `tests/test_pm_plans_verify_subprocess.py`** (import `pm-plans-verify.py` via `importlib.util`, same convention as `test_pm_audit_closure.py`):
1. Normal exit: stub validator script prints `{"status":"pass"}` → helper returns `status=pass`.
2. Timeout: stub sleeps > timeout → helper returns `status=fail`, `error=subprocess_timeout`, `timeout_seconds` set, returns within bound.
3. Process-group kill: stub spawns a child that inherits stdout/stderr and sleeps long; helper times out, kills the group (assert `process_group_killed=True` and the child PID is no longer alive via `os.kill(pid,0)` → `ProcessLookupError`), and returns structured failure (not hanging).
