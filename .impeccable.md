## Design Context

### Users

Software engineers and technical operators using Puppet Master as a desktop orchestrator for AI coding workflows. They typically work inside a local workspace/repo, frequently switching between dashboard, wizard/interview flows, and orchestrator views while monitoring progress, evidence, and run-state.

Key constraints:
- Work is keyboard-first (tab navigation, enter activation, predictable focus order).
- Users need always-visible status cues (orchestrator state, warnings/blocked counts, tool/usage context).
- Users may toggle between a decorative retro experience and an accessibility-first Basic experience.

### Brand Personality

Retro-futuristic “IDE theater” with hard edges and crisp visual hierarchy. The interface feels precise and engineered—less “AI chat vibes,” more “instrument panel.” The Basic theme feels calmer and more readable, prioritizing clarity and reduced motion.

### Aesthetic Direction

The UI uses three guiding flavors:
- Retro Dark / Retro Light: pixel grid + paper texture + scanlines + hard shadow offsets; Orbitron (display) + Rajdhani (body).
- Basic: reduced visual noise (no retro effects), system/Inter fonts, gentle borders, and accessibility-first behavior.

Visual and layout principles:
- IDE shell rhythm (title bar, activity bar, primary content, side panel, bottom panel) with consistent spacing tokens.
- Cards and bento widgets follow a consistent grid/spacing language—intentional asymmetry is allowed, but spacing remains systematic.

### Design Principles

1. Theme tokens as the source of truth
   - Use theme tokens for colors, borders, radii, shadows, and typography.
   - Avoid hard-coded “random” colors in component styles; prefer token usage so themes remain coherent.

2. Accessibility is non-negotiable in Basic
   - Basic must meet WCAG AA contrast requirements.
   - Focus indicators must always be visible for keyboard users.
   - Keyboard navigation behavior must match what users expect for tabs, lists, and selectable surfaces.

3. Reduced motion + animation safety
   - Honor `prefers-reduced-motion`.
   - Retro motion should be decorative and never required for understanding.
   - Basic mode must avoid decorative animation by default.

4. Interaction clarity across states
   - Every interactive element supports default/hover/focus/active/disabled/error/loading/success.
   - Empty states should teach what to do next.

5. Screen reader mitigations
   - Use ARIA roles/attributes where possible for tab-like controls and important dynamic regions.
   - Ensure the active/selected state is exposed (for example, `aria-selected` on tabs).
