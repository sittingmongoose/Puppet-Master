## Original Goal update source and terminal custody

SIR-049 adopts only the existing `cmd.chat.goal.update` identity and CV-342 request/result. Actual original SIR dispatch/request/outcome custody and Goal's independently accepted full replacement agree on normalized scope/topology/operation/command instance, payload hash, dispatch frame/target generation, actor, permission, return route and original acceptance. Routing strings, copied request/outcome bytes, a creation source or a constructor map cannot supply that source. U0 retains complete source audit, exact original input and initial immutable progress/head in SP-299's actual absent-key source transaction without mutating the Goal or issuing a terminal result.

Source acknowledgement, producer occurrence, body mutation, observation/persistence and terminal acknowledgement times retain their separate original owners. Genuine Direct Save requires no new confirmation; actual agent instruction/approval resolution remains the existing provider's duty. No source field may be filled by a present default after original custody is lost.

U4 privately stages the authentic typed result, original CommandOutcome and central UICommandResponse through their actual original issuers. It captures the exact current admitted progress head and terminal-selected immutable epoch, checks every complete source/result/outcome/response/physical member join, and atomically publishes those original members plus `StorageTerminal` at the actual original SIR terminal boundary. No SIR outcome becomes terminal before its joined members, and later copying or repair cannot establish the original atomic result. If native topology cannot supply that boundary or an explicitly supported equivalent original member transaction, terminal issuance stays unavailable while earlier body/event effects remain true.

Success requires independently authenticated original body receipt and shared event/first-receipt/full-value custody. No-effect requires proved zero accepted body/event effect and safe original pending release. Unresolved/partial results use the exact existing recovery_required/terminal_unknown meaning only if the original typed result is representable and admitted. CV-333 result hashes remain RFC 8785, separate from SP-299's exact arbitrary-precision physical encoder. Known unsupported numeric routes refuse before coupled work wherever knowable; late discovery preserves exact original progress/effects and leaves terminal unavailable. A committed-body recovery_required result needs the same original numeric body facts and cannot bypass that limitation.

Terminal result/outcome/response and selected progress epoch are immutable. Duplicate identity with different original bytes/source refuses; genuine replay returns exact original members with only CV-333 replay decoration and performs no body/event/source reissue. Later original-owner effect recovery may advance progress/head without changing the old terminal selector/hash/snapshot or turning its unknown command into success. Missing original old epoch/result custody makes replay unavailable, not a lookup against the current head. Audit is content-free and does not reconstruct purged input. Actual current installation and audit checks apply after all returning helpers at final staging, publication and disclosure.
