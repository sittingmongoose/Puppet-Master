## Terminal Protocol Fixture Rows And Terminal Record Wire Contract — 2026-11-25

This addendum completes `### Terminal Fixture Matrix And Record Minima` (FABLE Deferred Action Concrete Repair Addendum) for `#SMPFS-124` and `#SMPFS-125` through `#SMPFS-136`. It supplies the fixture rows that the matrix format only described, and gives each of the eleven record minima a closed wire shape and an owner. It creates no WorkNodes, NodeSeeds, executable queues, implementation files, storage families or EventRecord families, and it changes no behaviour that `#SMPFS-127`, `#SMPFS-129`, `#SMPFS-130`, `#SMPFS-158`, `#SMPFS-162`, `#SMPFS-181` or `#SMPFS-183` already state; each expected result below is that unit's rule applied to one byte stream.

### Terminal protocol fixture rows

**Replay inputs.** The `input_bytes` column is the replay byte stream itself. It is written with C escapes: `\e` is 0x1B, `\a` is 0x07, `\\` is one backslash, `\xHH` is the byte HH, and every other character is its ASCII byte. `<S>` stands for the fixture session's shell-integration secret, which the harness mints per run and substitutes before replay. `<N × c>` stands for exactly N copies of the byte `c` (N written in decimal), so a long stream is still one exact byte sequence. A row that names a file or shared-memory object states its exact path or name, its bytes and who creates it; the harness creates it before replay and checks afterwards whether it still exists. On the Windows build the harness maps a `/tmp/` or `/var/tmp/` path to the matching folder under its own temporary folder and a shared-memory name to a named shared memory object of the same name, and substitutes the base64 of the mapped path the way it substitutes `<S>`; the expected result is the same. A row whose input is a user action (paste, focus change, mouse click, pasteboard content) states the action and the bytes Puppet Master must write to the PTY. The `input_bytes` column is the normative replay data; no replay file or screen hash is checked into `Plans/`, because the planning phase has no reference parser and `<S>` is minted per run. The matrix's grouping fields map onto each row as follows. `input_bytes_ref` names the corpus file `terminal-fixtures/<fixture_id>.bin` that the build's harness writes from the decoded `input_bytes` (with `<S>` and any mapped path substituted) before each replay. `expected_screen_hash` is the SHA-256 of the reference parser's screen state after replay; it is unpinned until the reference parser exists, is then pinned in the corpus manifest on the first run that passes every assertion in the row, and may never be pinned from a run that fails one. `expected_event_refs[]` are the records the row's `expected_result` names, compared as normalized records (below); a row that names none expects none beyond the session's ingestion, backpressure and render records. The assertions in `expected_result` are normative; the hash only detects later drift.

**Harness defaults.** 80 columns by 24 rows, main screen, terminal focused, user looking at the tab, local session typed by the user, OSC 52 policy `allow`, bracketed paste, focus reporting, mouse reporting and synchronized output off until the stream enables them. A row states any change to these.

**Every row three ways.** Each row is replayed (1) whole, (2) split at every byte boundary into two reads (`#SMPFS-130`), and (3) on the macOS, Linux, Windows and WSL builds of the parser. All replays of a row must give the identical screen state, PTY replies and normalized records; no byte of a control sequence may appear in the grid in any of them. The normalized records are every record emitted while the stream is replayed except `TerminalIngestionReceipt`, `TerminalBackpressureState` and `TerminalRenderFrame`, in emission order, with the fields each run mints itself removed (`terminal_session_id`, the record's own identifier `receipt_id`, `event_id`, `anchor_id`, `decision_id`, `snapshot_id` or `diagnostic_id`, and every field ending `_utc`) and each `ref` replaced by the content it names; the session-start `TerminalProfileResolution` is not part of a replay. The three excluded records follow read boundaries and paint timing, so a split replay legitimately yields more of them and different `byte_count` and `protocol_family` values (a read can end inside an OSC); for them every replay must instead show that the `accepted_by_pty` receipts and the `parsed_to_grid` receipts each sum their `byte_count`, accepted or not, to the length of the decoded stream, that every receipt is `accepted: true` unless the row names a rejection, and that the last render frame's `screen_hash` is the hash of the final screen state. A row's own frame assertion (such as `tpf-sync-update`) must hold in every replay.

### Terminal record wire contract

The eleven records of `### Terminal Fixture Matrix And Record Minima` are values of the Puppet Master terminal engine (`#SMPFS-184`). Their owner is the engine instance of the one terminal session named by `terminal_session_id` (`TerminalProfileResolution`: the engine instance that is starting that session); they live in memory for that session and are dropped when it ends. None of them is a storage family, a storage value, an EventRecord or a seglog row. What a terminal keeps across restarts is exactly what `Plans/storage-plan.md#SP-332` keeps (the session record and the saved scrollback with its command records); none of these eleven is added to it, and a restored tab mints new anchors rather than reading old ones.

**Wire shape.** When a record leaves the engine it is one JSON object (RFC 8259, UTF-8) with exactly the record's minimum fields plus `record_type`, a constant equal to the record name, and `schema_version`, the constant `"1.0.0"`. Unknown fields, missing required fields and values outside the types below are refused; a field marked `?` may be absent but is never `null`. A record leaves the engine only over the boundaries its row names: the web GUI terminal transport (DL-139, `Plans/FinalGUISpec.md#F3-583`), the user-requested diagnostic bundle (`#SMPFS-076`, which carries shell content only as transcript content it labels absent, partial or included), the in-process accessibility bridge (`#SMPFS-126`, `#SMPFS-131`), and agent reads (`#SMPFS-182`).

**Field types.** `id`: string matching `^[A-Za-z0-9][A-Za-z0-9._:-]{0,127}$`. `utc`: RFC 3339 instant ending in `Z`. `count`: integer 0 to 2^64−1. `ref`: opaque string of 1 to 256 bytes naming an in-memory buffer of the same session; it is never a path and never carries the content. Inside the engine's process (the accessibility bridge and agent reads) the reader resolves a `ref` against the engine's own buffer. The web GUI terminal transport crosses a process boundary, and the remote web client shares no memory with the Server's engine, so there a `ref` is resolved against the transport message rather than shared memory: the message that carries a record also carries, beside the record object and keyed by the record's `ref` value, the content the receiving side needs, and the receiver keeps that content under the same `ref` in its own copy of the session for as long as the session's buffer would. Client to Server, a `TerminalInputEvent` message carries the input bytes named by `payload_ref`; Server to client, a `TerminalRenderFrame` message carries the changed grid rows named by each `dirty_region_refs[]` entry (the row diff the web terminal draws, `Plans/FinalGUISpec.md#F3-583`), and a `TerminalAccessibilitySnapshot` message carries the text named by `screen_reader_text_ref`. The record object itself is still exactly its row's fields, so the refusal of unknown fields is unchanged, and the content beside it is never written to the diagnostic bundle except as `#SMPFS-076` allows. `hash`: `^[0-9a-f]{64}$` (SHA-256). `path`: absolute path string as the host reports it. `bool`: JSON boolean.
