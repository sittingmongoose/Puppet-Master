## Teach Capture, Confirm, and Cancel Schema Addendum (2026-11-28)

Closes the owner-schema definitions referenced by `Plans/Commands_System.md` central command contract records for `cmd.chat.teach.capture`, `cmd.chat.teach.confirm`, and `cmd.chat.teach.cancel` and by `Plans/agent-rules-context.md` (Standing instructions current binding). All three commands retain `handler_unavailable` until native handler admission, and no EventRecord family is admitted by this addendum.

- `cmd.chat.teach.capture` (`handlers::assistant_memory::teach_capture`): `Plans/assistant_memory_contracts.schema.json#/$defs/TeachCaptureRequest` -> `Plans/assistant_memory_contracts.schema.json#/$defs/TeachCaptureResult`. Opens the Teach sheet in `mode: new | correct` from `origin_surface: slash | natural_language | message_menu | wand | teach_document` with `persisted: false` on every result (`status: opened | refused`). Supports both Project scope (`scope_kind: project`, non-empty `project_id`, `application_scope` forbidden) and genuine application scope (`scope_kind: application`, `project_id: null`, required `application_scope` matching `WorkflowScopeV2` with `scope_kind: application`, `scope_partition: app`, `project_id: null`, `project_home_server_id: null`, `named_plan_id: null`, and non-empty `server_id`). Chat origin surfaces require a non-empty `thread_id`; `teach_document` (Standing instructions) permits `thread_id: null` without fabricating a synthetic thread id. `mode: correct` requires `target_memory_id` or `target_rule_source` (`app.agent_rules.application_markdown` | `.puppet-master/project-rules.md`).
- `cmd.chat.teach.confirm` (`handlers::assistant_memory::teach_confirm`): `Plans/assistant_memory_contracts.schema.json#/$defs/TeachConfirmRequest` -> `Plans/assistant_memory_contracts.schema.json#/$defs/TeachConfirmResult`. Preserves Project-scoped confirm (`scope: project`, non-empty `project_id`, optional `target_rule_source: .puppet-master/project-rules.md`, `application_scope` forbidden) and extends `TeachConfirmRequest` to accept genuine application-scoped saves for Rules for every project (`scope: user`, `project_id: null`, `public_safe: true`, required `application_scope` `WorkflowScopeV2` with `scope_kind: application`, optional `target_rule_source: app.agent_rules.application_markdown` and `expected_revision`), refusing any `project_id: null` save without `application_scope` and refusing any non-null `project_id` on `app.agent_rules.application_markdown`. Legacy `scope: thread` retains non-empty `thread_id`; `scope: project` and `scope: user` accept `thread_id: null` when invoked from `teach_document` without an active chat thread. That `thread_id: null` acceptance (here and on capture) is owner-layer only: the outer `ChatOwnerCommandRequestV2` / `ChatOwnerCommandResultV2` envelope in `Plans/application_workflow_contracts.schema.json` requires a non-empty `thread_id`, so a thread-less Standing instructions invocation is not dispatchable until an admitted thread-less Settings envelope exists (`Plans/agent-rules-context.md` current binding).
- `cmd.chat.teach.cancel` (`handlers::assistant_memory::teach_cancel`): `Plans/assistant_memory_contracts.schema.json#/$defs/TeachCancelRequest` -> `Plans/assistant_memory_contracts.schema.json#/$defs/TeachCancelResult`. Discards a pending Teach capture draft without writing (`persisted: false`, `status: cancelled | refused`), supporting both Project scope (`scope_kind: project`, non-empty `project_id`, `application_scope` forbidden) and genuine application scope (`scope_kind: application`, `project_id: null`, required `application_scope` `WorkflowScopeV2` with `scope_kind: application`).
