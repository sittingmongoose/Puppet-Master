### Windows console component deployment

DL-035 requires PM to ship a PM-managed, version-pinned Windows console component package (ConPTY/OpenConsole). Release Supply Chain owns the exact trusted installation and loader/component pairing, official-source/build provenance, hashes/signing, SBOM/license evidence, compatible component layout/exports/ABI/architectures, release/update ownership and rollback for this package, consuming the existing binary-provenance, install/update and RSC-008 minimum gates. Package publication alone is not proof that the installed component pair is compatible. Unverified, unpinned or silently substituted components must not be admitted.

When the bundle is absent, untrusted or incompatible, PM uses an explicit, disclosed fallback to the operating-system copy. Preserve the actual source/version and fallback reason for the Section15 host-provenance doctor (SMPFS-132), and disclose version-dependent effective behavior. An unavailable or unsupported OS copy yields honest capability loss/startup failure; fallback does not relax platform acceptance or widen supported Windows versions. A component update or fallback must not hot-swap a live process host, duplicate its session, or replay a command. Failed update/rollback must leave an explicitly verified usable component path or an actionable unavailable state. Console creation failures remain typed against the exact session under the process-host contract; an uncertain startup outcome is not permission to try the other copy blindly or duplicate a possibly started process.

This package is the approved Windows OS-component deployment boundary. Section15 owns PM's VT parser, grid/scrollback, selection, command-block overlay, renderer adapter and direct-OS-API PTY host. No third-party emulator, parser or PTY-abstraction library, or code copied from a reference terminal, is admitted into those PM components by this packaging policy. Reference terminals remain study subjects only.

Release acceptance exercises absent, untrusted and incompatible bundles, installation/provenance verification, console creation failure, the supported-host resize/Unicode/teardown matrices, failed update and rollback, and visible bundle-versus-OS source/version/fallback disclosure. Preserve the R1/R2 engine/host fixtures retargeted to PM's own implementation in Section15, including independent process completion and retained-output/read completeness. These are acceptance obligations, not executed results; this owner amendment selects no Windows support expansion or terminal engine dependency and creates no new PlanUnit.
