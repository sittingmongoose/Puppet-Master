## 7. Backup, restore, compaction, and optional storage enhancements

- **Compaction:** Normative mechanics are in `Case L durable-state owner canon` below. Compaction copies the exact retained set into a verified successor generation, preserves semantic identities, publishes through the same-directory `CURRENT` pointer, and never rewrites a closed source segment.
- **Backup/restore:** Verified shared-boundary backups are required for canonical non-rebuildable redb state. Amended 2026-10-31 (DL-270): per BRS-031 a brief capture barrier records one consistent point; sealed segments and payload packs copy in the background incrementally; redb copies from a read snapshot; derived families are not backed up; and no writer lock is held while copying. The backup surfaces show the last verified backup, its level and what a restore from it would lose (BRS-031). Restore is selected in the startup recovery shell but executes offline through staged verification and a durable journal; JSON/JSONL exports are not restore inputs.
- **Export:** Amended 2026-10-31 (DL-270): export thread or run history as JSONL or JSON on request through `pm export`, read from seglog and the render pages and filtered by thread_id, with optional `pm export --sqlite` (SP-342); no JSONL mirror exists to read from (SP-339). `pm db dump`, `pm inspect` and `pm tail` (SP-339) are command-line reads with no `cmd.*` id; they are recorded in the command catalog's disposition table (UCC-212, CS-107), not registered as User Commands. The in-app record inspector opens through the existing `cmd.storage.open_value`. The reclaim action in storage health is the existing `cmd.storage.compaction.request` (SP-340).
- **Read replicas:** Not applicable for embedded redb; if we move to a server-backed store later, read replicas can serve dashboard/Usage reads.
- **Per-project seglog:** The MVP seglog is app-global under `storage/seglog`; EventRecord scope partitions projects. Per-project physical logs are deferred and are not specified by this plan.
- **Event schema registry:** Required infrastructure for payload validation and doc generation; this plan owns payload registry/workflow while `Plans/Contracts_V0.md` owns the top-level envelope.
- **Streaming projector:** Optional richer UX path; correctness still depends on committed projector state and durable checkpoints.
