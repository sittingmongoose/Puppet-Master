  - Locked function contract (2026-11-25; the `-> String` signature in ARC-009 stays as an illustration of the formatted text only): the pipeline is `get_agent_rules_context(request: &AgentRulesContextRequest) -> AgentRulesContextResult`. It never panics and never returns a bare string; every outcome is a result. Each `warnings[]` and `errors[]` entry is `{code, source_path?, detail}` where `code` is closed. Warning codes: `project_rules_missing` (a project is set but `.puppet-master/project-rules.md` does not exist; Project rules are omitted), `scoped_agents_skipped` (a scoped `AGENTS.md` was outside the cone or disabled by `scoped_agents_enabled`), `budget_threshold_exceeded` (bytes over the warn threshold, non-strict), `truncated` (deterministic truncation per ARC-029 removed illustrative sections; ARC-030 records it). Error codes: `invalid_request` (a typed-request rule below is broken: for example missing `request_id`, `computer_id` or `application_rules_ref`, neither `thread_id` nor `run_id`, `project_id` and `project_rules_ref` not present together, or `max_bytes` not a positive integer), `source_revision_stale` (a source's current revision differs from the one named in `source_revisions[]`; the caller re-resolves the revisions and starts again), `application_rules_unreadable`, `project_rules_unreadable` (the file exists but cannot be read or is not valid UTF-8), `budget_exceeded_strict` (strict mode is on and the block is still over `max_bytes` after truncation). Partial-output decision: the result is usable if and only if `errors[]` is empty. With warnings only, `formatted_block_ref` names the assembled block and the caller prepends it (ARC-010). With any error, `formatted_block_ref` is null, `byte_count` is 0, and the caller must not start the agent run: Orchestrator, Interview and Assistant refuse that dispatch with the first error code as the reason. No caller may fall back to a partial block, for example application rules alone when project rules exist but are unreadable. The pipeline does not retry. A read error is evaluated again only when the caller starts again or the user retries; `invalid_request` and `budget_exceeded_strict` stay failed until their input changes.
  - Typed request (2026-11-26; carries ARC-009's scope-aware input, so the field list in the bullet above is extended, not replaced). `AgentRulesContextRequest`: `request_id` string (UUID); `caller` closed enum `orchestrator | interview | assistant`; `computer_id` string (required: the actual work Computer whose applicable application context is read, ARC-004; it is never a Project identity); `thread_id?` string and `run_id?` string (the application/thread identity: Interview and Assistant carry `thread_id`; Orchestrator carries `run_id`, plus the `thread_id` of the thread that started the run when there is one; at least one of the two is present); `project_id?` string and `project_rules_ref?` string (present together exactly when a Project is bound; both absent is `project_path=None`, which omits Project rules only); `application_rules_ref` string; `source_revisions[]` array of `{source_ref, revision}` objects, both strings, with one entry for each source the caller resolved: the application-rules record `app.agent_rules.application_markdown` (always), the work Computer's application context (when it exists) and `.puppet-master/project-rules.md` (when a Project is bound, its revision being the SHA-256 of the file bytes); `scoped_agents_enabled` boolean; `max_bytes` integer, at least 1; `created_at_utc` string (RFC 3339 UTC). The pipeline reads exactly the named revisions and never substitutes a newer one; app sidecar paths it reports are named by the request's real `computer_id`, `thread_id` and `run_id`, never a Project placeholder. `AgentRulesContextResult` keeps the fields listed above.
