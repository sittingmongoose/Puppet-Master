  - Locked function contract (2026-11-25; the `-> String` signature in ARC-009 stays as an illustration of the formatted text only): the pipeline is `get_agent_rules_context(request: &AgentRulesContextRequest) -> AgentRulesContextResult`. It never panics and never returns a bare string; every outcome is a result. Each `warnings[]` and `errors[]` entry is `{code, source_path?, detail}` where `code` is closed. Warning codes: `project_rules_missing` (a project is set but `.puppet-master/project-rules.md` does not exist; Project rules are omitted), `scoped_agents_skipped` (a scoped `AGENTS.md` was outside the cone or disabled by `scoped_agents_enabled`), `budget_threshold_exceeded` (bytes over the warn threshold, non-strict), `truncated` (deterministic truncation per ARC-029 removed illustrative sections; ARC-030 records it). Error codes: `invalid_request` (missing `request_id` or `application_rules_ref`, or `max_bytes` not a positive integer), `application_rules_unreadable`, `project_rules_unreadable` (the file exists but cannot be read or is not valid UTF-8), `budget_exceeded_strict` (strict mode is on and the block is still over `max_bytes` after truncation). Partial-output decision: the result is usable if and only if `errors[]` is empty. With warnings only, `formatted_block_ref` names the assembled block and the caller prepends it (ARC-010). With any error, `formatted_block_ref` is null, `byte_count` is 0, and the caller must not start the agent run: Orchestrator, Interview and Assistant refuse that dispatch with the first error code as the reason. No caller may fall back to a partial block, for example application rules alone when project rules exist but are unreadable. The pipeline does not retry. A read error is evaluated again only when the caller starts again or the user retries; `invalid_request` and `budget_exceeded_strict` stay failed until their input changes.
