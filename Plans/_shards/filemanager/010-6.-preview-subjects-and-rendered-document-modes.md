## 6. Preview subjects and rendered document modes

Preview subjects preserve the source file or artifact identity before selecting a renderer. Markdown, Mermaid, HTML, SVG, image, and generated document previews use shared preview/session identity so chat, editor, browser, and FileManager links resolve to the same subject instead of opening unrelated panes. Amended 2026-11-23 (`DL-2601`, `F-162`, `DR-093`): large Markdown file previews respect `F-028`'s configured hard file cap and truncation while using virtualized parser-confirmed closed-block chunking (`~4 KiB` UTF-8 byte target chunks, single blocks over `128 KiB` UTF-8 bytes shown as raw source, link/footnote reference definitions extracted strictly across the admitted buffer revision without scanning past truncation, `Select All` selecting the full admitted range and Copy writing it to the clipboard, and revision-checked `RTIM-033` task checkbox edits allowed only in writable buffers); `F-070` `preview_untrusted` subjects and `§11.5` Backup snapshot browsing automatically set the `inert` pipeline option with no user toggle or Settings row (non-navigable links, zero image/network/filesystem fetches, suppressed content mutation actions, raw HTML escaped as text); and relative image/sibling-link resolution keeps image paths literal and runs inside the unified `ACD-643` dispatch order before unknown-scheme rejection, applying a strict literal-first path-vs-`:line[:col]` order covering `notes:12`, `2026-11-23T14:05/README.md`, root-level `README.md`, Windows drive paths, blocked UNC fetches, and spaces.
