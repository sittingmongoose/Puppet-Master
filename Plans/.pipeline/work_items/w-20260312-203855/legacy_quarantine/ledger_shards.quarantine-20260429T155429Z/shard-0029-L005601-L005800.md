L005695: ### Resume-url implication
L005696: - `resume_url` is the clearest existing deep-link contract, but it is too narrow to carry the full cross-surface model by itself.
L005697: - Recommended rule:
L005698:   - keep human-meaningful deep-link URLs for recovery/resume
L005699:   - but normalize their decoded payload into the same routing contract used by in-app search and command routing
L005700: - That avoids a split world where URL-based navigation and in-app navigation speak different schemas.

L005702: ### Search-result direction
L005703: - Search results should not merely open a page; they should reconstruct context.
L005704: - Good rule:
L005705:   - search result activation restores the correct scope before selecting the target
L005706: - Example:
L005707:   - for historical Orchestrator objects:
L005708:     - set `focused_run_id`
L005709:     - switch to the correct tab
L005710:     - apply any filter payload
L005711:     - open inspector on the target object
L005712: - Same idea applies to:
L005713:   - `Show in Ledger`
L005714:   - `Show in Usage`
L005715:   - `Resume Wizard`
L005716:   - thread message deep links

L005719: - Runtime artifacts and receipts already imply good pivot behavior:
L005720:   - preserve canonical usage identity
L005721:   - preserve run/thread/attempt/worktree linkage
L005722:   - do not invent feature-local routing semantics
L005723: - The next-step recommendation is:
L005724:   - all “Open in …” / “Show in …” actions should become thin wrappers over the shared routing payload

L005726: ### Persistence implication
L005727: - Because earlier research established `focused_run_id`, historical-run mode, and project-state persistence, routing needs a persistence-aware rule:
L005728:   - some route activations should update stored view state
L005729:   - others should be transient focus changes only
L005730: - Example:
L005731:   - explicit search navigation to a historical run likely should update persisted Orchestrator focused-run state
L005732:   - hover previews or temporary compare pivots should not necessarily rewrite persistent state
L005733:
L005734: ### Trust / stale-data implication
L005735: - Routing also intersects with projection trust.
L005736: - Good rule:
L005737:   - if the target surface is degraded, the route should still land on the canonical fallback representation when possible rather than fail opaque
L005738: - Example:
L005739:   - deep link to a concern during projection degradation might route to exact record view / Ledger-backed inspector instead of the normal rollup tab presentation
L005740:
L005741: ### Contradictions / gaps surfaced
L005742: - Current docs have several route-like mechanisms, but they are still defined per feature rather than by one shared navigation payload.
L005743: - Without normalization, the app will likely accumulate:
L005744:   - inconsistent result activation behavior
L005745:   - duplicate context reconstruction logic
L005746:   - subtle mismatches between command palette, search, widgets, and deep links
L005747: - `resume_url` is currently stronger than some Orchestrator pivots in terms of specificity, which suggests the more generic routing layer is still underdefined.
L005748:
L005749: ### Candidate fixes to carry forward
L005750: - Define one shared routing/deep-link payload for search, command palette, widget drill-downs, recovery links, and cross-surface pivots.
L005751: - Add stable `object_kind` / `object_id` vocabulary for the newer Orchestrator object model and adjacent runtime actors.
L005752: - Make route activation restore scope, not just surface.
L005753: - Normalize “Open in …” and “Show in …” commands as adapters over the same routing payload.

L005755: ### Do-not-forget details

L005757: - URL deep links and in-app search routes should decode to the same internal navigation model
