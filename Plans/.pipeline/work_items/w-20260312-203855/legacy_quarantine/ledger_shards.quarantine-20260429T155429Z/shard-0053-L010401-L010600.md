L010494: ### Key findings
L010495: - The bridge fields now want a precedence rule, not just a field inventory.
L010496: - `provider_attempt_ref` appears on `attempt_record` and is the closest thing to a provider/runtime execution trace handle.
L010497: - `usage_event_ref` appears on receipts and Usage/docs as the canonical bridge into Ledger/Usage history.
L010498: - receipt records already carry the external-operation lineage:
L010499:   - Source Control / repo/worktree/branch
L010500:   - GitHub workflow/job/step
L010501:   - Docker context/image/publish/template
L010502:   - Kubernetes context/namespace/workload/rollout
L010503: - Those three are not substitutes for one another. They are bridges to different layers of the same attempt.
L010504:
L010505: ### Recommended bridge-field rule
L010506: - `attempt_id` remains the canonical local runtime execution anchor.
L010507: - `provider_attempt_ref` is the canonical bridge to provider/runtime execution details for that attempt.
L010508: - `usage_event_ref` is the canonical bridge to cost/usage history for that attempt or artifact.
L010509: - receipt records are the canonical bridge to external side-effect lineage for that attempt.
L010510:
L010511: ### Practical join model
L010512: - start from `attempt_id`
L010513: - from there:
L010514:   - follow `provider_attempt_ref` to provider/runtime trace and low-level execution evidence
L010515:   - follow `usage_event_ref` to canonical Usage/Ledger identity
L010516:   - follow receipt refs to Git/Actions/Docker/Kubernetes lineage
L010517:   - follow `artifact_id` / `linked_artifact_id` for renderable outputs and evidence objects
L010518:
L010519: ### Important non-rule
L010520: - none of these bridge fields should become a replacement primary key:
L010521:   - `provider_attempt_ref` does not replace `attempt_id`
L010522:   - `usage_event_ref` does not replace runtime identity
L010523:   - receipt refs do not replace artifact identity
L010524:

L010527:   - `attempt_id`
