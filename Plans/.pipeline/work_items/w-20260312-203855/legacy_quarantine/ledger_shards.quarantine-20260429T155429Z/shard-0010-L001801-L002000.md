L001929:   - ownership is still described as run/tier/subtask worktree ownership
L001930:   - Source Control rows expose `owner run/tier when present`

L001939:   - MiscPlan cleanup = cleaning files inside a workspace/worktree
L001940:   - this distinction exists, but the UI/state model does not yet clearly separate lane lifecycle from cleanup actions

L001942: ### Emerging boundary model
L001943: - Recommended boundary:
L001944:   - `Orchestrator` owns package lane-pool operational truth for the active run:
L001945:     - which package owns which lane pool
L001946:     - which lane is baseline vs active vs suspect/restoring vs historical/retired
L001947:     - why a lane is blocked, weakly integrated, or cleanup-eligible
L001948:     - which action is allowed from runtime/governance state
L001949:   - `Source Control` owns repo/worktree execution and inspection operations:
L001950:     - open
L001951:     - compare
L001952:     - diff/history/graph
L001953:     - recover
L001954:     - archive/prune/remove when policy permits
L001955:     - explicit disabled reasons for destructive actions
L001956: - Practical interpretation:
L001957:   - Orchestrator should be the stronger lane/worktree operations overview.
L001958:   - Source Control should be the narrower but deeper Git/worktree inventory and manipulation surface.
L001959:   - Orchestrator CTAs should route into Source Control for Git-native operations with exact project/run/package/lane/worktree context preserved.

L001961: ### Candidate object model shift
L001962: - Existing doc wording implies `worktree` is the primary user-visible object.
L001963: - Rewrite direction implies a new object stack:
L001964:   - `Feature Seam`
L001965:   - `Work Package`
L001966:   - `Lane`
L001967:   - `Worktree`
L001968: - Recommended modeling rule:
L001969:   - `Lane` becomes the primary operational object in Orchestrator.
L001970:   - `Worktree` remains the concrete filesystem/Git backing for a lane instance.
L001971:   - a lane may preserve historical identity after the live worktree has been cleaned up, archived, or removed.
L001972:   - Source Control can still list worktrees directly, but should also expose lane/package ownership and lifecycle state when known.
L001973:
L001974: ### Lifecycle state direction
L001975: - Current docs have action verbs like `recover`, `prune`, `remove`, and `Clean all worktrees`, but not a strong shared lane lifecycle.
L001976: - Recommended lane/worktree lifecycle vocabulary:
L001977:   - `baseline`
L001978:   - `active`
L001979:   - `suspect`
L001980:   - `restoring`
L001981:   - `retained`
L001982:   - `cleanup_eligible`
L001983:   - `archived`
L001984:   - `removed`
L001985:   - `historical`
L001986: - Working interpretation:
L001987:   - `historical` is record truth and can coexist with `archived` or `removed`
L001988:   - `archived` means lane/worktree metadata and lineage stay visible, but the live execution surface is no longer active
L001989:   - `removed` means the live worktree directory is gone
L001990:   - `cleanup_eligible` is a policy/queue state, not the same thing as already removed
L001991:   - `suspect` and `restoring` are operational states visible in Orchestrator first and in Source Control second
