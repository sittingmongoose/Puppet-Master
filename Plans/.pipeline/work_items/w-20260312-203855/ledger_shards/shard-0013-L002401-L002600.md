L002401:   - redb/Tantivy/JSONL are disposable projections
L002402:   - replay/rebuild targets a deterministic `target_seq`
L002403:   - UI freshness notifications should derive from committed projection state, not ad-hoc polling
L002404: - Usage already names the user-trust problem clearly:
L002405:   - stale values surprise users
L002406:   - trust drops when the UI presents old numbers as if they are current
L002407:   - current mitigation pattern is `Last updated` plus an explicit `Refresh`
L002408: - FinalGUISpec already has compatible safety rules:
L002409:   - event/projection streams are the correctness source
L002410:   - the GUI must not imply hidden fallback or hidden retry behavior
L002411:   - blocked/recovery actions bind to canonical projections/records
L002412: - What is still missing is an explicit shared trust policy for all projection-backed surfaces, especially Orchestrator tabs.
L002413:
L002414: ### Recommended trust-state model
L002415: - Recommended projection trust states:
L002416:   - `current`
L002417:   - `refreshing`
L002418:   - `stale`
L002419:   - `degraded`
L002420:   - `unavailable`
L002421: - Working interpretation:
L002422:   - `current`: projection is caught up enough for normal use
L002423:   - `refreshing`: old committed projection still visible while refresh/rebuild runs
L002424:   - `stale`: projection is usable for context but may not reflect current runtime truth
L002425:   - `degraded`: projector/scan partially failed or a dependency signal is missing; some fields/sections are less trustworthy
L002426:   - `unavailable`: projection cannot currently answer the surface contract
L002427:
L002428: ### Action-gating direction
L002429: - Strong recommendation:
L002430:   - read-only navigation may continue on `stale` and some `degraded` projections if the UI says so clearly
L002431:   - live mutating / decision-bearing actions must tighten on trust state
L002432: - Suggested policy:
L002433:   - `current`: all normal actions allowed
L002434:   - `refreshing`: allow normal read actions; mutating actions may continue if backed by runtime truth rather than stale page cache
L002435:   - `stale`: allow inspection and historical navigation; require refresh or direct runtime revalidation before sensitive live actions
L002436:   - `degraded`: restrict to safe inspection and canonical recovery paths; do not allow ambiguous live actions
L002437:   - `unavailable`: route to record-backed fallback views or explicit recovery/refresh actions
L002438: - Important rule:
L002439:   - page state must not silently stand in for runtime state when freshness/trust is insufficient
L002440:
L002441: ### Fallback-view direction
L002442: - Recommended fallback hierarchy:
L002443:   - prefer native projection-backed surface when trust is `current`
L002444:   - if trust drops, keep the surface open but show:
L002445:     - trust badge
L002446:     - last-updated time
L002447:     - degraded reason
L002448:     - refresh / recover action
L002449:   - when necessary, fall back to canonical record-backed views:
L002450:     - `History`
L002451:     - `Ledger`
L002452:     - direct evidence/record inspectors
L002453: - This fits the existing split:
L002454:   - `History` = chronological durable story
L002455:   - `Ledger` = exact record inspection
L002456:   - projection-backed operational views can degrade without erasing auditability
L002457:
L002458: ### UI contract direction
L002459: - Every projection-backed operational surface should expose at least:
L002460:   - trust state
L002461:   - last updated time
L002462:   - degraded/stale reason when not current
L002463:   - whether actions are partially gated
L002464: - Likely good surface behavior:
L002465:   - `Progress`: show run-level trust banner or chip when projections are stale/degraded
L002466:   - `Seams`: allow browsing, but gate actions that depend on current promotion/blocker truth
L002467:   - `Node Graph`: keep historical graph and current selections visible, but flag when live node state may be stale
L002468:   - `Evidence`: artifact browsing can remain available; live verdict/action affordances may gate
L002469:   - `History` / `Ledger`: usually the fallback-safe surfaces because they are closest to canonical records
L002470:
L002471: ### Contradictions / gaps surfaced
L002472: - No shared projection freshness schema is currently obvious across Usage, Orchestrator, Source Control, and other projection-backed surfaces.
L002473: - Usage has concrete stale-data mitigations, but Orchestrator currently lacks equally explicit stale/degraded trust copy and action rules.
L002474: - FinalGUISpec has good safety language, but it does not yet appear to define one reusable trust-state UI contract for projection-backed tabs/widgets/panels.
