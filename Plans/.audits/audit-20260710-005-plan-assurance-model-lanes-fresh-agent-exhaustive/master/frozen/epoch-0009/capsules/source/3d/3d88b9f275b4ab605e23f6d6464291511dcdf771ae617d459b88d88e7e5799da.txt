L00000143	- `text` (single sentence)
L00000144	- `created_at`

L00000173	<a id="4-retrieval-indexes"></a>
L00000174	## 4. Retrieval + indexing contracts
L00000175	
L00000176	Assistant memory retrieval is implemented as:
L00000177	- **Tantivy** lexical search over gist text fields
L00000178	- **USearch** semantic ANN over deterministic embed text
L00000179	
L00000180	### 4.1 Tantivy (lexical)
L00000181	
L00000182	Canonical indexed fields (minimum):
L00000183	- `id` (keyword)
L00000184	- `kind` (keyword)
L00000185	- `status` (keyword)
L00000186	- `verification_state` (keyword)
L00000187	- `pinned` (bool/keyword)
L00000188	- `tags` (keyword/text)
L00000189	- `claims_text` (text; concatenated)
L00000190	- `summary` (text)
L00000191	- `details` (text; optional)
L00000192	- `updated_at` (date/numeric)
L00000193	
L00000194	Rule: Lexical index updates MUST be delete+add by `id`, and full lexical rebuild MUST be supported from `assistant_memory.redb`.
L00000195	ContractRef: ContractName:Plans/storage-plan.md, ContractName:Plans/assistant-memory-subsystem.md#7-gui-and-maintenance
L00000196	
L00000197	### 4.2 USearch (semantic ANN)
L00000198	
L00000199	Canonical mapping:
L00000200	- Vector entry -> `MemoryGist.id`
L00000201	- Persist ANN state in `assistant_memory_vectors.usearch` via serialize/deserialize
L00000202	- Persist `gist_id -> vector_slot` mapping (and tombstone state) in `assistant_memory.redb`
L00000203	
L00000204	Deterministic embed text:
L00000205	- `embed_text = kind + "\n" + join(tags) + "\n" + join(claims[].text)` (exclude `details`)
L00000206	- `embed_text_hash = sha256_utf8(embed_text)` as lowercase hex SHA-256 over the exact UTF-8 bytes
L00000207	- `text_hash = sha256_utf8(kind + "\n" + join(tags) + "\n" + join(claims[].text) + "\n" + summary + "\n" + details_or_empty)` as lowercase hex SHA-256 over the exact UTF-8 bytes
L00000208	
L00000209	Rule: USearch embeddings MUST be computed from deterministic `embed_text` and MUST use `embed_text_hash` to detect no-op updates and deduplicate repeated Auto triggers.
L00000210	ContractRef: PolicyRule:Decision_Policy.md§2, ContractName:Plans/assistant-memory-subsystem.md#5-verification-and-triggers
L00000211	
L00000212	Rule: Deletes/updates MUST use tombstones and MUST support deterministic periodic full rebuild (re-embed + repack) from canonical `assistant_memory.redb`.
L00000213	ContractRef: ContractName:Plans/assistant-memory-subsystem.md#7-gui-and-maintenance, PolicyRule:Decision_Policy.md§2
L00000214	
L00000215	### 4.3 Canonical write + index update order
L00000216	
L00000217	Canonical write order:
L00000218	1. Write canonical `MemoryGist` change to `assistant_memory.redb`
L00000219	2. Enqueue Tantivy + USearch index updates
L00000220	3. Apply index updates asynchronously
L00000221	4. Expose deterministic rebuild operations for recovery
L00000222	
L00000223	Rule: Canonical writes to `assistant_memory.redb` MUST succeed independently of indexing, and index failures MUST be recoverable without data loss.
L00000224	ContractRef: ContractName:Plans/assistant-memory-subsystem.md#7-gui-and-maintenance, ContractName:Plans/storage-plan.md

L00000228	<a id="5-verification-and-triggers"></a>
L00000229	## 5. Verification + triggers (Evidence-Backed Gists)
L00000230	
L00000231	### 5.1 Verification intent
L00000232	
L00000233	Verification exists to prevent prompt injection of incorrect or stale continuity.
L00000234	
L00000235	Rule: By default, only `verification_state = Verified` gists are eligible for capsule assembly and per-turn retrieval injection.
L00000236	ContractRef: ContractName:Plans/assistant-memory-subsystem.md#6-prompt-injection-contract, PolicyRule:Decision_Policy.md§2
L00000237	
L00000238	### 5.2 Trigger contracts
L00000239	
L00000240	#### 5.2.1 AutoRunBoundary (end of each Assistant run)
L00000241	
L00000242	AutoRunBoundary is invoked exactly once at the end of each Assistant run (after the Assistant produces its final response).
L00000243	It builds **one** candidate gist from run artifacts (changed paths, tool results, commits/PR refs when present) so that memory gists can be generated even when no Plans/SSOT files were touched.
L00000244	
L00000245	Rule: AutoRunBoundary MUST run at the end of each Assistant run and MUST create/update at most **one** `MemoryGist` per run with `source = AutoRunBoundary`.
L00000246	ContractRef: ContractName:Plans/assistant-memory-subsystem.md#5-verification-and-triggers, PolicyRule:Decision_Policy.md§2
L00000247	
L00000248	Rule: AutoRunBoundary MUST deduplicate candidates across runs using `embed_text_hash` and normalized EvidenceRefs (no duplicate persisted gist for identical claim/evidence sets).
L00000249	ContractRef: ContractName:Plans/assistant-memory-subsystem.md#4-retrieval-indexes, PolicyRule:Decision_Policy.md§2
L00000250	
L00000251	Rule: AutoRunBoundary MUST evaluate deterministic verification rules (§5.3) before persisting and MUST set `verification_state` to `Verified` when the rules are satisfied; otherwise it persists as `Unverified`.
L00000252	ContractRef: ContractName:Plans/assistant-memory-subsystem.md#5-verification-and-triggers, PolicyRule:Decision_Policy.md§2
L00000253	
L00000254	Rule: AutoRunBoundary MUST respect `assistant.memory.auto_save_unverified`; when disabled, it MUST drop newly-proposed gists that remain `Unverified` at the end of the run.
L00000255	ContractRef: ConfigKey:assistant.memory.auto_save_unverified, ContractName:Plans/assistant-memory-subsystem.md#9-deterministic-defaults
L00000256	
L00000257	#### 5.2.2 AutoMilestone (promotion event; less frequent)
L00000258	
L00000259	AutoMilestone is a promotion event that runs when verification-relevant evidence becomes available (commit created, PR opened, tests/build/lint completed, artifact produced, or user confirms “done” via GUI action).
L00000260	It MAY create/promote an `Outcome` gist and MAY refresh verification_state.
L00000261	
L00000262	Rule: AutoMilestone MUST be idempotent, MUST be deduplicated per `(gist_id, evidence_ref)` pair, and MUST be rate-limited to at most **once per run**.
L00000263	ContractRef: ContractName:Plans/assistant-memory-subsystem.md#5-verification-and-triggers, PolicyRule:Decision_Policy.md§2
L00000264	
L00000265	Rule: AutoMilestone MUST create/promote at most one `Outcome` gist per run when any milestone occurs: tests transition failing→passing, a commit is created, a PR is opened, or the user confirms “done” via a GUI action.
L00000266	ContractRef: ContractName:Plans/assistant-memory-subsystem.md#5-verification-and-triggers, PolicyRule:Decision_Policy.md§2
L00000267	
L00000268	Rule: If AutoMilestone is triggered in a run, it MUST execute before AutoRunBoundary persistence so the run-end candidate reflects any within-run promotions.
L00000269	ContractRef: ContractName:Plans/assistant-memory-subsystem.md#5-verification-and-triggers, PolicyRule:Decision_Policy.md§2
L00000270	
L00000271	### 5.3 Deterministic verification rules
L00000272	
L00000273	`verification_state` enum:
L00000274	- `Unverified` (default)
L00000275	- `Verified`
L00000276	- `Discarded`
L00000277	
L00000278	Rule: Auto-generated gists MUST be saved as `Unverified` unless they satisfy a deterministic verification rule below.
L00000279	ContractRef: PolicyRule:Decision_Policy.md§2, ContractName:Plans/assistant-memory-subsystem.md#5-verification-and-triggers
L00000280	
L00000281	Rule: A gist MUST transition to `Verified` if and only if ANY holds:
L00000282	1) It has a `Commit { hash, repo_id }` EvidenceRef.
L00000283	2) It has a successful `TestRun` or `BuildRun` EvidenceRef (`exit_code == 0`) AND it has a `Diff` or `Artifact` EvidenceRef.
L00000284	3) It has a `PlanRef` EvidenceRef AND `kind` is `Decision` / `Constraint` / `Preference` / `Landmine`.
L00000285	ContractRef: SchemaID:pm.evidence.schema.v1, PolicyRule:Decision_Policy.md§2
L00000286	
L00000287	Rule: A gist MUST NOT transition to `Verified` if `evidence_refs[]` is empty.
L00000288	ContractRef: SchemaID:pm.evidence.schema.v1, PolicyRule:Decision_Policy.md§2
L00000289	
L00000290	Rule: Manual “Verify” MUST re-run deterministic validation; if validation fails, the gist MUST remain `Unverified` unless `assistant.memory.allow_manual_verify_without_evidence = true` (default `false`).
L00000291	ContractRef: ConfigKey:assistant.memory.allow_manual_verify_without_evidence, PolicyRule:Decision_Policy.md§2
L00000292	
L00000293	Rule: “Discard” MUST set `verification_state = Discarded` and discarded gists MUST be excluded from automatic injection and default search results.
L00000294	ContractRef: ContractName:Plans/assistant-memory-subsystem.md#6-prompt-injection-contract, PolicyRule:Decision_Policy.md§2

L00000298	<a id="6-prompt-injection-contract"></a>
L00000299	## 6. Prompt injection contract (token protection)
L00000300	
L00000301	Memory is continuity and project state. Memory is not rules.
L00000302	
L00000303	Rule: Prompt assembly MUST treat memory as a distinct context source that is separate from application/project rules pipeline output.
L00000304	ContractRef: ContractName:Plans/agent-rules-context.md, ContractName:Plans/assistant-chat-design.md#17-context--truncation
L00000305	
L00000306	### 6.1 Always-loaded capsule (Verified-only by default)
L00000307	
L00000308	Always inject a tiny **Working Set capsule** for the active project:
L00000309	- Budget default: `350` tokens
L00000310	- Sections (fixed order): Project Capsule bullets, Current Thread paragraph, Recent decisions, Recent blockers
L00000311	- Source: eligible gists selected by pins + activation scoring (eligibility defaults to `verification_state = Verified`)
L00000312	
L00000313	Rule: Capsule assembly MUST enforce the configured hard token cap before sending any Assistant prompt.
L00000314	ContractRef: ConfigKey:assistant.memory.capsule_budget_tokens, ContractName:Plans/assistant-chat-design.md#17-context--truncation
L00000315	
L00000316	Rule: Capsule assembly MUST exclude `verification_state != Verified` gists by default. `Unverified` gists MAY be included only by explicit user action; pinned Unverified gists MUST NOT be auto-included unless `assistant.memory.allow_pinned_unverified_injection = true`.
L00000317	ContractRef: ConfigKey:assistant.memory.allow_pinned_unverified_injection, ContractName:Plans/assistant-memory-subsystem.md#5-verification-and-triggers, PolicyRule:Decision_Policy.md§2
L00000318	
L00000319	### 6.2 Per-turn retrieval injection (Verified-only)
L00000320	
L00000321	Per user turn:
L00000322	1. Execute lexical search (Tantivy) + semantic search (USearch)
L00000323	2. Merge/rerank with activation scoring
L00000324	3. Inject up to `N` gists (`N` default `5`)
L00000325	4. Inject only derived `summary` text (1–2 sentences each)
L00000326	
L00000327	Rule: Retrieval injection MUST NOT exceed max item count and MUST remain summary-only.
L00000328	ContractRef: ConfigKey:assistant.memory.max_injected_items_per_turn, ContractName:Plans/assistant-memory-subsystem.md#3-data-model
L00000329	
L00000330	Rule: Retrieval injection MUST exclude `verification_state != Verified` gists by default. `Unverified` gists MAY be included only by explicit user action; pinned Unverified gists MUST NOT be auto-included unless `assistant.memory.allow_pinned_unverified_injection = true`.
L00000331	ContractRef: ConfigKey:assistant.memory.allow_pinned_unverified_injection, ContractName:Plans/assistant-memory-subsystem.md#5-verification-and-triggers, PolicyRule:Decision_Policy.md§2
L00000332	
L00000333	### 6.3 Activation scoring (required components)
L00000334	
L00000335	Activation scoring must include:
L00000336	- `pinned` boost
L00000337	- kind/status weighting
L00000338	- recency decay (`half_life_days`)
L00000339	- access signals (`access_count`, `last_access_at`)
L00000340	- retrieval blend (BM25 + ANN scores)
L00000341	
L00000342	Deterministic activation score:
L00000343	
L00000344	`score = (0.50 * normalized_bm25 + 0.50 * normalized_ann + pinned_boost + kind_status_weight + access_weight) * recency_multiplier`
L00000345	
L00000346	Defaults: `pinned_boost = 0.20` when pinned else `0`; `kind_status_weight = 0.10` for Verified active project gists, `0` for other eligible Verified gists; `access_weight = min(0.15, ln(1 + access_count) * 0.03)`; `recency_multiplier = 0.5 ^ (age_days / effective_half_life_days)`; `effective_half_life_days = half_life_days` unless overridden by the Done rule below. Missing BM25 or ANN scores normalize to `0`; ties sort by newer `updated_at`, then lexical `id`.
L00000347	
L00000348	Rule: Done-status gists MUST decay faster using `effective_half_life_days = half_life_days * 0.5`.
L00000349	ContractRef: ConfigKey:assistant.memory.done_decay_multiplier, ContractName:Plans/assistant-memory-subsystem.md#9-deterministic-defaults
