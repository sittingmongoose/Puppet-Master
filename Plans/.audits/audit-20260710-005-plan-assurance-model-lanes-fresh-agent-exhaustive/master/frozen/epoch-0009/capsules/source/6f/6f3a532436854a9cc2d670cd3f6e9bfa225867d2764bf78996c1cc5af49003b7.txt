L00000801	### Event ordering guarantees
L00000802	
L00000803	1. **Per-node sequential**: All events for a given `node_id` MUST be processed in emission order. The event bus MUST NOT reorder events within a single node's event stream.
L00000804	2. **Cross-node eventual**: Events from different nodes have no guaranteed relative order. Consumers MUST be idempotent and tolerate out-of-order delivery across nodes.
L00000805	3. **Deduplication**: The event bus MUST deduplicate events by `(event_name, node_id, attempt_id, ts)` tuple. Duplicate deliveries are silently dropped.
L00000806	4. **Wakeup coalescing**: Multiple wakeup triggers arriving within a single scheduler pass window are coalesced into one scheduler pass. The `wake_reason` for the pass records the first trigger; additional triggers are logged but do not cause additional passes.

L00000810	### Replan generation lifecycle
L00000811	
L00000812	`replan_generation` is a per-run monotonic `u32` counter starting at `0` for the initial graph.
L00000813	
L00000814	- Increments by exactly 1 each time a replan is applied and the canonical graph is updated via `run.graph_canonical_locked`.
L00000815	- A replan is defined as any structural change to the canonical graph (adding/removing/reordering nodes or edges).
L00000816	- Attempts, safe points, and blocked projections created under generation N become stale when generation increments to N+1.
L00000817	- Stale attempts remain queryable for audit but are never resumable.
L00000818	- There is no practical maximum value.
