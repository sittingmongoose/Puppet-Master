L00000037	## 2. Deterministic defaults (must be autonomous)
L00000038	When multiple valid choices exist and higher-precedence sources do not decide:
L00000039	
L00000040	1) **Prefer the simplest safe default** that does not expand scope.
L00000041	   - Example: choose a single host (GitHub.com) rather than adding multi-host abstractions.
L00000042	
L00000043	2) **Prefer API-only over CLI subprocesses** when both are possible and Spec Lock forbids the CLI.
L00000044	
L00000045	3) **Prefer idempotent behavior**.
L00000046	   - If an operation can be repeated safely, implement it as idempotent (no double-side-effects).
L00000047	
L00000048	4) **Prefer bounded retries**.
L00000049	   - Retries MUST have explicit limits and backoff.
L00000050	   ContractRef: PolicyRule:Decision_Policy.md§2
L00000051	
L00000052	5) **Prefer stable IDs over inferred labels**.
L00000053	    - UI commands use `cmd.*` IDs; event types use stable `type` strings.
L00000054	    - For OpenCode `/server-bridge` decisions, prefer `connection_profile_id` for persisted account/server identity and use `selectable_unit_id` only as an additive scheduler `/debug` field, not as a user-facing replacement for `account_id`.
L00000055	    - Provider-account policy decisions keep `usage_record` growth attribution-relevant: add fields only when they materially affect rollups, explanation, or cross-surface attribution.
L00000056	    - Provider/account `/identity`, execution role, and operational identity remain distinct; `Plans/Prompt_Pipeline.md` (`/Prompt_Pipeline.md`) owns effective runtime record and `/account` resolution steps for binding/identity semantics.
L00000057	    - Debug investigation IDs use `investigation_id` as the grouping identity across evidence, attachments, verification steps, fixes, and existing session IDs; `thread_id`, `run_id`, `dev_session_id`, `terminal_session_id`, and `browser_session_id` remain linked identifiers rather than replacing that grouping key.
L00000058	
L00000059	6) **Prefer current provider/account policy over stale provider tables**.
L00000060	   - Section `6. Provider-specific behavior` rows for Codex/Copilot/Gemini/Cursor/OpenCode are advisory when stale; current selection policy is owned by Contracts, Multi-Account, Models, and provider contracts.
L00000061	   - Remaining provider-table cleanup is an edge-case review for collisions and provider-specific awkward raw names, not a blocker for the core requested/effective account contract.

L00000240	### PolicyRule: no_secrets_in_storage
L00000241	
L00000242	**Scope:** All persistent stores (seglog, redb, Tantivy indexes).
L00000243	
L00000244	**Rule:** Persistent stores MUST NOT contain secrets (tokens, passwords, API keys, OAuth refresh tokens). Tokens live only in the OS credential store (platform keyring). Violations are P0 bugs requiring immediate remediation.

L00000246	**Rationale:** Secrets in persistent stores risk exfiltration via backup, log export, or crash dump. The OS credential store provides encrypted, access-controlled storage.

L00000259

L00000261	### 6.1 Ambiguity (multiple valid choices)
L00000262	
L00000263	
L00000264	**Definition:** The specification leaves open a technical or design choice where multiple options would equally satisfy user intent.
L00000265	
L00000266	**Resolution rule:** Apply a deterministic default from §2. Log to `Plans/auto_decisions.jsonl` with schema `pm.auto_decisions.schema.v1`. No user interaction required.
L00000267	
L00000268	**Examples:**
L00000269	- Choosing a buffer size
L00000270	- Picking a retry count
L00000271	- Selecting a color within a brand palette
L00000272	
L00000273	ContractRef: `PolicyRule:Decision_Policy.md§2`, `SchemaID:pm.auto_decisions.schema.v1`
L00000274

L00000277	### 6.2 Missing User Intent / Insufficient Specification
L00000278	
L00000279	**Definition:** The user has not expressed what they want — the system cannot infer intent because the choice materially affects product behavior or scope. This is NOT a technical implementation detail; it is a product decision only the user can make.
L00000280	
L00000281	**Resolution rule:** The system MUST generate a clarification question. It MUST NOT apply a deterministic default. The clarification question is captured in the requirements quality report (`Plans/requirements_quality_report.schema.json`, field `needs_user_clarification[]`).
L00000282	
L00000283	**Examples:**
L00000284	- "Should the wizard allow importing from a URL or only local files?"
L00000285	- "Should failed iterations retry automatically or pause for user review?"
L00000286	
L00000287	ContractRef: `SchemaID:pm.requirements_quality_report.schema.v1`, `PolicyRule:Decision_Policy.md§4`

L00000292	
L00000293	The §4 rule ("plans must not depend on humans making decisions mid-run") applies to **runtime execution** (orchestrator runs, agent iterations, verification gates).
