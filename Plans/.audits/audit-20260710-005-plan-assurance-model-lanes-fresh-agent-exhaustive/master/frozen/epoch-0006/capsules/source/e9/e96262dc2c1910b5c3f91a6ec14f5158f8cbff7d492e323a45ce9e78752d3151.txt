L00002005	### 11.2 Support-tier vocabulary
L00002006	
L00002007	Support tiers are canonical capability labels:
L00002008	- `native` - provider exposes the operation as a first-class path that PM can map directly.
L00002009	- `native (model)` - the selected model/provider already exposes the capability and PM reuses the same account/auth surface.
L00002010	- `native-ish` / `near-native` - provider has a near-native or near-equivalent path but PM still normalizes or supplements it.
L00002011	- `pm_composed` - PM can synthesize or assemble the operation from lower-level primitives such as provider search, provider fetch, PM-native Site Reader, crawl, or map traversal.
L00002012	- `pm-composed` - display/source-lineage alias for `pm_composed`; stored support-tier canon normalizes to `pm_composed`.
L00002013	- `fallback-only` - provider path exists only as backup and is not the preferred posture.
L00002014	- `partial` - provider supports only a reduced subset of the operation family.
L00002015	- `unsupported` - no supported path exists in MVP.
L00002016	
L00002017	Capability tier and routing posture are separate dimensions. Site Reader primacy for `webfetch` is a routing rule, not a capability erasure.
