L00000171	- `gemini_cli` (`Gemini CLI`) as retired/source-lineage vocabulary only

L00000240	Rules:
L00000241	- `account_id` is the internal stable key.
L00000242	- `provider_identity` is descriptive provider-native metadata only.
L00000243	- secrets remain outside config/state stores; actual `/tokens/keys` remain only in OS credential storage.
L00000244	- separate auth families that change quota semantics remain separate account rows.
L00000245	- the canonical account-registration shape is `{ account_id: ulid, provider_id, display_name, auth_method, credential_ref, created_at, last_used_at, status }`; additive runtime/health fields may extend this shape without replacing the canonical keys.
L00000246	- `status` is the user-facing lifecycle summary and closes to `active | expired | revoked | error`.
L00000247	
L00000248	Field definitions:
L00000249	- `credential_ref` is a pointer to where the credential lives, never the secret itself. Format: `{credential_store}:{key_path}`.
L00000250	- supported `credential_ref` stores are:
L00000251	  - `os_keychain` for OS-native secret stores (macOS Keychain, Windows Credential Manager, Linux Secret Service)
L00000252	  - `env` for environment-variable indirection
L00000253	  - `file` for encrypted file-backed credentials
L00000254	  - `cli` for credentials delegated to an external CLI tool/runtime
L00000255	- example `credential_ref` values:
L00000256	  - `os_keychain:pm/openai/account_abc123`
L00000257	  - `env:OPENAI_API_KEY`
L00000258	  - `file:~/.config/pm/credentials/antigravity_cli.json`
L00000259	  - `cli:antigravity/default`
L00000260	- `auth_surface` is the enum describing where/how the credential is consumed at runtime.
L00000261	- `auth_surface` values are:
L00000262	  - `header_bearer` for `Authorization: Bearer <token>`
L00000263	  - `header_api_key` for provider-specific API-key headers such as `x-api-key`
L00000264	  - `query_param` for API key in query string; this path is deprecated and PM should warn before use
L00000265	  - `cli_managed` when the CLI runtime performs auth internally and PM delegates execution
L00000266	  - `oauth_token` for OAuth2 access tokens attached through the `Authorization` header
L00000267	- each provider definition MUST specify its supported `auth_surface` values so the HTTP client knows how to attach credentials and so account validation can reject incompatible pairings early.
L00000268	
L00000269	Examples:
L00000270	- Codex `ChatGPT` and Codex `API key` rows are separate account rows.
L00000271	- many ChatGPT-backed Codex accounts and many API-key-backed Codex accounts may coexist under the same Codex provider entry; switching, usage display, cooldown behavior, and preferred-account logic must preserve the auth-family identity.
L00000272	- Gemini Direct API-key accounts remain separate from Antigravity CLI account/profile rows because direct API and CLI-runtime routes live on different provider entries. Gemini CLI auth-backed rows are retired/source-lineage only.

L00000355	## 5. Auto-rotation
L00000356	- **Switch boundary:** Switching happens only at attempt/message boundaries. Never switch mid-attempt.
L00000357	- **Soft-threshold boundary:** soft-threshold auto-switch behavior must not switch mid-turn; for soft-threshold pressure, PM waits until a turn/attempt boundary unless hard exhaustion, cooldown, unhealthy account, or another hard failover condition requires in-run retry.
L00000358	- **Completed ownership rule:** A completed message/attempt always belongs to the account it actually used. The next message/attempt re-resolves and may switch immediately.
L00000359	- **Sticky behavior:** Routing is conservative and sticky. A recovered higher-priority account does not immediately steal traffic back unless policy and health justify it.
