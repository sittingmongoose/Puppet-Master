L00000029	## 1. Definitions
L00000030	
L00000031	<a id="DEF-AGENT"></a>
L00000032	### 1.1 Agent
L00000033	
L00000034	An **Agent** is a running AI execution unit. It is a concrete instance within a Puppet Master run — a provider process that receives a compiled context (system prompt, instructions, conversation history) and produces a response stream. The Orchestrator spawns Agents for each node in the run graph. An Agent is ephemeral; it exists only for the duration of its run.
L00000035	
L00000036	ContractRef: ContractName:Plans/Contracts_V0.md, ContractName:Plans/Executor_Protocol.md
L00000037	### 1.2 Subagent
L00000038	
L00000039	A subagent is a child run that resolves a Persona for the child task. It is not merely “the parent Persona, but smaller,” and it is not defined by provider-native agent-file syntax.
L00000040	
L00000041	ContractRef: ContractName:Plans/Tools.md, ContractName:Plans/Prompt_Pipeline.md, ContractName:Plans/CLI_Bridged_Providers.md
L00000042	
L00000043	Rules:
L00000044	- the child Persona may differ materially from the parent Persona.
L00000045	- the child Persona does not auto-inherit from the parent.
L00000046	- provider-native agent files may seed or export Persona content, but PM Persona storage remains canonical.
L00000047	- OpenCode evidence that child sessions with `session.parentID` and compaction requests are force-marked as `agent` is adapter classification evidence only; it does not redefine PM Persona identity or child-run semantics.
L00000048	- crew mode may reuse the same Persona across many members while varying the model/provider selection.
L00000049	
L00000050	ContractRef: ContractName:Plans/Models_System.md, ContractName:Plans/orchestrator-subagent-integration.md, ContractName:Plans/interview-subagent-integration.md
L00000051	### 1.3 Persona (canonical term)
L00000052	
L00000053	A **Persona** is the assigned role definition that shapes an Agent's or Subagent's behavior. It is a static, declarative artifact — a YAML-frontmatter Markdown file — that acts as a **behavior-and-runtime contract**. In addition to identity, instructions, default permissions, and skill references, a Persona MAY declare provider/model/variant preferences, optional runtime control preferences, tool-usage guidance, aliases, and UI-facing metadata. When the Orchestrator or Interview phase manager selects a Persona for a run, the Persona's content and runtime metadata feed both the Agent's compiled context and the effective runtime resolution flow.
L00000054	
L00000055	Expanded scope note: §10.2 is normative and extends this definition without replacing it.
L00000056	
L00000057	**Key distinctions:**
L00000058	
L00000059	| Concept | What it is | Lifetime | Mutability |
L00000060	|---------|-----------|----------|------------|
L00000061	| **Persona** | A role definition (file on disk) | Persistent until user deletes | User-editable via GUI |
L00000062	| **Agent** | A running AI process assigned a Persona | Ephemeral (one run) | Immutable once spawned |
L00000063	| **Subagent** | An Agent spawned by another Agent | Ephemeral (one delegated task) | Immutable once spawned |
L00000064	
L00000065	ContractRef: ContractName:Plans/Glossary.md, ContractName:Plans/Tools.md
L00000066	
L00000067	<a id="DEF-PROVIDER-NATIVE"></a>
L00000068	### 1.4 Separation from provider-native concepts
L00000069	
L00000070	A Persona is **not** a provider-native "agent" (e.g., OpenCode's `Agent.Info`, Cursor's agent definitions under `.cursor/agents/`). Provider-native agent configs are consumed by the Provider facade (`Plans/CLI_Bridged_Providers.md`) as transport-level concerns. Personas are a Puppet Master abstraction that sits above the provider layer.
L00000071	
L00000072	A Persona is **not** a provider-native "skill" or "plugin." Skills (`Plans/Skills_System.md`) are invocable context-injection units. Plugins (`Plans/Plugins_System.md`) are extension modules with hook-based lifecycle. A Persona MAY reference skills via `default_skill_refs` but does not contain skill logic itself.
L00000073	
L00000074	ContractRef: ContractName:Plans/CLI_Bridged_Providers.md, ContractName:Plans/OpenCode_Deep_Extraction.md

L00000078	## 2. Storage layout
L00000079	
L00000080	<a id="STORAGE-LAYOUT"></a>
L00000081	
L00000082	Persona files are stored in a deterministic two-tier layout. Project-local Personas override global Personas by `persona_id`.
L00000083	
L00000084	ContractRef: PolicyRule:Decision_Policy.md§2
L00000085	
L00000086	### 2.1 Project-local
L00000087	
L00000088	```
L00000089	.puppet-master/personas/<persona_id>/PERSONA.md
L00000090	```
L00000091	
L00000092	Scoped to the project workspace root. These Personas are available only when that project is active.
L00000093	
L00000094	### 2.2 Global
L00000095	
L00000096	```
L00000097	~/.config/puppet-master/personas/<persona_id>/PERSONA.md
L00000098	```
L00000099	
L00000100	Available across all projects. Overridden by a project-local Persona with the same `persona_id`.
L00000101	
L00000102	### 2.3 Resolution order
L00000103	
L00000104	When resolving a Persona by `persona_id`:
L00000105	1. If `persona_id` is a protected built-in ID from §6, resolve the PM-owned bundled `PERSONA.md` definition first. User-created project or global files may not shadow protected built-ins.
L00000106	2. Check `.puppet-master/personas/<persona_id>/PERSONA.md` in the active project root.
L00000107	3. If not found, check `~/.config/puppet-master/personas/<persona_id>/PERSONA.md`.
L00000108	4. If not found, the Persona is unresolved. The Orchestrator MUST fall back to a bare-context run (no Persona-specific instructions injected) and log a warning.
L00000109	
L00000110	**Folder-name invariant:** The folder name MUST match the `id` field in the PERSONA.md frontmatter. A mismatch is a validation error.
L00000111	
L00000112	ContractRef: ContractName:Plans/Personas.md#PERSONA-VALIDATION
L00000113	### 2.4 Built-in scope
L00000114	
L00000115	Protected built-ins and bundled first-party specialties use the same `PERSONA.md` schema as user Personas, but their source scope is different:
L00000116	- protected core built-ins are PM-owned, user-immutable, and not deletable or disableable by the user.
L00000117	- bundled first-party specialty Personas are PM-owned defaults that users may customize, disable, and restore to the shipped default.
L00000118	- PM may update shipped protected and bundled definitions across product versions; user immutability does not mean the product definition is permanently frozen.
L00000119	- imported provider-native agent files are seed/import sources only and never become the runtime source of truth.
L00000120	
L00000121	ContractRef: ContractName:Plans/Personas.md#RESERVED-PERSONAS, ContractName:Plans/FinalGUISpec.md

L00000125	## 3. Persona format (schema)
L00000126	
L00000127	<a id="PERSONA-SCHEMA"></a>
L00000128	
L00000129	A Persona file (`PERSONA.md`) consists of YAML frontmatter followed by a Markdown body containing the Persona's system instructions.
L00000130	
L00000131	ContractRef: PolicyRule:Decision_Policy.md§2, ContractName:Plans/DRY_Rules.md
L00000132	
L00000133	### 3.1 YAML frontmatter
L00000134	
L00000135	```yaml
L00000136	---
L00000137	id: "rust-engineer"
L00000138	name: "Rust Engineer"
L00000139	description: "Expert Rust developer specializing in systems programming, memory safety, and zero-cost abstractions."
L00000140	default_mode: "regular"
L00000141	default_platform: null
L00000142	default_permissions_profile: null
L00000143	default_model: null
L00000144	default_variant: null
L00000145	temperature: null
L00000146	top_p: null
L00000147	reasoning_effort: null
L00000148	talkativeness: "model_default"
L00000149	default_skill_refs: []
L00000150	disabled_plugins: []
L00000151	preferred_tools: []
L00000152	discouraged_tools: []
L00000153	tool_usage_guidance: ""
L00000154	tags: ["language", "rust", "systems"]
L00000155	aliases: []
L00000156	---
L00000157	```
L00000158	
L00000159	### 3.2 Field definitions
L00000160	
L00000161	| Field | Required | Type | Description |
L00000162	|-------|----------|------|-------------|
L00000163	| `id` | **Required** | `string` | Unique Persona identifier. See §3.3 for validation rules. |
L00000164	| `name` | **Required** | `string` | Human-readable display name. Max 100 characters. |
L00000165	| `description` | **Required** | `string` | One-paragraph description of the Persona's expertise. Max 500 characters. |
L00000166	| `default_mode` | Recommended | `string` enum | Default run mode (`ask`, `plan`, `regular`, `yolo`) per `Plans/Run_Modes.md`. If omitted, inherits from run config. |
L00000167	| `default_platform` | Optional | `string` or `null` | Preferred provider/platform for this Persona. Runtime resolution and fallback semantics are defined in `Plans/Models_System.md`. |
L00000168	| `default_permissions_profile` | Recommended | `string` or `null` | Named permissions profile to apply when this Persona is active. References a profile defined in the Permissions system (`Plans/Permissions_System.md`). `null` means inherit from run config. |
L00000169	| `default_model` | Optional | `string` or `null` | Default model identifier (`provider_id/model_id`) for this Persona. Selection priority and validation per `Plans/Models_System.md`. `null` means inherit. |
L00000170	| `default_variant` | Optional | `string` or `null` | Default variant name for this Persona (e.g., `"fast"`, `"powerful"`). Variant semantics per `Plans/Models_System.md`. `null` means inherit. |
L00000171	| `temperature` | Optional | `number` or `null` | Preferred sampling temperature when the active provider transport supports it. Unsupported values are recorded as skipped, not silently applied. |
L00000172	| `top_p` | Optional | `number` or `null` | Preferred nucleus sampling value when supported by the active provider transport. |
L00000173	| `reasoning_effort` | Optional | `string` or `null` | Preferred provider-specific effort/reasoning level when supported. |
L00000174	| `talkativeness` | Optional | `string` enum | Persona-level verbosity/collaboration preference. Allowed values: `talk_a_lot_more`, `talk_more`, `talk_a_little_more`, `model_default`, `talk_a_little_less`, `talk_less`. This is a behavior/instruction control, not a provider sampling knob. |
L00000175	| `default_skill_refs` | Recommended | `string[]` | List of skill IDs to auto-load when this Persona is active. References skills per `Plans/Skills_System.md`. Empty array means no auto-loaded skills. |
L00000176	| `disabled_plugins` | Optional | `string[]` | List of plugin IDs to silence during hook dispatch when this Persona is active. Plugins listed here are not unloaded, only skipped during hook invocation. Semantics per `Plans/Plugins_System.md` §7.3. Empty array means no plugins disabled. |
L00000177	| `preferred_tools` | Optional | `string[]` | Tool IDs the Persona should proactively prefer when planning execution. Guidance only by default; it does not override Permissions allow/ask/deny enforcement. |
L00000178	| `discouraged_tools` | Optional | `string[]` | Tool IDs the Persona should avoid unless needed. Guidance only by default. |
L00000179	| `tool_usage_guidance` | Optional | `string` | Freeform tool-planning guidance for this Persona. |
L00000180	| `tags` | Recommended | `string[]` | Categorization tags for filtering and search. Values from: `phase`, `task`, `subtask`, `iteration`, `cross-phase`, `language`, `domain`, `framework`, and freeform tags. |
L00000181	| `aliases` | Optional | `string[]` | Natural-language invocation aliases and display synonyms used during Persona resolution. |
L00000182	
L00000183	### 3.3 Validation rules
L00000184	
L00000185	Persona validation MUST enforce:
L00000186	- `id` uses lower-case kebab-case (`[a-z0-9]+(-[a-z0-9]+)*`) and matches the storage folder name.
L00000187	- `id` is globally unique within its source scope after project/global resolution.
L00000188	- user-created project/global Personas may not use or shadow protected core IDs from §6.
L00000189	- imported provider-native files that collide with protected IDs are imported only as non-authoritative seed material or saved under a non-reserved ID chosen by the user/import flow.
L00000190	- `name` and `description` are required and must stay within the limits in §3.2.
L00000191	- enum fields must use the canonical values from their owner systems.
L00000192	- provider/model/runtime-control preferences are validated against `Plans/Models_System.md` at resolution time; unsupported controls are recorded as skipped or clamped, not silently applied.
L00000193	- `default_skill_refs`, plugin IDs, and tool IDs must reference known registries when those registries are available; unresolved refs are displayed as readiness warnings rather than hidden.
L00000194	- protected core built-ins are read-only to user edit flows, cannot be deleted or disabled, and cannot be project-overridden.
L00000195	
L00000196	ContractRef: ContractName:Plans/Models_System.md, ContractName:Plans/Skills_System.md, ContractName:Plans/Plugins_System.md, ContractName:Plans/Permissions_System.md
L00000197	
L00000198	### 3.3A Field naming alignment with runtime identity
L00000199	
L00000200	Persona-related runtime identity fields align to the shared owner contract:
L00000201	- `requested_persona`
L00000202	- `effective_persona`
L00000203	
L00000204	ContractRef: ContractName:Plans/Contracts_V0.md
L00000205	
L00000206	`_id` variants are retired from canonical runtime payload examples.
L00000207	### 3.4 Markdown body
L00000208	
L00000209	The Markdown body following the frontmatter contains the Persona's system instructions. This content is injected into the Agent's compiled context (see §5). There are no structural constraints on the body beyond valid Markdown. Recommended sections: expertise areas, behavioral guidelines, output format preferences.

L00000215	<a id="GUI-PERSONAS"></a>

L00000217	The primary Persona management surface is **Agent Config > Personas**. Settings remains a routing/help surface for policy-bearing controls and may link into Agent Config, but Settings is not the main Persona prompt browser or editor.
L00000218	
L00000219	ContractRef: ContractName:Plans/FinalGUISpec.md, ContractName:Plans/DRY_Rules.md
L00000220	
L00000221	### 4.1 Personas library and editor (Agent Config > Personas)
L00000222	
L00000223	Agent Config > Personas MUST provide:
L00000224	
L00000225	1. **Library view:** Table of all resolved Personas grouped by protected core, bundled specialty, project-local, global, imported seed, disabled, and advanced/internal where applicable. Columns: Name, ID, Scope, Chat selectable, Child/subagent eligible, Tags, Description (truncated), Readiness, and Source. Sorted alphabetically by display name inside each group; project-local entries sort before global when IDs match.
L00000226	
L00000227	2. **Create:** "New Persona" opens an editor form with fields for `id`, `name`, `description`, `default_mode` (dropdown), `default_platform`, `default_permissions_profile` (dropdown or null), `default_model`, `default_variant`, `temperature`, `top_p`, `reasoning_effort`, `talkativeness`, `default_skill_refs` (multi-select from skill registry), `preferred_tools`, `discouraged_tools`, `tool_usage_guidance`, `aliases`, `tags` (tag input), and a Markdown body editor. L00000228	
L00000229	3. **Prompt visibility:** Selecting a row shows a prompt preview pane and an effective runtime/control summary. The editor must expose the stored Markdown body and a requested/effective compiled prompt preview when enough runtime context is available. Unsupported or skipped controls are shown as skipped, disabled, or clamped rather than silently accepted.
L00000230	
L00000231	4. **Edit:** Row click or edit opens the same editor pre-populated. Editing a global Persona while a project is active offers "Save as project override" (creates project-local copy) or "Save globally." Protected core built-ins are read-only in the editor; users can duplicate them under a non-reserved ID but cannot modify or shadow the protected ID.
L00000232	
L00000233	5. **Disable and restore:** Bundled first-party specialty Personas can be disabled and restored to the shipped default after user customization. Protected core built-ins cannot be disabled. User-created and imported Personas can be deleted with confirmation.
L00000234	
L00000235	6. **Delete:** Delete button with confirmation modal. Deleting a project-local Persona that overrides a global one reveals the global version. Deleting a global Persona with no project override removes it entirely. Delete is not shown for protected core built-ins.
L00000236	
L00000237	7. **Schema validation on save:** On every save, validate the PERSONA.md against the schema (§3). Display inline errors for: invalid `id` format, reserved `id` usage, name/description length violations, invalid `default_mode`, folder-name mismatch, and attempted protected-ID shadowing. Block save until errors are resolved.
L00000238	
L00000239	ContractRef: ContractName:Plans/Personas.md#PERSONA-SCHEMA, ContractName:Plans/Personas.md#PERSONA-VALIDATION

L00000263	## 5. Integration: Persona application to a run
L00000264	
L00000265	<a id="PERSONA-INJECTION"></a>
L00000266	
L00000267	### 5.1 Selection
L00000268	
L00000269	Persona selection must be deterministic and must not silently collapse child roles into the parent Persona.
L00000270	
L00000271	ContractRef: ContractName:Plans/Tools.md, ContractName:Plans/Prompt_Pipeline.md, ContractName:Plans/Run_Modes.md
L00000272	
L00000273	Canonical child Persona resolution order:
L00000274	1. explicitly requested child Persona
L00000275	2. child subagent type or child task-type mapping
L00000276	3. weak parent Persona hint only when compatible and still ambiguous
L00000277	4. safe general-purpose fallback
L00000278	
L00000279	Compatibility guard:
L00000280	- the weak parent hint cannot override the requested child task.
L00000281	- it cannot override runtime/provider restrictions.
L00000282	- it cannot be used to widen permissions or mode.
L00000283	- if no specialized match is safe, the fallback is a general child Persona, not a copy of the parent Persona.
L00000284	
L00000285	Crew default:
L00000286	- crew members normally share the same task framing.
L00000287	- they often share the same Persona.
L00000288	- model/provider diversity, not Persona diversity, is the default defining behavior of crew mode.
L00000289	
L00000290	ContractRef: ContractName:Plans/Models_System.md, ContractName:Plans/FinalGUISpec.md, ContractName:Plans/orchestrator-subagent-integration.md
L00000291	### 5.2 Context injection
L00000292	
L00000293	Persona injection for child runs operates on a reconstructed handoff bundle, not on a blind copy of the parent prompt state.
L00000294	
L00000295	ContractRef: ContractName:Plans/Prompt_Pipeline.md, ContractName:Plans/assistant-memory-subsystem.md, ContractName:Plans/storage-plan.md
L00000296	
L00000297	Child Persona context rules:
L00000298	- inject the effective child Persona content resolved from PM Persona storage.
L00000299	- include current task, working context, required constraints, and requested/effective runtime state.
L00000300	- include the current effective context-shaping state without making a lossy child copy the only truth.
L00000301	- do not forward Assistant memory to child runs.
L00000302	- child runs inherit only the effective compatible subset of parent-allowed tools, skills, plugins, and MCP capabilities.
L00000303	
L00000304	ContractRef: ContractName:Plans/Skills_System.md, ContractName:Plans/Plugins_System.md, ContractName:Plans/Permissions_System.md
L00000305	### 5.3 Run-mode interaction
L00000306	
L00000307	The Persona's `default_mode` field interacts with the run mode system (`Plans/Run_Modes.md`) as follows:
L00000308	
L00000309	| Source | Priority | Description |
L00000310	|--------|----------|-------------|
L00000311	| Explicit run-envelope `mode` | Highest | User- or Orchestrator-specified mode for this run. |
L00000312	| Persona `default_mode` | Lower | Applied only if the run envelope does not specify a mode. |
L00000313	| System default (`regular`) | Lowest | Applied if neither run envelope nor Persona specifies a mode. |
L00000314	
L00000315	ContractRef: ContractName:Plans/Run_Modes.md

L00000332	
L00000333	<a id="RESERVED-PERSONAS"></a>
L00000334	
L00000335	The following Persona IDs are **protected Puppet Master core built-in IDs**. They MUST NOT be used for user-created Personas and MUST NOT be shadowed by project-local or global Persona files. When the corresponding built-in `PERSONA.md` definitions are present, they remain selectable and assignable according to the eligibility table below.
L00000336	
L00000337	ContractRef: PolicyRule:Decision_Policy.md§2, ContractName:Plans/Personas.md#PERSONA-VALIDATION
L00000338	
L00000339	| Reserved ID | Display label | Planned purpose | Chat selectable | Child/subagent eligible | Mutability |
L00000340	|-------------|---------------|-----------------|-----------------|-------------------------|------------|
L00000341	| `assistant` | Assistant | Default direct-chat Persona with broad capability and a warm, collaborative, helpful style. | Yes, default for chat | No | Protected core built-in |
L00000342	| `general-purpose` | General | Broad work-first execution Persona for complex multi-step work that combines inspection, action, and verification. | Yes | Yes | Protected core built-in |

L00000378	## 8. OpenCode baseline and Puppet Master deltas
L00000379	
L00000380	<a id="BASELINE-DELTAS"></a>
L00000381	
L00000382	Per `Plans/OpenCode_Deep_Extraction.md` §7B and §9B:
L00000383	
L00000384	### 8.1 Baseline
L00000385	
L00000386	OpenCode defines agents via `Agent.Info` schema with fields: `name`, `description`, `mode`, `prompt`, `permission`, `model`, `steps`, etc. User-defined agents override via config. Subagents are invoked via the `task` tool. The explore agent is a read-only subagent with a dedicated prompt.
L00000387	
L00000388	### 8.2 Puppet Master deltas
L00000389	
L00000390	1. **Persona as file artifact:** OpenCode stores agent definitions in code (`agent.ts`) and config. Puppet Master stores Personas as files on disk (`PERSONA.md`) in a deterministic layout, enabling user editing, project-level overrides, and GUI management without code changes.
L00000391	2. **Separation from provider-native agents:** OpenCode agents are tightly coupled to the OpenCode runtime. Puppet Master Personas are provider-agnostic; the Provider facade translates Persona instructions into provider-specific invocation.
L00000392	3. **No in-code persona content:** Puppet Master does not hardcode Persona descriptions/prompts in source code. All Persona content lives in `PERSONA.md` files resolved at runtime.
L00000393	4. **Reserved-ID enforcement:** OpenCode has no concept of reserved agent names. Puppet Master reserves IDs for planned future Personas (§6).
L00000394	5. **Provider-native reusable agents:** `Claude Code CLI` native reusable-agent/subagent support is real (`--agent`, `--agents`, and the `agents` command). PM treats that as a native-specialized-agent projection path for Personas when applicable, not as plain prompt stuffing and not as the same primitive as the PM Persona registry.
L00000395
