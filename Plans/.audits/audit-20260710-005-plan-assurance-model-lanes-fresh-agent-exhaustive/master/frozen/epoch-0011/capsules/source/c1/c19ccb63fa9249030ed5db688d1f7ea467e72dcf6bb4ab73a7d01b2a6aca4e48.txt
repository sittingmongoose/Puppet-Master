L00000498	
L00000499	Provider integrations (Cursor, Claude Code, OpenCode, Codex, GitHub Copilot, Gemini) support **hooks**, **skills**, **plugins**, **extensions**, and **MCP servers**. These can complement (not replace) Puppet Master's own prepare/cleanup and orchestration.

L00000502

Puppet Master does **not** rely on platform-specific hooks or scripts to perform workspace cleanup, so behavior is consistent across all supported providers and does not require the user to install or configure per-provider hooks.
L00000504	- **Subagents and plan mode:** Subagent names and plan-mode flags are passed in the **prompt or CLI args** (per platform_specs and runners). L00000550	- **DRY:** Define default shortcuts in one place (e.g. `DRY:DATA:default_shortcuts` in `src/config/` or `src/gui/shortcuts.rs`); GUI and key-handling code both read from that source.
L00000551	
L00000552	**Acceptance criteria (Shortcuts screen):**
L00000553	
L00000554	- User can open **Config → Shortcuts** (or Config → Advanced → Shortcuts) and see a list of all actions and their current bindings.
L00000555	- User can change a binding via "Change" or double-click; after recording a new key combo, binding updates and persists; if the key is already bound to another action, show error (see §7.11) and do not save.
L00000556	- User can reset one action to default or reset all to defaults; persisted overrides are updated and key map is rebuilt.
L00000557	- Shortcut list reflects the same key map used by Puppet Master (composer, prompt fields); changes take effect immediately after save.
L00000558	
L00000559	**Data flow:**
L00000560	
L00000561	- **Config field:** `GuiConfig.shortcuts` (or `keyboard_shortcuts`): map from action id (e.g. `MoveToLineStart`) to `KeyBinding`; only overrides stored; missing key = use default.
L00000562	- **Key map rebuild:** When user saves a change (edit or reset), update `GuiConfig.shortcuts`, persist config, then call `build_key_map(default_shortcuts(), gui_config.shortcuts)` and store result in app state; all key handling uses this map until next change.
L00000563	
L00000564	**Error handling:**
L00000565	
L00000566	- **Duplicate binding (key already used by another action):** Reject with tooltip/toast "Already used by &lt;ActionName&gt;" per §7.11; do not update config.
L00000567	- **Config load failure (corrupted shortcuts):** Fall back to defaults and show toast per §7.11; see §8.8 for checklist.
L00000568

L00000571	- Key handling in the GUI layer (Slint) must route key events using the configured shortcuts, not hardcoded bindings. On load, load overrides from config and merge with defaults.
L00000572	- Accessibility: ensure shortcut list is keyboard-navigable and that the "record new shortcut" flow is clearly announced (e.g. "Press the new key combination").

L00000583	### 7.8 Agent Skills (GUI)
L00000584	
L00000585	A **GUI screen** is required to let users **manage Agent Skills**: discover, list, add, edit, remove, and configure permissions for skills that agents can load. Skills are reusable instruction sets defined as `SKILL.md` files in folders; discovery follows project and global paths compatible with OpenCode and platform CLIs (Cursor, Codex, Claude, etc.). See [OpenCode Agent Skills](https://opencode.ai/docs/skills/) for the canonical model (frontmatter, discovery, permissions).
L00000586	
L00000587	**Placement:** Add under **Config** (e.g. **Advanced** tab → "Skills" or a dedicated **Skills** tab), or under **Settings**. Use widgets from `docs/gui-widget-catalog.md` (e.g. `page_header`, `styled_button`, `selectable_label` / `selectable_label_mono` for skill names and paths).
L00000588	
L00000589	**Skill model (aligned with OpenCode baseline per `Plans/OpenCode_Deep_Extraction.md` §7F):**
L00000590	
L00000591	- **One folder per skill**, with a `SKILL.md` inside. Recognized fields in frontmatter: `name` (required), `description` (required), `license`, `compatibility`, `metadata` (optional map).
L00000592	- **Discovery paths** (single source of truth in backend, §7.10):
L00000593	  - Project: `.puppet-master/skills/<name>/SKILL.md`, `.claude/skills/<name>/SKILL.md`, `.agents/skills/<name>/SKILL.md` (walk up from cwd to git worktree).
L00000594	  - Global: `~/.config/puppet-master/skills/<name>/SKILL.md`, `~/.claude/skills/<name>/SKILL.md`, `~/.agents/skills/<name>/SKILL.md`.
L00000595	- **Name validation (OpenCode-aligned):** Regex `^[a-z0-9]+(-[a-z0-9]+)*$`, 1-64 chars, no leading/trailing `-`, no consecutive `--`; MUST match directory name. **Description:** 1-1024 chars.
L00000596	
L00000597	**Permissions integration:**
L00000598	
L00000599	- Skills are **permission-gated** using the `permission.skill` key in `Plans/Permissions_System.md` §5. The `skill` permission key supports per-skill patterns (e.g., `{ "my-skill": "allow", "internal-*": "deny", "*": "allow" }`).
L00000600	- **Per-Persona overrides:** A Persona's `default_skill_refs` (`Plans/Personas.md` §3.2) lists skill IDs to auto-load. Per-Persona permission profiles (`Plans/Permissions_System.md` §2.4, priority 3) may further restrict or allow specific skills.
L00000601	- **Disabling skill tool per Persona:** A Persona MAY set the `skill` permission key to `deny` in its permission profile to disable skill loading entirely for runs using that Persona.
L00000602	- **Skills in tool description:** Skills are listed in the `skill` tool description with `<available_skills>` XML blocks containing name and description. The agent invokes a skill via `skill({ name })` which loads the skill's content on demand. Skills are also registered as invokable commands (so `/skillname` works from the command palette).
L00000603	- Skill directories are automatically added to the `external_directory` allowlist for permission purposes (`Plans/Permissions_System.md` §3.3).
L00000604	- Skill tool calls are protected from pruning during `/compaction`.
L00000605	- If PM adopts Xeditor-inspired incremental summarization, `Plans/assistant-chat-design.md` and related `/assistant-chat-design.md` context `/compaction` shards must stay aligned with skill/tool-call preservation so incremental summaries do not drop recoverable skill lineage.

L00000650	### 7.9 Backend: Desktop Shortcuts
L00000651	
L00000652	Backend components required so the Desktop Shortcuts GUI (§7.7) and in-app key handling work.
L00000653	
L00000654	**Data and types:**
L00000655	
L00000656	- **ShortcutAction:** Enum or struct identifying each action (e.g. `MoveToLineStart`, `MoveToLineEnd`, ...). One variant per row in the default table in §7.7. Tag **DRY:DATA:shortcut_actions**.
L00000657	- **Default shortcuts:** A const or fn `default_shortcuts() -> Vec<(ShortcutAction, KeyBinding)>` (or `HashMap<ShortcutAction, KeyBinding>`) as the single source of truth. **DRY:DATA:default_shortcuts.** KeyBinding represents modifier + key (e.g. Ctrl+A, Alt+F); use a type that can be serialized for config and compared for conflicts.
L00000658	- **Config shape:** `GuiConfig.shortcuts` (or `keyboard_shortcuts`): map from action id (string or enum name) to user key binding. Only overrides are stored; missing key means use default.
