L00003373	**Gap #15: Hook execution order and dependencies**
L00003374	
L00003375	**Issue:** When multiple hooks are registered (built-in + platform-native), what is the execution order? Can hooks depend on each other? What if one hook blocks execution?
L00003376	
L00003377	**Mitigation:**
L00003378	- **Execution order:** Built-in hooks run first (ActiveSubagentTrackerHook, TierContextInjectorHook, StaleStatePrunerHook), then platform-native hooks, then custom hooks.

L00003380	- **Blocking:** First hook that blocks stops execution. Log which hook blocked and why.

L00003382	**Gap #16: Structured output parsing reliability**
L00003383	
L00003384	**Issue:** Platform output formats may vary (JSON vs JSONL vs text). Parsers may fail on edge cases (malformed JSON, partial output, streaming output). How do we handle parsing failures gracefully?
L00003385	
L00003386	**Mitigation:**
L00003387	- **Multi-pass parsing:** Try JSON parse first, then JSONL, then text extraction. Use best-effort parsing with fallbacks.
L00003388	- **Partial output handling:** If parsing fails, extract what we can (e.g., `task_report` from text even if `findings` missing). Mark tier as "complete with warnings."
L00003389	- **Parser testing:** Comprehensive test suite for each platform parser with edge cases (malformed JSON, unicode, large outputs, streaming).
L00003390	- **Parser versioning:** Track parser version and platform CLI version. Update parsers when platform CLI changes.

L00003392	**Gap #17: Remediation loop infinite retry risk**
L00003393	
L00003394	**Issue:** Remediation loop could retry indefinitely if findings never resolve (e.g., false positives, unrelated failures). How do we detect and break infinite loops?
L00003395	
L00003396	**Mitigation:**
L00003397	- **Max retries:** Hard limit (default: 3) on remediation retries per tier.
L00003398	- **Progress detection:** Compare findings between retries. If findings unchanged after 2 retries, escalate (don't retry again).
L00003399	- **Escalation threshold:** After max retries, escalate to parent-tier orchestrator. Parent-tier can decide to skip, fix manually, or re-plan.
L00003400	- **Timeout:** Remediation loop has overall timeout (e.g., 30 minutes). If timeout exceeded, escalate.

L00003403	
L00003404	**Issue:** Memory files may become stale (outdated decisions), conflict between runs (different decisions), or grow unbounded. How do we manage memory lifecycle?
L00003405	
L00003406	**Mitigation:**
L00003407	- **Versioning:** Each memory entry has timestamp. Load only recent entries (e.g., last 30 days) unless explicitly requested.
L00003408	- **Conflict resolution:** When loading memory, detect conflicts (e.g., "Rust + Actix" vs "Python + FastAPI"). Prompt user or use most recent decision.
L00003409	- **Pruning:** Prune old memory entries (older than threshold, e.g., 90 days) unless marked as "persistent."
