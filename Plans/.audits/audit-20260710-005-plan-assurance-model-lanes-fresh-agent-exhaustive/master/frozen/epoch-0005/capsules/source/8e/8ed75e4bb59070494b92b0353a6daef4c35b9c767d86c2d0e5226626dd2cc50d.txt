L00000164	## 1. Executive Summary
L00000165	
L00000166	This document is the authoritative GUI specification for the Puppet Master desktop application, replacing the retired Rust/Iced-lineage GUI with a Slint 1.17.1 implementation on Rust stable 1.96.1. The design follows an IDE-shell layout (Activity Bar + Primary Content + Side Panel + Bottom Panel) with three user-facing theme families (Retro Dark, Retro Light, Basic Modern) backed by deterministic built-in palette variants plus user-created custom themes, detachable panels, and a rearrangeable dashboard.
L00000167	
L00000168	The current GUI uses a two-row header with 16 flat navigation buttons above a single full-width content area. This wastes screen real estate and forces constant page-switching. The new layout follows a three-column IDE shell inspired by VS Code / JetBrains, dressed in the existing retro-futuristic aesthetic.
L00000169	
L00000170	Key changes from the retired Rust/Iced-lineage GUI:
L00000171	- **Layout:** Single-page-at-a-time replaced with persistent IDE shell (Activity Bar, Primary Content, Side Panel, Bottom Panel)
L00000172	- **Navigation:** 16 flat buttons replaced with 5-group Activity Bar + Command Palette
L00000173	- **Settings restructure:** Old `Settings` becomes `App Settings`; old `Config` becomes `Settings`; Login and Doctor merge into unified Settings
L00000174	- **New views:** Usage page, File Manager panel, editor surface, Chat panel, Agent Activity pane, Artifacts, Source Control, GitHub Actions, Docker Manager, and Run & Debug side-panel surfaces
L00000175	- **Bottom runtime zone:** Terminal, Problems, Output, Ports, and the classical **Debugger** / **DAP Debugger** live here; normal browsing and HTML preview remain editor-tab or detached-window browser surfaces rather than bottom-panel tabs
L00000176	- Coarse surface vocabulary treats primary-content pages `/views`, side-panel destinations, bottom-panel surfaces, and Orchestrator tabs as shell categories, not interchangeable route identities.
L00000177	- **Themes:** Three theme families with full extensibility and deterministic built-in variants
L00000178	- **Real-time:** Event-driven updates via Rust channels and `invoke_from_event_loop`, not polling
L00000179	- **Panels:** Chat and File Manager are detachable; shell state remains identity-safe when re-docked
L00000180	- **Project bar:** Instant project switching from title bar with full state preservation and reload
L00000181	- **Language detection:** Auto-detect project languages, display badges, and suggest LSP/tool presets
L00000182	- **Sound effects:** Optional audio feedback for key events via `rodio`
L00000183	- **Catalog and sync:** Community content catalog with install/update/remove flows and config export/import bundles
L00000184	- **SSH remote editing:** Edit files on remote hosts via SSH/SFTP with connection management and offline resilience
L00000185	- **Debug workflows:** Assistant Debug Mode is a first-class chat workflow overlay; the classical DAP surface remains a separate debugger surface
L00000186	- **Product name:** `Puppet Master`

L00000208	### 2.2 Native Desktop Renderer Contract
L00000209	
L00000210	Native desktop targets Windows, Linux, and macOS through the Slint Winit backend. The compiled renderer availability order is Winit + Skia, Winit + FemtoVG-wgpu, then Winit software renderer. Runtime selection resolves in this order: `SLINT_BACKEND` explicit override, persisted renderer preference, compiled Skia default, FemtoVG-wgpu fallback, and software emergency fallback. `SLINT_BACKEND` remains valid for debugging, CI, and operator override, but persisted preferences must not silently override an explicit environment override. Startup diagnostics record the requested backend, effective backend, fallback reason, platform, GPU/driver summary when available, and whether the fallback was operator-selected or automatic.
L00000211	
L00000212	### 2.3 Web/WASM GUI Contract
L00000213	
L00000214	The first GUI implementation includes both the native desktop target and a Slint Rust WASM web GUI. The web GUI is a Slint/WASM canvas client compiled as a Rust `cdylib` with `wasm-bindgen`, `wasm-pack`, or an approved equivalent toolchain and loaded by a minimal HTML/canvas bootstrap. The web target does not use React, Tauri, or DOM-rendered product UI. Browser JavaScript is limited to generated or minimal bootstrap glue needed to load the WASM canvas client, route static assets, attach the canvas, and connect to approved local services.
L00000215	
L00000216	Browser-only WASM is not allowed to pretend it owns OS capabilities. It must not claim direct ownership of PTY, project filesystem mutation or watching, process/container execution, CEF-class browser embedding, system tray, native windows, native child windows, or raw native OS drag/drop. When a capability is unavailable in the browser sandbox, the UI shows the capability state, degraded reason, and the approved native or daemon-mediated route.
L00000217	
L00000218	### 2.4 Trusted Local Daemon Contract
L00000219	
L00000220	The web GUI may use OS-owned capabilities only through a trusted local Puppet Master daemon. The daemon boundary requires authenticated local origin or pairing, origin and CSRF protection, capability probing before feature enablement, explicit permission requests for sensitive operations, receipt/audit events for granted or denied actions, redaction before display or persistence, degraded reasons when the daemon is absent or narrowed, and deterministic agent-test hooks for fixture mode and browser automation. The web GUI consumes daemon capability receipts; it does not infer authority from localhost reachability alone.
L00000221

L00000237	### 2.6 SVG Icon And No-Emoji UI Contract
L00000238	
L00000239	Production GUI surfaces use bundled local SVG assets referenced by stable `icon_id`. The production UI must not use emoji, emoji-like pictographs, Dingbat-style pseudo-icons, or Unicode pictographs as controls, badges, status indicators, or decorative substitutes for icons. Concept glyphs from PMConcept or other source-lineage artifacts map only to approved `icon_id` entries before promotion.
L00000240	
L00000241	The local SVG manifest includes `icon_id`, file path, semantic label, theme behavior, size slots, accessible label, fallback text, and any state-variant mapping. Icons are never the sole carrier of state: every icon-only control has an accessible label, tooltip or equivalent label projection, keyboard/focus behavior, and nearby or programmatic state text. Network/CDN icon fonts or remote SVG/icon imports are forbidden for production GUI source.

L00000243	### 2.7 GUI Web Dev/Test Workflow
L00000244	
L00000245	The web GUI development workflow uses a local trusted daemon plus a static web route, fixture mode, browser automation smoke tests, screenshots/state capture, deterministic state hooks, and fast rebuild/reload loops. Development preview controls may expose reload, fixture-mode selection, screenshot/state capture, and daemon capability inspection only in configured development or automated-test builds. Production builds must not enable dev/test, MCP, live-preview, fixture, or browser automation controls unless an explicit production configuration authorizes that capability and records the permission/audit surface.
