L00000134	#### 7A.1 Plan mode
L00000135	
L00000136	**File pointers:**
L00000137	- System reminder injected for plan agent: `packages/opencode/src/session/prompt/plan.txt`
L00000138	- Plan mode enforcement & plan-to-build switching: `packages/opencode/src/session/prompt.ts` -> `insertReminders()` (line ~1321)
L00000139	- Plan exit tool (asks user to switch to build): `packages/opencode/src/tool/plan.ts` -> `PlanExitTool`
L00000140	
L00000141	**Behavior summary:**
L00000142	- When the active agent is `plan`, OpenCode injects a `<system-reminder>` block into the last user message's parts (as a synthetic text part). This reminder declares plan mode as ACTIVE and states: "STRICTLY FORBIDDEN: ANY file edits, modifications, or system changes."

L00000145	- `PlanExitTool` uses `Question.ask()` to ask the user "Would you like to switch to the build agent?". On approval, it creates a synthetic user message with `agent: "build"` and text "Execute the plan", effectively switching the agent for the session.
L00000146	- There is also an experimental plan mode flag (`Flag.OPENCODE_EXPERIMENTAL_PLAN_MODE`) that controls a richer plan mode flow with plan file creation/detection, phase instructions, and a build-switch reminder when transitioning from plan to build.

L00000247	
L00000248	
L00000249	**File pointers:**
L00000250	- Compaction logic: `packages/opencode/src/session/compaction.ts`
L00000251	- Compaction agent prompt: `packages/opencode/src/agent/prompt/compaction.txt`

L00000264	### 7C. Permissions and Approval Mechanics
L00000265	
L00000266	#### 7C.1 Permission resolution algorithm
L00000267	
L00000268	**File pointers:**
L00000269	- Core resolver: `packages/opencode/src/permission/next.ts` -> `evaluate()` (line ~236)
L00000270	- `fromConfig()`: line ~46; `merge()`: line ~64
L00000271	
L00000272	**Behavior summary:**
L00000273	- `PermissionNext.evaluate(permission, pattern, ...rulesets)` merges all rulesets (via flat concatenation), then calls `merged.findLast(rule => Wildcard.match(permission, rule.permission) && Wildcard.match(pattern, rule.pattern))`.
L00000274	- **Last match wins**: because `findLast` is used, rules appended later (higher-priority rulesets) override earlier ones. `PermissionNext.merge(...rulesets)` simply concatenates arrays; rule order within each ruleset is preserved.
L00000275	- If no rule matches, the default is `{ action: "ask" }`.
L00000276	- The `ask()` function iterates over all patterns in the request; if any pattern evaluates to `"deny"`, a `DeniedError` is thrown immediately. If any evaluates to `"ask"`, a permission request is published to the bus and the function blocks on a Promise. `"allow"` continues to the next pattern.
L00000277	
L00000278	#### 7C.2 Granular object-syntax matching
L00000279	
L00000280	**File pointers:**
L00000281	- `fromConfig()`: `packages/opencode/src/permission/next.ts` (line ~46)
L00000282	
L00000283	**Behavior summary:**
L00000284	- Config permissions can be simple strings (`"*": "allow"`) or objects where keys are patterns and values are actions (`read: { "*": "allow", "*.env": "ask" }`).
L00000285	- `fromConfig()` converts the config representation to a `Ruleset` (array of `{permission, pattern, action}` rules). For object syntax, each key-value pair becomes a separate rule with the outer key as `permission` and the inner key as `pattern`.
L00000286	
L00000287	#### 7C.3 Wildcard matching
L00000288	
L00000289	**File pointers:**
L00000290	- Wildcard engine: `packages/opencode/src/util/wildcard.ts`
L00000291	
L00000292	**Behavior summary:**
L00000293	- `*` matches 0+ characters (converted to `.*` in regex), `?` matches exactly 1 character (converted to `.`).
L00000294	- **Special case**: If a pattern ends with ` *` (space + wildcard), the trailing portion becomes optional. This allows `"ls *"` to match both `"ls"` and `"ls -la"`.
L00000295	- Home expansion (`~` and `$HOME`) is handled in `PermissionNext.expand()` before rule creation, not in wildcard matching.
L00000296	- On Windows, matching is case-insensitive.
L00000297	
L00000298	#### 7C.4 Special guards: external_directory, doom_loop
L00000299	
L00000300	**File pointers:**
L00000301	- Default permission setup: `packages/opencode/src/agent/agent.ts` -> `state()` (lines ~56-73)
L00000302	- `disabled()` check: `packages/opencode/src/permission/next.ts` (line ~247)
L00000303	
L00000304	**Behavior summary:**
L00000305	- `external_directory`: Defaults to `"ask"`. Controls whether tools can access files outside the working directory. Whitelisted directories (truncation glob + skill directories) are auto-allowed.
L00000306	- `doom_loop`: Defaults to `"ask"`. Guards against infinite/repetitive behavior.
L00000307	- `question`, `plan_enter`, `plan_exit`: Default `"deny"` globally, selectively enabled per agent (e.g., `question: "allow"` for build and plan agents).
L00000308	
L00000309	#### 7C.5 Ask UI semantics (once / always / reject)
L00000310	
L00000311	
L00000312	**File pointers:**
L00000313	- Reply enum + `reply()` function: `packages/opencode/src/permission/next.ts` (lines ~89-233)
L00000314	
L00000315	**Behavior summary:**
L00000316	- `once`: Resolves the pending permission promise; one-time approval. No persistent rule is saved.
L00000317	- `always`: Adds a new `"allow"` rule to the session-scoped approved ruleset for each pattern in the request's `always` array. Then resolves the current request AND auto-resolves any other pending permission requests in the same session that now pass evaluation.
L00000318	- `reject`: Rejects the current request's promise with either `CorrectedError(message)` (if the user provided feedback text) or `RejectedError` (bare rejection). Additionally, rejects ALL other pending permission requests for the same session.
L00000319	
L00000320	#### 7C.6 Default .env deny rules
L00000321	
L00000322	**File pointers:**
L00000323	- Default read permissions: `packages/opencode/src/agent/agent.ts` (lines ~67-72)
