L00000084	## Route-aware progression and packet verification gates
L00000085	
L00000086	Progression gates are the canonical owners of promotion evidence, route/open packet verification, and compatibility checks before run sealing and archival.
L00000087	
L00000088	### Promotion classes and required evidence
L00000089	
L00000090	Promotions follow these classes:
L00000091	- **READY**: Sufficient concerns resolved, approval status clear, usage within bounds, and no blocking externalities.
L00000092	- **STAGED**: Promotion state is pending; promotion review window is open and waiting for coordinator review or automated gate judgment.
L00000093	- **HELD**: Temporary gate; promotion may proceed after external condition clears (e.g., rate limit window, dependent run completion).
L00000094	- **REJECTED**: Promotion gate failed; promotion cannot proceed unless the gate criterion is waived by escalation or project rule.
L00000095	
L00000096	Evidence for each promotion class:
L00000097	- READY: `concern_summary` clear or resolved-with-mitigation, `approval_summary` in final state, `usage_summary` within budget, `route_target_reachability` verified, `blockers` field is empty array.
L00000098	- STAGED: `coordinator_review_id`, `review_deadline_utc`, `active_blockers[]`, `pending_external_conditions[]`.
L00000099	- HELD: `hold_reason`, `expected_clear_time_utc`, `blocking_external_condition_id`.
L00000100	- REJECTED: `rejection_reason`, `rejected_criterion`, `waiver_required`, `escalation_contact`.
L00000101	
L00000102	### Route-aware wiring evidence
L00000103	
L00000104	Route awareness requires:
L00000105	- `route_target` is reachable and has not changed between build time and promotion time.
L00000106	- `OpenSubject` resolution is still valid (e.g., the GitHub issue still exists, the workspace path is still writable).
L00000107	- Route/open commands that were executed during the run are reflected in the promotion artifact.
L00000108	- Route side-effects (file writes, PR opens, issue comments) are linked in the `route_completion_refs[]` field.
L00000109	
L00000110	### route_target/OpenSubject packet checks
L00000111	
L00000112	Packet verification gates check:
L00000113	- Every `route_target` in the run packet is present in the promotion artifact as a reachability confirmation.
L00000114	- Every `OpenSubject` in the run packet is present as a resolution confirmation or explicit waiver (if the subject became unreachable).
L00000115	- Cross-packet route/open references are coherent: if run A routes to run B's artifacts, run B's artifacts must be sealed before run A is promoted.
L00000116	
L00000117	### Compatibility fallback and contradiction-fail rules
L00000118	
L00000119	
L00000120	- If a route_target becomes unreachable between build and promotion, the promotion enters HELD state instead of failing silently.
L00000121	- If an OpenSubject resolution contradicts the prior intent (e.g., the issue was closed externally), the gate emits a REJECTION with `rejection_reason: 'subject_state_contradiction'`.
L00000122	- Waiver paths: project admins may waive route reachability or subject contradiction using a durable `gate_waiver_rule` in the project config.
