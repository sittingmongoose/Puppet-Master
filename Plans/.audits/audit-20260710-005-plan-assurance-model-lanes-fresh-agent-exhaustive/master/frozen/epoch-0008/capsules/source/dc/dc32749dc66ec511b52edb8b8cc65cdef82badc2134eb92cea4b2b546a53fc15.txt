L00000910	## 17. LSP verification gate, evidence, subagent selection (implementation spec)
L00000911	
L00000912	This section defines the **contract, config, failure handling, evidence schema, and integration points** for the LSP diagnostics verification gate, LSP snapshot in evidence, and subagent selection from LSP so an agent can implement with no gaps. Cross-reference: Plans/feature-list.md (Verifier registry, LSP additional enhancements), Plans/Tools.md (§3.1 lsp tool), Plans/orchestrator-subagent-integration.md (subagent selection).
L00000913	
L00000914	### 17.1 LSP diagnostics verification gate
L00000915	
L00000916	#### Contract

<<< AUTHORITATIVE_CORE canonical_document_lines=917-1301 >>>
L00000917	
L00000918	- **When it runs:** At configured **tier boundaries** before promotion. It MAY be enabled for `phase`, `task`, and/or `subtask`; default: **phase boundary only**. Implementations MAY also run an iteration-local preflight, but that is advisory and MUST NOT replace the configured boundary gate.
L00000919	- **Tier boundaries:** Configurable per tier: phase, task, subtask. At least one of these must be enabled for the gate to run; when the orchestrator reaches that boundary (e.g. "subtask passed"), the LSP gate runs as one of the criteria before the tier is marked passed.
L00000920	- **Scope:** What files are checked. One of:
L00000921	  - **`changed_files`** -- Only files that were modified in the last iteration (or in the current subtask). Requires tracking changed paths (e.g. from git diff or execution engine "files touched").
L00000922	  - **`open`** -- Only files currently open in the editor (or in the run context). Requires LSP client to know "open" set for the run.
L00000923	  - **`project`** -- All project files that have an LSP server (bounded: e.g. under project root, or only files with open documents). Default: **`changed_files`** to keep checks fast and relevant.
L00000924	- **"No LSP errors" meaning:** Configurable severity threshold:
L00000925	  - **`error`** -- Gate passes if there are **no diagnostics with severity Error** in scope. Warnings and Info are ignored.
L00000926	  - **`error_and_warning`** -- Gate passes if there are **no diagnostics with severity Error or Warning** in scope. Info is ignored.
L00000927	  - Default: **`error`**.
L00000928	
L00000929	#### Config
L00000930	
L00000931	- **Where:** Verification tab (Settings or Config → Verification). Can be **global** (one setting for all tiers) or **per-tier** (override per phase/task/subtask). Recommendation: global `lsp_gate` with optional per-tier override in tier config.
L00000932	- **Schema (config key `verification.lsp_gate` in redb):**
L00000933	
L00000934	**LSP Gate Default Values (Resolved):**
L00000935	- `enabled`: **false** (opt-in per project)
L00000936	- `scope`: **"changed_files"** (only check files modified in this tier)
L00000937	- `block_on`: **"errors"** (errors block, warnings do not)
L00000938	- `tier_boundaries`: **["phase"]** (check at phase boundaries only by default)
L00000939	- `timeout_seconds`: **10** (LSP query timeout)
L00000940	- `when_unavailable`: **"skip"** (if LSP server is not running, skip the gate — do not fail)
L00000941	
L00000942	Config key: `verification.lsp_gate` in redb. All values are overridable per project via `.puppet-master/config.json`.
L00000943	
L00000944	```json
L00000945	{
L00000946	  "lsp_gate": {
L00000947	    "enabled": false,
L00000948	    "scope": "changed_files",
L00000949	    "block_on": "errors",
L00000950	    "tier_boundaries": ["phase"],
L00000951	    "timeout_seconds": 10,
L00000952	    "when_unavailable": "skip"
L00000953	  }
L00000954	}
L00000955	```
L00000956	
L00000957	| Field | Type | Values | Default |
L00000958	|-------|------|--------|--------|
L00000959	| `enabled` | bool | true, false | **false** |
L00000960	| `scope` | string | `"changed_files"` \| `"open"` \| `"project"` | **`"changed_files"`** |
L00000961	| `block_on` | string | `"errors"` \| `"errors_and_warnings"` | **`"errors"`** |
L00000962	| `tier_boundaries` | string[] | `["phase"]`, `["task"]`, `["subtask"]`, or combination | **`["phase"]`** |
L00000963	| `timeout_seconds` | number | positive integer | **10** |
L00000964	| `when_unavailable` | string | `"skip"` \| `"fail"` | **`"skip"`** |
L00000965	
L00000966	- **GUI:** Verification tab: "LSP diagnostics gate" subsection: Enable checkbox; Scope dropdown (Changed files / Open files / Whole project); Block on (Errors only / Errors and warnings); Tier boundaries (checkboxes: Phase, Task, Subtask); Timeout (seconds). Persist in same config blob as `VerificationConfig` (e.g. extend `VerificationConfig` or nested `lsp_gate`).
L00000967	
L00000968	#### Failure behavior
L00000969	
L00000970	- **Gate fails (LSP errors in scope):** The gate report for that tier has `passed: false`; the **criterion** for the LSP gate has `met: false` and `actual` set to a summary (e.g. "3 LSP errors in scope (see evidence)").
L00000971	- **Orchestrator behavior:** Same as for any failed gate: **retry** (next iteration) if retry policy allows; else **escalate** or **stop** per tier config (e.g. `task_failure_style`). No special case for LSP gate.
L00000972	- **User notification:** Standard gate failure path: Dashboard/Gate report shows failure; optional toast "LSP gate failed: N errors in scope." Evidence (LSP snapshot) is attached so user can inspect.
L00000973	
L00000974	#### Evidence attachment
L00000975	
L00000976	- **When:** When the LSP gate **runs** (whether it passes or fails), attach an **LSP diagnostics snapshot** to the gate report. So: **always** capture snapshot at gate run time; store it as evidence linked to that gate run.
L00000977	- **Where stored:** See §17.2. The snapshot is written to `.puppet-master/evidence/lsp-snapshots/` (or embedded in gate report artifact); the GateReport or EvidenceStore references it (e.g. `evidence_type: "lsp_snapshot"`, path to JSON file).
L00000978	
L00000979	#### Integration point
L00000980	
L00000981	- **Who calls LSP:** A new verifier **`LspGateVerifier`** (or **`lsp_gate_verifier`**), registered in `VerifierRegistry` (e.g. in `verifier.rs` `register_defaults`). Criterion type: `verification_method: "lsp"` or `"lsp_gate"`.
L00000982	- **Where:** New module `puppet-master-rs/src/verification/lsp_gate_verifier.rs`. It implements `Verifier`: on `verify(criterion)`, it reads scope and block_on from criterion (or from a shared LSP gate config injected into the verifier), calls the LSP client to get current diagnostics for the resolved paths, and returns `VerifierResult { passed, message, evidence }`. Evidence contains or references the LSP snapshot.
L00000983	- **Gate runner:** No change to gate_runner flow: it already dispatches by `criterion.verification_method` to the registry; when the criterion is LSP gate, the registry returns `LspGateVerifier`, which runs.
L00000984	- **LSP client API:** The LSP client (e.g. in `src/lsp/` or `src/lsp/client.rs`) must expose **get current diagnostics for paths**:
L00000985	  - Signature (conceptual): `get_diagnostics_for_paths(paths: &[PathBuf], project_root: &Path) -> Result<Vec<LspDiagnosticEntry>, LspGateError>`.
L00000986	  - Returns: list of diagnostics (path, line, character, severity, message, source) for the given paths. If a path has no server or no diagnostics, it contributes an empty list. The client uses the existing DiagnosticsCache (from `publishDiagnostics`) and/or triggers a request if needed; must respect timeout (e.g. 15 s) and return partial results or error on timeout.
L00000987	
L00000988	#### Implementer wiring (config and gate report)
L00000989	
L00000990	- **VerificationConfig:** Extend the existing verification config (e.g. `VerificationConfig` in `config/gui_config.rs` or equivalent) with an optional **`lsp_gate`** field (nested struct matching the schema above: `enabled`, `scope`, `block_on`, `tier_boundaries`, `timeout_seconds`, optional `when_unavailable`). Persist in the same blob as other verification settings. **Verification tab UI:** Add "LSP diagnostics gate" subsection with controls bound to this struct.
L00000991	- **Criterion injection:** When building gate criteria for a tier (e.g. in `build_gate_criteria` or where acceptance criteria are converted to criteria), if `lsp_gate.enabled` is true and the current tier boundary (phase/task/subtask) is in `lsp_gate.tier_boundaries`, add a criterion with `verification_method: "lsp"` (or `"lsp_gate"`) and pass scope/block_on (in criterion params or from shared config). No change to criterion type enum beyond adding this method.
L00000992	- **GateReport / evidence:** Use the **existing** evidence pipeline: `VerifierResult` carries `evidence` (e.g. path to snapshot file or artifact id); the gate runner aggregates per-criterion results into `GateReport`; EvidenceStore (if present) persists artifacts per existing rules. No new GateReport field required; LSP snapshot is stored as an artifact referenced by the LSP criterion's result.

L00000996	### 17.2 LSP snapshot in evidence
L00000997	
L00000998	Prompt-consumable LSP/debug evidence may auto-ingest at most the top five evidence items by current relevance `/severity`; after that cap, additional diagnostics or trace material enter summarization-only mode unless the user explicitly opens the full runtime artifact.
L00000999	
L00001000	#### Schema (per diagnostic entry)
L00001001	
L00001002	Store one JSON file per snapshot (e.g. one per gate run). Each entry in the snapshot:
L00001003	
L00001004	```json
L00001005	{
L00001006	  "path": "src/main.rs",
L00001007	  "line": 1,
L00001008	  "character": 0,
L00001009	  "severity": "Error",
L00001010	  "message": "expected type",
L00001011	  "source": "rust-analyzer",
L00001012	  "code": "E0308"
L00001013	}
L00001014	```
L00001015	
L00001016	- **path** -- Relative to project root or absolute; same as LSP URI normalized to path.
L00001017	- **line** -- 0-based or 1-based per LSP spec (LSP uses 0-based); **Decision:** Store and display 1-based in evidence and UI; convert to 0-based only at the LSP protocol boundary.
L00001018	- **character** -- Offset in line (0-based).
L00001019	- **severity** -- "Error" | "Warning" | "Info" | "Hint".
L00001020	- **message** -- Diagnostic message.
L00001021	- **source** -- Optional; server name (e.g. rust-analyzer).
L00001022	- **code** -- Optional; diagnostic code if provided by server.
L00001023	
L00001024	#### File format and location
L00001025	
L00001026	
L00001027	- **Directory:** `.puppet-master/evidence/lsp-snapshots/`.
L00001028	- **Filename:** `lsp-snapshot-{gate_id}-{timestamp}.json` or `lsp-snapshot-{tier_id}-{session_id}.json` so it is unique and tied to the gate run.
L00001029	- **Content:** Single JSON object: `{ "captured_at": "ISO8601", "scope": "changed_files"|"open"|"project", "project_root": "...", "diagnostics": [ {...}, ... ] }`.
L00001030	
L00001031	#### When captured
L00001032	
L00001033	- **Before run:** Not required for gate-only use.
L00001034	- **After run (when gate runs):** Yes. When the LSP gate verifier runs (at tier boundary), it captures the snapshot **at that moment** (after iteration, before promotion). So: **one snapshot per gate run** at the time the gate is evaluated.
L00001035	- **Optional "before and after":** For richer audit, config could allow capturing snapshot before iteration and after; then two files per run. MVP: **after only** (at gate run time).
L00001036	
L00001037	#### Who triggers
L00001038	
L00001039	- **Gate runner** (via LspGateVerifier). The verifier is invoked by the gate runner when a criterion with `verification_method: "lsp"` is evaluated. The verifier (1) gets diagnostics from LSP client for scope, (2) writes snapshot JSON to `.puppet-master/evidence/lsp-snapshots/`, (3) attaches evidence to VerifierResult (path to snapshot file), (4) returns passed/failed. EvidenceStore (if wired) can also persist the path; GateReport criteria already carry per-criterion evidence from VerifierResult.
L00001040	
L00001041	ContractRef: ContractName:Plans/LSPSupport.md

L00001043	### 17.3 Subagent selection from LSP
L00001044	
L00001045	- **Where in the flow:** When the orchestrator is about to **select a subagent for the next node** (task or subtask), it can optionally query LSP diagnostics for **files in scope** for that node. **Decision:** Default **off**. Config key `orchestrator.lsp_subagent_bias` (bool, default false). When true, call `get_diagnostics_for_paths` and apply bias toward matching-language subagent. If any file has diagnostics (e.g. errors) from a language server X, **prefer** the subagent that matches language X (e.g. rust-analyzer → rust-engineer, pyright → python-pro).
L00001046	- **"Files in scope" definition:** One of (configurable or fixed):
L00001047	  - **Changed in last iteration** -- Files modified in the most recent iteration (same as LSP gate scope `"changed_files"` for consistency).
L00001048	  - **Open in editor** -- Files currently open in the run/context.
L00001049	  - **Node's file list** -- If the node has an explicit list of files (e.g. from PRD or plan), use that list.
L00001050	  - Default: **changed in last iteration** for consistency with LSP gate.
L00001051	- **Documentation:** This behavior is specified in **Plans/orchestrator-subagent-integration.md** (Subagent selection from LSP) and summarized here. Implement in the same place that performs `select_for_node`: after building node context, optionally call LSP client `get_diagnostics_for_paths(scope_paths)`; from the returned diagnostics, derive language(s) from `source` or from file extension → server id mapping; then bias subagent selection toward matching language (e.g. add to ProjectContext or NodeContext: "prefer_subagents": ["rust-engineer"] when Rust errors present).
L00001052	- `Plans/orchestrator-subagent-integration.md` / `/orchestrator-subagent-integration.md` remains the owner for subagent-selection wiring; its runtime structs must carry the rewrite execution identity and concern model when LSP diagnostics bias a node.
L00001053	
L00001054	ContractRef: ContractName:Plans/LSPSupport.md, ContractName:Plans/orchestrator-subagent-integration.md
L00001055	
L00001056	Bias rules (canonical):
L00001057	- LSP bias is a **tie-breaker / ranking hint**, not an absolute selector.
L00001058	- Explicit plan requirements, node override lists, or hard-coded contract needs (for example `required_subagents`) take precedence over LSP bias.
L00001059	- Preferred scope order is: explicit node file list -> changed files in current node -> open files.
L00001060	- Default bias threshold is diagnostics with severity `Error`; implementations MAY optionally include `Warning` when configured.
L00001061	- The chosen bias inputs and outcome SHOULD be persisted in run metadata or verification evidence so selection remains explainable.
L00001062	
L00001063	ContractRef: ContractName:Plans/LSPSupport.md, ContractName:Plans/orchestrator-subagent-integration.md
L00001064	### 17.4 Failure modes (LSP gate and diagnostics)
L00001065	
L00001066	| Failure | Behavior | Evidence / reporting |
L00001067	|---------|----------|----------------------|
L00001068	| **LSP client not ready** | Gate does not run, or runs with a **skip** result. **Decision:** When LSP gate is enabled but client not ready: **skip** the criterion; set `actual: "LSP client not ready"`. Config: `lsp_gate.when_unavailable`: `skip` | `pass` | `fail`, default **skip**. Gate does not block on LSP startup. |
L00001069	| **Timeout when querying diagnostics** | LspGateVerifier uses a timeout (e.g. `timeout_seconds` from config). On timeout: **fail** the criterion with `actual: "LSP diagnostics query timed out"`. Attach partial snapshot if any diagnostics were collected before timeout. |
L00001070	| **No server for language** | For some files in scope there is no LSP server (e.g. unknown extension). Those files contribute **no diagnostics** (empty list). Gate passes for that file; only files with a server are checked. No special failure. |
L00001071	| **Server crash or disconnected** | Same as "LSP client not ready": skip or pass per config; do not fail the entire gate unless config says "fail when LSP unavailable". |
L00001072	| **Empty scope (changed_files/open/project)** | If scope resolves to zero files (e.g. no files changed), gate **passes** (nothing to check). |
L00001073	
L00001074	ContractRef: ContractName:Plans/LSPSupport.md
L00001075	
L00001076	Implement these in `LspGateVerifier` and in the LSP client's `get_diagnostics_for_paths` (timeout, not-ready check).
