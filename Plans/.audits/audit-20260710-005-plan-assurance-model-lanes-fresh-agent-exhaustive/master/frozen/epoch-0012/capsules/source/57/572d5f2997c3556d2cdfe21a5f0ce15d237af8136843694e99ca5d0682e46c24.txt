L00005422	### Parallel Execution Configuration
L00005423	
L00005424	**Concurrency caps rationale:** Per-platform concurrency limits exist for two reasons:
L00005425	
L00005426	1. **Provider rate limits:** Each platform (Cursor, Codex, Claude Code, Gemini, Copilot) enforces rate limits on concurrent requests. Exceeding them causes throttling, errors, or temporary bans.
L00005427	2. **Dev-machine load:** Agent processes consume CPU, disk I/O, and memory on the machine hosting the project folder. Running too many concurrent processes degrades the user's development environment.
L00005428	
L00005429	**Source of caps:** The canonical concurrency limits are defined in the `Canonical crew-cap and availability rules` `executionLimits` anchor above. The plan graph defines only dependency structure (`depends_on`, plus blocking edges such as `blockers`/`unblocks` where applicable); max concurrent is an execution/config concern. See `Plans/Crosswalk.md` §3.7 for the ownership table.
L00005430	
L00005431	**Crew limits vs agent limits:** These are separate concepts:
L00005432	- **Per-platform agent cap:** limits individual concurrent agent/subagent processes per platform. This is what hits rate limits and machine load.
L00005433	- **Crew cap** (`maxConcurrentCrewsPerPlatform`): limits concurrent crew groups per platform. A crew is a logical group of subagents working together.
L00005434	
L00005435	Both limits apply: a crew spawn must not exceed either the crew cap or the per-platform agent cap. See the `Canonical crew-cap and availability rules` `executionLimits` anchor for canonical values.
