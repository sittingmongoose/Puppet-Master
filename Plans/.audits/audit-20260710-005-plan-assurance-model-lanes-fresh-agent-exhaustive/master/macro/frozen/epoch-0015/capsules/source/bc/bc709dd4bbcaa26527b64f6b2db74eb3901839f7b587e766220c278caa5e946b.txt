L00000031	## 1. Definitions
L00000032	
L00000033	<a id="DEF-FORMATTER"></a>
L00000034	### 1.1 Formatter
L00000035	
L00000036	A **Formatter** is an external command that transforms a file's content to conform to a style or convention. Puppet Master invokes formatters after file-write/edit operations during Hosted Tool Execution (HTE). Formatters are stateless; they read a file, transform it in-place, and exit.
L00000037	
L00000038	<a id="DEF-FORMATTER-EVENT"></a>
L00000039	### 1.2 Formatter trigger event
L00000040	
L00000041	The formatter trigger event is an internal event equivalent to `File.Edited` — emitted whenever a hosted tool (`write`, `edit`, `patch`, `multiedit`) successfully modifies a file. This event carries the file path and extension.
L00000042	
L00000043	ContractRef: ContractName:Plans/Glossary.md, ContractName:Plans/Run_Modes.md#STRATEGY-HTE

L00000047	## 2. Lifecycle
L00000048	
L00000049	<a id="LIFECYCLE"></a>
L00000050	
L00000051	### 2.1 When formatters run
L00000052	
L00000053	Formatters run **after every file write/edit performed by hosted tools** (HTE strategy only). When a tool modifies a file:
L00000054	
L00000055	1. The tool completes and emits a `File.Edited` event with the file path.
L00000056	2. The formatter engine determines the file extension and finds matching enabled formatters (§3, §4).
L00000057	3. Matching formatters are invoked **sequentially** in registration order.
L00000058	4. The formatted file replaces the tool's output on disk.
L00000059	
L00000060	Rule: Formatters MUST NOT run during Delegated Agent Execution (DAE). In DAE mode, the provider CLI manages its own formatting; Puppet Master performs no post-hoc formatting.
L00000061	
L00000062	DAE analytics and `/blocked` truth still require a post-hoc `tool-event` story in the provider/run-mode event owners; the formatter subsystem records only HTE formatter events and must not synthesize DAE tool-event history after the fact.
L00000063	
L00000064	ContractRef: ContractName:Plans/Run_Modes.md#STRATEGY-HTE, ContractName:Plans/Run_Modes.md#STRATEGY-DAE
L00000065	
L00000066	### 2.2 Formatting changes in diffs and evidence
L00000067	
L00000068	
L00000069	When a formatter modifies a file beyond whitespace-only changes, the diff between the tool's output and the formatted output is recorded in the evidence ledger as a `format.applied` event:
L00000070	
L00000071	```
L00000072	{
L00000073	  "event_type": "format.applied",
L00000074	  "formatter_id": "rustfmt",
L00000075	  "file_path": "src/main.rs",
L00000076	  "diff_bytes": 142,
L00000077	  "timestamp": "..."
L00000078	}
L00000079	```
L00000080	
L00000081	This ensures reviewers can distinguish agent-authored changes from formatter-applied changes.
L00000082	
L00000083	ContractRef: ContractName:Plans/Contracts_V0.md#EventRecord
L00000084	
L00000085	### 2.3 Error handling
L00000086	
L00000087	If a formatter command exits with a non-zero status:
L00000088	- The original tool output is **preserved** (the file is not corrupted).
L00000089	- A `format.error` event is logged with the formatter ID, file path, exit code, and stderr.
L00000090	- The pipeline continues; formatter failures do not block the run.
L00000091	
L00000092	ContractRef: PolicyRule:Decision_Policy.md§2

L00000132	## 4. Configuration
L00000133	
L00000134	<a id="FORMATTER-CONFIG"></a>
L00000135	
L00000136	### 4.1 Global disable
L00000137	
L00000138	Setting `config.formatters.enabled = false` disables **all** formatters globally. No formatters run regardless of per-formatter config.
L00000139	
L00000140	ContractRef: PolicyRule:Decision_Policy.md§2
L00000141	
L00000142	### 4.2 Per-formatter config
L00000143	
L00000144	Each formatter can be individually configured:
L00000145	
L00000146	```toml
L00000147	[formatter.rustfmt]
L00000148	disabled = false
L00000149	command = ["rustfmt", "--edition", "2021", "$FILE"]
L00000150	environment = { RUST_LOG = "warn" }
L00000151	extensions = [".rs"]
L00000152	```
L00000153	
L00000154	| Field | Type | Default | Description |
L00000155	|-------|------|---------|-------------|
L00000156	| `disabled` | `bool` | `false` | When `true`, this formatter is skipped even if detected. |
L00000157	| `command` | `string[]` | Built-in default | Command and arguments. `$FILE` is replaced with the file path at execution time. If empty (`[]`), the formatter is skipped. |
L00000158	| `environment` | `map<string, string>` | `{}` | Environment variables set when running the formatter command. |
L00000159	| `extensions` | `string[]` | Built-in default | File extensions this formatter handles. Overrides the built-in extension list. |
L00000160	
L00000161	### 4.3 `$FILE` placeholder
L00000162	
L00000163	The literal string `$FILE` in the `command` array is replaced with the absolute path of the file being formatted at execution time. If `$FILE` does not appear in the command, the file path is appended as the last argument.
L00000164	
L00000165	### 4.4 Custom formatters
L00000166	
L00000167	Users can define custom formatters by adding entries to the config with `command` and `extensions`. Custom formatters have no auto-detection; their `enabled()` check is always `true` (unless `disabled = true`).
L00000168	
L00000169	```toml
L00000170	[formatter.my-custom-formatter]
L00000171	command = ["my-fmt", "--fix", "$FILE"]
L00000172	extensions = [".xyz", ".abc"]
L00000173	```
L00000174	
L00000175	### 4.5 Config persistence
L00000176	
L00000177	Formatter config is stored in:
L00000178	- **Global:** `~/.config/puppet-master/config.toml` under the `[formatter]` section.
L00000179	- **Project:** `.puppet-master/config.toml` under the `[formatter]` section (overrides global per-formatter).
L00000180	
L00000181	ContractRef: ContractName:Plans/Plugins_System.md#PLUGIN-CONFIG

L00000222	## 6. OpenCode baseline and Puppet Master deltas
L00000223	
L00000224	<a id="BASELINE-DELTAS"></a>
L00000225	
L00000226	Per `Plans/OpenCode_Deep_Extraction.md` §7E and §9E:
L00000227	
L00000228	### 6.1 Baseline
L00000229	
L00000230	OpenCode formatters run automatically after every `File.Event.Edited` bus event. Built-in formatters auto-detect availability via binary checks and config file presence. Config `formatter: false` disables all. Per-formatter config: `{ disabled, command, environment, extensions }`. `$FILE` placeholder in command arrays. Custom formatters added via config with `command` and `extensions`.
L00000231	
L00000232	### 6.2 Puppet Master deltas
L00000233	
L00000234	1. **Event-driven trigger in Rust:** OpenCode uses a TypeScript bus event system. Puppet Master implements the trigger via internal event dispatch after hosted tool write/edit operations.
L00000235	2. **Formatter auto-detection in Rust:** OpenCode uses `BunProc.which()` for binary detection. Puppet Master uses `which` crate or PATH search via `path_utils::resolve_executable`.
L00000236	3. **Evidence tracking:** OpenCode does not explicitly track formatting diffs. Puppet Master records `format.applied` events with diff metadata in the evidence ledger.
L00000237	4. **HTE-only enforcement:** OpenCode runs formatters regardless of execution strategy. Puppet Master restricts formatters to HTE mode only; DAE delegates formatting to the provider CLI.
L00000238	5. **GUI settings:** OpenCode has no GUI. Puppet Master provides a dedicated Formatters settings tab with per-formatter config editing.
L00000239	
L00000240	ContractRef: ContractName:Plans/OpenCode_Deep_Extraction.md

L00000244	## 7. Acceptance criteria
L00000245	
L00000246	<a id="ACCEPTANCE"></a>
L00000247	
L00000248	These criteria are testable assertions that MUST hold for any conforming implementation.
L00000249	
L00000250	ContractRef: ContractName:Plans/Formatters_System.md, ContractName:Plans/Progression_Gates.md
L00000251	
L00000252	<a id="AC-FMT01"></a>
L00000253	**AC-FMT01:** Formatters MUST run after every file write/edit performed by hosted tools in HTE mode. Formatters MUST NOT run in DAE mode.
L00000254	
L00000255	<a id="AC-FMT02"></a>
L00000256	**AC-FMT02:** Setting `config.formatters.enabled = false` MUST disable all formatters globally.
L00000257	
L00000258	<a id="AC-FMT03"></a>
L00000259	**AC-FMT03:** Per-formatter `disabled = true` MUST prevent that formatter from running, even if auto-detection passes.
L00000260	
L00000261	<a id="AC-FMT04"></a>
L00000262	**AC-FMT04:** The `$FILE` placeholder in command arrays MUST be replaced with the actual file path at execution time.
L00000263	
L00000264	<a id="AC-FMT05"></a>
L00000265	**AC-FMT05:** Formatter errors (non-zero exit) MUST NOT corrupt the file. The original tool output MUST be preserved.
L00000266	
L00000267	<a id="AC-FMT06"></a>
L00000268	**AC-FMT06:** Formatting changes MUST be recorded as `format.applied` events in the evidence ledger with diff metadata.
L00000269	
L00000270	<a id="AC-FMT07"></a>
L00000271	**AC-FMT07:** The GUI Formatters tab MUST display all formatters with enable/disable toggles, and support per-formatter command/environment/extension editing.
