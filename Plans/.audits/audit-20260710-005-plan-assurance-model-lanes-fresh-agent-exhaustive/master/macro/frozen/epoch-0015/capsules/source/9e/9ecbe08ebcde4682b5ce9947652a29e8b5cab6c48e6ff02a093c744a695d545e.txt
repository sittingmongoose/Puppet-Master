L00000036	## 2. Don't duplicate canonical contracts
L00000037	
L00000038	A doc that consumes orchestration, routing, runtime identity, approval, or worktree/lane behavior must consume the owning contract rather than restating feature-local canon.
L00000039	
L00000040	Rules:
L00000041	- owner docs are updated before consumer docs when canon changes
L00000042	- stale canonical text must be replaced or retired; append-only clarification is not sufficient when old text would remain misleading
L00000043	- a consumer doc must not preserve an older model as a peer option once a replacement canon exists
L00000044	- summary, checklist, and feature-list mirrors do not re-own canon and must be reconciled after owner docs change
L00000045	- `Plans/newtools.md` (`/newtools.md`) and its MCP `/web-tooling` origin text are consumer alignment only; verify them against canonical owners before treating older tooling prose as live canon. `Plans/newfeatures.md` (`/newfeatures.md`) is promoted-feature `/origin` summary material and must be reconciled whenever owner docs change so origin text does not remain misleading.
L00000046	- Firecrawl/lost-spec packet impact checks keep `Plans/MCP_Integration.md` (`/MCP_Integration.md`), `Plans/feature-list.md` (`/feature-list.md`), `Plans/newfeatures.md` (`/newfeatures.md`), and `Plans/human-in-the-loop.md` (`/human-in-the-loop.md`) in scope when MCP availability, summary `/reference` surfaces, promoted-feature summaries, or approval ladder / HITL semantics would otherwise remain misleading.

Blocked-episode `gap-005` cleanup must distinguish globally missing canon from owner-defined canon that is only absent from Tools and `/chat/usage` consumers.
L00000095	
L00000096	Route reconciliation updates owner docs first, then consumer docs consume the canonical route/object model; consumer pages must not invent `/object` or page-local identity rules as peer canon.

L00000193	## 7.1 Packet-fidelity semantic matching
L00000194	Packet-fidelity checks used by VERIFIER packet preflight and SCRIBE self-check MUST ignore standalone lines whose trimmed text starts with `ContractRef:` on both the packet-text side and the file-text side before substring matching.
L00000195	
L00000196	Required matching order:
L00000197	1. Strip standalone `ContractRef:` lines from both texts.
L00000198	2. Convert CRLF to LF.
L00000199	3. Trim trailing whitespace per line.
L00000200	4. Collapse runs of spaces/tabs to a single space.
L00000201	5. Collapse 3+ blank lines to 2 blank lines.
L00000202	6. Perform substring matching on the normalized texts.
L00000203	
L00000204	This semantic matching rule exists only for packet-fidelity/self-check comparisons and MUST NOT weaken ContractRef enforcement in run-gates or any other plan-quality gate.
L00000205	
L00000206	ContractRef: Primitive:DRYRules, Gate:GATE-009, PolicyRule:Decision_Policy.md§2
