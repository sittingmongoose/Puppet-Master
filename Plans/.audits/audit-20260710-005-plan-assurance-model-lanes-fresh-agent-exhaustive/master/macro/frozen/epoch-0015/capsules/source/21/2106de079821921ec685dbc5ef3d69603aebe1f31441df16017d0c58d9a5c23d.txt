L00000068	Primitive:RouteTarget / Primitive:OpenSubject
L00000069	
L00000070	Route targets and open subjects are the canonical way to name destinations and inspection points across GUI, CLI, help, and underlying services. This section clarifies the boundary: ownership and canonical semantics live in Plans/Contracts_V0.md; this section explains how surfaces navigate them.
L00000071	
L00000072	#### Route target navigation rules
L00000073	
L00000074	
L00000075	1. CLI `-r`/`--route` and GUI "Save" buttons resolve route_target strings through a cascade:
L00000076	   - `file://...` → local file system (requires file permissions)
L00000077	   - `github://owner/repo/path` → GitHub repository (requires auth and branch access)
L00000078	   - `workspace://project/concern` → internal workspace (always allowed, creates if absent)
L00000079	   - `share://sharepoint-url` or `notion://...` → external service (depends on integration availability)
L00000080	2. If route is ambiguous (e.g., `~/output` with no scheme), the active Persona's default route is used.
L00000081	3. Crosswalk does not own the decision; it documents how the decision made in Contracts_V0.md and Models_System.md flows through to the UI.
L00000082	
L00000083	#### Open subject navigation rules
L00000084	
L00000085	
L00000086	1. GUI "Open" and "Inspect" buttons normalize open requests to an OpenSubject and route through the orchestrator's concern/help/artifact resolution.
L00000087	2. Subject types: `file`, `concern`, `help_entry`, `project_state`, `run`, `artifact_storage`.
L00000088	3. Crosswalk describes which surfaces can open which types; canonical ownership rules are in Contracts_V0.md.
