L00000052	## Rule Scope Model
L00000053	
L00000054	The normative model is not a Phase/Task/Subtask/Iteration hierarchy and does not create runtime role policy. The durable instruction scopes are:
L00000055	
L00000056	### Application-Level Rules (Puppet Master)
L00000057	- **Scope:** every agent run under Puppet Master, regardless of whether the work is Assistant, Interview, Orchestrator, or a delegated child run
L00000058	- **Purpose:** global policies that apply everywhere
L00000059	- **Storage:** redb settings key `app.agent_rules.application_markdown`
L00000060	- **Bootstrap:** if empty, seed from the Puppet Master repo `AGENTS.md`
L00000061	
L00000062	### Project-Level Rules
L00000063	- **Scope:** every agent invocation that runs against a selected project/workspace
L00000064	- **Purpose:** project-specific conventions, tooling expectations, and non-obvious constraints
L00000065	- **Storage:** `<project_root>/.puppet-master/project-rules.md`
L00000066	
L00000067	### Order and precedence
L00000068	- Application rules are always included first.
L00000069	- Project rules are included when a project context exists.
L00000070	- Application rules win over project rules on conflict.
L00000071	- Node/work-package/attempt-specific context is **not** another rules layer; it belongs to the Work Bundle and Memory Bundle.
L00000072	
L00000073	ContractRef: ContractName:Plans/storage-plan.md, ContractName:Plans/Prompt_Pipeline.md, ContractName:Plans/Contracts_V0.md, ContractName:AGENTS.md

L00000075	## Feeding Rules Into Every Agent
L00000076	
L00000077	### Single Rules Pipeline (DRY)
L00000078	
L00000079	- **Concept:** One module or function that, given (optional) project path, returns a **single formatted block** of text: "Application rules" + "Project rules" (if project path is set and project rules exist). All callers use this block when building prompts or system prompts.
L00000080	- **Signature (EXAMPLE only):** `get_agent_rules_context(application_config, project_path: Option<&Path>) -> String`. Returns the concatenated rules block (with optional headers like "## Application rules" and "## Project rules" for clarity inside the prompt).
L00000081	- **Callers:**
L00000082	  - **Orchestrator:** When building the iteration prompt (or system prompt) for each node, call the rules pipeline with the current workspace path; prepend or append the returned block to the prompt (or inject via the context injection hook or a dedicated "rules injector" step).
L00000083	  - **Interview:** When building any prompt that goes to an agent (research, validation, phase Q&A), call the rules pipeline with the interview's target project path; include the block in the prompt.
L00000084	  - **Assistant:** When the user has a project selected, call the rules pipeline with that project path and include the block in the context sent to the CLI. When no project is selected, call with `project_path: None` so only application rules are included.
L00000085	- **DRY:** Rule content lives in one place per layer (application store, project file). The pipeline is the single place that assembles them; no copy-paste of "Context7" or "DRY" into multiple prompt builders.
L00000086	  ContractRef: Primitive:DRYRules

L00000129	## Instruction Bundle Integration (Application + Project + Scoped `AGENTS.md`)
L00000130	
L00000131	This plan's durable rules pipeline remains the user-editable source of rules text, but every agent invocation assembles a deterministic **Instruction Bundle** instead of relying on legacy injector naming.
L00000132	
L00000133	**Instruction Bundle order:**
L00000134	1. Application rules
L00000135	2. Project rules (when a project is selected)
L00000136	3. Scoped `AGENTS.md` instruction chain, when enabled
L00000137	
L00000138	Rules:
L00000139	- the shared rules pipeline outputs rules content only; it does not inject attempt journals, parent summaries, or assistant-only memory
L00000140	- Assistant memory, Attempt Journal, and Parent Summary are separate memory/context injectors and MUST NOT masquerade as rules text
L00000141	- provider cache controls such as `copilot_cache_control` and Anthropic-like cache-marker eligibility are resolved by Prompt Pipeline/provider owners using explicit provider and model-id evidence; the rules pipeline must not infer cache behavior from rule text or model-id heuristics
L00000142	- within the scoped `AGENTS.md` chain, closest scope wins and identical content is deduplicated deterministically
L00000143	- Application rules outrank Project rules and all scoped `AGENTS.md` content; Project rules outrank scoped `AGENTS.md`
L00000144	- prompt builders for Assistant, Interview, Orchestrator, and delegated child runs all use the same assembly order and names
L00000145	- provider-native instruction loaders may be configured to read equivalent context files; for Gemini, settings can override `context.fileName` so `AGENTS.md` is included alongside or instead of the native Gemini context filename

L00000150	## Feature Spec (Verbatim)
L00000151	
L00000152	This feature defines deterministic, low-bloat context management for Puppet Master's node-graph runtime: run/work-package -> node -> attempt. It is a product requirement for the finished Puppet Master application, not a description of the current repo layout.
L00000153	
L00000154	### Purpose
L00000155	Define deterministic, low-bloat context management for Puppet Master's node-graph runtime: run/work-package -> node -> attempt. This is a product requirement for the finished Puppet Master application, not a description of the current repo layout.
L00000156	
L00000157	### Goals
L00000158	1. Fresh context per attempt with durable learning.
L00000159	2. Deterministic bundle assembly that minimizes token waste.
L00000160	3. Scoped instructions (`AGENTS.md`) that remain short and relevant.
L00000161	4. Three user-configurable context injectors with defaults:
L00000162	   - Parent Summary (default ON)
L00000163	   - Scoped `AGENTS.md` beyond top-level (default ON)
L00000164	   - Attempt Journal (default ON)
L00000165	5. Controlled promotion of stable learnings into the nearest appropriate `AGENTS.md`.
L00000166	
L00000167	### Artifact Types (SSOT Definitions)
L00000168	#### A) Instruction Files (Durable)
L00000169	**Name:** `AGENTS.md`
L00000170	**Scope:** applies to the subtree rooted at the directory containing it.
L00000171	**Lightness rule:** short invariants, constraints, and non-obvious conventions only.
L00000172	
L00000173	#### B) Attempt Journal (Ephemeral, per node attempt)
L00000174	**Name:** `attempt_journal.md` (or structured equivalent) stored in PM sidecar state for the relevant node scope.
L00000175	**Purpose:** prevent repeated failed attempts.
L00000176	**Injection:** only the most recent journal for the same node lineage is injected into the next attempt when enabled.
L00000177	
L00000178	#### C) Parent Summary (Ephemeral, per handoff)
L00000179	**Name:** `parent_summary.md`
L00000180	**Budget:** 5–10 lines hard cap.
L00000181	**Injection:** injected into attempt context when enabled.
L00000182	
L00000183	#### D) Promotion (Controlled, optional)
L00000184	
L00000185	
L00000186	Promotion moves stable, reusable learnings into the nearest appropriate `AGENTS.md` when the learning is non-obvious, stable, and scope-relevant.
L00000187	
L00000188	### Context Assembly Semantics (Deterministic Cone)
L00000189	
L00000190	
L00000191	Puppet Master constructs explicit bundles for each agent run:
L00000192	1. **Instruction Bundle**
L00000193	2. **Work Bundle**
L00000194	3. **Memory Bundle**
L00000195	
L00000196	#### Instruction Bundle
L00000197	Always includes top-level `AGENTS.md` when present. When scoped `AGENTS.md` is enabled, include the applicable chain from root to the current scope directory, with closest-scope precedence and deterministic deduplication.
L00000198	
L00000199	#### Work Bundle
L00000200	
L00000201	
L00000202	Contains only what is needed to execute the current node/attempt: objective, acceptance criteria, inputs, allowed tools, and explicit constraints.
L00000203	
L00000204	#### Memory Bundle
L00000205	When enabled, inject the most recent node-lineage Attempt Journal and/or the bounded Parent Summary. Assistant-only memory remains Assistant-only and is not injected into unrelated orchestrator/interview/delegated runs.
L00000206	
L00000207	### Visibility Rules
L00000208	- coordinating runs/packages see coordinating objectives and summaries, not every child attempt journal by default
L00000209	- node execution sees the current node objective, scoped instruction chain, and node-relevant memory only
L00000210	- delegated child attempts inherit the same Instruction Bundle ordering plus child-specific Work/Memory Bundles
L00000211	- verification/review attempts use the same assembly semantics; they do not reintroduce deprecated execution-hierarchy vocabulary
L00000212

L00000215	## Visibility examples (coordinating run → work package → node → attempt)
L00000216	### Coordinating run sees
L00000217	- Instruction: application/project rules plus the relevant scoped instruction chain
L00000218	- Work: run and work-package objectives / acceptance criteria
L00000219	- Memory: bounded summaries relevant to coordination, not every child attempt journal by default
L00000220	
L00000221	### Work-package coordinator sees
L00000222	- Instruction: application/project rules plus the applicable scoped instruction chain
L00000223	- Work: work-package objectives / acceptance criteria
L00000224	- Memory: package-level notes and summaries, not unrelated node-attempt journals
L00000225	
L00000226	### Node execution sees
L00000227	- Instruction: top-level plus the applicable scoped instruction chain
L00000228	- Work: node objectives / acceptance criteria
L00000229	- Memory: node-relevant memory only; coordinating summaries remain bounded
L00000230	
L00000231	### Attempt execution sees
L00000232	- Instruction: the same applicable instruction chain for the bound node scope
L00000233	- Work: this attempt's exact objective + acceptance criteria
L00000234	- Memory: latest attempt journal (if enabled) + parent summary (if enabled)
L00000235	- Excludes: unrelated branches, long histories, and parent full reasoning by default
