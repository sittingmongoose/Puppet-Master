L00000664	## 5. Per-Persona runtime preferences
L00000665	
L00000666	<a id="PERSONA-MODEL-OVERRIDES"></a>
L00000667	
L00000668	A Persona MAY specify preferred runtime settings in the PERSONA.md frontmatter (defined in `Plans/Personas.md` §3.2):
L00000669	
L00000670	```yaml
L00000671	---
L00000672	id: "rust-engineer"

L00000682	```
L00000683	
L00000684	| Field | Required | Type | Description |
L00000685	|-------|----------|------|-------------|
L00000686	| `default_platform` | Optional | `string` or `null` | Preferred provider/platform. `null` or absent means inherit from the selection chain (§2). |
L00000687	| `default_model` | Optional | `string` or `null` | Model identifier in `provider_id/model_id` format. `null` or absent means inherit from selection priority (§2). |
L00000688	| `default_variant` | Optional | `string` or `null` | Preferred variant preset. `null` or absent means inherit from the selection chain (§2). |
L00000689	| `temperature` | Optional | `number` or `null` | Preferred sampling temperature when supported by the active provider transport. |
L00000690	| `top_p` | Optional | `number` or `null` | Preferred nucleus sampling value when supported. |
L00000691	| `reasoning_effort` | Optional | `string` or `null` | Preferred effort/reasoning level when the provider transport exposes it. |
L00000692	
L00000693	Rule: Persona runtime preferences participate at priority 2 in the selection chain (§2). They are overridden by explicit run-envelope or surface-level overrides (priority 1) but override surface defaults, config defaults, last-used state, and internal defaults.
L00000694	
L00000695	Rule: If a Persona specifies a preferred platform/model/variant that is not available, the system logs a warning and falls through to the next priority level. The run is NOT blocked.
L00000696	
L00000697	Rule: If a Persona specifies runtime controls (`temperature`, `top_p`, `reasoning_effort`) that the active provider transport does not support, those controls MUST be recorded as skipped and excluded from the effective runtime state rather than silently ignored.

L00000703	## 6. Variants system
L00000704	
L00000705	
L00000706	<a id="VARIANTS"></a>
L00000707	
L00000708	### 6.1 Definition
L00000709	
L00000710	A **Variant** is a named model preset that the user can quickly switch between. Variants provide a fast way to cycle through models without editing config.
L00000711	
L00000712	### 6.2 Built-in variants
L00000713	
L00000714	Puppet Master ships with a set of built-in variants based on available providers:
L00000715	
L00000716	| Variant name | Target model | Description |
L00000717	|-------------|-------------|-------------|
L00000718	| `default` | Per selection priority (§2) | The system-selected model. Always available. |
L00000719	| `fast` | Smallest/cheapest available model | Optimized for speed and cost. |
L00000720	| `powerful` | Largest/most capable available model | Optimized for quality. |
L00000721	
L00000722	Built-in variants are resolved dynamically based on available providers at runtime. If a variant's target model is unavailable, the variant falls back to the `default` variant.
L00000723	
L00000724	### 6.3 Custom variants
L00000725	
L00000726	Users can define custom variants in config:
L00000727	
L00000728	```toml
L00000729	[[variants]]
L00000730	name = "my-variant"
L00000731	model = "anthropic/claude-sonnet-4"
L00000732	description = "My preferred model for code review."
L00000733	
L00000734	[[variants]]
L00000735	name = "cheap"
L00000736	model = "openai/gpt-5-mini"
L00000737	description = "Budget-friendly option."
L00000738	```
L00000739	
L00000740	| Field | Required | Type | Description |
L00000741	|-------|----------|------|-------------|
L00000742	| `name` | **Required** | `string` | Unique variant name. Regex: `^[a-z][a-z0-9-]{0,30}[a-z0-9]$`. |
L00000743	| `model` | **Required** | `string` | Model identifier in `provider_id/model_id` format. |
L00000744	| `description` | Optional | `string` | Max 200 characters. |
L00000745	
L00000746	### 6.4 Disabling variants
L00000747	
L00000748	Built-in and custom variants can be disabled:
L00000749	
L00000750	```toml
L00000751	[variants_disabled]
L00000752	"fast" = true
L00000753	```
L00000754	
L00000755	Disabled variants do not appear in the model picker or variant cycling UI.
L00000756	
L00000757	### 6.5 Variant cycling
L00000758	
L00000759	The user can cycle through enabled variants via:
L00000760	- A keybind (configurable, default unbound).
L00000761	- The model picker dropdown in the Chat panel.
L00000762	- The command palette.
L00000763	
L00000764	When a variant is selected, its `model` field is used as the active model for subsequent runs (priority 3 in §2). The active variant is persisted per session (not across restarts unless `config.default_variant` is set).
L00000765	
L00000766	### 6.6 Per-Persona variant overrides
L00000767	
L00000768	
L00000769	A Persona MAY specify a preferred variant via a `default_variant` field in PERSONA.md frontmatter:
L00000770	
L00000771	```yaml
L00000772	default_variant: "powerful"
L00000773	```
L00000774	
L00000775	When set, this variant is pre-selected when the Persona is active. The user can still cycle to another variant during the session.
L00000776

L00000779	### 6.7 Model aliases (friendly names)
L00000780	
L00000781	
L00000782	Model aliases are optional friendly names that resolve to canonical model identifiers (`provider_id/model_id`) during model override parsing (for example, natural-language `model_override` in media generation).

<<< CONTEXT_AFTER canonical_document_lines=783-794 >>>
L00000783	
L00000784	Deterministic alias resolution requirements:
L00000785	- Alias keys MUST be normalized by lowercasing and collapsing spaces/underscores/hyphens.
L00000786	- Resolution order for user-provided model text is: alias → exact model id → exact display name.
L00000787	- If no match is found, the caller receives a model-unavailable result from the requesting subsystem.
L00000788	
L00000789	Aliases and variants are distinct concepts: aliases are lookup keys for model resolution, while variants are named model presets selected by the user.
