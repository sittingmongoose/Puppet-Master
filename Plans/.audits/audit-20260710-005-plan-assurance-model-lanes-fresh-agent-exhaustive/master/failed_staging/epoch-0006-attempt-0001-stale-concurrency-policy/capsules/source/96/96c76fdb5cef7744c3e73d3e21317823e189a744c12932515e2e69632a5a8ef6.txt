L00000469	### Publish flow
L00000470	#### Publish execution, approval, and blocked-outcome contract
L00000471	
L00000472	The canonical publish path is a **two-step** model:
L00000473	
L00000474	1. `cmd.orchestrator.build_run` performs local build / preview preparation only.
L00000475	2. `cmd.orchestrator.push_image` performs remote DockerHub publication only.
L00000476	
L00000477	Normative rules:
L00000478	- `cmd.orchestrator.build_run` MUST NOT create DockerHub repositories, push images, create remote template repos, or push remote template repos.
L00000479	- `push_policy = after_build` means Puppet Master automatically dispatches `cmd.orchestrator.push_image` **after** a successful local build result exists; it does **not** fold remote publish into `build_run`.
L00000480	- A direct user click on **Build** approves build only.
L00000481	- A direct user click on **Push image** approves image push only.
L00000482	- If the target DockerHub repository is missing, repository creation remains a separate side effect and requires its own confirmation/approval.
L00000483	- If managed Unraid template-repo push is later requested, that remote push is a separate side effect and requires its own approval.
L00000484	- `docker.publish.failed` means Puppet Master attempted the publish operation and the operation failed at runtime.
L00000485	- `docker.publish.blocked` means Puppet Master intentionally did not execute the remote side effect because confirmation or permission approval was missing, rejected, or cancelled.
L00000486	
L00000487	#### Missing-repository interruption and resume contract
L00000488	
L00000489	If `cmd.orchestrator.push_image` resolves a missing target repository:
L00000490	
L00000491	1. Puppet Master MUST preserve the local build result and enter `awaiting_repo_creation_confirmation`.
L00000492	2. Puppet Master MUST emit `docker.repository.create.confirmation_requested`.
L00000493	3. Confirming creation dispatches `cmd.docker.create_repository.confirm`.
L00000494	4. On successful repository creation, Puppet Master resumes the pending `cmd.orchestrator.push_image` attempt without forcing a rebuild.
L00000495	5. If repository creation is cancelled, rejected, or blocked by policy, Puppet Master MUST emit `docker.publish.blocked` with:
L00000496	   - `reason_code: repo_creation_not_confirmed`
L00000497	   - `blocked_step: create_repository`
L00000498	   - `allowed_action_ids[]`
L00000499	6. `docker.publish.blocked` MUST preserve the already-built local image/result so the user can retry without rebuilding.
L00000500	
L00000501	- publish uses DockerHub-targeted image tags and namespace/repository selection
L00000502	- push policy remains `manual` by default with optional `after_build`
L00000503	- after successful push, capture and surface:
L00000504	  - pushed tags
L00000505	  - digest(s)
L00000506	  - registry host
L00000507	  - target namespace/repository
L00000508	  - platform list
L00000509	  - sanitized logs path
