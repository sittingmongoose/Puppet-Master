# Per-surface "what the GUI must show now" briefs (from current Plans shards, 2026-07-08)

Citations: `dir/NNN` = Plans/_shards/<dir>/<NNN-…>.md. Read the cited shard when you need more depth.

## GLOBAL SHELL (finalguispec/009, 010, 014)
Title bar (28px: wordmark, compact project context, theme toggle, gear) → Activity bar (icon nav, always visible; 5 groups per delta_digest) → Primary content → side panel (240–480px, one surface at a time, detachable) → Bottom panel (120–300px collapsible: Terminal/Problems/Output) → Status bar (24px: chat mode, platform▾, model▾, ctx 42k/128k, orchestrator status, index progress). Command palette Ctrl+K/Ctrl+P (centered overlay top-third; prefixes: none=pages/commands/recent/files, `>`=commands, `@`=file/symbol, `/`=slash). Breadcrumb strip 20px `Group > Page`. Tier-1 shortcuts: Ctrl+K palette, Ctrl+L focus chat, Ctrl+N new thread, Ctrl+Shift+E File Manager, Ctrl+Shift+F Search, Esc close/stop. System tray (when minimize-to-tray): icon accent when running; menu Show/Hide | Pause/Resume Orchestrator | Quit; notifications for HITL, run complete, rate limit.
Shared status vocabulary: Running, Ready, Blocked, Needs Attention, Degraded, Stale, Detached, Not Configured. Every disabled control: inline reason + tooltip with exact blocking condition + recovery CTA. "Explain this state" affordance (ELI5 + expert) on status pills/disabled buttons/blocked banners. Empty-state taxonomy (distinct): Not relevant / Not configured / Unavailable / No data yet / No results for current filter.
Two widget catalogs: FinalGUISpec §8 = atomic components; Widget_System = composed page widgets (only these are add/move/resize-able).

## 1. ORCHESTRATOR (orchestrator_page/003, finalguispec/013 §7.1, run_graph_view/003-005, widget_system/006)
Seven fixed tabs: Progress | Plan Compile | Seams | Node Graph | Evidence | History | Ledger. Only Progress is widget-composed. Page-level `focused_run_id` + `focus_mode = live|historical` (persistent banner/chip when historical).
- Progress: hosts widget-orchestrator-progress + 13-widget catalog — progress.run-overview (execution-unit tree), current-task (active node inspector), lane-health, node-throughput, blocked-concerns, approval-queue, recovery-status, artifact-receipts, worktree-state, account-pressure, account-switches, escalation-stack, attention-summary. Historical mode → summary or locked + "switch back to live".
- Plan Compile: compile projection; launch reconciliation after Approve And Build (pending-launch shell → binds durable PlanCompileRun).
- Seams: compact seam/lane rollups first; packages + node problem lists expand lazily.
- Node Graph: canvas + right detail inspector; package-group swimlanes, seam boundaries, parallel lanes (NOT phases); minimap/search/overlays, zoom+pan, generation-aware branch/rejoin; virtualization for thousands of nodes. Inspector answers: requested/effective provider/model/effort/persona/account, usage/token/cost, worker policy, retry/review/promotion state, lane/worktree/snapshot, linked evidence/artifacts. Diff cards cap 50 lines → "View Full Diff".
- Evidence: verdicts/receipts/findings pane + artifacts pane, bidirectionally linked. History: chronological durable story. Ledger: exact record inspection, routeable ids.
Node states queued|running|attention_required|blocked|recovering|degraded|complete. Actions Inspect|Focus run|Open evidence|Request approval|Acknowledge|Dismiss|Resolve|Retry recovery. Alerts advisory|attention_required|blocked|escalated|degraded_projection. Projection freshness current|refreshing|stale|degraded|unavailable (degraded → disable mutation).
Concerns: lifecycle active|acknowledged|resolved|dismissed; resolution_kind fixed|accepted_risk|superseded|merged|split|invalidated|obsoleted_by_patch|obsoleted_by_recovery; blocked-owner (8): Runtime, Package Overseer, Seam Overseer, Corroboration, Graph Patch, Recovery, User, External Resource; escalation ladder info|watch|attention_required|blocked|escalated. Blocked worktree cards show affected files + "Open Conflict Assistant".
Flows: Approve And Build → auto-switch here → Plan Compile pending-launch → binds. HITL gate → Dashboard CTA + spawned chat thread → resolve either place. Pause/Resume via tray/controls. Cross-tab deep links carry focused run. Owner-route pivots cmd.orchestrator.open_in_source_control|open_in_github_actions|open_in_docker_manager|open_kubernetes|open_receipt.
Terminology: seam/package/node/lane/worktree; active_run_id vs focused_run_id; promotion classes lane_to_package, package_to_seam_available, seam_complete.

## 2. PLANNING WIZARD (planning_wizard/005 PWIZ-002…014, finalguispec/030, /013 §7.6)
ONE workspace — collapsible parent named for the plan, containing child topic threads + final integration + final review + audit/repair activity. Regions: topic map, active chat panel, live plan preview (document pane), source/annotation/readiness panels. Child threads load on selection.
Topic cards states: not_started, active, ledger_syncing, ledger_synced, compiling, auditing, repairing, ready, impacted, reopened, deferred, blocked + dependency/origin badges. Dynamic topic map (evidence-driven; controller ops add/split/merge/rename/defer/reopen/reorder/mark-impacted). Possible topics: overview, product behavior, GUI/UX, backend, data, integrations, security, permissions, testing, deployment, migration, observability, risks.
Long-running stages always show progress ("audit pass 2 of 3, 4 findings fixed").
Interview: shared question system — question text, suggested option chips, mandatory "Something else" freeform, draft answer state; multi-question questionnaires, answer any order, revise before submit. Controller auto-resolves from evidence, applies safe defaults w/ recorded assumptions; asks user ONLY genuine product direction / risk acceptance / destructive authority / credentials / legal / irreconcilable ambiguity.
Project context (independent of intent): greenfield / existing local / existing Git / remote SSH / fork-upstream. Work intents (multi): new product / feature / refactor-rewrite / bugfix / contribution PR. Read-only discovery: git status, branch, remotes, file tree, package managers, frameworks, test commands.
Final review = live doc preview + selection context menu + comments + source inspection + challenge + targeted revision + annotation status; supports uploaded reference images + generated wireframes/architecture/data-flow/state diagrams (artifact IDs, provenance, topic links).
**Approve And Build** = the only final approval-to-launch control (never START/BUILD/Start Chain/Approve & Continue; no second confirmation). CAS over displayed currentness values (PlanningRun revision, topic map version, project-context hash, PlanUnit + acceptance index hashes, testing policy hash, audit closure hash) → fails closed if changed → success writes approval_cas_receipt, publishes PlanApproved, binds exactly one PlanCompileRun, then auto-switch to Orchestrator > Plan Compile.
Flow: intake (project attach; "Imported from Assistant Chat/Deep Plan" banner w/ user goal, scope summary, included-plan y/n, open-questions count, has_gui hint; active project → preloaded feature path) → discovery → topic interview loop (fresh topic agent + Context Capsule; closure → Overseer conversion → Topic Plan Draft → scoped fidelity audit → repair → Ready) → final integration (Final Plan Pack) → final audit/repair (parallel read-only specialists → findings → bounded repairs → re-audit) → compile-readiness gate (zero-incomplete: no stubs/TODOs/placeholders; only user_approved_incomplete_item) → final review → Approve And Build.
Terminology: PlanningRun, planning_run_id, thread_group_id, topic map, Planning Context Capsule, Topic Plan Draft, Final Plan Pack, ApprovedPlanPack, Planning Amendment, AuditCycle/AuditFinding/RepairAttempt/AuditClosure/CertificationReceipt.

## 3. ASSISTANT CHAT (assistant-chat-design/007,010,017,020,022,027; finalguispec/013 §7.16, /030)
Vertical split: stream 70% / composer 30%. Sticky thread header: editable title, mode badge, persona indicator, model indicator, token summary, quick actions (search/rename/duplicate/archive/settings); context circle = context-state entrypoint (hover → Usage/Tokens/est. Cost/More Details; click → "Compact Now"; More Details → thread-scoped Context Detail Pane editor tab, Curated: Overview/Breakdown/Messages + Raw).
Control strip: Provider▾, Model▾, Reasoning/effort (when supported), Worktree icon (unbound dimmed / bound-clean lit / bound-dirty lit+dot / bound-conflict lit+warning; hidden if no git). Changes apply next turn.
Stream: virtualized; types user|assistant|system|tool_result|operation_card|blocked_notice|subagent_card|error. Inline activity cards (compact 5 lines, expanded 15, log cap 50 → route to owning surface). Sticky unread marker, "New messages below", jump-to-latest w/ count.
Composer: multiline; mode selector min Steer+Queue; attachments; send/stop morph; disabled-state explanation. Copy affordances on code blocks + every message. Stop/Edit/Resend only on most-recent user message (no Delete). Queue FIFO max 2, transient; "queue full" state.
Plan panel (Plan/Deep Plan modes only): current plan, live TODO tracker (pending|in_progress|completed|blocked|skipped), plan states draft|approved|executing|completed|blocked|superseded; focus-active-step; jump-to-doc.
Modes (5): Ask (read-only), Agent (execute; yolo opt-in), Debug (evidence-first; distinct styling; 8-phase target_binding→cleanup), Plan, Deep Plan (rich doc in preview editor). PT segmented Light|Balanced|Comprehensive (default Balanced). Overlays: Interview, BrainStorm, Crew.
Subagents/Crew: real-time status chips (name, running|waiting|done|failed, elapsed); header count badge; collapsible cards (collapsed Persona/Task/Status; expanded work stream + thought stream + state + context + result). Child status queued|running|awaiting_parent|blocked|complete|failed|cancelled. Fan-out → batch card → subgroups of 10. Children escalate to parent; parent asks user in main thread. Crew = multi-model coordination w/ inspectable crew board.
Flows: wizard recommendation card (reason + "Add a new Feature or Enhancement" + "Stay in Chat") → wizard intake w/ imported-context banner. Dashboard CTA "Continue in Assistant" injects run/package/seam/node context. HITL → dedicated thread; typing "approve and continue" works. Stop → cancel_grace 3000ms → cancelled.

## 4. GITHUB (github_integration/005, github_api_auth_and_flows/003, finalguispec/010)
Two panels, never merged. **Source Control** (local Git-first): accordion sections w/ counts; subviews Changes (staged/unstaged/untracked; stage/unstage/discard/commit/push/pull/fetch/sync; stash; branch ops; incoming/outgoing; conflict inline actions; AI commit-message gen), History, Graph, Worktrees, Branches/Stash. Deterministic compare origins (unstaged→index↔working; staged→HEAD↔index; untracked→empty↔working; history→commit↔first-parent; conflict→3-way). Worktrees = single-column expandable rows: glyph + branch + chevron + owner label (`Thread: <title>` / `Orch: <lane label>` / `Manual`); expanded: Path/Base/Age + Open Files/Compare/Merge/Remove/Create PR/Open Thread/Open Lane. Filter bar All|Threads|Orchestrator|Manual (persists per-project). Ownership badges, prune protection, safe-point awareness.
**GitHub Actions**: subviews Current Branch (branch-scoped readiness, latest runs, status checks, rerun/cancel/pin, links to Source Control), Workflows (inventory, run history/detail, log follow, workflow_dispatch forms, pin/unpin), Settings (secrets/variables/environments names-only readiness, permissions, runner labels, pinned workflows, auth diagnostics). Failure triage (failing job/step, last logs, changed files, likely next action, auto-expand failing step, open-in-browser fallback). Replay-from-last-known-good (cmd.github.actions.compare_last_success). Actions-to-code pivots (open_related_diff, open_related_worktree). Event-driven + bounded refresh; stale snapshots labeled + cannot authorize dispatch. Blocked reasons: actions_no_github_remote|auth_required|auth_expired|missing_scope_runtime|missing_scope_admin|workflow_not_dispatchable|missing_secret|missing_variable|missing_environment|environment_review_required|environment_wait_timer|branch_rule_mismatch|dispatch_input_invalid|workflow_file_invalid. Repo lifecycle: active|renamed_redirected|transferred|deleted|archived|remote_mismatch|historical_only.
Auth: device-code flow (verification_uri + user_code + expiry + scopes; polling); missing scopes → reconnect-with-expanded-scopes CTA; requested vs effective account; capability disclosure ("can view runs but cannot dispatch").

## 5. DOCKER MANAGER (containers_registry_and_unraid/005, finalguispec/013 §7.4.8A)
First-class side panel; replaces "Docker Manage"; subsumes Unraid. Auto-hide when no container project (setting default on; detection detected|manually_enabled|not_detected). Subviews: Containers | Images | Compose | Registries (Docker Hub first) | Build/Bake | Publish/Unraid | advanced Networks/Volumes/Contexts | conditional Kubernetes (project-focused; cluster-wide toggle default OFF). Podman alternate in same surface. Persists per-project (runtime/context, subview, grouping, asset row).
Containers: lifecycle, logs, inspect, attach/shell, stats, "Open running container" (only w/ real URL); access intelligence (URL/port/health/shell detection, candidates when uncertain). Images: build/pull/push/tag/inspect/remove/prune, digest visibility. Compose: project lifecycle, service subsets, logs, scenario runner (named subsets/profiles/env/ports; save/run/edit/delete; stale marker). Build/Bake: Dockerfile target selection, Buildx/Bake discovery, build preview, project-aware inference. Publish/Unraid: auth, requested-vs-effective, protected repo creation (hard_gate), digest receipts, publish chain view (local build → pushed tag/digest → Hub repo state → Unraid template follow-ons → downstream; missing-link for partial), Unraid XML gen + template-repo status row. Kubernetes: apply/diff/rollout/logs/exec/port-forward/workloads/Helm basics; governance blocked states (RBAC/namespace/admission/quota/remote_mismatch).
Flows: build → preview → explicit /tag/push release → repo-creation confirm → publish → XML → template commit → one-click push. Cleanup advisor (dry-run, projected savings, protected assets). Drift detection. indeterminate_remote_outcome receipts w/ "Refresh remote state".

## 6. DASHBOARD (finalguispec/013 §7.2, /027, widget_system/006)
Widget grid, responsive columns (2 <1200 / 3 1200–1600 / 4 >1600), 8px gutters; drag-reorder + edge-resize + snap; crosshatch drag handle top-left; CTA cards elevated w/ accent left border. Default = exactly 4 widgets (orchestrator-progress, active-lanes, recent-results, custom-metrics); broader widget.* library = catalog candidates. Layout key widget_layout:v1:dashboard. Warnings (usage limits, config gaps, Doctor findings, run review) + CTAs (approve/acknowledge/run-fix) — chat-addressable; HITL CTA spawns dedicated thread + direct "Approve & continue"; "Continue in Assistant" handoff. Add Widget: menu → catalog → confirm placement/size.

## 7. USAGE (usage-feature/009,011,017)
Fully widget-composed 4-col grid; per-widget gear (time window, platform filter, chart type); all Usage widgets Dashboard-hostable. Defaults: widget.quota_summary 2x1 (5h/7d bars per platform + plan type), widget.alert_thresholds 2x1, widget.analytics_chart 2x2, widget.budget_donuts 2x2, widget.tool_usage 2x2 (invocations, latency p50/p95, error rate, index_used mix), widget.multi_account 2x2 (accounts, active/effective marker, plain-language status, pressure/cooldown, stale label), widget.ledger_table 4x3 (event ledger, filtering, JSON export). Quota always-visible (5h+7d vs limit, plan e.g. Pro/Team). Alerts at 80% + rate-limit-hit w/ suggested action. Cost attributed to effective_account_id. Per-thread usage lives in chat, NOT here. Provider buckets separate (Cursor inferred vs reported; Codex plan vs API-billed distinct).
