Reopen the same round without charging again. Review the proposed Plan, cancel its preview or explicitly create it, and inspect it in the ordinary Plan document tab. ### Research can become stale

Exhaustive adds a labelled supplied reference extract and a broader impact-review section. The disclosure's source-change control can revise the actual fixture while its source-bound inspection is pending, or after the Plan preview is created. An obsolete callback or confirmation is refused. Recheck the current source and review again. The source artifact opens in the ordinary shared artifact viewer, not a separate source store/viewer. The reference extract is supplied and illustrative: no current web fetch or provider research is claimed.

### One allowance, every participant

A finite set of concrete decisions contains a duplicate proposal from a second recorded participant. Their semantic identity is merged before presentation. The run presents ten actual questions through successive eligible frontiers. At exhaustion, another question is refused without failing planning. Enable Grill Me: the same count remains ten and the allowance rises to 35. Answer the dependent eleventh decision, then disable Grill Me. All eleven answers remain; the limit is ten and remaining is zero. The final unasked item is explicitly non-blocking, so synthesis and an explicit Build remain available.

### An open decision can block Build

Repeat the allowance boundary with the last item classified as a required destination-permission decision. The resulting Plan visibly retains that unresolved Build blocker. It is the explicit blocker—not the exhausted allowance—that disables Build. The underlying Build handler enforces the same rule.

## Shared owners and boundaries

`question-budget-protocol.js` is the sole concept question-counter owner. `plans.js` and the existing `brainstorm-protocol.js` consume it. Charges are derived from stable presented-question identities, reuse/research from actual resolution records, and effective totals from the frozen policy plus the current Grill Me setting. There is no per-participant or Grill-only pool. The factory ceilings are 3/6/8/10/15/20 and the extension is 25; explicit custom values remain explicit. Templates and validation receipts are a **reduced local scoped profile**, not proof of a production standard-schema compiler. ```bash

python3 APPLY_BATCH14.py --repo "/path/to/isolated-worktree" --apply \
  --backup-dir "/absolute/path/outside-checkout/b14-backup"

Do not copy an older cumulative archive over another agent's edits.
