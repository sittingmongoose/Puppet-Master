# Batch 12 — Back Seat Driver

This is a bounded, session-only **HTML concept checkpoint**, built on the installed guarded Batch 11 repair. It is not native runtime, production storage, registered BSD command/event wiring, live provider execution, or a governance seal. The old age-driven BSD example has been replaced by an evidence-dependent local protocol and two complete workflows.

## Start here

Open the generated standalone or `index.html`. In **Demo Studio → Back Seat Driver · complete local workflows**, choose:

**Catch a missing measurement.** Configure the advisor before starting; dismiss the guide if desired. Start local work. The missing measurement raises a held concern, with no public warning. Continue without a measurement, then Review current work. The same concern is reconfirmed against a newer evidence generation and appears once with source-linked evidence. Repeating the review does not create another note. Dismissal preserves closure for unchanged evidence. Record measurement and finish the local primary work independently.

**Resolve it before delivery.** Start local work, record the measurement, and Review current work. The local inspector computes the recorded sample inputs as 6% additional writes against an 8% bound. Current-generation silence clears the held concern. Evidence and history remain inspectable, but no warning is put into the ordinary conversation. Finish local work is a primary-fixture operation, not BSD approval.

The SQL is **not executed**. The sample arrays are explicitly recorded fixtures; arithmetic and version/currentness transitions execute locally. The Adversarial checks disclosure accepts other valid sample arrays, so outcomes are not keyed to one fixture identity or a pre-authored success message.

BSD can also be configured through the existing grouped **wand → Assistance → Back Seat Driver** route. The compact Context row and **Context More Details** project the same scoped state. No demo commands have been added to the product wand.

## What changed

`bsd-protocol.js` is the single local state-machine owner. It keeps separate project policy revisions, frozen workflow binding revisions, thread/run/stage assignments, advisor epochs/cursors, bounded input manifests, cycles, finding identities, closures, usage counters, and local receipts. A source-reader callback supplies primary truth. The advisor has no primary writer.

`bsd.js` projects that state into existing shared model/Persona pickers, the detached Configure modal, the compact Context row, Context More Details, evidence/history disclosures, local usage/transcript inspection, scoped JSON export, and attributable public advice cards. Historical advice copied into a branch is explicitly source-conversation history, not current advice or a borrowed advisor assignment.

`bsd-demo-batch12.js` owns the primary local fixture, versioned SQL/measurement artifact, recorded sample inputs and asynchronous read-only inspector. Only explicit primary controls change its work. Dismissing the guide does not remove work controls or discard playback state. Delayed results retain their original target, generation and epoch.

The generated outputs are built from modules through `build.py`. Protected `motion.*`, `variants-a.*`, `variants-b.*`, `variants-c.*`, and `orbit.*` remain byte-identical to the repaired Batch 11 baseline.

## Important boundaries that are exercised

Configuration is detached until save; opening/editing/cancelling creates no assignment or provider use and does not change the primary model or Persona. CAS revision/epoch checks reject stale forms. The ten stage rows use Inherit, Off, Auto and On. Settings defaults and the frozen active binding are different concepts; explicit reconfiguration creates a new binding revision and re-primes the advisor.

An asynchronous concern or critical is held. A repeat at the same generation cannot release it; a genuinely newer current generation must reconfirm it. A late result cannot clear a newer held finding. A callback cannot forge its frozen-boundary flag, generation, epoch or input manifest. New primary identity/history and advisor identity fence earlier callbacks. Advisor self-compaction retains held findings and closures.

Off creates no assignment and no fabricated provider attempt. Auto's closed trigger set and On eligibility are evaluated within explicit policy refusals. Unknown provider cost and tokens remain unknown. Local evaluations are labelled separately from provider calls.

Finding normalization, exact object references, severity escalation/downgrade rejection, per-cycle emission budget, duplicate suppression, closure and reopening are tested against the actual protocol. The deterministic local identity digest is **not** a cryptographic integrity or security guarantee.

Read-only tool admission is a fixed allowlist. Forbidden or malformed output is quarantined whole, before its advice can be published. One re-prime is allowed, followed by assignment pause and one recorded host-warning count on a repeated unsafe turn. The warning count and health are inspectable local state, not a production notification dispatch. Failure, quota refusal and unavailable advisor fixtures do not change the primary result. A user-paused primary cannot be awakened by BSD.

Catch-up uses a bounded deadline and explicit abort. The engine tests its timing with an injected clock; the terminal browser case exercises a real zero-wait cap. This is not a durable server timer or an implementation of waiting across process restart.

## Deliberate concept limits

The examples are intentionally scoped. The input materializer exercises bounded public fixture deltas, constraints, typed reference fields, watch text and redaction receipts. It does not establish production secret detection, filesystem/process sandboxing, AuthBrowser isolation, full Goal/Plan/PlanUnit/To-Do integration or external research dispatch. Negative lexical/tool-carrier fixtures are not security certification.

The source adapter supplies trigger kinds and materiality. The protocol tests all ten declared Auto kinds and policy refusals; it does not implement every production workflow's automatic trigger detector. Sensitivity is configured and frozen; the sample's explicit 8% predicate does not claim a complete semantic sensitivity classifier.

The local advisor context-maintenance threshold uses a disclosed **20,000-character stand-in**, not provider token estimates or context-window limits. Provider token counts and caching performance are not inferred from it.

PRD Builder and Planning Wizard are **Start/Cancel and frozen-binding previews** in the local workbench. Selecting either and cancelling creates no binding, assignment or usage; explicit owning Start freezes the chosen stage. These are not their actual full onboarding/planning journeys, hidden WorkNode executions, or native integration proof. The separate Settings/onboarding source lanes are untouched.

`cmd.bsd.*`, central events, storage, wiring and native registration remain separate obligations. `nativeCommand()` explicitly returns `command_not_registered`; local receipts carry `native: false`, `primary_run_mutated: false` and `authority_granted: false`. An accepted local result carrier is not a successful review: the outcome still distinguishes failed, timed-out, quarantined, held, cleared and emitted.

No durable restart recovery is claimed. Closure survives local advisor reset/self-compaction, not a browser reload. No prototype state is silently persisted to a production setting key.

## Reproduce verification

From this directory, with Python Playwright, Pillow, Chromium, Node, and recording tools already installed:

```bash
python3 build.py --check
python3 tests/b12/run.py verify --outdir /tmp/pm-b12-verify
python3 tests/b12/run.py regressions --outdir /tmp/pm-b12-regressions
python3 tests/b12/run.py record-survives --outdir /tmp/pm-b12-record-survives
python3 tests/b12/run.py record-resolves --outdir /tmp/pm-b12-record-resolves
python3 tests/b12/run.py timing-survives --outdir /tmp/pm-b12-timing-survives
python3 tests/b12/run.py timing-resolves --outdir /tmp/pm-b12-timing-resolves
python3 tests/b12/run.py frames \
  --video /tmp/pm-b12-record-survives/survives/workflow.mp4 \
  --outdir /tmp/pm-b12-frames-survives
```

Use new output directories; the launcher will not overwrite earlier evidence. It installs nothing, keeps outputs outside the source directory and runs previous regressions serially. Browser scripts also accept a selected `--html` path for adversarial/currentness reproductions.

The execution environment blocked both `file://` and loopback HTTP before application loading. Browser evidence therefore uses the complete standalone through `set_content`. That restriction does not prove normal navigation works elsewhere; it is a stated unverified loading path.
