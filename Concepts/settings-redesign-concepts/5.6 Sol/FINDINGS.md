# 5.6 Sol — corrected Settings findings

No winner is selected or recommended. These findings describe a material correction across four still-distinct concepts.

## 1. The omission materially affected all four concepts

The missing full-thread Performance register and the mispathed provider adjudication were not harmless packet defects. They changed shared behavior used by Index House, Switchboard, Wayfinder, and Ledger, and therefore required implementation, fixture, candidate-artifact, coverage, and test changes across all four.

The causal changes are concrete:

- Eager shared manager data became a compact startup/search module plus a dynamically imported selected-detail module.
- Generic loading/progress moved to the sole `ObservableWork` projection; made-up determinate progress is rejected.
- Resource/pressure presentation moved to a `RuntimeResourceGovernor` projection with the six exact permit outcomes. Settings requests and displays policy; it does not compute a second policy.
- Manager caches gained byte bounds and inactive eviction; heavy subscriptions gained reference counts and release; large data gained 40-row virtual windows.
- Persistence became compact, debounced, byte-limited, and transient-aware; search, focus, scrollspy, loading, and hydration do not become durable payload churn.
- Rendering gained frame-coalesced, latest-wins scope patches and concept-only counters instead of treating every event as permission for a full-scene replacement.
- Provider setup gained the controlling explicit-first-acquisition rule, official-source review, exact Host/Environment, separate authentication, coalescing, continuation currentness, generation identity, and human/Advanced Details separation.
- Deterministic pressure profiles and motion lifecycle rules were added, including hidden/inactive clock shutdown and active-preview-only sound animation.
- Every concept's candidate command, wiring, DRY, Plan-owner, impact, and 47-row manager-coverage artifacts were corrected.
- The tests were replaced with causal state and render-contract checks and a Firefox-focused W3C harness that fails closed when the host cannot create a browser session.

The materiality claim is therefore based on changed code and changed causal tests, not on an assertion that the omitted sources had already been covered.

## 2. Shared contracts did not erase the bakeoff

The concepts retain different ways of understanding location and state:

- **Index House** remains an address/provenance archive.
- **Switchboard** remains a readiness and signal-routing surface.
- **Wayfinder** remains a prerequisite/checkpoint/recovery route.
- **Ledger** remains a dense requested/effective and receipt folio.

The common runtime projections are semantic inputs. Each concept still uses its own hierarchy, spatial behavior, materials, typography, focus treatment, and motion participant mapping. Nothing in the correction ranks those approaches.

## 3. Home and search must stay compact

Settings Home should orient before it manages. It should show cached destination summaries, freshness, attention, scope, and the next action without opening all Vaults, providers, tools, Servers, or resource managers.

The current design now has a measurable contract:

- compact Home/search data is available without evaluating the detail module;
- baseline search has exactly 148 compact rows;
- the deterministic scale fixture reaches exactly 825 rows;
- search results are capped and carry no manager payload;
- one selected manager loads its detail once; and
- stale generations cannot replace the currently selected detail.

This is Node concept evidence. A real Slint implementation still needs native model, startup, memory, and input-to-paint measurements.

## 4. Progress belongs to work, not animation

`ObservableWork` is the single projected source for phase, state, wait/queue reason, progress kind/source, trustworthy completed/total values, heartbeat, capabilities, blocking scope, result refs, and receipt refs. A UI card may render that projection but does not own the operation.

The correction matters visually: cached values can remain visible during refresh; the reason for waiting is explicit; indeterminate work does not invent a denominator; cancel/background/retry controls appear only when valid; and terminal/recovery states remain distinct.

The deterministic concept now causally checks manager-load and provider-refresh cancellation/retry fencing, including fresh generations and rejection of late completion. That remains concept-state evidence: it does not certify cancellation or fencing of a real production backing job, which still requires production runtime integration and evidence.

## 5. Resource policy has one owner

`RuntimeResourceGovernor` remains the sole admission/policy owner. Settings expresses requested policy and projects effective state. A Project Home Server or Execution Host may coordinate/enforce the same contract, but does not become a second global governor.

The concepts can demonstrate all six outcomes and deterministic legacy, memory, disk, route, network, metered, thermal/Low Power, and large-catalog profiles. Those fixtures show presentation and shedding order only. They do not prove real fairness, interactive reserve, CPU/RAM limits, process pools, battery behavior, or physical host performance.

## 6. Boundedness is part of Settings correctness

The corrected concept contract now includes:

- a byte-bounded selected-manager cache with inactive eviction;
- one bounded heavy-detail subscription with reference-counted release;
- 40-row list windows with stable selected-row inclusion;
- compact persisted state capped at 64 KiB;
- 250 ms debounce with a 1 s maximum wait;
- transient-event persistence suppression; and
- narrow render scopes with coalesced, latest-wins patches.

These constraints turn performance prose into inspectable concept behavior. They do not establish production budgets; final limits require native profiling.

## 7. Provider acquisition is now causally separate from authentication

The corrected policy is exact:

```text
not bundled or baseline-preseeded
not silently first-acquired by Project/model/provider/Goal/Plan/WorkNode/agent/Auto/On
explicit human setup action
official source reviewed
exact Host and Environment selected
installation and authentication separate
post-consent lifecycle management allowed
resume only while the continuation is current
```

Existing-install selection does not imply acquisition or authentication. Identical setup requests coalesce; different environments remain distinct. Normal cards use human identities. Paths, shims, roots, hashes, and procedure IDs live under Advanced Details. This closes the major policy/copy/data gap caused by the correction source.

The provider authority found under the original packet's `reference/` directory is byte-identical to the correction-root member, but the baseline artifacts supplied no durable receipt proving it had been opened. Presence was not treated as proof of review.

## 8. Completeness is a matrix, not an empty `missing` array

Each concept now classifies all 47 source families. Across the 188 cells, 57 are `demonstrated`, 111 are `shared_grammar`, 12 are `deferred_named_owner`, and 8 are `missing`.

The two missing cells in every concept preserve separate source traceability for the original Future Server Module Shell and the corrected Server insertion. Their exact canonical owner is unresolved, so both UI representations remain inspect-only and mutation-blocked. They do not represent two engines. No command, backend, networking behavior, host-selection algorithm, sync engine, or update engine is minted here.

Puppet Master app/content updates, Product Onboarding, and Doctor have named deferred insertion contracts. They remain navigation/return seams, not simulated owner state machines.

## 9. Motion is state-dependent and finite

Film-level motion means continuity and causality, not background activity. The corrected design preserves semantic state under reduced motion, cancels superseded sequences, stops hidden/inactive decorative clocks, and runs the sound meter only while preview audio is playing.

CSS and Node/render-contract checks can inspect gating and settled state in the HTML concept. They cannot establish native Slint timer behavior, GPU/renderer efficiency, OS reduced-motion integration, idle CPU/wakeups, or physical power use.

Old browser-pass counts are superseded and are not retained as current correction evidence.

## 11. Current residual risks

- The exact canonical Server owner is unresolved and fail-closed.
- The Firefox host cannot create a browser session, so layout, keyboard, interaction, accessibility, motion, and provider-policy assertions remain unexecuted in a real browser for this correction.
- Native Slint and physical-hardware validation remain external gates.
- Candidate command IDs, payloads, wiring, DRY roles, schemas, and Plan owners remain provisional and `NOT_MINTED` until canonical owner adjudication.
- Deterministic fixtures do not authenticate providers, install software, mutate files, send notifications, restore backups, run containers/tests, clean workspaces, or configure Servers.

The corrected result is therefore: material repair with passing state/structural evidence and named residuals, not certification, readiness, or a winner.
