# Reference Review and Repair Requirements

The missing Performance register is controlling input for logical-thread scaling, bounded execution lanes, progressive hydration, byte-bounded caches, startup behavior, low-memory degradation, loading/progress truth, ResourceGovernor ownership, and older-hardware/poor-network testing.

Review the implementation, not only the packet prose. Check whether each concept:
- lazily hydrates large managers and detail panels;
- avoids scanning every provider/tool/server/resource at startup;
- virtualizes large lists and unsubscribes inactive detail surfaces;
- uses truthful loading/wait/error states instead of simulated progress;
- remains functional under reduced CPU/RAM, slow disk, poor network, and large catalogs;
- keeps resource and provider state external to model prompts;
- does not invent a second resource governor or progress owner.

The final provider adjudication overrides any permissive baseline-bundling language in older references. Correct visible copy, fixtures, candidate commands, and impact registers if they imply silent acquisition or pre-seeded provider CLIs.
