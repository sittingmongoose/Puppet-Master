# Repository Baseline and Known Failure Patterns

At the supplied repository state, each bakeoff model folder has four concepts. Add seven new concepts without repairing the originals.

The current Settings inventory contains 828 records across 12 categories. Read it directly; do not rely on an older reduced search fixture.

Known failure patterns the new concepts must avoid:

- visually different Home skins leading into one shared manager application;
- manager links opening a manager from another concept;
- `shared_grammar` counted as demonstrated coverage;
- search results routed by grouped-array index rather than stable result ID;
- left shell/Activity Bar overlaying content at narrow widths;
- Settings Home dominated by calls to action instead of major destinations;
- provider manager combining every account/model/install/routing/usage/diagnostic control into one wall;
- multiple competing navigation systems: app rail, Settings rail, manager sequence, tabs, list, and breadcrumbs without a clear hierarchy;
- fake 825-row scale generated from a much smaller baseline rather than actual inventory;
- eager manager hydration and startup probe storms;
- global/project scope controls contrary to the current Project-only decision;
- literal novelty skins replacing Puppet Master theme behavior.

Treat these as regression cases even when the original concepts still contain them.
