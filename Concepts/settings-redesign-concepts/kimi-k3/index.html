Settings redesign bakeoff Concept model: kimi-k3

Eleven ways to rebuild Settings

Concepts 01–04 are the original bakeoff (one shared demo system). Concepts 05–11 are the 2026-08-18 seven-concept bakeoff: each is a complete, self-contained Settings system over the full 828-setting inventory — its own Home, universal search with exact deep links, every manager family, project-only settings, and a one-time Copy Settings From Another Project flow.

This gallery is a comparison surface, not a ranking. Open each concept in the ConceptHub to exercise width, theme, and reduced-motion controls, or open standalone and use the top-bar demo controls.

Concept 01

Concord

Editorial dossier IA. Settings as a calm reading document: a front-page Home, a single reading column with a margin inspector, and managers as annotated chapters.

  • Full-width destination rows with purpose and health lines
  • Margin inspector hosts requested/effective and value-source detail
  • Context & Instructions, Memory, Personas, Goal, Crew, Permissions & FileSafe, Back Seat Driver
Motion: slow ease-out crossfades; panels slide from the triggering edge.
Open Concord
Concept 02

Resonance

Studio console IA. Settings as a control room: a dashboard Home, console panels in the workspace, waveform sound tiles, and an event-to-destination routing matrix.

  • Notification destinations as cards with masked, receipted test sends
  • Sound library with SVG waveforms and pack import checks
  • Theme studio with hover preview and TOML editor fallback demo
Motion: staggered transform+opacity reveals; waveform pulse on preview.
Open Resonance
Concept 03

Foundry

Engineering bench IA. Settings as a dense workbench: resource tables with health columns, a right detail drawer, and managers with search, add actions, and a health summary strip.

  • Terminal profile editor with ANSI palette wells and live preview
  • LSP/formatter registries with requested/effective attachment
  • Shortcut recorder capturing real keydowns, conflict highlighting
Motion: precise micro-transitions; stable-height accordions, no clipped animation.
Open Foundry
Concept 04

Vault

Ledger and timeline IA. Settings as an evidence ledger: capacity meters, retention timeline bars, receipt lists with hash chips, and a stepped import/export wizard.

  • Settings lifecycle as a stepped flow: preview, validate, apply, receipt, rollback
  • Storage, artifacts, and cleanup with dry-run plans and receipts
  • Future Servers & Hosting insertion shell with named owners
Motion: timeline scrub on retention bars; stepped wizard slides.
Open Vault

Open Tabbed Organizer

One shared system underneath

  • Core dataset (shared/data/pm-core-data.js): 12 humanized categories, representative settings across all nine value states and six exposure levels, and 9 provider families covering all 17 required fixtures.
  • Shared engine (shared/lib): fuzzy search with typed results and deep links, hash router with Back/forward support, scrollspy with oscillation guard, pub/sub demo store with honest simulated receipts, ConceptHub bridge.
  • Quiet full shell: title-bar sprout inbox (the only in-app notification surface), Activity Bar, side panel, Assistant panel, bottom panel, status bar — visible in every Hub preview.
  • All eight themes (Friendly, Glass, Retro, Basic × dark/light) and a reduced-motion path that reaches identical final states.
  • Every simulated action reports itself as simulated. Nothing pretends a real sign-in, install, purchase, or provider call happened.

What to inspect in each concept

  • Home: cross-category search with typed results, needs-attention / continue-setup / recommended notices, calm state, recents.
  • Workspace: scrollspy, subcategory jumps, deep links (#/c/<category>/<sub>/<setting>), Back/forward restore, value-state rows, squeezed navigation.
  • Provider manager: connection groups, multi-account fields, installation cards, update lifecycle, catalog last-known-good, requested-versus-effective models.
  • Assigned managers per concept, each reachable from the Demo scenarios drawer in normal, empty, failed, and unavailable states.
  • Cross-cutting: all eight themes, reduced motion, keyboard sanity, no clipped labels at 900–2500 px.
