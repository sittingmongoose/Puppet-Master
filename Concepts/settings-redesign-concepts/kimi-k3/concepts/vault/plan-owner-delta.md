# Vault — plan-owner delta (kimi-k3)

## Owners with direct impact

- **FinalGUISpec** — the ledger-and-timeline composition is a fourth
  verified pattern: capacity meters, scrubbable SVG retention bars,
  hash-chipped receipts, stepped lifecycle wizard.
- **Storage** — five areas (internal recovery snapshots / Settings backup /
  Project backup / Full Server backup / workspace cleanup) are visually
  separated and independently described; retention anchors, minima, and
  legal holds are first-class.
- **Settings inventory + schema** — lifecycle flows skip managed rows and
  migrate legacy keys by name; receipts disclose sources.
- **Runtime Artifacts/Outputs** — PM-owned vs provider-native identity is
  required; redaction applies on export.
- **Worktrees/Git/GitHub** — exact tool installation health; forge features
  sit behind an explicit connection; unmerged work is never cleaned.
- **Containers/Registries** — human top-level cards with typed unavailable
  states and the shared tool lifecycle.
- **Release/updates owner** — the future Updates module is reserved with
  this owner named; provider updates use the shared grammar.
- **Binary Locator/installation lifecycle** — SCM and container tools use
  the same confidence vocabulary as provider CLIs.
- **UI Command Catalog** — lifecycle candidates
  (`cmd.settings.export/import.*/reset.*/copy_from_project.*`,
  `cmd.storage.backup.open`, `cmd.artifact.manager.open`) are new; canon
  has no lifecycle verbs today.

## Owners touched through shared grammar

## Required supersessions demonstrated

1. Raw format dropdown for settings transfer → stepped lifecycle flow.
2. Universal settings inheritance → Copy Settings From… is a one-time
   transactional copy; the destination's independence is stated in copy.
3. Old chip/bloom Settings contract → full destination workspace.
4. Invalid inventory values → nine-state vocabulary only.
5. Server-module speculation → insertion cards are deferred with named
   owners and contracts; WSL is optional, native Windows complete.
