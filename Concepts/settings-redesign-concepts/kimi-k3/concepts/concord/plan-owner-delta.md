# Concord — plan-owner delta (kimi-k3)

Impacts are stated against the packet owner list. Concord is a demo concept:
no canon is minted here; every candidate ID is provisional and censused in
`candidate-command-delta.json`.

## Owners with direct impact

- **FinalGUISpec** — Concord adds a third verified composition pattern
  (dossier: front page / reading document + margin inspector / manager
  chapters). The spec should admit the margin inspector as a candidate
  RequestedEffectiveInspector home.
- **Settings inventory + schema** — new optional `setting.error` slot;
  provider `installations[]`, `updatePolicy`, `updateState`; account
  `isolation/authSource/profileRoot`. Invalid historical inventory values
  (anything outside the nine-state vocabulary) are treated as superseded.
- **Models System** — capability evidence + freshness, Fast/Normal,
  effort, requested-vs-effective inspector are required row content.
- **Multi-Account** — isolation strategy labels are mandatory row content;
  switching affects future requests only.
- **CLI Bridged Providers** — CLI-owned OAuth must never render a PM OAuth
  form; the launcher copy is the only affordance.
- **Provider OpenCode** — external server routes show `managed-externally`
  update state and honest usage unavailability.
- **Prompt Pipeline** — the admission receipt and AGENTS.md precedence
  chain are diagnostic surfaces; exposing them never injects the registry
  into prompts.
- **Assistant Memory** — half-life changes retrieval activation only;
  Assistant-only hidden memory is flagged as never used by automated
  systems.
- **Personas** — behavior-not-authority row is required; conversation mode
  and access profile are separate axes.
- **Goal Runtime** — Settings owns defaults/ceilings; live run state stays
  with the Orchestrator; Usage reports capacity.
- **Orchestrator/Subagents** — Crew requested-vs-effective with queued
  waves is the capacity-honesty pattern.
- **Planning Wizard / PRD Builder** — quality-guarded routes; no silent
  downgrade of user-facing planning.
- **Permissions** — ordered rules, last-match-wins trace, per-tool
  overrides, doom-loop threshold/action, per-persona profiles, five scopes.
- **FileSafe** — the floor card shows health/boundary/scopes/repair and
  never encourages bypass.
- **UI Command Catalog** — see the delta register; `cmd.settings.bloom.open`
  superseded (compat alias only if a caller census requires it).
- **Release/updates owner** — provider update policy defaults and truthful
  update states are part of the manager grammar.
- **Binary Locator/installation lifecycle** — confidence labels gate
  management: unknown owner → manual-only, never guessed.

## Owners touched only through shared grammar

Media; Commands; MCP; Skills; Plugins; Tools; LSP; Formatters; File
Manager; Testing; Worktrees/Git/GitHub; Containers/Registries; Storage;
Runtime Artifacts/Outputs — Concord renders these as ordinary workspace
rows (or references them) and leaves the dedicated managers to the other
kimi-k3 concepts.

## Required supersessions demonstrated

1. Old Settings chip/bloom/no-sidebar contract → Settings is a full
   destination with its own shell-complete workspace.
2. Stale right-side-panel language → the margin inspector is inside the
   Settings surface and is not a second panel.
3. `regular/yolo` mode coupling → mode vs access-profile separation on the
   Personas manager.
4. Invalid inventory values → all rows use the nine-state vocabulary; text
   tokens are `auto` / `inherit` / `not-configured`, never blank.
