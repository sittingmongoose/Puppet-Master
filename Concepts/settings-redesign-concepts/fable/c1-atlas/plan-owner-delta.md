## 2. Supersessions demanded

1. **Chip/bloom Settings contract.** The old chip/bloom no-sidebar architecture is superseded by the persistent workspace (here: TOC + numbered document). `cmd.settings.bloom.open` is flagged retire, with a compatibility alias to `cmd.settings.open` only if telemetry shows callers.
2. **Stale right-panel language.** Any plan text describing Settings navigation in a right side panel is superseded: the Activity Bar is the narrow left rail controlling one adjacent left side-panel slot, and this concept coexists with it.
3. **Conversation-mode / access-profile coupling.** The retired pairing of the "regular" conversation mode with an unrestricted access profile must be struck wherever it survives. Access is exactly Ask for approval / Auto accept edits / Auto / Full Access; Plan and Review are effect-limited, not tool-free; Personas and modes cannot grant access.
4. **Invalid inventory values.** Rows whose blank string secretly meant auto/inherit/disabled are superseded by explicit value states; the inventory census (817–826 discrepancy) must be corrected before new rows are minted.

## 3. Boundary confirmations

- **Settings vs Usage vs Orchestrator vs Doctor.** Settings owns defaults and ceilings (Appendix G renders the boundary note verbatim); Usage reports capacity (sustainable-now is read-only here, with the wave warning); the Orchestrator admits actual work; Doctor owns deep diagnosis — boundary checks here return receipts, not repairs.
- **BSD is read-only.** Bounded deltas in, comments out; tool access fixed read-only; it cannot widen authority and primary work never blocks merely because it failed. Chat overrides last one turn or one thread.
- **FileSafe is the floor.** Non-bypassable under every profile, Persona, and rule; external directories are read-only entries added only through explicit review; the UI offers no bypass and says so.
- **Provider CLIs are acquired explicitly.** The cursor-cli offer is user-triggered, official-source, exact host/environment, never bundled or demand-triggered; install and sign-in stay separate acts; unknown/ambiguous ownership stays manual-only (local Ollama shows no update/repair action at all).
