fable · Settings Bakeoff

Eleven answers to one question: what organizes Settings?

Two waves of work live in this folder. The original four concepts (2026-08-08 cumulative packet) are preserved below exactly as built. The seven new concepts (2026-08-18 packet) follow — each one a complete, self-contained Settings system over the full 828-row inventory, project-only, with every required manager family demonstrated natively.

Each concept replaces the current chip-and-modal Settings with the same three-surface architecture — a search-centric Home, a one-category-at-a-time Workspace, and dedicated Managers — but each is organized around a different first principle, and each proves a different quarter of the manager grammar natively (agent policy in Atlas, ambience and input in Mission Control, developer tooling in Focus Stack, data lifecycle in Ledger). They share demo data, semantics, and themes; they deliberately do not share a skeleton. Every concept carries its own six-file impact register in a sibling folder of the same name.

C1

fable · Atlas

Settings as a well-edited reference manual

Atlas makes the humanized taxonomy the hero and uses editorial devices as structure, not skin: every domain is a numbered section with a running header, a short prologue, and status typeset as marginalia in a dedicated margin column. Editing happens inline in the document itself, and the managers become appendices of the same book — reached through the table of contents and inline cross-references such as "See Appendix A".

Search
A full-width bar above the directory; typing morphs the directory in place into grouped results under persistent part headers — no overlay.
Navigation
A persistent leader-dot table-of-contents tree; the loaded section expands and a sliding ink dot in the right gutter tracks the active subcategory.
Managers
Appendices in the same book — Providers & models, Memory, Context & Instructions, Personas, Goal & Automation, Crew, Permissions & FileSafe, and the Back Seat Driver. Connected servers and Language servers remain as numbered cross-reference stubs proven natively in Focus Stack.
Editing
Inline in the document rows; advanced and diagnostic entries sit behind per-subcategory disclosures.
Motion
"Typesetting" — content composes once in reading order with short staggered steps; reduced motion collapses to a single simultaneous state.

C2

fable · Mission Control

Settings as an operational console

Mission Control makes system state the hero: Home leads with a strictly ranked triage stack above a grid of destination stations that each show live health, and a persistent global health strip stays present on every surface. The manager relation is inverted — managers are the primary surfaces, and ordinary settings hang off stations as secondary configure drawers. It is built for the user who opens Settings because something needs doing.

Search
A docked command bar in the home header; results open as a keyboard-first palette layer with owner-category breadcrumbs.
Navigation
Station cards on Home; inside a category, a proportional minimap is the primary scroll-position instrument.
Managers
Primary surfaces — live consoles for Providers, Notifications & Sounds, the Sound Library with uploads and packs, Appearance with custom TOML themes, Spellcheck & Dictionaries, Desktop & tray, Teacher, and Media routes. Crew moved to Atlas and is cross-referenced honestly.
Editing
In configure drawers attached to stations; status changes morph glyph and label together, never color alone.
Motion
"Instrumental" — quick, precise, state-driven; refresh shimmers only the refreshing region while last-known-good data stays solid.
Open Mission Control
C3

fable · Focus Stack

Settings as layered focus

Focus Stack makes attention the hero: Home is nearly empty — one dominant search field, a short stack of large typographic destination plates, and notices folded into a single collapsed queue. Every navigation pushes a full-height sheet onto a visible layer spine (Home, then Category, then Manager) that can be popped, and disclosure is always navigation — advanced settings, row help, and warnings each push their own sheet rather than expanding in place. It is the lowest-density concept, with progressive disclosure taken furthest.

Search
The hero object of Home — one large field; results replace the destination plates within the same stack.
Navigation
A spatial sheet stack with a visible layer spine; an outline chip opens the in-category jump overlay; plates remember position and offer resume.
Managers
Sheet stacks on the same spine — Providers, Connected servers, Language servers, Formatters, Files & editor, Terminal profiles, Commands & shortcuts, Skills, Plugins, Tools, and the Testing & Debug matrix; list, detail, and diagnostics each get a layer.
Editing
On the focused sheet only; anything deeper (advanced, help, warnings) pushes a half-sheet instead of expanding inline.
Motion
"Spatial continuity" — origin-anchored push and pop carries wayfinding; the reduced-motion mode is designed first-class, with the spine and breadcrumb making depth legible without animation.
Open Focus Stack
C4

fable · Ledger

Settings as an object browser

Ledger makes metadata the hero and the inspector the interaction surface: every setting is a record with provenance, document rows are read-only, and selecting a row loads it into a persistent inspector where all editing happens — provenance chain, requested-versus-effective diff, and reset included. The navigator is a query engine, and Home is a sortable, filterable settings table rather than a directory. It is the highest-density concept, built for the expert who wants to interrogate configuration.

Search
A persistent query bar with state chips ("managed", "differs from default") mounted at the top of the navigator on every surface; it filters navigator and document simultaneously by dimming non-matches.
Navigation
A navigator column plus query filtering; the scrollspy marker steps discretely; Home mirrors the navigator as a compact index table.
Managers
Record collections in the same navigator-and-inspector grammar — Providers, Storage & Retention, Backup & Restore, the transactional Settings Lifecycle (import preview, conflicts, atomic apply, rollback), History & Sessions, Runtime Artifacts, Source Control & Worktrees, GitHub Actions, Containers & Registries, Web/Search/Fetch, the Project Search Index, Workspace Cleanup, and the reserved Server module shell.
Editing
Inspector-side only — rows are records, the inspector is the sole editing surface.
Motion
"Instantaneous" — zero choreography as a deliberate philosophy; state swaps are immediate, and the concept doubles as proof the design system works motionless.
Open Ledger

Seven new concepts · packet 2026-08-18

The second wave: seven complete Settings systems

Each concept below independently carries the full PM shell, a simple search-first Home, universal search with exact deep links, all 12 inventory categories and 828 rows, the one-time Copy Settings From Another Project transaction, and all 42 required manager families (plus nine named-owner insertion shells). They share only headless data, search, and state (_shared2/); every visible surface is concept-native.

Managers

How to compare

  • Width: use the hub's Page width control (760–2500, presets at 760 / 900 / 1280 / 1700 / 2200 / 2500) and combine it with the shell's rail and Assistant toggles — effective content width is what matters.
  • Themes: all eight themes (Friendly, Glass, Retro, Basic, each in dark and light) are available from the palette button in the titlebar; semantic status language is identical across themes.
  • States: each concept page mounts a States drawer (bottom-right) with eight scenario presets — baseline, calm, attention-heavy, usage-exhausted, invocation-failed, managed-workspace, first-run, offline — twelve composable fixture overlays (import conflict, rollback complete, theme fallback, storage pressure, and more), and the full trigger registry grouped by family.
  • Deterministic links: every state is also reachable by URL — #/manager/<id>, #/setting/<id>, #/search/<query> with ?scenario=, &fixture=, &trigger=, and &instant=1 parameters. The README lists a full cookbook.
  • Reduced motion: toggle it from the titlebar on any page; every concept reaches identical end states, and the calm scenario renders with no permanent animation.
