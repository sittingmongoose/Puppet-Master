Four ways to rebuild Settings

Four genuinely different information architectures over one shared settings system: the same demo data, the same eight themes, the same state rules — four different answers to search, navigation, managers, and motion.

This gallery is a comparison surface, not a ranking. Open each concept in the ConceptHub to exercise width, theme, and reduced-motion controls, or open standalone and use the top-bar demo controls.

Concept 01

Atlas

Directory IA. Settings as an annotated reference work: a structured directory of destinations, a three-region workspace (outline, document, context gutter), master–detail managers.

  • Search replaces the directory in place, grouped by destination
  • Outline tree scrollspy with a right-side context gutter
  • Provider manager plus Memory and MCP managers
Motion: settled utility — layout first, single continuity flip.
Open Atlas
Concept 02

Constellation

Command-center IA. The query is the home: a command field reshapes the page, destinations are command cards with verbs, and a right-edge minimap drives scrollspy in the workspace.

  • Type immediately — the whole home becomes results
  • Segmented destination bar + section minimap jumps
  • Provider manager plus Context & Instructions and Terminal managers
Motion: directed continuity — shared-element transforms, short cascades.
Open Constellation
Concept 03

Ledger

Document IA. Settings as a calm, typographically led document: an editorial home, a single reading column with a floating table of contents, and managers as dedicated chapters.

  • Front page leads with decisions, not decoration
  • Floating TOC tracks reading position; squeeze collapses it to a rail
  • Provider manager plus Personas and Skills/Plugins/Tools managers
Motion: print precision — near-zero, markers glide only when allowed.
Open Ledger
Concept 04

Workbench

Ops-console IA. Settings framed around system health: an ops board home, drawer navigation with sticky section headers, and control-room managers with a diagnostics drawer.

  • Omnibox search in the console bar; status band summarizes health
  • Sticky section headers show live position while scrolling
  • Provider manager plus Crew and Media managers
Motion: mechanical snap — fast drawers, status ticks, no drift.
Open Workbench

One shared system underneath

  • Shared demo dataset (shared/data/pm-settings-demo.js): 11 humanized categories, 129 settings across all nine value states and six exposure levels, 7 provider families covering every required connection state.
  • Shared engine (shared/lib): fuzzy search with deep links, scrollspy/jump helper with oscillation guard, pub/sub demo store with honest simulated receipts, ConceptHub bridge.
  • All eight themes (Friendly, Glass, Retro, Basic × dark/light) and a reduced-motion path that reaches identical final states.
  • Every simulated action reports itself as simulated. Nothing pretends a real sign-in, purchase, or provider call happened.

What to inspect in each concept

  • Home: normal, several needs-attention items, continue-setup and recommended items, cross-category search, calm state, rail/Assistant panel combinations.
  • Workspace: category start, scrollspy updates, subcategory jump stability, global-search deep link, setting focus treatment, default/inherited/managed/unavailable/risky rows, advanced disclosure, squeezed navigation.
  • Managers: provider not installed through requested-versus-effective route differences, plus two more dedicated managers per concept.
  • Cross-cutting: all eight themes, reduced motion, keyboard sanity, no clipped labels at 760–2500 px.
