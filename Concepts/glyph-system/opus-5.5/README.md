# Puppet Master glyph system (Opus 5.5, pm7-glyphs)

Jared, 2026-10-10 (RAIL-4): the 5.6 Pro chat's neon glyphs are the Puppet Master defaults, used everywhere, with new
glyphs in the same neon-sign language for what the chat never had. PLN-3: redesign the terminal tab colours and icons.

`PMGlyphCatalog.html` is the catalog for Jared's review: every glyph, drawn by the real renderer, in every look (Basic,
Friendly, Glass, Retro, NieR), light and dark, at real sizes, and with Reduced Motion. It is generated; never edit it.

## Layout

| Path | What it is |
|---|---|
| `../../chat-assistant-concepts/5.6 Pro/neon-icons.js`, `neon-icons.css` | The source set and the neon grammar (c56 owns them). Read in place, never copied or redrawn. |
| `src/registry/00-loader.js` | `window.PMG`: `PMG.def(name, record)` adds a new glyph through `PM56_NEON.register`; `PMG.map(name, record)` records which PM7 items a chat glyph now stands for. The file header is the format reference. |
| `src/registry/families/<family>.js` | One file per glyph family (terminal, panels, rail, ...). One designer owns a family file, so branches merge cleanly. |
| `src/bridge/pm7-looks.css` | PMConcept7's own look tokens, generated by `tools/extract_looks.py`. |
| `src/bridge/pm7-glyph-inks.css` | Glyph inks per look (`--pmg-ink-<tone>`), generated by `tools/tune_inks.py`: every tone >= 3.1:1 on every field. |
| `src/bridge/pm7-bridge.css` | Restates the chat's token names from the glyph inks, and the weight ladder by rendered size. |
| `src/data/*.json` | Catalog data: `families`, `status` (order, PM7 additions, the words each surface uses), `decisions` (cards for Jared), `ink-report` (generated). |
| `src/catalog/` | The catalog shell, chrome and renderer. |
| `docs/NEON-GRAMMAR.md` | The grammar notes for new glyphs (pm7-glyphs-designer2), confirmed by the lead. |

## Commands

```
python3 Concepts/glyph-system/opus-5.5/tools/extract_looks.py     # after PMConcept7's palette changes
python3 Concepts/glyph-system/opus-5.5/tools/tune_inks.py         # refit the glyph inks (exit 1 on a failed fit)
python3 Concepts/glyph-system/opus-5.5/tools/build_catalog.py     # write PMGlyphCatalog.html
python3 Concepts/glyph-system/opus-5.5/tools/build_catalog.py --check
python3 Concepts/ConceptHub/validate.py Concepts/glyph-system/opus-5.5
```

Designers preview with `build_catalog.py --out <scratch path>` and keep their own builds off the committed page; the lead
rebuilds `PMGlyphCatalog.html` after each merge.

## Ink tokens

`--pmg-ink-blocked`, `-attention`, `-working`, `-changed`, `-done`, `-paused`, `-idle` per look, plus
`--pmg-ink-concept` (PM7's secondary text). Glyphs never name these directly: a status glyph takes its tone class
(`nx-t-<tone>`, or `PMG.status(key)`), and the bridge feeds the tone the fitted ink.
