Architecture Draft

This document is actively being written by the Architect Reviewer subagent based on our conversation...

1. Framework Choice

The system is architected as a native desktop application using Rust. The frontend leverages the Slint UI framework instead of Iced or React to provide a fluid, premium desktop experience with declarative, easily maintained component definitions.

2. Multi-Agent Data Flow

graph TD;
A[Slint UI Components] -->|MPSC Channels| B(Rust Orchestrator Core);
B --> C{Redb Persistence Layer};
B --> D[Agent Task Queue];
D --> E((Cursor Provider));
D --> F((Claude Provider));
E --> C;
F --> C;

3. State Management

State is entirely event-sourced through the Orchestrator loop. All state transitions regarding execution tiers (Phase -> Task -> Subtask -> Iteration) are handled sequentially to avoid race conditions and guarantee determinism.

4. Persistence Strategy

Data persistence relies on redb (an embedded key-value store in Rust) and the standard file system. File system interactions are strictly guarded by the FileSafe verification gates to prevent accidental overwrites during autonomous execution.

Product Requirements Document

Status: Approved | Version: 1.0

1. Executive Summary

Puppet Master is a cross-platform desktop IDE designed to orchestrate AI agents for automated coding. It leverages Rust and Slint for a highly responsive user experience.

2. Functional Requirements

  • FR1: The system shall support 4 tier phases for execution: Phase, Task, Subtask, Iteration.
  • FR2: It must integrate natively with multiple providers: Cursor, Gemini, Codex, Claude Code, Copilot.
  • FR3: A visual node graph (DAG) representation of tasks must be provided.
  • FR4: Must include a multi-agent interview wizard for capturing requirements.

3. Non-Functional Requirements

  • NFR1: Native performance with application launch time under 500ms.
  • NFR2: The UI framework must be based on Slint for declarative performance.
  • NFR3: Agent memory scaling must not exceed token quotas (budget caps must be supported).

4. Multi-Pass Review Process

The system integrates an automated multi-pass document validation and canonical alignment to ensure the PRD conforms strictly to the schema before any code execution starts.

5. Out of Scope

Mobile application and cloud deployment orchestration are deferred to version 2.0.
