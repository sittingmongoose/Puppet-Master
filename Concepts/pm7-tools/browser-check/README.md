# PuppetMaster browser-check kit

Checks for the published page `Concepts/PMConcept7.html` (or a private build), run with browser-check (`browser-check guide`, or `Agent-Guides/browser-check.md` on the Cursor share). Follows the PM7 plan's browser rules:
- loads the page as `file://` with a cache-buster on every load, and `?o55=off` unless asked;
- re-applies and confirms explicit stored media requests after each navigation; Reduced Motion has no default;
- uses one GPU browser per run. A lane gets at most 2 browsers and 1 recording unless the lead gives it more, and `browser-check slots` shows what the machines have free.

The default page is the committed one, which moves only at milestones. To test your change, build it (`python3 Concepts/onboarding/opus-5.5/tools/build.py --out <scratch>.html`) and pass `--set page=`.

```sh
K=Concepts/pm7-tools/browser-check
OUT=$(mktemp -d)                                               # private to this run: /tmp is shared with other lanes
browser-check run $K/checks                                    # boot, looks, widths, reduced motion, sandbox and the lane checks
browser-check run $K/checks/looks.check.mjs --set lookShots=1  # list every look for viewing
browser-check run $K/checks --set page=$OUT/build.html         # a private build
browser-check run $K/providers --set page=$OUT/build.html      # provider logins, separately
browser-check run $K/checks --set sandbox=1                    # every check in T3's sandbox (below)
```

**T3's sandbox, one switch.** `--set sandbox=1` runs every check, the provider checks too, with the page as T3's file preview shows it: inside `t.openInSandbox` at its default flags, `allow-scripts allow-forms allow-popups allow-downloads` (an opaque origin, no storage, no modals). `--set sandbox=0` runs every check on a normal page. Without the switch each check keeps its own surface: a normal page, the provider logins in the sandbox, and a check that covers both surfaces (`native-dialogs`, `plate-text`, `hover-light`, `pip-voice-room`, `qa2-chatpip`) runs both; with it, only the one it picks. `sandbox` always runs in the sandbox. A check opens the page with `t.app.open()`, which returns the frame the app is in (`t.root`, what `t.until` and `t.css` read, is the same frame), so a new check runs on both surfaces with no wrapper of its own: don't write a sandboxed iframe by hand. The provider checks' old `--set surface=normal|sandbox` still works and says to use the new name.

Parallel runs are safe: each gets its own browser and run folder. Give each its own copy of the build (a rebuild during a run mixes builds) and its own `--out`. The page loads as `file://`, so `--host` can't open it: to use another machine, ssh there with a checkout of the branch (`~/.local/bin/browser-check`). Motion claims need the VM, Windows or Nas1, because the Mac records about 36 fps and refuses pixel checks while recording.

## Helpers for lane checks

```js
const LOADER = '<your surface selector>';    // the element your lane owns
export default async function (t) {
	await t.app.open();                      // fresh load: cache-buster, o55=off, default look, default viewport, waits for ready
	await t.app.look('nier-dark');           // one of the ten looks, not persisted; waits out NieR's switch-on, cover and input hold
	await t.app.resetLayout();               // block Home's localStorage writes and clear them
	await t.visible(LOADER, 'loader on top');
	await t.still(LOADER, 'NieR loader still');                         // compositor frames, not a rAF probe
	await t.app.look('friendly-dark');
	await t.moving(LOADER, 'loader breathes', { ms: 2400 });
	await t.crop('loader', LOADER, 'loader at 16 px: eyes read through the band');
}
```

`t.app.look()` returns once the requested look is painted **and** the page's own `PM_LOOK_COVERED()` is false. The NieR reboot paints the new look under a pointer-transparent plate and holds trusted presses until the plate's reveal, so a painted look can come before the page takes input back: a click in between is swallowed while a hit-test already lands on its control (KIT-LOOKCOVER). The wait is bounded at 20 s and adds no sleep; a cover that never clears fails the test with `look <name> cover clears`, naming the plate or the transition that still holds the pointer, instead of letting a later click vanish.

`t.app.open()` resets the saved look and the viewport only at the boundary between checks: a test's **first** open starts from the default saved look and the config viewport, 1920×1080. The next document clears its own storage before any page script — which also removes the look the outgoing page saved on pagehide — so a look or a viewport left by the check before it does not change this one. **Later opens in the same test keep both** the storage and the viewport, so a reopen or reload stand-in still sees what the check saved (the product saves on pagehide). A size the test asks for — `t.viewport(...)`, `page.setViewportSize(...)`, or `t.newContext({ viewport })` — is kept. The previous check's media emulation (`t.emulate`) is cleared at the boundary too, so a leaked Reduced Motion does not remove the next check's transition hold. `t.app.look` still does not persist; `t.app.resetLayout()` clears the saved layout (and drops that page's hidden writes) for a check that wants a clean layout without opening again.

`helpers/press.mjs` exports `press(frame, locator)` for an already-present control whose bounds keep moving. It scrolls to the control, hit-tests its center and each enclosing iframe, and sends a real mouse click at that point. Check the returned `ok` and the action's effect. A rejected press reports the hit or the reason.

## Motion

The kit has no Reduced Motion default. Request it with `await t.emulate({ reducedMotion: 'reduce' })` before opening the app; browser-check preserves that request on navigation. `reduced-motion` checks both the media query and `O55.motion.reduced()` inside the returned app frame. A plain `t.app.open()` does not enable Reduced Motion.

`t.moving` and `t.still` compare real compositor frames. They are a quick gate, not the verification standard. The plan requires 60 fps recordings watched frame by frame, so for a motion claim:

```sh
browser-check run $K/checks/my-motion.check.mjs --record ~/pm-scratch/<lane>/loader.mp4
```

Record one check file, not the folder: `widths` changes the viewport, which a recording refuses, and so does opening a new window. Call `t.mark('drag start')` in the check. The summary prints the seconds of each mark into the recording, and `browser-check frames loader.mp4 --run <run folder>` writes native frames at the marks. Every-frame review is in `Agent-Guides/gpu-recording.md`. Keep working recordings on local disk, not the share, and copy to `PuppetMaster-Evidence/` only what the lane must keep.
