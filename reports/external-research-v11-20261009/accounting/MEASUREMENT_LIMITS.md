# ER11 measurement limits — root calculator v2

Use `python3 accounting/calculate-v2.py` from the reconstructed campaign runtime. The helper v1 figures are obsolete; [original component limits](ORIGINAL_COMPONENT_LIMITS.md) preserve its path and interval-union mistakes.

- Artifact mtime is last saved complete final/map, not first complete bytes. Delivery uses actual host terminal timestamp, not root poll time.
- Additive occupied intervals include retained-author wait; parallel actors each charged. Missing host runs leave arm total null. Shared paired evaluation charged once in experiment, never twice.
- Native cumulative Goal counters kept per session, never summed with overlapping token/usage fields. Billing/subscription and campaign token totals are unavailable. Per-context input/cache/output/reasoning snapshots are retained where exposed; their accumulation semantics are unqualified and they are not summed.
- Host queue uses supported run requestedAt to startedAt; acceptedAt in dispatch is tool-return observation and can follow native start, reported separately. Candidate clocks start at frozen arm setup before accepted dispatch; queue and root handoff delays included. Source acquisition within arms charged. Campaign/bootstrap/case design is experiment overhead, not free or an invented per-arm cold setup allocation.
- Stage deadlines measured at host terminal; last-science timestamps can independently be earlier. Native exact completion timestamp unknown. Strict method/native qualification remains separate.
- All 80 original cells retained, including unstarted and failures; savings shown only for both-source-PASS delivery pairs with failure-inclusive rows alongside. No confidence/reliability/affordability claim from descriptive ratios.

Host queue is `requestedAt` to `startedAt`; dispatch `acceptedAt` is the observed tool return and may follow native start. It is reported separately. Missing endpoints remain null. Source quality, delivery, actual native lifecycle observations, settings/provenance, timing and comparative-method eligibility are distinct. Actual positive active/complete Goal observations are retained alongside unknown exact native completion timestamps.

All 80 original cells remain in v2 output. Shared paired assessment is counted once in experiment occupancy. Failed helpers, both qualification attempts and the stopped monitors are charged through exact observed distinct host runs; the root native cumulative counter is never called a campaign total. Missing active-run records, root occupation and cold shared preparation allocation keep the campaign subtotal explicitly partial. Unknown subscription usage and billing prevent an affordability claim.

Provider host context snapshots do expose input, cached-input subset, output, and reasoning-output subset for some Muse/zcode contexts. They are retained per context with observed scope; their accumulation/billing semantics are unqualified, so they are not summed into campaign usage or treated as billable session totals. Missing per-context fields stay null. Earlier blanket wording that these categories were unavailable was too broad; it applies to campaign totals and billing, not the existing snapshots.
