# Final — S11 accessibility-video research (control arm, method M11 v1, stage research)

One self-contained consolidated final for the brief: a modest public video resource site for a disability advocacy organization, where forty prerecorded recordings need captions, keyboard-friendly playback, transcripts, translation drafts, and controlled author corrections. Basis: independent discovery over public primary sources captured with bounded evidence (immutable IDs S01–S11 captured; S12 BBC Subtitle Guidelines and S13 Amara access-failed and are cited nowhere as evidence; register in `source-map.json`, excerpts in `sources/`), a frozen six-clause thin plan revealed after discovery was saved, and a plan comparison draft reviewed by a fresh critic pass (`critic-revision.md`). The brief's standing constraints hold throughout: accessibility improvement must not depend on one automated score, and evidence comes from actual tool/spec/release behavior.

## What the discovery established (O1–O3)

**Format and requirements.** Captions are a WCAG Level A obligation (SC 1.2.2: "Captions are provided for all prerecorded audio content in synchronized media…"), satisfied by the `<track>`+WebVTT route (technique H95) or always-visible open captions (G93); captions must include non-speech information — "sound effects, music, laughter, speaker identification and location" — and the named failures (F8, F74, F75) are concrete audit targets. Audio description is the Level AA obligation (SC 1.2.5), with proportionate techniques for this inventory being G203 (a static text alternative describing a talking-head video), G78 (a second user-selectable described audio track), and G226 (description mixed into the soundtrack); extended description (G8) is the expensive end. WebVTT itself (W3C CR Draft, 20 May 2026) carries the governing mechanics: millisecond timestamp precision (exactly three ASCII digits), six cue settings (vertical, line, position, size, align, region) each usable at most once per cue, UTF-8 files starting with `WEBVTT` served as `text/vtt`, unique cue identifiers free of `-->` and line breaks, and an ordering invariant — cue start times must be non-decreasing and each end time must exceed its start — that any merge or translation pipeline can silently violate. Styling runs through `::cue`; `::cue-region` is unsupported in every browser, so region layout must never be load-bearing; a `<track>` with `kind` requires `srclang`, and only one track may be `default`.

**Players.** Video.js (current stable v10.0.1, changelog dated 2026-10-02) targets WAI-ARIA 1.2 and WCAG 2.2, ships keyboard operability per the WAI-ARIA Authoring Practices patterns (Enter/Space on buttons, arrows/Home/End/PageUp/PageDown on sliders, Escape on popovers), manages ARIA automatically (slider roles with live values, state-driven `aria-label`, focus-trapping dialogs that return focus), and announces confirmed state through a batched live region so routine time updates stay silent. It deliberately ships no caption-appearance menu: rendering is delegated to the browser, styled via `::cue`, per the CVAA-aligned design where viewers use their OS/browser caption preferences — a custom style panel would be an org-built enhancement. Integrators who customize layouts inherit real duties: re-add the status announcer, give custom triggers accessible names ("Tooltips are visual only"), test contrast over changing video (WCAG 1.4.3/1.4.11), keep touch targets ≥24×24 CSS px, and handle autoplay/reduced-motion (2.2.2) at page level. The ecosystem has consolidated: Plyr — itself accessible (space/K, arrows, 0–9 seek, M/F/C/L shortcuts, full VTT support, i18n) — is deprecated with security updates only, its team having joined the Video.js 10 effort alongside Vidstack and Media Chrome.

**Issue/fix/release evidence.** video.js issue #2746 ("Accessibility of the Captions Settings dialog", opened 2015-10-27) reported unassociated labels, broken focus management, no Esc close, and confusing options in exactly the dialog this site will use; it was fixed ~16 months later (closed 2017-02-21 by commit 0d0dea4, "feat: fix accessibility of the captions setting dialog (#4050", following PR #4025, milestone "WCAG 2.0 Compliance"). Lessons: caption-dialog a11y is historically where players break, so acceptance testing must traverse that dialog specifically, and ~16-month a11y-fix latency is realistic planning data for volunteer-maintained tools. Release feeds show active maintenance (video.js swapped access-sniff for pa11y in v8.24.2; Subtitle Edit ships automated daily betas, latest v5.3.0-beta26 from commit 1653608). Evidence-absent items, stated plainly: no captured source quantifies ASR/MT accuracy or sets review thresholds (WAI's AV guidance is silent on it); BBC-class editorial timing defaults (reading speeds, line lengths, duration floors) were not captured after repeated access failures, so any timing policy must be set as explicit internal policy or grounded in a new source; Amara's team/review model for controlled corrections remains unverified.

**Validation basis.** WAI's evaluation overview: "no tool alone can determine if a site meets accessibility standards" — the primary-source footing for layered validation (automated scans in a supporting role, WAI Easy Checks for non-technical volunteers, keyboard-only and screen-reader passes with VoiceOver/NVDA/JAWS, involvement of people with disabilities, WCAG-EM sampling for any conformance claim).

## Plan comparison — exact per-P dispositions (O4)

The frozen plan read verbatim: "P1: Host MP4 files and WebVTT captions. P2: Use the browser default player. P3: Generate translations automatically. P4: Edit captions in a text editor. P5: Publish one transcript per video. P6: Run an automated accessibility scanner."

- **P1 — already-covered.** The substrate is exactly what H95 assumes. Conditions adopted as a publish gate: all P1-paragraph invariants above (ordering, unique IDs, `-->`-free payloads, ms precision, single default track, kind⇒srclang). Uncertain: MP4 hosting specifics (codec ladder, CDN) are not covered by captured sources.
- **P2 — rejected as stated; correction: adopt Video.js v10.** Rejected on the positive case for a maintained player with documented keyboard/ARIA behavior and the ecosystem consolidation behind it — not on a measured native-controls failure, which the captured set does not contain (native controls remain a fallback, and their cross-browser variance is unverified). Caption-style panel: optional enhancement / user decision; platform caption preferences are the documented default.
- **P3 — correction: automatic generation for drafts only.** The brief asks for translation drafts and automation fits that; publication requires a human review gate because no evidence supports machine output as publishable and F8/F75 name exactly the omission modes it produces. Amara-class review platforms stay unverified (S13) and are not cited. User decision: language set and reviewer staffing.
- **P4 — correction: dedicated caption editor behind the validity gate.** Subtitle Edit (cross-platform, daily betas, actively maintained) is the discovered workbench; a plain text editor cannot see the ordering/`-->`/ID invariants and silently breaks files. Text-editor spot fixes are acceptable only followed by the gate. Its exact format/translation feature set is unverified. User decision: whether corrections flow through a versioned store for audit.
- **P5 — correction: keep the baseline, upgrade the artifact.** One transcript per video is right; make it a descriptive transcript ("Ideally, make it a descriptive transcript that also includes text description of the visual information"), which also serves talking-head description via G203; G78/G226 where genuine description is warranted. Description depth per video is a budgeting user decision.
- **P6 — correction: scanners are one layer.** A scanner-as-gate is rejected by WAI's statement and the brief's own constraint. Layered protocol as above, plus caption-specific checks (F8/F74/F75) and a mandatory keyboard/screen-reader traversal of the captions settings dialog (the #2746 defect class). Absent BBC evidence, timing policy is internal or newly sourced.

Retained constraints from the brief: modest scope; advocacy-org context; forty recordings; captions, keyboard playback, transcripts, translation drafts, controlled author corrections; timing and rights constraints — rights/licensing specifics are unaddressed by the captured sources and remain an organizational legal task, flagged uncertain rather than guessed.

## Executed checks vs proposed discriminating validations (O6)

Executed in this stage, all locally verifiable: HTTP source access with bounded capture (11 captured, 2 access-failed and recorded with error modes and timestamps), immutable-ID source register, artifact ordering (goal dispatch 20:28:43Z; source-map 20:36:35Z; discovery 20:39:04Z; reveal 20:39:11Z; draft 20:43:58Z), and the critic pass. No site, player, or VTT file exists yet, so nothing below has run — each proposal is stated so it can fail:

1. **Validity-gate rejection test** — inject a deliberately broken VTT (non-monotonic start, duplicate ID) into the publish pipeline and require hard rejection; passing proves the P1 conditions are enforced rather than documented.
2. **Keyboard+screen-reader task pass** — a screen-reader user completes play/pause, caption toggle, and full captions-settings-dialog traversal keyboard-only; any failure names the integration duty missed.
3. **Draft-vs-review error measurement** — per video, a 20-cue sample comparing machine translation draft to post-review text; two consecutive batches under the org's correction threshold justify reducing review depth — turning P3's uncertainty into data.
4. **Upgrade regression watch** — pin the video.js minor version; before each upgrade, diff release notes for a11y/caption fixes (the #2746→#4050 chain is the template); a captions-dialog fix triggers a repeat of check 2.
5. **Timing-policy pilot** — if an internal caption timing policy is adopted (the BBC gap), spot-check ten published videos with Easy Checks; policy-practice drift is the failure signal.

Open questions carried forward, unchanged: the #2746 release boundary; authoritative editorial timing defaults; a primary-source-grounded controlled-correction pattern; Subtitle Edit's exact capabilities; SRT↔WebVTT conversion hazards (general knowledge, unverified here). Usage/billing: unobserved, null. Native Goal terminal completion occurs only after these artifacts are saved; unobservable lifecycle fields remain UNKNOWN per the lifecycle record.
