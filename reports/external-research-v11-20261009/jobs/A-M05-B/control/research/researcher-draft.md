# Draft — accessibility-video plan review

**Case:** S11 · **Stage:** research · **Research basis:** frozen [`discovery.md`](discovery.md), [`source-map.json`](source-map.json), and exact revealed [plan](revealed-plan.md).  
**Status:** complete planning deliverable; no project runtime or media assets were supplied, so implementation and accessibility validation are proposed, not executed.

## Recommendation

For this forty-recording site, establish an organization-controlled source and publication workflow first: keep each authorized video and its caption/transcript/translation files addressable by stable asset ID; publish WebVTT as the web timed-text format; maintain one approved source-language caption and transcript package per recording, plus distinct language-tagged translation files and reviews as funded; keep machine translations and corrections as unpublished drafts until an authorized fluent human approves them. Retain prior published versions and record provenance. Choose a player and editor after a small representative pilot.

Able Player is a strong specialist candidate for the public web interface because it supplies keyboard and screen-reader controls, adjustable caption display, interactive transcripts, and the Video Transcript Sorter; pin a tagged release rather than using `develop`, serve local WebVTT tracks to retain transcript/search/customization features, and test the actual artifact. For source editing and time alignment, pilot Subtitle Edit 5.2.0 on an organization-managed workstation with a deliberately local speech engine if any automated transcription is allowed. Keep Amara as an optional web-collaboration path if distributed, multilingual editing outweighs the external-service/data-governance cost. YouTube Studio is an option if the organization already hosts there, but does not become the sole caption/transcript master without a decision about platform dependence and export. These are candidates from public documentation, not installed or tested tools. [S05–S12]

Keep native `<video>`/`<track>` as a lower-dependency alternative if the site has capacity to build the transcript/navigation layer and test its native controls in target browsers. In either architecture, store the actual approved timed text independently from the player so video delivery and editorial corrections are not bound to one vendor. [S03–S05]

| **P1: “Host MP4 files and WebVTT captions.”** | **Correct; retain conditionally; hosting is a user decision.** | Keep WebVTT as the web caption/description/chapter delivery format. Serve the source-language `kind="captions"` track and separate `kind="subtitles"` translation tracks with correct `srclang` and user-facing `label`. Do not assume one MP4 encoding plays in every target browser: decide the allowed media codecs/containers from the selected hosting/browser support matrix and supply supported source(s) or a fallback. Decide whether media is site/CDN-hosted or externally hosted, whether local copies remain authoritative, and whether each item is cleared for public display and caption/transcript/translation adaptations. If an external embed is chosen, keep an approved local VTT master. [S03–S05, S12, S15] |
| **P2: “Use the browser default player.”** | **Reject as a final product requirement; native controls remain an alternative to pilot.** | “Browser default” is underspecified and does not provide the transcript/correction workflow by itself. The HTML media element/track model is a sound low-dependency baseline, but transcript presentation, focus/order, caption/language selection, responsive behavior, fallback, and assistive-technology differences still need product decisions and validation. Pilot native controls plus a structured transcript against a tagged Able Player build. Able Player is a candidate, not an automatic compliance guarantee. Do not use its untagged development branch based on the observed regression chain. [S03, S05–S08] |
| **P3: “Generate translations automatically.”** | **Reject as a publish-quality rule; retain machine translation only as an optional draft aid.** | Automatic translation may accelerate a first draft only if the organization approves the engine, rights and processing path, language pair, and disclosure. It cannot be the final publication/review gate: a fluent human must check meaning, names, advocacy terminology, speaker labels, sound cues, timing/line segmentation, and locale conventions. Maintain a separate state per language (`draft`, `review`, `approved`, `published`, `withdrawn`) and keep unreviewed drafts out of public track selectors. If no qualified reviewer exists for a language, identify it as a pending user decision rather than claiming a translation is accessible. Local/remote engines differ in whether recording text leaves the machine; editor choice alone does not settle that. [S09–S11, S15] |
| **P4: “Edit captions in a text editor.”** | **Correct; plain text remains an expert/emergency option.** | Text editing is useful for spelling/wording, review diffs, and some SRT/VTT cleanup, but it is weak for aligning forty recordings and can introduce timestamp/format errors. Use a media-aware editor with playback and waveform/spectrogram and point/visual sync for timing, such as Subtitle Edit; use listening and human review to establish the actual caption content. Export valid WebVTT and retain a plain-text/VCS or other controlled history of approved versions if that fits the organization. Test conversion round trips where an exchange format is needed; don't assume every TTML/SRT styling or cue feature maps exactly. [S04, S09, S10] |
| **P5: “Publish one transcript per video.”** | **Correct; retain one source-language transcript as a minimum, not the complete multilingual/accessible package.** | Give every video a readable, searchable transcript with speaker turns and meaningful non-speech audio, linked close to the player. Preserve language metadata. Publish a distinct reviewed transcript for each translation language if one is offered; mark drafts unpublished. An interactive transcript with seek points is an optional enhancement and should be tested for extra tab stops and cue/chapter reading order. Decide clip-by-clip whether a transcript/time-based alternative is enough for the selected requirement or whether important visual-only information calls for an audio-description track/version. A transcript of audio does not describe silent visual information. [S01–S05] |
| **P6: “Run an automated accessibility scanner.”** | **Reject as the only validation or release gate; retain scanning as one optional markup check.** | A scanner can find some page/markup issues, but cannot establish accurate captions, appropriate translations, usable timing/readability, correct descriptions, or working assistive-technology interaction. Combine syntax/asset checks with full-content human review, keyboard and screen-reader testing, target browser testing, user feedback, and per-item rights/status review. There is no single automated accessibility score that certifies this package. [S01, S02, S04, S14] |

## Proposed content and operations model

Use a manifest with one stable ID per recording and one record per language/track. For each, identify media URL/version or content hash; original language; each track kind and locale; file path/URL; status; revision; author and approver; source editor/engine (if any); source hash; review/approval dates; relevant rights/consent; and any known uncertainty. Track title, duration/timebase, owner/license, speakers and terminology, visual-only content decision, source-language caption and transcript status, translation language/reviewer status, and published URLs. Keep the files portable and exportable.

Use separate workflow gates:

1. **Rights and intake:** verify ownership/license/permission for public video and audio, music/performances/third-party material, caption/transcript/translation creation and publication, and any tool processing; record limits and expiration. Check participant release/consent/privacy constraints. Do this before uploading recordings to a vendor or publishing a text derivative. The U.S. statute is only an example; the applicable jurisdiction and exceptions are not known. [S15]
2. **Caption source draft:** an approved human may transcribe directly or use a permitted ASR draft; do not label raw ASR “captions complete.” Include intelligible dialogue, speaker identity when needed, and meaningful sound/music. Match language/locale to speech. [S02, S09, S14]
3. **Editorial and timing review:** a trained/fluent editor compares the complete audio/video, fixes errors, and aligns cues with playback. Use Subtitle Edit's visual tools as assistance; no waveform is ground truth. A second person checks language and high-impact details (names, numbers, disability terminology, quotations, sound cues). Maintain an organization style sheet and use character-per-second/line-length numbers only as warning flags adopted after language/user review. [S09, S14]
4. **Translation draft and approval:** create a separate language track from the approved source, preserving meaning and necessary sound/speaker information. Require a fluent reviewer with an escalation path for disputed terms; track human approval and date. For external services such as Amara or online ASR/translation endpoints, decide access, retention, terms, rights, export, and deletion before use. [S09–S11, S15]
5. **Publish and correction:** publish only approved files. Provide a correction-request path, verify a report against the recording and authorized text, edit a draft, review it, publish a new revision, and retain the prior revision/decision. Do not expose drafts or silently overwrite corrected public tracks. If open direct edits are desired, that is a separate account/access-control and contributor-rights decision.

For web delivery use a named track such as `<track kind="captions" src="...en.vtt" srclang="en" label="English captions">`; use `subtitles` for translation text. Select at most one default caption/subtitle language and make that choice explicit. Validate VTT before publication and render it in the actual player. Cue starts are ordered but distinct cues may overlap, so flag questionable overlaps for human inspection rather than prohibiting them syntactically. A natural-language transcript may be HTML for headings and reading order, with timed links if they aid navigation; keep it synchronized with caption revisions. [S03–S05]

## User decisions and unresolved uncertainty

The organization must choose: required languages and locales; minimum accessibility target/jurisdictions; media hosting/retention and whether to self-host a copy; player, browser and assistive-technology support matrix; caption ownership and approval roles; whether ASR/MT may be used and which engines/endpoints may receive media; collaborator identity and direct-edit rights; correction turnaround and public attribution; transcript presentation/download policy; the video-by-video audio-description decision; and exact rights holder, permissions, participant releases and limits. The number forty does not itself establish workload: pilot representative durations/languages and time review effort before promising a deadline or budget.

Uncertainties not resolved by public documentation: actual browser/native control behavior in the target user matrix; whether Able Player's merged `develop` fix has shipped in a newer release after the inspected release page; runtime behavior with this site's own media, CSP, formats and layout; the selected Subtitle Edit build's feature parity and remote-data behavior/configuration; Amara service-tier rights/retention and team workflow; all source-video and contributor clearances; and what spoken/visual information each recording carries. These should remain visible decisions, not be filled with assumptions.

## Discriminating validation proposals (not executed)

1. **Player pilot:** for one representative clip with a caption track, a translation, transcript, chapter, and a no-caption or no-source edge case, compare a tagged Able Player release with native controls in the audience's selected browsers, mobile viewport/zoom, keyboard, and screen-reader matrix. Test actual production-built assets. Record task failures, focus sequence, accessible names, caption selectors, transcript/seek operation, fullscreen/resizing, and recovery. Choose a path only after the target users can complete those tasks.
2. **Regression fence:** pin the candidate player release; test YouTube/Vimeo only if used, local media, media without source children, captions without transcript, all documented constructor forms if applicable, and no-caption fallbacks. Build from the exact dependency lock, run release tests, and open every required demo/page. Issue #775 shows why testing a stale committed bundle separately from a freshly built branch matters. This is a proposed test based on a reported regression; this researcher did not reproduce it. [S06–S08]
3. **Caption content:** sample one short, one long, multiple-speaker, music/noisy, and visual-information-heavy recording. A human listens/watches the complete sample and checks exact words, speaker attribution, meaningful sound, timing, readability, caption placement, names/terminology, and transcript correspondence; get feedback from intended users and use the findings to set the editorial style. Expand content review to every recording before its first public release.
4. **VTT and packaging:** run a parser against every track; assert encoding/header, parse success, increasing cue starts, positive cue duration, within-media end, correct locale/label/kind, accessible asset URL/MIME/CORS and one intentional default track. Test allowed overlaps with manual review. Render in each selected browser/player; if converting SRT/TTML, compare representative before/after cues and content rather than trusting a successful export.
5. **Translation quality:** for each locale, compare approved source and target language with a fluent reviewer, including names, advocacy terms, punctuation, speaker/sound context, timing and line segmentation. Block publication until reviewer identity and approval version are recorded.
6. **Visual access and alternatives:** review each complete video for important visual-only information, on-screen text and action. Decide and record whether source audio already conveys it, a time-based media alternative is planned, or audio description is required at the selected conformance target. Test chosen description delivery and transcript order. [S01]
7. **Correction and rights rehearsal:** exercise a correction request through triage, draft, review, new-version publication, rollback, deletion/withdrawal and search/index/embed updates. Separately check that each source asset and language derivative can be created, stored, sent to a chosen tool, and published under the documented permissions.
