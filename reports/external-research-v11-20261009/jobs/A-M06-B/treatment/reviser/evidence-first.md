## 2. Primary-source derivations per brief need

### F1/F6 — packaging, fixity, and what a checksum proves
- RFC 8493 (BagIt V1.0, published **October 2018** per the direct rfc-editor fetch — the
  research dossier's "November 2018" is a lineage error): bag = directory layout +
  `bagit.txt` (BagIt-Version 1.0) + per-algorithm manifests; valid bag = every manifest
  checksum verifies. Bag 1.0 tools **MUST support SHA-256 and SHA-512**, SHA-512
  recommended default for new bags; MD5/SHA-1 optional for backwards compatibility.
  [../critic/sources/dossier-rfc8493.md#c01; ../research/sources/dossier-bagit.md#s04]
- `Payload-Oxum` (OctetCount.StreamCount) is a fast completeness pre-check only; full
  checksum validation is still REQUIRED before calling a bag valid.
  [../critic/sources/dossier-rfc8493.md#c01]
- bagit-python README (direct fetch): `--md5/--sha1/--sha256/--sha512` flags; README
  states "SHA256 and SHA512 are generated by default"; `--validate --fast` checks
  structure + payload-oxum WITHOUT recomputing digests (so fast validation is not fixity);
  `BagValidationError.details` yields `ChecksumMismatch` / `FileMissing` / `UnexpectedFile`.
  Exact latest release tag UNKNOWN (Releases section empty on fetched page; default-branch
  evidence). [../research/sources/dossier-bagit.md#s05]
- Asymmetric evidence note: a search-level PyPI summary claiming MD5-by-default has no
  fetched page behind it (direct PyPI fetch FAILED); a failed-fetch snippet must not be
  retained co-equal with a direct primary fetch. The open question that remains is which
  release tag the README text describes. [../research/sources/dossier-bagit.md#s06]
- Checksum ≠ provenance, structurally: BagIt manifests bind bytes to digests written at
  packaging time by whoever wrote them; "not designed to be secure against active
  attacks"; tamper protection needs "additional measures, such as digital signatures";
  bag-info.txt is "intended primarily for human use" (unauthenticated). No identity or
  custody primitive exists in the format; provenance must ride as separate evidence
  (donor identity, transfer agreement, custody log) bound to the transfer.
  [../critic/sources/dossier-rfc8493.md#c01; ../research/sources/dossier-bagit.md#s04]
- Audit-rubric framing: NDSA Levels of Digital Preservation (created 2013; V2.0 2019;
  V2.1 March 2026) treats fixity and provenance/information content as separate staged
  functional areas; matrix text itself lives on OSF and was not fetched (only version
  dates are evidence-backed). [../critic/sources/dossier-ndsa-levels.md#c02]

### F2 — malware/quarantine separation
- ClamAV is signature-based; definitions update via freshclam (digitally signed updater,
  DNS version queries); submitted signature changes take **at least 48 hours** to
  propagate; detection therefore has an open-world gap — "not detected" is not "clean"
  until definitions catch up, which is exactly what a time-boxed quarantine with rescan
  addresses. Supported platforms: Ubuntu 22.04/24.04, Debian 12/13, AlmaLinux 9/10,
  Alpine 3.22, Fedora 41/42, openSUSE 15, FreeBSD 13/14, macOS 13–15, Windows 10/11.
  Resource floor: minimum **3 GiB+ RAM** (3–4 GiB advised for Docker-like constrained
  environments), 1 CPU ≥ 2.0 GHz, 5 GiB disk. No version-EOL policy or guaranteed update
  cadence is stated on the page (absence recorded).
  [../critic/sources/dossier-clamav.md#c04; ../research/sources/dossier-clamav.md#s14]
- Quarantine mechanics: `--move`/`--copy`/`--remove` options; clamscan reloads
  definitions per run (slow, always current) vs clamdscan daemon (fast, cached
  definitions) — a conscious operational choice. ClamAV outage = transfer blocker where
  scanning is mandatory. [../research/sources/dossier-clamav.md#s14;
  ../research/sources/dossier-archivematica.md#s02]
- Pipeline precedent: Archivematica's ClamAV-powered "Scan for viruses" microservice runs
  at multiple transfer+ingest points; infected material fails rather than ingests (as
  documented for **1.8.1**-era docs — see version-condition note in §4).
  [../research/sources/dossier-archivematica.md#s01]
- Issue chain (O3 anchor): #691 "Scan for viruses not being triggered after remove from
  quarantine", reported ~2019-05-15, closed 2019-10-30, label "Status: won't fix" — the
  quarantine exit edge proceeds to format identification without a rescan. Evidence limit:
  issue-list metadata only; body and linked commits unfetched; behavior on any current
  release unverified, so the honest reading is "reported skip, upstream declined, current
  status unknown" and the compensating rescan-on-release stands as defense-in-depth
  regardless. #869 "antivirus scanning can't be disabled" (closed 2021-06-18) makes
  scanning a mandatory step — an availability coupling on ClamAV.
  [../research/sources/dossier-archivematica.md#s15, #s16]

### F3 — understandable rejection reports
- Natural rejection taxonomy straight from tool behavior: `ChecksumMismatch` /
  `FileMissing` / `UnexpectedFile` (bagit-python validation details); Payload-Oxum
  failure as a fast "transfer incomplete, re-send" class before slow digest recompute;
  identification-failure (claimed extension vs identified format) as another class.
  [../research/sources/dossier-bagit.md#s05; ../critic/sources/dossier-rfc8493.md#c01;
  ../research/sources/dossier-pronom-droid.md#s12]
- Precedent surface: Archivematica routes virus-found transfers to a `failed` directory
  with email fail reports (legacy ~1.1-era wiki; version-conditioned).
  [../research/sources/dossier-archivematica.md#s03]

### F4 — metadata repair
- Identification is the evidence input for repair: DROID (TNA, open source, PRONOM-based;
  container signatures in DROID 6+) compares claimed extension vs identified format.
  Version conditions: identification outcomes depend on the PRONOM signature-file version;
  utility v2 (October 2020) added container-signature sequence support; exact current
  signature-file version UNKNOWN. [../research/sources/dossier-pronom-droid.md#s12, #s13]
- Evidence-backed alternative identifier: Siegfried v1.11.9 (2026-09-27, Apache-2.0,
  Go ≥1.25) — PRONOM signatures plus freedesktop MIME-info/LOC FDD/Wikidata; full-file
  scans by default; `sf -droid` DROID-compatible output; `sf -serve` server mode; packaged
  for Homebrew, Debian/Ubuntu APT, FreeBSD, Arch, Windows, WASM.
  [../critic/sources/dossier-siegfried-verapdf.md#c05]
- Evidence gap: the TNA DROID page 404'd at access (C07) — no stage in this arm holds a
  fetched DROID version; and neither predecessor stage's retained evidence names a tool
  that *performs* repairs (e.g., ExifTool/FITS-family) — repair-tooling evidence is absent
  and must be stated as absent or newly fetched. [../critic/sources/dossier-failed-fetches.md#c07]
- PDF/A-specific validation candidate veraPDF has no pinned release (parser repo fetch;
  dual GPL-3.0+/MPL-2.0; Java 8–25 + Maven build) — provisional only.
  [../critic/sources/dossier-siegfried-verapdf.md#c06]

### F5 — repeatable transfer history
- Canonical OSS born-digital step order usable as the event model even for file-based
  intake: create disk image → virus check → identify file types → fixity → sensitive
  content review → extract. [../research/sources/dossier-bitcurator.md#s11]
- Repeatability conditions: record algorithm, tool, and tool version per event; record
  PRONOM signature-file version per identification or identification is not reproducible;
  record ClamAV definition currency per scan (48 h propagation latency means scan results
  are only interpretable against the definition set used).
  [../research/sources/dossier-pronom-droid.md#s13; ../critic/sources/dossier-clamav.md#c04]
- Rubric candidate for auditing the history/rejection design: NDSA Levels V2.1.
  [../critic/sources/dossier-ndsa-levels.md#c02]

DART 3 (APTrust, GUI+CLI BagIt packaging driven by machine-checkable BagIt profiles,
uploads to generic S3/BagIt endpoints — donor-side conformance without APTrust membership;
exact release number UNKNOWN) (F1/F6 donor side) [../research/sources/dossier-aptrust-dart.md#s07–#s09];
ClamAV (F2); DROID/PRONOM or Siegfried (F4 evidence, F3 rejection class); BitCurator +
Consortium workflows (disk imaging, PII discovery — materially different intake for donors
arriving with physical media) (F2/F4/F5 media path) [../research/sources/dossier-bitcurator.md#s10];
Archivematica (full OAIS pipeline alternative). Materially different architecture axes:
donor-side profile conformance (DART) vs staff-side pipeline validation (Archivematica)
vs composable minimal harness (bagit-python + Siegfried/DROID + ClamAV + append-only event
log on one host); file-package intake vs media imaging intake (BitCurator).

## 6. Independent low-cost deployment derivation (from cited evidence only)

Minimal viable path consistent with the above: one Linux LTS host (Ubuntu 22.04/24.04 per
the ClamAV support list) with **≥4 GiB RAM** budgeted (ClamAV's own 3 GiB+ floor alone),
running: BagIt validation per RFC 8493 rules (SHA-256/512; full validation, fast mode only
as a pre-check); a ClamAV quarantine lane with time-boxed release + rescan-on-release
(compensating control independent of #691's current status); Siegfried (`sf -serve`) or
DROID for PRONOM identification with signature-file version recorded; append-only
per-transfer event log following the canonical step order, emitting plain-language
accept/reject reports from the validation taxonomy; donor side via DART + BagIt profile
(or archive-side re-bagging of arbitrary ZIPs so a manifest exists from receipt).
Archivematica (v1.18.0 line) is the heavier alternative when normalization/AIP outputs are
needed; both share the BagIt interchange layer. Original constraints retained: small
donors, low cost, regional-archive staff, repeatable history, checksum proves fixity only.
