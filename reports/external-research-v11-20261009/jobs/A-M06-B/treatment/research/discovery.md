Derived product context from the brief: a regional historical archive receiving digital
packages from small donors needs (1) package validation, (2) malware/quarantine

transfer history, under the explicit constraint that a checksum does not prove
provenance, at low cost, with interoperable tools.

## O1 — Discovered tools, products, materially different approaches

1. **Archivematica** (Artefactual, OSS) — full OAIS transfer→ingest pipeline with a
   ClamAV "Scan for viruses" microservice at multiple pipeline points (S01); infected
   transfers routed to a `failed` directory (S03); processing behavior — including the
   optional quarantine stage and its duration — governed by `processingMCP.xml`
   (evidence-first; shipped default value still UNCONFIRMED). Competing approach:
   accept raw transfers and let the pipeline validate.
2. **BagIt (RFC 8493) + bagit-python** (LoC, OSS) — the interchange wrapper (S04, S05).
   Competing approach: validate where the package is built, not inside a monolithic
   pipeline.
3. **DART 3 (APTrust, OSS)** — GUI/CLI BagIt packaging for non-technical donors, driven
   by BagIt profiles, uploads to any generic S3/BagIt endpoint (S07–S09). Competing
   approach: push conformance to the donor side with a machine-checkable profile.
   Directly fits "small donors"; works without APTrust membership.
4. **BitCurator** (OSS) + published small-institution workflows (CPRER 2018, Educopia,
   BitCurator Consortium) — disk imaging, PII discovery, filesystem analytics for donors
   who arrive with physical media instead of packages (S10, S11). Competing approach:
   acquire at the media layer when the donor cannot package at all.
5. **DROID/PRONOM + signature files** (TNA) — format identification for validation and
   metadata repair, versioned signature files, container signatures in DROID 6+ (S12,
   S13). Unfamiliar-to-most-archives detail: identification is only reproducible if the
   signature-file version is recorded in the transfer history.
6. **ClamAV** — the detection engine underneath (S14); scan mode (clamdscan vs clamscan)
   and definition freshness are operational conditions, not afterthoughts (S02).

Materially different architecture axes derived from these: donor-side profile
conformance (DART) vs staff-side pipeline validation (Archivematica); file-package
intake vs media imaging intake (BitCurator); monolithic pipeline vs composable
bagit-python/DROID/ClamAV harness a small archive can run on one VM.

## O2 — Primary source/code behavior: governing defaults, units/types, limits, applicability

- **RFC 8493 mandates and recommends** (S04, direct quote retained): BagIt 1.0 tools
  MUST support SHA-256 and SHA-512; SHOULD enable SHA-512 by default for bag creation.
  Units: per-file hex digests in `manifest-<alg>.txt`; `payload-oxum` = octets.bytes
  (byte count + file count) used by fast validation.
- **bagit-python observed behavior** (S05, direct README fetch at 21:17 UTC): flags
  `--md5/--sha1/--sha256/--sha512`; README states "SHA256 and SHA512 are generated by
  default"; `--validate --fast` checks structure + payload-oxum WITHOUT recomputing
  digests — so fast validation does not verify fixity; `BagValidationError.details`
  yields `ChecksumMismatch` / `FileMissing` / `UnexpectedFile`.
  **Exception/conflict recorded**: a search-level PyPI summary (S06, 21:13 UTC) claimed
  MD5-by-default; the direct PyPI fetch FAILED at 21:16 UTC; the later, primary README
  contradicts the summary. Recorded as unresolved version-drift; neither cited as sole
  truth (see source-map.json `conflict_with`). Applicability: any default-algorithm
  claim must be pinned to an installed version before production reliance.
- **Archivematica governing defaults** (S01–S03, S16): virus scanning cannot be
  disabled (#869 closed 2021 — mandatory step; a ClamAV outage blocks all transfers);
  scan runs at multiple transfer+ingest points; failures land in
  `/sharedDirectoryStructure/failed`; quarantine stage + duration live in
  `processingMCP.xml` (search-level indication: default effectively 0 days/off; value
  UNCONFIRMED — repo file not fetched).
- **ClamAV limits** (S14): signature-based; `--move/--copy` quarantine options; open
  window until definitions catch up — quarantine exists to rescan after freshclam
  updates. clamdscan fast but daemon-cached definitions; clamscan slow but always
  current.
- **Checksum ≠ provenance, structurally** (S04): manifests bind bytes to a manifest,
  written at packaging time, by whoever wrote it; BagIt has no identity or custody
  primitive; `bag-info.txt` is unauthenticated free text. Provenance must be carried as
  separate evidence (signed transfer agreement, donor identity, custody log) and bound
  to the transfer, not inferred from a passing digest.
- **PRONOM versioning** (S13): identification depends on signature-file version;
  utility v2 (Oct 2020) added container-signature support; PRONOM web beta in progress.

## O3 — Issue/fix/regression/release chains

**Primary chain — Archivematica #691 (pinned):** "Problem: Scan for viruses not being
triggered after remove from quarantine", reported ~2019-05-15, closed 2019-10-30,
label **"Status: won't fix"** (S15, issue-list fetch). The quarantine path's exit edge
skips the virus scan entirely, jumping to "identify file format". Upstream knew and
declined to fix. Consequence for the brief: quarantine release is exactly where
malware/quarantine separation is decided, and the stock pipeline does NOT guarantee a
rescan there — a deployment must add a compensating control (rescan-on-release) or
accept a documented gap. This single chain justifies a staff-facing transfer-history
event for "quarantine released + rescanned".

**Secondary chains:** #869 "antivirus scanning can't be disabled" (closed 2021-06-18) —
scanning is a mandatory step, an availability coupling (S16). PRONOM Signature Dev
Utility v1→v2 (Oct 2020) and the PRONOM web beta — registry evolution that changes
identification results over time (S13). bagit-python default-algorithm drift (S05 vs
S06 conflict) — implementation/spec alignment changed across versions and summaries.

**Evidence absent/inapplicable, stated honestly:** issue #691's body and any linked
commits were not fetched (list metadata only); no ClamAV CVE chain was pulled this
session (absent, not claimed); Archivematica's shipped `processingMCP.xml` default
quarantine value and bagit-python's exact release tag remain unpinned (listed in
source-map.json `unresolved`); DART release number UNKNOWN.

## O6 — Proposed discriminating validations (NONE executed — no runtime available)

Proposals (each would discriminate between two readings; none have run):
1. On a disposable Python env, `pip install bagit` at the pinned release, create a bag
   with defaults and inspect `manifest-*.txt`: discriminates S05 (SHA-256/512 default)
   against S06 (MD5 default) reading.
2. Fetch Archivematica's shipped `processingMCP.xml` from the repo at the pinned
   release: discriminates "quarantine off by default" from "quarantine on with N days".
3. In a throwaway Archivematica VM, run a transfer into quarantine, release it, observe
   the microservice sequence: reproduces (or refutes) the #691 skip on the current
   release — tests whether the won't-fix behavior still exists.
4. Feed a bag with a mutated payload byte to `--validate --fast` vs full validation:
   fast should pass where full fails — demonstrates fast-validation is not fixity
   verification, informing rejection-report design.
5. Identify the same file set under two PRONOM signature-file versions: demonstrates
   reproducibility requires recording the version in transfer history.
