# Discovery — community oral-history collection

**Stage:** research, before case-plan reveal.  
**Scope from the brief:** a searchable public collection of 2,000 hour-long recordings, volunteer transcripts, multilingual speakers, consent restrictions, staff correction of words and speakers, preserved source audio, time-linked excerpts, and withdrawal of an interview or restricted segment.  
**Evidence:** source identities and locators are in [source-map.json](source-map.json); bounded source notes are indexed in [sources/README.md](sources/README.md). No predecessor artifacts were declared. No plan-only case file was read.

## Pre-plan findings

### Product and system shapes

1. **Community-governed, self-hosted archive:** Mukurtu CMS is an unfamiliar but relevant community-archive option. Its protocol model lets a community define access groups and distinguish open material from material visible only to logged-in protocol members [S01]. When an item carries several protocols, the default sharing rule is All; Any is more inclusive. Item and media settings can diverge, which can keep descriptive metadata discoverable while restricting audio. Mukurtu warns that item and media settings do not automatically stay consistent unless the media-sync behavior is enabled [S02, S03]. This is a meaningful fit for community-specific restrictions, but the research did not establish time-range rules within one file, transcript-segment enforcement, automated withdrawal, or performance at this collection size.

   **Readiness condition:** the selected v4 code README says v4 is in active development/testing, not a production-ready release. It requires MySQL or MariaDB, PHP 8.4 support, and correct private-file configuration outside the web root for access control; PostgreSQL is not supported and Apache is not extensively tested [S04]. The community model is worth piloting only after confirming the supported release, operator capacity, hosting fit, security/update policy and whether segment restrictions can be enforced. The user manual is itself marked in development.

2. **Hosted multi-archive portal:** Oral-History.Digital offers a different approach: a hosted interview portal and editorial environment with transcript editing, timecodes, translation support, multilingual search, access grants and an “accessible upon request” status [S05–S07]. Its help describes SRT, ODS, ODT, VTT and CSV transcript inputs, sentence-level timecodes for pinpoint search/indexing/captions, inline corrections, and external ASR4Memory transcription [S06]. The research found two material limits: full-text search requires a registered user with archive access [S07], and transcripts are uploaded one media file at a time while mass upload is still described as in preparation [S06]. Its controls are described at interview/media-file scope; no public evidence reviewed here confirms fine-grained restrictions for a small time range within one hour-long recording.

   **Readiness condition:** this is potentially lower-operations if the community can use the hosted platform, but eligibility, cost, rights/data terms, storage location, export/exit path, anonymous public access, segment restriction and withdrawal behavior all need confirmation. Version labels need reconciliation: the project software page shows 1.4.1, while the linked public repository’s current release page shows v2.11.0 at commit dc81cfa5ffab8819d2f168b5f7fcfe9ab876ede3, dated October 8, 2026 [S05, S08]. These may refer to different components; do not assume the hosted portal runs that repository release.

3. **Separate catalog, preservation storage and synchronized viewer:** OHMS is a modular option when audio already lives in a repository or controlled media host. The University of Kentucky describes OHMS as linking word-level search to moments in interviews and offers an account request [S15]. The OHMS Viewer is separately installed on a PHP server, reads exported OHMS XML from a configured tmpDir, and depends on the archive’s audio/video host and player integration [S16]. This can add transcript/index discoverability without replacing master-audio storage. It does not by itself provide a preservation repository or establish rights control over the source media.

   A lower-cost labor path is possible when full transcription is infeasible: publish a reviewed interview catalog and a volunteer-created thematic index, then add transcripts selectively. OHA guidance expressly treats indexing as an alternative access tool, not merely a failed transcription [S09]. Indexing avoids claiming completeness that a rough ASR transcript does not provide, but still requires consistent terms, reviewer time, and approved access.

These are materially different choices: community-operated protocol governance; hosted editorial and search service; or a composition of a CMS/catalog, separately preserved media, and viewer. A pilot should compare total staff/hosting/maintenance workload and policy fit, not only license price. No prices or billing data were observed.

### Transcription, correction and multilingual coverage

Human transcripts and automatic speech recognition both need review. OHA recommends reviewing drafts for accuracy, proper names and dates, documenting a shared style guide, and noting meaningful differences between the recording and transcript. It allows ASR as a rough draft, not a reliable final transcript; if a transcript is not feasible, a topical index can still aid search [S09].

Whisper is an optional local draft generator, not a universal multilingual policy. Its model card reports uneven quality by language, accent and dialect, hallucinated text and repeated output; it says speaker classification/diarization is not robustly evaluated [S10]. In code, condition_on_previous_text is a boolean defaulting to true: prior-window output is used as context, and disabling it trades window-to-window consistency for fewer repetition loops or timestamp drift. word_timestamps is boolean, false by default and marked experimental; it uses cross-attention and dynamic time warping. clip_timestamps uses seconds, and the optional hallucination-silence threshold also uses seconds and requires word timestamps [S11]. Keep the original language transcript distinct from a translation, and keep model output separate from the human-approved text.

A concrete evolution chain reinforces that distinction. A user report on v20230306 compared the same audio with word timestamps off and on, then observed earlier subtitles repeated in a silent tail [S12]. Maintainers merged PR #1052, and v20230307 described a fix for that repetition/hallucination report; v20230306 also recorded a fix for an infinite loop from incorrect timestamp tokens (#914), with a later alignment fix (#1087) [S13, S14]. The PR discussion also contains a report that repetition persisted in a separate reproduction. This proves a reported defect, response and release history, not that all such defects are resolved.

**Applicability rule:** do not claim the 2,000 hours are suitable for any single recognizer. Make ASR optional per language and recording class. First obtain permission for any processing and choose whether processing can remain local. Build a consented reference sample spanning languages, dialects, overlapping speech, code-switching, speaker counts, audio quality and long/silent endings. Compare transcript error by language, speaker-attribution accuracy, timestamp offsets, failure/repetition rate, volunteer correction time, and privacy constraints. Keep model, release, language setting, prompt, decoding flags and output provenance so later corrections are traceable. If a language/class fails the agreed bar, use human transcription/indexing or leave the material untranscribed rather than silently treating weak output as equivalent.

### Consent, restrictions and withdrawal

The archive’s permission model must precede bulk upload. OHA advises documenting releases, access/use limits and background material; honoring narrator intent and the release over the interview lifecycle; and distinguishing access from ownership. It does not create a universal right to delete a preservation master or decide what a withdrawal clause means [S09]. A specific decision is needed about what withdrawal means for this project: remove public access, restrict to a community, remove only a segment, or destroy specified copies when required by agreement.

Store the consent record and restriction with a stable interview/segment identity and effective dates. Keep a distinction between the preservation master, access derivative, transcript/translation, time-linked index, search index, cached copy and exported file. A restriction on one moment is not satisfied by hiding the interview’s landing page if an unredacted audio URL, transcript snippet or search result remains public. If segment-level access is required, test a design that gates a time-bounded derivative and its text/index together; split or redact the access copy where the player or platform cannot enforce a secure range. Avoid placing an indefinite public media URL inside an otherwise restricted catalog record.

For withdrawal, make a reversible public takedown the initial operational state while an authorized curator confirms the applicable agreement. Propagate the decision to player URLs, derivatives, transcripts, translations, indexes, search results, shares, embeds and caches. Keep the preservation master restricted when that matches the documented agreement; if the agreement requires destruction, record and verify deletion from the defined replicas/backups and document the preservation event. This is a proposed policy pattern, not a claim that any product implements it. Community stewards need authority and an audit record; privacy restrictions and safety may also require limiting public names, transcript downloads and usage analytics.

### Preservation and provenance

Keep source audio as an authoritative, unmodified master. Create streaming/caption/transcription copies as derivatives with explicit version and time-base lineage; never let volunteer edits overwrite the master. On ingest, compute fixity, retain source file format/identity/rights/context, and keep geographically or administratively separate copies. BagIt 1.0 is a practical package for transfer and file manifests: a valid bag checks listed payload and tag files, tools must support SHA-256/SHA-512, and new bags should default to SHA-512. BagIt does not itself provide redundancy, ACLs or preservation operations [S18]. PREMIS gives a compatible model for algorithm/digest, fixity-check events and outcomes, plus rights granted and time-bounded restrictions [S19]. A community-readable policy and documented restore process matter as much as adopting the names of standards.

For each correction or access change, retain who changed what, when, why, affected interview/segment and the version of transcript/audio derivative. Record accepted corrections separately from unresolved speech, uncertain spelling, translation disagreement and redaction. Do not present speaker attribution as certainty when volunteers or diarization disagree.

## Proposed discriminating validations — not executed

1. **Rights and access matrix:** create one harmless test record with public metadata/private audio, an all-members rule, an any-members rule, an open record with a restricted media asset, and a single restricted segment. Check anonymous visitor, each protocol role, direct audio URL, player, download, transcript view, index search, metadata API/export, cache and a second browser/session. Revoking access should take effect on previously issued links within the agreed maximum delay.
2. **Withdrawal propagation:** withdraw one entire recording and restrict a second one only between two known timecodes. Assert public playback/search/transcript/index no longer returns those bytes or words, while authorized users see the approved replacement. Check CDN/browser/server caches, embeds, feeds, backups, export jobs and old links; document whether the master is retained or destroyed under each consent condition.
3. **Audio and transcript editing:** on a consented 60-minute test recording, correct a word, a speaker label, an uncertain passage and a translation; confirm the original audio hash remains identical, the transcript revision is attributed, timestamps still point to the intended passage, and a full export/import round-trip preserves language, speaker, rights and timing.
4. **ASR pilot:** run each candidate model only on approved representative clips, including code-switching, low-resource languages, dialects, overlap and silence. Compare reviewed reference text, word error rate by language, speaker labels, timestamp tolerance, hallucinated text and volunteer editing minutes. Test current versions and settings; do not infer fitness from a prior fix alone.
5. **Capacity and costs:** use representative file sizes and the actual host/browser/network; measure upload/resume, one-hour playback/range seeking, transcript/index query latency, concurrent volunteer editing, backup/restore and storage/egress. Obtain current hosting/service quotes and data terms. No price or cost total was observed here.
6. **Preservation:** generate and validate a BagIt test package with payload and tag manifests; compare SHA-512 at ingest and after copy/restore; deliberately corrupt one copy to confirm alert and recovery. Record fixity events/outcomes and a test restriction/rights record in the selected PREMIS profile.
7. **Editorial usability:** ask volunteers with different language and technical backgrounds to perform correction, speaker disambiguation, timecode adjustment, translation review and a rights hold. Measure completion time and error rate, and confirm that a user cannot accidentally publish a draft.
