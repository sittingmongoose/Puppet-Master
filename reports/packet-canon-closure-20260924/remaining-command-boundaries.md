## Specification versus implementation

Already explicit native obligations—authenticated owner producers, real provider
effects, protected secret consumption, current permission checks, native replay,
Rust/Slint handlers and GUI/security/recovery proof—remain implementation work.
Static schemas and Python consistency tests neither supply nor certify them.

In contrast, missing selected values, conflicting outcome composition, undefined
filters/mappings and absent exact storage key/value/retention/migration authority
are specification gaps. They cannot be declared implementation-only merely because
a generic envelope, handler name, opaque reference or passing fixture exists.
The registry's 34 pending custody rows are logical dispositions, not 34 engines;
each still needs its actual owner adjudication where its specification is missing.

Unanswered decisions remain in finite-remaining-queue.md and
current-owner-decision-boundaries.md: dictionary custody, Settings import/facets,
shortcut import, formatter custody, DRY writer relationship, conflicting capability
evidence and additional Usage Ledger query meanings. The Server/Environment
supervisor mapping and original Ego manifest/skill custody remain separate.

Back Seat Driver, Context Lens, Help/Teacher and assistant-chat Plan/Full Thread/
platforms remain protected newer designs. Project NamedPlan is not thread
