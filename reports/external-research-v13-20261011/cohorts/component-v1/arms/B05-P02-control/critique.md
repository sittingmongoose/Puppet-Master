# Critique of the investigator draft

The draft has a useful foundation: explicit decoding, `csv.reader`, streaming, preview/confirmation, row-level diagnostics, source/profile consistency, staging, cancellation, privacy, and a validation fixture matrix all fit the brief and plan. Its earlier direct-write approach is correctly retired for violating failure atomicity. This review retains those mechanisms while correcting claims that could silently change inventory values or discard data.

## Material issues and dispositions

1. **Header auto-detection is not proof.** The draft's instruction to use `has_header` to prove and automatically skip the first row is unsafe. CPython 3.13.9 documents a sampled heuristic with both false positives and false negatives (CPY-DOC, CSV-HEADER). Disposition: reject the guarantee; use the result only as a suggestion and ask the user whether row one is a header. This protects a first-row SKU from silent loss.
2. **`QUOTE_NONNUMERIC` is not schema-aware inference.** It converts every unquoted field to `float`; it will not preserve unquoted numeric-looking identifiers as text. This contradicts the exact-text and SKU requirements. Disposition: reject this reader mode for the default import; read strings and apply user-confirmed schema conversions later.
3. **Default CSV cannot recover null versus empty.** The writer's `None` to empty-string mapping is documented as non-reversible. A regular reader returns strings. Disposition: reject the claimed automatic round-trip. Ask for a null convention. In CPython 3.13.9, `QUOTE_NOTNULL` provides an explicit unquoted-empty/null convention, but only when the source actually follows it; preserve marker/sidecar alternatives with escaping rules.
4. **The one-MiB “row byte cap” is wrong.** `field_size_limit` applies to one parsed field and its implementation counts decoded characters, not bytes. It does not cap full rows or memory from many fields. Disposition: reject the units/scope and amend with separate byte, character, field-count, record, file, and staging limits.
5. **Streaming helps, but does not alone bound peak memory.** A full-file list is avoided, yet the current row is materialized. Disposition: amend the streaming claim and cap the full logical record/field count.
6. **The physical-line diagnostic idea is right.** `reader.line_num` differs from the logical record count for multiline rows. Disposition: keep and show both.
7. **Ragged-row handling needs one more validation layer.** `DictReader` exposes extra/missing cells, but also skips blank rows, and dictionary construction can collapse duplicate headers. Disposition: amend: validate headers and row length before mapping, define blank/ragged policies, and represent missing separately from null.
8. **Malformed CSV needs an explicit strictness setting.** CPython defaults to permissive mode; `strict=True` raises for some malformed syntax. Disposition: accept this criticism and set strict parsing as the proposed default, subject to vendor fixtures.
9. **Storage atomicity is an application guarantee.** Staging is right, but the CSV library does not guarantee atomic inventory publication. Disposition: keep it as a hard design constraint and require persistence-layer failure-injection tests.
10. **Preview/import integrity should be measurable.** Reusing a profile is necessary. File metadata alone cannot guarantee unchanged content. Disposition: amend with a full-content fingerprint and re-confirmation if it changes; assess the additional I/O for very large sources.
11. **Evidence must stay bounded.** The supplied draft says upstream files were inspected and that no vendor importer test ran. This review independently inspected the official CPython 3.13.9 docs, code, and upstream tests, but did not execute those tests or a behavior witness. Disposition: keep the distinction between inspected tests and executed tests.

Full decision records with evidence, rationale, and final destinations are in [criticism-dispositions.md](criticism-dispositions.md). The remaining uncertain decisions are product-specific: supported vendor profiles and encodings; header, blank-row, and ragged-row policies; per-column type rules; null convention; and device-specific limits. CPython sources cannot settle those decisions.
