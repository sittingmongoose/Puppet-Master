# Brief-only discovery: accessible recording review annotations

**State:** Completed before the one-time plan release. This file records findings from the exact released brief only; it does not interpret or anticipate the withheld plan. Source IDs remain fixed in [the source index](sources/index.md) and [source-map.json](source-map.json).

## Evidence and candidate approaches

- Treat each comment as an independent, stable record that targets a specific immutable local recording version. A durable ID, source-content identity, start/end, body, creation/edit metadata, and optional channel hint preserve identity when comments overlap. A path, duration, sample rate, or filename alone cannot prove that a replacement is the same recording. Conservatively mark annotations unmatched when the exact source identity changes; require a deliberate, listened-to reattachment before applying them to a file with a lead-in, resampling, or other changed content. This is a proposed safety policy, not a W3C requirement. [HTML-01] [ANNOT-01]
- Use a documented half-open interval `[start,end)`; reject reversed and empty ranges for interval comments, while preserving point markers as a separately named kind. The Web Annotation / Media Fragments vocabulary supplies portable seconds-based temporal targeting; WaveSurfer and Peaks APIs also expose region bounds in seconds. Store a rational media-presentation time (integer value plus timebase) if the selected playback engine exposes one; convert for display/export without claiming that decimal digits guarantee playback accuracy. If a PCM frame index is used, bind it to the source version and sample rate. Record actual seek completion/readback because a player can clamp to seekable ranges or trade precision for speed. [MEDIA-01] [ANNOT-01] [HTML-01] [WS-CODE-01] [PEAKS-API-01]
- Make keyboard operation primary: accessible play/pause and coarse seek controls, labeled time fields, explicit “mark start” / “mark end” actions, nudge buttons/keys, and a chronological comments list with next/previous navigation. Each item should announce its start/end, text, and stable identity; overlap must remain separately navigable. A waveform region may be a visual aid, but must not be the only editor, target, focus stop, or source of meaning. This fits the brief and APG keyboard guidance; an optional slider still needs a human screen-reader check. [WAI-01] [AUD-KBD-01] [ELAN-UI-01]
- Transcript is an optional jump/association route. Attach only supplied, versioned transcript spans and their documented timecodes. If a transcript has text but no authoritative timestamps, preserve an exact text quote/span without synthesizing a media time. Keep the keyboard recording-and-comments workflow complete when no transcript exists. A text-position anchor is brittle across transcript edits, so pair it with a quote and transcript version identity. [ANNOT-01]
- Export a standalone UTF-8 TSV/CSV (one row per comment) with stable ID, recording label/content fingerprint, readable start/end such as `HH:MM:SS.mmm`, comment text, and explicit interval convention. Preserve exact machine times and provenance in a JSON sidecar or optional Web Annotation JSON-LD; do not put audio or a sensitive absolute local path in the export. Audacity’s tab-delimited start/end/text format is a useful precedent, but its current manual says exports from multiple label tracks are combined, while an open 3.4.x report describes selection/export regressions; these are reasons to test round-trip behavior rather than assume a familiar tool’s export contract. [AUD-LABEL-01] [AUD-ISSUE-01] [ANNOT-01]
- Compare a direct keyboard-first time form/ledger, optional waveform-region views (WaveSurfer or Peaks), Audacity-style labels, ELAN/EAF tiers, and Web Annotation serialization. A direct editor works without a transcript or waveform and supports overlapping text records. WaveSurfer v8.0.2 and Peaks v3.4.2 offer useful visual and media-adapter patterns, but region manipulation is pointer-centered in the WaveSurfer code/tests, and Peaks keyboard support is optional/default-off and distinct from a semantic comment list. ELAN brings mature tiered annotation and manual time entry, but its tier constraints add complexity for arbitrary overlapping comments. Web Annotation offers interoperable selectors but does not prescribe a player, persistence service, or UI. [WS-CODE-01] [WS-TEST-01] [PEAKS-API-01] [ELAN-UI-01] [EAF-SPEC-01] [ANNOT-01]
- Media risks are part of the proposal: long audio can exceed full-decode memory; VBR and library/player timing can desynchronize a rendered waveform from heard playback; seek requests may clamp, wait, or land at a nearby supported time. For local-only use, any waveform peaks should be generated/read on-device and never uploaded. Keep the original file immutable and stereo channels synchronized on the same timebase. These limits need a capability-tested player adapter rather than a fixed-engine assumption. [WS-README-01] [WS-ISSUE-01] [PEAKS-API-01] [PEAKS-ISSUE-01] [HTML-01]

## Validation to propose; not executed

1. Manually operate every playback, interval creation/edit, overlap selection, comment navigation, and export action by keyboard only with a screen reader; test focus order, announcements, time units, and a non-color indicator.
2. Use synthetic stereo PCM fixtures at two sample rates, a long recording, VBR media, overlapping/adjacent intervals, a point marker, and absent / untimed / timed transcripts. Compare saved rational times with the engine’s completed seek position and heard passage.
3. Hash/bind an original fixture, then replace it with a version containing a lead-in and another resampled version. Verify both become visibly unmatched and none of the original comments auto-seek or silently inherit the new identity.
4. Round-trip comments through the human-readable export and sidecar, including overlap, UTF-8 punctuation, multiline/quoted text, exact times, source identity, and missing-transcript state. Verify playback leaves source bytes unchanged and no network/audio upload path exists.

No application code, external test suite, browser, screen reader, sample recording, or executable witness was run in discovery. These are validation proposals; none is reported as passed.
