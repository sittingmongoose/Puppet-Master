# Draft plan: Accessible recording review annotations

The draft stores annotations as stable identifiers with start and end milliseconds, comment text and a recording hash. A keyboard action marks the current playback position; another closes the interval. A list offers navigation to each annotation, overlapping intervals remain separate, and text labels state their ranges. Review is possible without a transcript. Original local audio is never changed or transmitted.

When a transcript supplies timed segments, selecting a segment seeks to its supplied start time. Untimed transcripts are searchable text but do not create inferred timings. The draft assumes milliseconds reported by the playback API are stable enough for annotation round trips across supported formats. It also proposes restoring annotations after a recording replacement when the filename matches, warning only if duration differs. That replacement rule has not been justified, particularly for equal-duration files with changed lead-ins.

Comments export to a static text report with filename, hash and formatted ranges. The draft has not decided whether channel information or an explicit media-relative time basis is necessary. Focus should remain predictable while playback continues, but seek announcements and interval editing need platform-specific accessibility research. Proposed validation covers overlapping annotations, seeking near boundaries, different sample rates, replaced media, transcript absence and keyboard/screen-reader operation. No recordings or assistive-technology sessions have been used. Implementation should first establish annotation/media identity and then integrate the review controls.

This is a provisional draft for review after the declared reveal, not an endorsed answer. Resolve material assumptions through applicable primary evidence; retain open user-data questions when they cannot be answered from sources. No future product deployment is requested.
