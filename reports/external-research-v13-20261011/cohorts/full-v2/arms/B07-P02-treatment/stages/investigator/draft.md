# Accessible recording review annotations: research-backed proposal

**Status:** proposal for review after the single plan release. No implementation, deployment, or real-recording work is included. Source IDs and detailed source identity records are in [sources/index.md](sources/index.md) and [source-map.json](source-map.json).

## Proposed direction

Build a local review-record store behind a small playback adapter. Make keyboard marking, labeled time fields, and a chronological comment list complete on their own. Treat a waveform as an optional visual aid. A transcript adds a second route when its supplied segments carry timecodes; an untimed transcript remains searchable text and never creates media times.

Persist each review comment separately, with a stable comment ID and an immutable recording identity. Keep overlapping intervals as separate records. Bind positions to the media presentation timeline relative to the recording’s defined start, with half-open interval semantics: include the start and exclude the end. Keep the planned integer-millisecond representation if the owner accepts millisecond granularity; report it as a data/display resolution, never as a promise that every player can seek to the exact millisecond. WHATWG’s media model uses seconds, permits duration to be unknown/infinite, exposes seekable ranges, and makes seeking asynchronous. Its fast-seek operation trades precision for speed, while normal seek can clamp to an available range. A decimal number of places or an integer millisecond value cannot by itself establish heard-position accuracy. [HTML Standard](https://html.spec.whatwg.org/multipage/media.html) [Media Fragments 1.0](https://www.w3.org/TR/media-frags/)

For a local file, compute a SHA-256 digest of the exact file bytes. Keep the filename as a human-readable label; do not use filename or duration as identity. Store the digest with the comments and report it in exports. If the file’s digest changes, mark its comments unmatched and leave their times intact for review. Require a person to listen and deliberately reattach or re-mark a comment before it can target the changed file. A same-name, same-duration replacement with a different lead-in must never load the old positions automatically. A byte digest is deliberately conservative: a harmless metadata rewrite or transcode also changes it, so any equivalence/remapping policy for changed files needs an explicit owner decision. No consulted standard defines the application’s recording-identity policy. Hashing and waveform generation stay local; open media read-only and never transmit it.

Define the review time basis as milliseconds from the recording presentation timeline’s chosen zero. If a container/player reports a non-zero timeline origin, the adapter must normalize and record that conversion instead of mixing it with file-relative display time. Validate start < end for interval comments. The persisted range is [startMs,endMs), and an end at the recording duration is allowed. When a reviewer marks or seeks, retain the requested time and obtain the adapter’s completed/read-back position where it can be observed. On a mismatch, show the actual position and do not label the request as exact. Set an accepted tolerance for each supported engine and format; a future sample-accurate requirement would call for a rational media timebase or source-frame representation bound to that exact source version.

The source hash, sample rate, channel count, media duration, timeline origin, and format are useful source metadata. The annotation targets the whole recording by default, including both stereo channels. The brief does not require channel-specific comments. Offer a clearly named channel scope only if reviewers need it; show it in words and in the export, never with color alone. Never use a frame index without its sample rate and source identity.

## Keyboard and screen-reader flow

1. Focusable, named controls provide Play/Pause, a coarse seek control, a current-time display, smaller/larger nudge actions, and explicit Mark start, Mark end, Cancel range, and Save comment actions. Mark start records the current player time and announces the pending start. Mark end closes the range. Saving preserves the start and end independently of playback. A reviewer can also edit the labeled start/end fields directly.
2. Mark-start/end shortcuts work only in the review control context. Disable them while focus is in comment text, transcript search, or another text field. Provide a discoverable shortcut reference and remapping if the host platform has shortcut conflicts. Mouse and waveform operations may supplement this flow.
3. Keep keyboard focus on the reviewer’s chosen control while the playhead advances; do not rebuild or reorder the focused comment row every time playback updates. A completed seek keeps or returns focus predictably and reports the actual time in a polite status message. Avoid announcements on every playback tick.
4. The comment list sorts by start time, then end time, then stable ID. Every row has a text label containing its start, end, and comment; it remains distinguishable when intervals overlap or colors are disabled. Row actions let the reviewer seek to its beginning, edit its time or text, and move to the previous/next comment. A screen-reader user must be able to find and activate each action without entering the waveform.
5. A reversed or zero-length interval is not silently saved as a comment. Keep the range editable and announce the correction required. If point markers are ever added, give them a separate kind and label. They are an optional extension, not part of the brief’s interval-comment requirement.
6. The waveform can show synchronized channels and intervals, but its regions cannot be the only way to make or edit a comment. WaveSurfer’s 8.0.2 source defaults its regions to draggable/resizable and wires pointer, mouse, and touch interactions; its region Cypress tests exercise pointer dragging, region creation, point markers, and a stereo fixture, without a keyboard/screen-reader case in that file. Peaks.js 3.4.2 offers custom player and precomputed local waveform options, but keyboard controls default off and a 0.01-second nudge does not itself provide an accessible comments editor. [WaveSurfer regions source](https://raw.githubusercontent.com/katspaugh/wavesurfer.js/8.0.2/src/plugins/regions.ts) [WaveSurfer regions tests](https://raw.githubusercontent.com/katspaugh/wavesurfer.js/8.0.2/cypress/e2e/regions.cy.js) [Peaks.js API](https://raw.githubusercontent.com/bbc/peaks.js/v3.4.2/doc/API.md) The WAI-ARIA APG describes slider keys and time values, and warns that assistive-technology support can vary; use it for the optional seek control and still perform manual screen-reader testing. [WAI-ARIA APG Slider Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/slider/)

## Transcript route

A supplied timed segment links to a versioned transcript span and its supplied media start/end. Selecting the segment requests a seek to its supplied start; the adapter waits for completion and exposes the actual position. Do not adjust transcript timecodes by inference or treat search positions as media positions.

An untimed transcript is searchable and navigable as text, with no seek target unless a reviewer deliberately marks one while listening. Preserve a transcript version digest and stable segment ID when available. A text quote plus surrounding quote or position can help locate a changed transcript, but text positions are brittle across edits; a mismatch needs review. The Web Annotation model supports FragmentSelectors for media targets and TextQuote/TextPosition selectors for text, and it explicitly separates the data model from transport. Use it as an optional local serialization/interchange form, not as a reason to add a remote annotation service. [Web Annotation Data Model](https://www.w3.org/TR/annotation-model/)

## Persistence and export

Persist comments locally with fields equivalent to:

- Comment ID; body text; range start/end in integer milliseconds; explicit interval kind and [start,end) semantics.
- Recording digest and display filename; declared timeline origin, duration, sample rate, channel count, and format as captured for that source version.
- Optional transcript digest, segment ID, quote, and supplied timecodes.
- Optional channel scope, defaulting to all channels.
- A binding state such as current or unmatched, plus any human-confirmed reattachment record.

Keep local persistence independent of the player implementation. The adapter should report load state, current time, duration, timeline origin, seekable ranges, channel/sample-rate metadata, read-only local loading, completed seek, actual position, and unsupported/error state. Playback replacement must not rewrite comment times implicitly. The storage choice—project database or local sidecar—and backup behavior remain open because the brief does not define them.

Export one UTF-8 tab-delimited text report or CSV row per comment, with stable ID, filename, source hash, time basis, interval convention, readable start/end, text, and any explicit channel scope. Use hours that can grow beyond 24 and keep milliseconds in a fixed three-digit field. Escape tabs, quotes, newlines, and non-ASCII text correctly. Do not include a sensitive absolute file path. A small optional local JSON sidecar can preserve exact fields for software re-import; the static report stays readable by people. Export comments only—never audio. Audacity’s manual offers tab-separated start seconds, end seconds, and text as a precedent; it also documents combined multi-track export, while issue #5690 reported selection/export regressions in Audacity 3.4.x. Treat exports as a contract to validate, not as a behavior copied from a tool without checks. [Audacity label format](https://manual.audacityteam.org/man/importing_and_exporting_labels.html) [Audacity issue #5690](https://github.com/audacity/audacity/issues/5690)

## Alternatives and fit

| Approach | Useful evidence | Fit and limitation |
|---|---|---|
| Keyboard-first time fields, mark actions, and comment list | Audacity documents keyboard label tables and marking at selection/playback; APG specifies slider interaction. [Audacity keyboard commands](https://github.com/audacity/audacity-support/blob/main/basics/keyboard-shortcuts.md) | Strongest baseline for no-transcript, keyboard-only review. Requires the app to implement accessible focus, range validation, and actual-seek feedback. |
| WaveSurfer.js Regions | Versioned source has seconds-based regions, IDs, drag/resize, markers, and channel selection. Its 8.0.2 README warns about full-decode memory limits on large files and VBR waveform mismatch. [README](https://raw.githubusercontent.com/katspaugh/wavesurfer.js/8.0.2/README.md) | Useful optional waveform and region layer. It cannot be the keyboard editor by itself. The v6.6.1 long-file mismatch discussion is historical and not proof of a v8 defect; it supports testing long-file position/audio alignment. [Discussion #2737](https://github.com/katspaugh/wavesurfer.js/discussions/2737) |
| Peaks.js segments and points | API exposes second-based segments, precomputed waveformData, multichannel display, a custom player, keyboard option, and nudge value. GitHub lists 3.4.2 as stable and 4.0.0-beta.2 as prerelease; its README says current development moved to Codeberg. [API](https://raw.githubusercontent.com/bbc/peaks.js/v3.4.2/doc/API.md) [Releases](https://github.com/bbc/peaks.js/releases) | Attractive where media integration and local peaks matter. Pin and assess the maintained upstream first; keyboard must be enabled, and custom seeking needs audio/playhead checks. Open issue #573 is a custom-seek mismatch report, not a confirmed library-wide fault. |
| Audacity label workflow | Human-readable tab-delimited start/end/text export and keyboard actions for adding labels and setting boundaries. | Good benchmark for compact review controls and readable timing export. Its editor/export model and multiple label tracks need not be replicated; issue #5690 shows the risk of selected-state and export regressions. |
| ELAN/EAF tiered annotations | ELAN supports typed hh:mm:ss:ms boundaries and keyboard navigation. EAF 3.0 models time slots and constrained tiers. [Boundary entry](https://www.mpi.nl/tools/elan/docs/manual/Sec_Changing_the_boundaries_of_an_existing_selection_and_annotation.html) [EAF 3.0](https://www.mpi.nl/tools/elan/EAF_Annotation_Format_3.0_and_ELAN.pdf) | Good where transcription tiers and structured alignment are central. Its same-tier top-level annotations cannot overlap, so arbitrary overlapping free comments need multiple tiers or another model. It is heavier than needed when no transcript exists. |
| Web Annotation JSON-LD | Standard selectors can describe a media fragment and text fragment; the standard does not require a server/transport. | Useful optional interchange format. It does not supply the player, file-identity rule, review list, local persistence, or accessibility behavior. |

Do not choose WaveSurfer, Peaks, ELAN, or Web Annotation as a complete product based on this comparison. First validate the supported native player, platform, media set, and memory/precision envelope. The product can keep its accessible comment model while swapping visual or playback implementations.

## Existing coverage, corrections, and open owner decisions

**Already covered and retained:** stable IDs; comment body and time interval; local file hash; key-based interval marking; list navigation; independent overlap; text range labels; transcript-free review; timed transcript jump; untimed searchable transcript; no inferred times; immutable/local audio; readable filename/hash/range export; focus continuity; proposed boundary/sample-rate/replacement/transcript/accessibility validation; identity-first implementation order.

**Corrected or rejected:** a filename-plus-duration restoration rule is rejected. Same-name and equal-duration files can have different media passages. The claimed cross-format millisecond round-trip guarantee is corrected to a measured limit, not a default fact. A waveform drag operation cannot be the only editing method. Color cannot be the only way to distinguish ranges. No transcript timing may be invented, and no audio may be transmitted or modified.

**Optional improvements:** optional waveform peaks for long recordings, generated locally; optional Web Annotation JSON-LD export; optional transcript quote/version anchoring; explicit channel scope when a confirmed review task needs channel-specific comments. None is a prerequisite for a fully keyboard-operable, transcript-free review.

**Owner decisions to record before implementation:**

1. The required timing tolerance. Default recommendation: integer milliseconds with an explicit media-relative origin and an honest engine/format tolerance. If the brief later means sample-accurate marks, use a rational source timebase and test it against the chosen decoder.
2. The supported player/platform/media matrix and accessible test matrix. The playback engine is unspecified, so no exact codec/seek guarantee can be made here.
3. Whether byte-identical source identity is sufficient or a decoded-audio equivalence/remap feature is needed. Default to exact local SHA-256 and manual review for any changed digest.
4. Whether comments can target one stereo channel. Default to all channels.
5. Where local annotations live (project database or sidecar) and how backup/restore preserve source hashes.

## Integration and validation plan

**Integration order:** (1) define stable comment IDs, source digest, local time origin, millisecond conversion, interval validation, and unmatched-source state; (2) implement the read-only local media adapter with duration, channels, sample rate, seek ranges, and completion/readback; (3) implement keyboard mark/edit controls and the text-labeled comment list; (4) add optional timed-transcript association and local waveform peaks; (5) implement the readable report/sidecar; (6) test each declared platform and supported media format.

**Proposed checks (not executed in this stage):**

- Unit-test range conversion, half-open boundary behavior, start < end, end at duration, long-hour formatting, stable ordering, overlap preservation, ID persistence, source-hash binding, UTF-8 escaping, and transcript selector/version changes.
- With synthetic local fixtures, exercise mono and stereo PCM at 44.1 and 48 kHz, another declared rate, long duration, and VBR if supported. Place distinguishable sound events at known times, mark/seeks near interval boundaries, wait for completion, compare target/readback/heard event and the declared tolerance, and verify the comment list and export use the same time basis.
- Copy a fixture under the same filename, replace its contents with an equal-duration different lead-in, then test a resampled replacement. Confirm digest changes, comments become unmatched, and no list selection seeks to old times. Confirm byte-identical content at a new path is recognized by content identity if policy permits.
- Test no transcript, searchable untimed transcript, supplied timed segments, and a changed transcript file. Confirm the timed route uses only supplied times and the other cases never synthesize a seek position.
- By keyboard alone, create/edit/cancel overlapping comments, move through rows, seek, mark start/end, and export. Repeat with a screen reader on every supported target platform; check focus stability during playback, range/state announcements, item names/order, error recovery, and absence of color-only cues.
- Compare original source-file bytes before/after review; inspect local network behavior to confirm audio/transcript/peaks/comments are never sent remotely. Test unavailable/NaN duration, missing seek ranges, unsupported codecs, and a seek that completes at a different position.
- Round-trip the static report and optional sidecar with quotes, tabs, line breaks, non-ASCII text, a long filename, overlapping intervals, and source metadata. Confirm the report remains readable and does not expose an absolute path.

**Executed in this stage:** brief-only discovery and primary-source/repository-document review; WaveSurfer source and existing test file inspection; plan release and review. The referenced upstream test files were read, not executed. No application, build, downloaded code, browser, synthetic or private recording, screen reader, accessibility audit, or media fidelity check was run. Every validation bullet above is proposed work.
