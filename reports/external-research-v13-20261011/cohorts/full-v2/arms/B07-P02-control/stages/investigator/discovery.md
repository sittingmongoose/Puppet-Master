# Brief-only discovery — investigator, B07-P02-control

## Scope read
The brief requires a research-backed software proposal for local recording review: staff listen, create a time interval, and add a textual comment to long audio, sometimes stereo. It must work by keyboard and with a screen reader, keep overlapping comments distinct, offer transcript navigation only when a transcript exists, keep review possible without one, avoid fabricated transcript times, and prevent a replacement recording with a new lead-in or sample rate from silently inheriting wrong passage anchors. Export must be human-readable and include useful timing context. Mouse dragging, color-only distinctions, source alteration, and remote audio transmission are out of scope; deployment, private recordings, and recruiting interview subjects are not requested.

The exact comparison plan was withheld at this point and was not sought or read. This is brief-only discovery; clause-by-clause disposition belongs in the later draft after the declared release step.

## Product and interaction approaches
1. **Peaks.js (BBC, v3.4.2 stable)** provides zoomable/scrollable overview and detail waveforms, point and segment APIs, time values in seconds, and optional keyboard controls. Its API defaults keyboard binding off; arrow-key nudge is 0.01 seconds. Its tagged demo also uses numeric start/end inputs and a table-like segment list. This is useful evidence that a list-plus-time-fields workflow can sit beside a waveform, and that precomputed waveform data can separate visualization from decoding. The API and demo do not establish a complete screen-reader review workflow or keyboard creation/resizing of regions. A v4 beta is listed separately from the latest stable tag. [SRC-005, SRC-006]
2. **WaveSurfer.js (8.0.0)** offers a Regions plugin with independent region objects, IDs, second-based start/end values, drag and resize, min/max length, and region events. The v8 source implements create/move/resize through pointer/drag streams; no keydown handler was found in that source file. Treat it as a visual component candidate that needs an accessible list/field interaction layer and independent user testing. A recent release history records fixes for early seeks dropped before canplay, region event races, playhead time after pause, hidden-container NaN seeks, and neighboring-region in/out ping-pong. These are regression targets, not proof that a specific integration is correct. [SRC-007, SRC-008]
3. **Audacity Label Tracks/Label Editor** are a mature interaction reference, not an embedded library: labels can be point or region notes, Tab/Shift+Tab navigate labels, and a keyboard-accessible table editor can edit text and boundaries; plain-text label files are tab-delimited. The manual documents limits (labels over 260 characters may not reload; hundreds or thousands can slow the application) and export behavior that may select only the uppermost label track for Export Multiple. This pattern needs adaptation for overlap-safe comments and scoped exports. [SRC-009]
4. **A native annotation list with labeled numeric time controls** is the least engine-dependent route for full keyboard and screen-reader operation. Keep a compact list/table as the authoritative interaction; offer waveform and transcript views as additional routes into the same selected annotation. Each record needs an immutable annotation ID independent of interval coordinates. Expose start/end as editable time fields with clearly named “set start to playhead” and “set end to playhead” actions, plus direct playback, jump/step, save, and delete actions. Keep focus stable after edits and explain shortcut bindings. Overlap is ordinary data: do not merge, deduplicate, recolor-as-the-only-cue, or impose non-overlap validation.

## Timing, identity, and transcript findings
Use a per-media-version identity and exact source-relative interval. A locally computed SHA-256 plus stable asset UUID and decode facts (duration, sample rate, channel count, codec/container, and media timebase when available) lets the application recognize the same bytes without relying on a path. Store exact start/end in the asset's rational media timebase (or exact integer sample-frame coordinates for PCM with its sample rate recorded); present a readable HH:MM:SS.mmm export plus exact stored values. Treat intervals as half-open [start,end), matching W3C Media Fragments; require start < end and bounds within known duration. Distinguish requested position from the position the chosen backend actually reaches. Encoded audio and decoder APIs can seek with tolerances or incur delays; labels and seconds alone do not guarantee sample accuracy. W3C NPT time is seconds and does not imply frame accuracy. [SRC-001, SRC-002, SRC-010, SRC-011, SRC-012]

A changed hash is a new asset version, even when the path/name matches. Keep annotations attached to the old revision and surface the new recording as unmapped pending review; never reuse old offsets automatically. Provide an explicit, auditable alignment record from old asset version to new version (offset, optionally scale, method/evidence, confidence, reviewer, approval time), and only activate it after a human confirms a short set of sampled passage checks. A sample-rate change alone does not justify multiplying the displayed seconds; it changes sample coordinates and possibly decode behavior, while the same content may remain at the same media time. A changed lead-in requires an explicit offset or alignment decision. Original audio stays read-only.

Store transcript identity separately (local file/content hash plus revision). If untimed, offer quote/context navigation within the text only and leave the annotation interval/time unaltered; do not synthesize a timestamp. If timed cues are supplied by an authoritative transcript, retain cue provenance and state that a cue jump may be approximate. W3C TextPositionSelector identifies character positions, not audio seconds, and its specification warns that text position anchors are brittle after edits; optionally retain text quote and surrounding context, and mark stale anchors unresolved. A missing transcript simply removes that route. [SRC-002, SRC-003]

## Playback and media limits
Do not choose a playback engine based on the visual library. Define an adapter contract for local open, duration/seekable ranges, actual current position, stereo/channel information, requested seek accuracy, and completion/errors. GStreamer distinguishes KEY_UNIT seeking from ACCURATE seeking; accurate may be slower and may require decoding from earlier in the file. Apple AVPlayer makes the tolerance explicit: zero before/after tolerances request sample-accurate seeking with extra decode delay; nonzero tolerance permits landing nearby. Select a backend only after platform/codec packaging requirements are known and validate its observed position against the chosen editorial tolerance. Long-file display should use waveform peaks or windowed/level-of-detail rendering rather than assume full-file decode is cheap. Web Audio's decodeAudioData accepts the full encoded-data buffer and outputs PCM resampled to the context rate; full decoded float PCM memory grows with duration and channel count (48 kHz stereo for one hour is about 1.38 GB before overhead). Keep waveform preprocessing and playback entirely local. [SRC-004, SRC-010, SRC-011, SRC-012]

## Accessible operation and export
Treat waveform gestures as an optional convenience. Required paths should use focusable named controls, an ordered annotation list/table with text identity and start/end, clear overlap position/range descriptions, direct keyboard playback/jump/mark/edit operations, and a transcript pane only when available. Do not reserve global letter keys while a comment field is being edited. If a slider is included, follow the APG keyboard model and test it with screen readers; APG warns that touch screen-reader support for sliders varies. Meet the relevant WCAG 2.2 keyboard, focus/order, and use-of-color requirements, then perform manual tests with at least one keyboard-only route and supported screen-reader/platform combinations. WAI-ARIA APG is informative; WCAG is normative. [SRC-003, SRC-004]

Export one record per annotation, sorted by start then stable ID while preserving overlaps, with recording display name, a short content hash/revision label, exact and human-readable start/end, duration, optional channel scope, comment text, and a clear unresolved/replaced-source marker. Escape newlines and delimiters; use UTF-8. Keep a machine-readable companion if needed, but do not make it the only deliverable. W3C media-fragment syntax can be an interoperability option for a time range on an unchanged target resource, not a replacement for asset identity or a migration map. [SRC-001, SRC-002]

## Candidate disposition before plan release
- **Worth prototyping/benchmarking, no winner selected:** an accessible annotation list plus numeric fields backed by an engine adapter; Peaks.js and WaveSurfer.js as visual-layer candidates; precomputed local waveform peaks for long files; and Audacity's Label Editor as a keyboard interaction reference.
- **Use standards selectively:** W3C half-open media ranges and Web Annotation selectors inform serialization; they do not solve local asset revision, alignment, playback seek precision, or screen-reader behavior by themselves.
- **Rejected for this scope:** drag-only interval creation; color-only identity; time values applied silently across changed recordings; remote waveform or transcription processing; inventing cue times for untimed transcripts; and editing/re-encoding the original audio.
- **Uncertain until owner/product decisions:** desktop runtime/platform, playback backend, supported codecs, exact acceptable seek error, maximum annotation count/comment length, whether annotations can target an individual channel, and export format(s). No artifact, source code, private recording, or implementation test was executed in discovery.

## Validation proposals (not run)
1. Create overlapping and adjacent records, distinct IDs at identical coordinates, zero/duration boundary cases, malformed or reversed ranges, and large lists; round-trip save/export/import with no merge, loss, or time drift.
2. Exercise WAV/PCM and representative compressed local formats, mono and stereo, multiple sample rates, variable-bitrate/seek-index cases, long files, missing/corrupt/unsupported files, and a replacement with leading silence. Compare requested with actual seek position at start/end/interior; verify any mapping is explicit and reviewable.
3. With keyboard only, create/edit/save/delete comments, seek, mark, traverse overlapping records, and leave every widget without a pointer; verify no focus theft or shortcut capture in text fields. Repeat with supported screen readers, a missing transcript, and an available untimed/timed transcript.
4. Inspect local-only processing and original-file byte hash before/after; inspect exported UTF-8 text for timing context, overlap, escaping, revision identity, and unresolved mappings.
