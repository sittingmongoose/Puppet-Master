# Research-backed draft — accessible recording review annotations

## Decision summary
Build the review around a local, immutable media-version record and an annotation model with stable annotation IDs, independent overlapping intervals, optional transcript anchors, and exact per-version timing. Make the keyboard-operated annotation list and labeled start/end controls the reliable route; treat a waveform as an optional second route and as a visual aid. Keep the playback engine and waveform library behind adapters. This is a suitable integration direction for the brief; no UI library or playback engine is selected as the winning product.

The plan is correct to put identity before interaction integration. Two assumptions need correction before implementation: milliseconds returned by an arbitrary playback API do not guarantee stable cross-format annotation round trips, and filename equality is not enough to restore annotations to a replacement recording. Equal-duration files can still have different lead-ins. A new file revision must start unmapped unless exact byte identity or an explicit, reviewed alignment establishes the relationship.

## Integration model and alternatives

### Asset and annotation records
- `MediaRevision`: stable local UUID; SHA-256 of exact source bytes; filename/path as changeable display metadata; container/codec, channel count, source sample rate, duration, and source timebase if reported. Do not transmit the file or hash.
- `Annotation`: UUID; media-revision UUID; integer start/end in the revision's exact coordinate/timebase; text; created/edited metadata; optional channel scope; optional transcript anchor; revision-resolution state. Enforce start < end and known duration bounds, while allowing interval overlap.
- `TranscriptRevision`: local revision identity/hash, text, and optional supplied cue list with provenance. Text-only transcript has no time map. Use quote/context and character selectors only as text navigation; a stale transcript anchor is unresolved, not silently shifted.
- `Alignment`: explicit old-to-new asset relation, method/evidence, offset and optional scale, estimated confidence, reviewer, approval time, and confirmed sample passages. An automatically estimated local alignment may be offered only as a proposal for user confirmation; it must never activate silently.
- `PlayerAdapter`: open local file read-only; expose duration, seekable ranges, channels, position, load/error state, supported seek modes, seek completion, and actual position. Use a fast approximate mode for broad navigation if useful and a precise mode for placing/checking interval boundaries. Surface backend error and measured residual from requested position.

### Interaction choices

| Approach | Strengths | Limits for this brief | Role |
|---|---|---|---|

Browser/WebAudio decoding and component fit need benchmarking. | Candidate visual layer; keep list/fields beside it. v3.4.2 is stable; v4.0 beta.2 is prerelease, so do not base a release decision on the beta without a separate review. |
| WaveSurfer.js Regions | Region creation/editing, configurable drag/resize/min/max bounds, time values, and region events; active release has relevant seek/region regression fixes [SRC-007, SRC-008]. | Pinned source uses pointer/drag handlers and does not document a keyboard editor in the examined file; an accessible host interaction remains necessary. | Audacity Label Editor/Label Tracks pattern | Keyboard navigation through labels, tabular editing, point/range labels, plain-text export [SRC-009]. | Standalone editor rather than a library; documented text/count limits and uppermost-label-track Export Multiple behavior require caution. | Interaction precedent and possible import/export compatibility reference. |
| Web Annotation / Media Fragments serialization | Standard selector/target vocabulary, half-open time ranges, text and time fragment syntax [SRC-001, SRC-002]. | Does not supply local media hashing, changed-file alignment, player precision, accessible UI, or transcript synchronization. | Optional export/interchange envelope; preserve app-specific version and timebase fields. |

No waveform component is required to create, edit, navigate, export, or review annotations. For long recordings, profile local waveform generation and rendering first. Peaks documents both client computation and precomputed data; Web Audio decoding consumes encoded data into PCM and resamples to the audio context rate [SRC-005, SRC-012]. A 48 kHz stereo hour represented as 32-bit floats is roughly 1.38 GB before overhead. Favor local, cached, multi-resolution waveform peaks and visible-window rendering where the selected stack supports them; this is a performance proposal, not a measured result. Backend codec, container, seek-index, variable-bitrate, and local-file support are build/platform constraints, not assumed universal.

## Media and timing limits
- Store canonical time in each asset revision's source-relative rational media timebase; for PCM, an integer sample frame and explicit sample rate can preserve sample-coordinate identity. For compressed media, use the decoder's declared presentation timeline/timebase where reliable and preserve the backend's actual precision/tolerance. Avoid floating-point conversion as the persistence format.
- Millisecond output is practical for staff but loses sub-millisecond detail; it is not a promise that playback can land on that sample. Format seek limits, gaps, seekable ranges, decoder indexing, and asynchronous load/interrupted seek behavior must be discovered and surfaced.
- Compare the GStreamer accurate/key-unit modes and Apple AVPlayer tolerance behavior only if those backends match the runtime/platform. Both demonstrate a speed-versus-precision cost and completion behavior; neither is selected without codec/platform packaging evidence [SRC-010, SRC-011].
- A “replacement” is not a rename. Hash mismatch creates a new revision regardless of matching filename or duration. Exact hash match proves byte identity, but a different hash only suggests change; it does not prove whether content can be aligned. A local transcode may preserve media time despite sample-rate changes; verify, do not multiply old seconds by a rate ratio.
- Stereo visualization is optional and must label channels clearly. Decide whether notes refer to the mixed recording or a channel before adding channel controls/export fields.

## Already covered, optional improvements, rejected points, and open decisions

**Already covered by the brief and retained:** local-only processing; keyboard and screen-reader use; overlaps; optional transcript and a no-transcript workflow; no invented times; immutable original audio; useful human-readable timing; mono/stereo local media; engine not fixed; no drag-only operation; no color-only meaning; no deployment, recruitment, or private-recording trial.

**Optional improvements supported by the research:** a waveform overview plus zoom detail; a local precomputed waveform cache; W3C-compatible selectors in an additional export; a short “play around this annotation” action; explicit alignment review with a few passage samples; undo after boundary edits; explicit cue provenance and replacement state in the export. These are implementation choices, not added scope prerequisites.

**Rejected/corrected:** filename-based automatic reattachment; using unchanged duration as evidence of identical content; a blanket promise that API milliseconds are repeatable across all codecs and sample rates; treating color as the only signal; making drag-region interaction the only editor; generating times for an untimed transcript; remote processing or modification of source audio.

**Owner decisions that evidence cannot settle:** supported operating systems and native/web shell; approved player backend and codec/container list; acceptable seek residual for review; maximum file duration/annotation count/comment length; whether notes can be channel-specific; export format and retention policy; transcript file formats and which timed-cue sources count as authoritative; whether any candidate library fits the actual runtime/license/build constraints. Until these decisions are made, the adapter contract and file matrix remain proposals.

## Validation plan (all proposed, none run)
1. **Data model:** create overlapping, adjacent, coincident-time/different-ID, start-at-zero, end-at-duration, reversed, zero-length, out-of-range, and long-comment cases; save/reload/export/import and compare exact times, IDs, ordering, and text.
2. **Replacement safety:** exact duplicate bytes with renamed path; same filename/equal duration but different lead-in; same filename with changed sample rate; different encoding with identical audible content; truncated/replaced files. Confirm old revision remains intact, changed hashes are visibly unresolved, and no annotation seeks until a user approves an alignment. Confirm approved mapping on multiple listening samples before activating it.
3. **Seeking/media:** local PCM WAV and selected compressed formats; mono/stereo; 44.1/48 kHz; representative VBR and indexed/non-indexed files; missing/corrupt/unsupported files; short and long recordings. Request boundary/interior seeks before and after metadata, during an interrupted seek, and at file ends; measure actual landing, tolerance, repeatability, and playback through interval end. Profile memory, waveform build time, and rendering for one-hour stereo media.
4. **Accessibility:** keyboard-only, no mouse: open local file, play/pause, jump, mark both boundaries, correct values, add/edit/delete overlapping comments, move list focus, use transcript if present, save/export, and exit each control. Verify logical focus order, visible focus, no traps, no shortcut capture in text entry, and useful explicit seek/mark/save/error announcements without tick-by-tick speech. Repeat with the supported screen readers/platform accessibility APIs and with absent, untimed, and supplied-timed transcripts.
5. **Privacy, source preservation, export:** inspect implementation/network boundary to confirm no audio leaves the device; compare source-file hash before/after; inspect UTF-8 exports for exact and human times, revision identity, channel decision, overlap preservation, text escaping, and unresolved mapping labels.
