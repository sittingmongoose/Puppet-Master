# Supplier spreadsheet reconciliation

An existing stock-management application needs an import component for supplier spreadsheets. Suppliers send delimited text with inconsistent headers, decimal separators and product codes. Staff must preview changes against current stock records, distinguish a new product from an update and recover from a batch that stops halfway. The source files sometimes repeat a product row or reuse a product code after a discontinued item.

Research parsing, mapping, identity, duplicate handling, transactional application and a comprehensible review workflow. A file can contain up to eighty thousand rows. Staff should save a mapping profile but still see when a new file's structure no longer matches it. Reimporting the same file should not unknowingly add quantities twice. Invalid rows must remain traceable to their source location, and a canceled preview must not change stock. Do not silently coerce ambiguous numbers, treat a supplier code as globally unique, execute spreadsheet formulas, or overwrite staff notes from an unmapped column. Supplier data should stay local. Compare feasible parsing and reconciliation approaches and describe which user decisions are unavoidable. Recommend a staged integration and validation proposal, including what success and partial failure mean. No import of actual supplier data or modifications to the production stock database are requested.
