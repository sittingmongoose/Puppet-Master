# Fresh finite recipe materialization v2

This public, offline materializer creates a **new private caller-owned copy** of one finite recipe: `R0`, `A1`, or `A1+A8`. It extends materialize-v1 and preserves its mechanical safeguards. It does not run a research candidate, qualify science, replay historical bytes, or establish native response provenance/freshness/lifecycle. Root independently verifies and publishes later. Actual C/D outputs and independent assessments own science qualification.

| Public choice | Substantive scope | Time contract | Technique addition |
| --- | --- | --- | --- |
| R0 control | Complete original three fresh-context investigator → independent critic → complete reviser | Fixed stage caps 30/12/18 minutes, clipped to whole deadline | None |
| A1 treatment | Same complete original scope | Absolute initialization T0 +30/+42/+60 minutes, clipped to whole deadline | Transferred time only |
| A1+A8 frozen composite treatment | Same complete original scope | Exact A1 absolute +30/+42/+60 | Verbatim A8 critic/reviser delta files only; investigator unchanged |

All choices use identical common mechanics: authorized Luna Max route, **Standard requested** (`serviceTier: default`), native T3-owned prepare/dispatch/terminal dependencies, fresh brief-first independent discovery and one-shot exact plan reveal, full carried source byte/inventory pins, invocation clarification, and exact-goal-binding guard v1 before any case/source read or inference. Common mechanics are not treatment credit. Composite component gains must never be multiplied. Prospective C-R2 selection is frozen; this materializer does not revise that selection or assess its outcomes.

## Caller contract

Supply a **new nonexistent dedicated local destination**, unique new run ID, NEW caller-owned brief and exact plan, actual provider instance ID you are authorized to use, and newly chosen deadline/budget arguments. No expired historical configs, campaign cases, source answers, assessor feedback or prior winning sources. The CLI can validate identifiers, paths, clocks and bytes; it cannot prove that your inputs are new or that your authorization is valid. Root owns and reserves the destination and every stage exclusively.

Paths must be simple absolute ASCII paths containing only letters, digits and `/._-`; symlinks, traversal, canon/campaign run/helper paths and existing destinations are rejected. A provider ID must be a simple 1–64-character identifier, matching the actual current authorized catalog. The placeholder is rejected. Recipe stage budgets remain frozen at 1800/720/1080 seconds; explicitly supply these new run allocations and a 3600-second whole budget. Supply a timezone-aware absolute UTC deadline **in the future and at most 3600 seconds from materialization**. Setup, queue, tools, retries and writing all count. Do not extend or reset expired clocks. Starting preparation starts investigator time; A1 origin is original run initialization, never each later stage.

## Existing native bootstrap and lifecycle

Read the private `helpers/er12-screen-v1/bootstrap.js` and paste its **entire contents** into existing root T3 functions code mode. It contains inline existing root functions and needs no functions-store preload. For the composite its `py` commands go through the small pinned overlay; verification remains the base private materializer. Keep the pinned on-disk bootstrap unchanged and change only the invocation's `STAGE` from investigator to critic to reviser.

Before preparation the bootstrap verifies the materialized manifest and actual live authorized catalog: Luna Max, original Priority guard and Standard support, and child-task capability. Original config/run keep Priority for the original helper guard; prospective actual stage requests become Standard on **every choice and every stage**. Each later stage queries its exact returned predecessor taskIDs and requires `completed` plus explicit `hasPendingChildRuns: false`. Missing/unknown/active dependencies stop. It applies Standard → clarify → exact guard only to unused preparation, checks memory, then uses the existing native T3 dispatch. No new automatic advancement is introduced.

The exact guard puts the **exact immutable freeze.native_goal_objective** in the leaf request. Before any case/source reading or inference, each leaf activates exactly ONE actual native Goal, immediately passes the entire unmodified fresh native create/get response to the relocated existing assertion, and stops if activation or binding fails. No replacement Goal or objective repair. Save the unmodified native activation response as `native-goal-active.json`, complete outputs before completing the same Goal, and save its exact completion response as `native-goal-terminal.json`. Native Goal receipts are distinct from T3 task completion. The assertion checks envelope/identity/status/exact objective; it cannot independently establish authenticity, freshness, or the actual sequence. Offline synthetic envelopes prove shape checks only.

Investigator retains full independent brief-first discovery, alternatives, governing primary source conditions, source map and substantive discovery before its single exact plan reveal. Critic/reviser retain all original obligations and full outputs. Exact A8 is appended only to critic/reviser in the composite. Source identities may not silently rebind; complete carried source trees and inventory are frozen.

Retries retain the original request key, bytes and deadlines. Guarded unused-stage retries verify the exact overlay idempotently; clarification is not reapplied over guarded bytes. Partial transformation, used stages, tampering, changed inputs/source inventory, expired clocks or conflicting returned taskIDs stop rather than repair. Actual returned native dispatch/status responses retain their original provenance. A lost response retries the same native key inside the original clock; never invent a task ID.
