# Brief-only discovery — oral-history intake
Run A-F02-A8 · investigator stage · pre-plan release

## Brief boundary and method

This discovery uses only the released assignment and the exact brief about donated oral-history recordings. The comparison plan remains unreleased and has not been sought, inferred, or read. The proposal must preserve original media bytes, avoid cloud transcription and blanket transcoding, keep permissions conservative, distinguish media readability from preview capability, and handle missing or corrected transcripts independently. The museum has no fixed codec, catalog API, or stated operating system; these remain integration decisions rather than hidden assumptions.

I reviewed current primary documentation and released project material for FFmpeg/ffprobe, GStreamer, Symphonia, BagIt, WCAG 2.2, and the Library of Congress description of DROID/PRONOM. Their URLs, versions, locators, access time, observed operation, conditions/defaults, and applicability are indexed in source-map.json and sources/index.md. All observations below are evidence-based proposal inputs, not execution results. No media, collection, or executable code was tested.

## Feasible implementation families

| Approach | What it can do well | Constraint that affects this intake |
|---|---|---|
| FFmpeg libraries/ffprobe, with a separate playback surface | Broad container/codec demuxing; machine-readable format and stream reports; build/version reporting; explicit stream selection. The current official download page identifies 9.0.2 as latest stable, while explaining that release branches receive selected fixes more slowly than development [S01–S04]. | Support is a property of the shipped build and configuration. Format/codec support does not promise a valid duration or successful preview. The ffprobe manual exposes JSON and separate format/stream sections; it can report an error section and an unsuccessful positive exit when input cannot be opened/recognized [S02]. The formats manual documents a default 5-second analyzeduration and the latency/accuracy trade-off; duration probing is not extended at all costs [S03]. A fresh advisory describes a crafted-MP4 stack exhaustion through 9.0.2, so do not ship that affected build unchanged for donated files [S06]. |
| GStreamer Discoverer plus playback pipeline | One pipeline ecosystem can report duration, tags, stream topology, missing-plugin details, and playback state. Asynchronous discovery is a fit for a responsive desktop review flow [S08–S09]. | Available demuxers, decoders, and renderers depend on installed and packaged plugins. The Discoverer result enum explicitly separates invalid URI, error, timeout, busy, and missing plugins; missing plugins mean only that full discovery lacked some plugins [S08]. Plugin availability and support vary by distribution and packaging [S17]. Keep this local-file workflow offline and pin a patched runtime; the 1.28.8 security advisory is specific to RTP/SDP input, so it is not the same path as local-file ingest, but remains relevant to the framework version [S10]. |
| Symphonia in Rust, with an application-owned preview layer | A Rust-native library with automatic probing, decoding, tag reading, and a modular set of crates; it reduces a large C ABI surface and can support exact channel-aware decode [S11–S13]. | “Supported” does not mean enabled in the selected build. In 0.6.1, AAC-LC, ALAC, ISO/MP4, AIFF, CAF, MP1/2/3 are not default features in the manifest; some listed codecs are marked Good or Great rather than fully compliant [S11–S12]. No video/subtitle decode is needed here. Its release history records silent-MP3, mono-MP1 and malicious-file memory/panic fixes, demonstrating that representative regression/fuzz validation remains necessary [S13]. |
| Signature-based identification (e.g. DROID/PRONOM) paired with one decoder | Batch signature identification can add format-name/version/PUID evidence independent of an extension or playback library [S17]. | Signature identification is a separate capability from metadata extraction, integrity validation, or decoding. A match alone cannot prove the file is healthy or previewable; unmatched/ambiguous signatures need an explicit uncertain/manual state. |

These families can be combined behind a small adapter interface. Keep parser and preview capability profiles explicit per released build. Do not define a permanent “supported audio” list from a product name alone. The accepted codecs and wrappers should be a tested, versioned matrix and should state which formats are identified, probed, and previewed.

## Intake model and review behavior

1. **Preserve first.** Record the received path/name, size, timestamps as observed, and a SHA-256 before parsing. Read originals without metadata writes. For a portable handoff, copy bytes to a staged payload, hash the copy, compare it to the intake hash, then mark the copy complete only after verification. Write to a temporary name and atomically finalize; never truncate or edit the source. The checksum is integrity evidence, not proof of permission or identity. BagIt is a feasible folder packaging convention: payload files are opaque octets, and a valid package requires complete manifests with verified checksums [S14].
2. **Identify separately from decode.** Filename suffix is a hint only. Record signature/format-identification output and the parser’s actual container/demuxer, codec, stream count, sample rate, channel count/layout, bit depth where available, tags, byte size, and duration with source, units, and confidence. Preserve absent/unknown as null with an explanatory reason. File-format identification, parser success, and preview success are separate facts. Parser metadata can be incomplete; never make a guessed duration authoritative. Record the probing tool/version/build and any timeout or probe limit.
3. **Keep channel evidence.** Represent every audio stream and channel index/layout returned by the parser. Provide normal preview and explicit left/right or per-channel audition when meaningful, with channel labels supplied by volunteers kept distinct from technical channel indices. Never infer that channel 1 is interviewer and channel 2 is narrator. Do not persist a downmix or transcode as a condition of acceptance. If a preview path requires temporary decode/resampling, keep it in memory or a disposable cache and preserve the submitted source as the catalog payload.
4. **Use independent, typed states.** Avoid one overloaded “accepted/failed” field. Suggested axes:
   - media intake: "queued", "copied_verified", "identified", "metadata_partial", "unreadable", "needs_review", "accepted", "rejected";
   - preview: "not_attempted", "available", "unsupported_by_this_build", "failed", "timed_out";
   - transcript: "not_provided", "received", "matched", "ambiguous", "revision_received", "accepted", "rejected";
   - permission: "explicitly_granted", "explicitly_restricted", "missing", "conflicting", "needs_human_decision".
   
   “Unreadable media” means a parser/identifier cannot establish usable media facts after bounded probing, with the diagnostic and retry path recorded. “Preview unsupported” means identification/metadata succeeded but this installation lacks a renderer/decoder for audition; show a warning without converting the item into unreadable audio. A missing transcript is a neutral "not_provided" state, never an audio error. GStreamer exposes missing-plugin and parse/timeout distinctions, while its sample tutorial then treats every non-OK result as “cannot be played”; the intake UI must preserve the richer reason instead of copying that binary shortcut [S08–S09].
5. **Associate by supplied recording ID.** Parse the spreadsheet identifier as the primary crosswalk, preserving the raw value and a normalized comparison key. Require a unique exact/approved-normalized match between the row, media, and transcript; collisions or fuzzy-only matches go to a review queue, never auto-bind. Keep file basename as a hint. Store transcript file identity/hash, encoding/format, receipt time, associated recording ID, version/supersedes relation, and revision reason. Retain prior accepted transcript versions; a corrected transcript should not rerun or erase audio intake.
6. **Make restart safe.** Model one batch ID and immutable per-item ID, source hash, and state transitions. Persist a journal/SQLite transaction per item or atomic append-only event, with bounded concurrency and progress reporting. On restart, verify source identity/hash before reusing completed work; resume failed/incomplete items only, and never treat an incomplete copy/probe as success. Do not duplicate a catalog item merely because the operator restarted or received a transcript correction. Keep a stop/resume control and summary counts for the expected ~40 and upper-bound 500 items; capacity and concurrency require local measurement.
7. **Portable handoff without an assumed API.** Produce a self-contained directory package with exact source bytes under stable non-colliding relative names, UTF-8 JSON manifest as the lossless source of facts, a human-readable CSV projection for staff, transcript sidecars with version links, software/build provenance, permission state, parser diagnostics, and BagIt checksum manifests. Catalog adapter maps the stable manifest fields into the eventual API or staff import. Include relative paths, never workstation absolute paths. Re-verify the bag before release; catalog acceptance/transfer status is separate from intake acceptance [S14].
8. **Accessible review.** Keep every action keyboard operable in logical focus order, with visible focus, labelled controls, and no keyboard trap. Pair icons/colors with plain text. Present per-item and batch status as text, including “metadata read; preview unsupported by this installation,” “could not read media,” “no transcript provided,” and “permission missing—hold for staff”; announce async progress/results/errors without stealing focus. W3C’s WCAG 2.2 focus-order guidance and status-message SC support these as validation targets; whether WCAG web-content criteria bind a native desktop toolkit directly is an implementation-specific mapping question, but equivalent keyboard/text outcomes are explicit user requirements [S15–S16].

## Validation candidates and limits

Propose, but do not claim executed: golden fixtures for supported wrappers/codecs, deliberately wrong extensions, malformed/truncated files, unknown signatures, missing decoder, unavailable preview output, mono/stereo and two-channel speaker-separated examples, variable-rate/unknown-duration files, oversized tags, and interrupted reads; compare reported fields and duration against independent reference tools and human inspection. Verify original and staged-copy hashes byte-for-byte before/after each operation. Test duplicate IDs, Unicode/whitespace normalization, absent transcript, corrected transcript versioning, ambiguous spreadsheet joins, conflicting/missing permissions, and batch restart at each durable boundary. Run batch tests at 40 and 500 items, checking bounded memory, progress, cancellation, recovery and no duplicate export. Keyboard-only and screen-reader checks should exercise review, filter, preview/channel controls, warnings, errors, permission holds, and batch completion. Validate a handoff package from a different directory or machine and confirm BagIt manifests. Include adversarial malformed inputs in a qualified sandbox and track parser/runtime security updates.

No executable witness, repository checkout/build, package installation, collection access, test media, or live catalog integration was run. These are proposals for the draft, not completed checks.

## Unresolved choices for owner review

- Identify target operating systems and whether playback requires offline operation at all times.
- Confirm the catalog’s import formats/required fields and whether the museum wants BagIt-compatible packages or only its manifest/checksum subset.
- Define the supplied spreadsheet’s ID and permission vocabularies, and who can resolve conflicting or absent permissions.
- Confirm whether staff must label channels/speakers, which label vocabulary applies, and whether preserving both independent channels is sufficient.
- Agree a versioned codec/container support matrix and packaging/update policy after testing real-world permitted examples. Do not freeze “supported” based only on a library’s generic list.
