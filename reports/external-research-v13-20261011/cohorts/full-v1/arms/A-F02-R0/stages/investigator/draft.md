## Proposal summary

Build a local, non-destructive intake workflow around durable item IDs, source checksums, provenance-bearing probe results, independent transcript/permission links, keyboard and screen-reader review, and a self-contained portable export. Keep custody acceptance, preview availability, and public-use clearance separate. Do not auto-link by normalized filename, silently collapse channels, or rely on references outside the exported package. No single media stack is selected here: qualify the exact FFmpeg build, Symphonia feature set, or GStreamer plugin bundle against the same cleared sample corpus and the target operating systems before selection. DROID/PRONOM is an optional supplemental format identifier rather than an audio reader.

### Existing, rejected and uncertain items

Already covered and retained: batch manifest, original-byte preservation, optional preview, independent permission state, no cloud transcription, keyboard-accessible review, transcript correction history, and planned restart/channel/accessibility checks.

Rejected or materially changed: case/space-normalized stem as an automatic association; any handoff whose only media references point outside the copied package; a vague “unreadable original” status that does not identify which qualified reader failed; silent default track selection, channel mixing or speaker labeling; and any requirement to transcode every recording before it can be cataloged.

Still uncertain pending an owner decision or corpus evidence: donor/catalog identifier schema and duplicate rules; spreadsheet format and columns; accepted/rejected/held custody policy; which permission scopes authorize which downstream actions; transcript file types and timestamp conventions; required metadata fields; supported operating systems and UI toolkit; exact codec/format coverage required for “preview supported”; catalog manifest/API and whether rejected files travel; whether DROID/PRONOM IDs are required; distribution model and FFmpeg licensing/build configuration; and the response-time/memory target for 500 items.

## Evidence-backed approach comparison

**FFmpeg/ffprobe (candidate).** The upstream manual exposes structured container/stream probing, probe errors and version reporting, while FFmpeg can map tracks and split channels. FATE at tag n9.0.2 exercises multiple ffprobe output modes against a generated fixture (S02–S05). It offers the broadest-feeling single local path among these options, but no claim of universal format support is justified: demuxer/decoder availability depends on the actual configured build. Capture version/build configuration, test the distributed artifact, and review exact configuration/dependency licensing before bundling (S01, S02, S19). An external process is operationally straightforward but needs strict argument handling, timeouts, resource bounds and durable error parsing.

**Symphonia 0.6.1 (candidate).** Direct Rust integration may simplify application deployment and expose decoding buffers for per-channel preview. Its documented defaults are narrower than “all formats”; uncommon formats/codecs need explicit Cargo features, and Opus needs an adapter (S06–S07A). The v0.6.1 release records relevant audio fixes and malformed-input hardening (S08). Test the chosen features against the same fixture corpus. Its example demonstrates probing and selecting a default track, but the example’s panic/skip behavior is not an intake policy (S07). It should not be selected solely because the application is Rust.

**GStreamer (candidate where runtime packaging fits).** GstDiscoverer can return stream topology, duration and distinct missing-plugin, invalid-URI, error and timeout results; missing-plugin messages leave installation policy to the app (S10–S11). The installed plugin set governs actual support, so include its inventory/version in provenance and do not install missing plugins automatically. Its plugin ecosystem and asynchronous discovery may help an already-GStreamer deployment; dependency and plugin packaging make it a weaker default assumption for a small standalone app.

**DROID/PRONOM (supplement).** Use when staff need registry identifiers, format-version hints or batch mismatch reports, pinning both DROID and signature files (S12–S13). It only answers identification questions covered by its signatures; it does not establish that a stream decodes, yield duration or tell staff whether preview works. Its incomplete signature coverage rules out making a DROID match the sole acceptance gate.

No product is chosen until a rights-cleared representative corpus, actual donor spreadsheet, operating systems, distribution constraints and catalog import contract are known. Prefer a brief comparative pilot of the FFmpeg and Symphonia candidates; include GStreamer if the target environment already ships its runtime. Compare truthful support outcomes, track/channel handling, restart/error recovery, binary/plugin footprint, licensing and 500-item responsiveness instead of comparing marketing codec lists.

## Proposed staged integration

1. **Inventory and safeguards:** create local batch/item IDs; import the spreadsheet into staging; retain row values/provenance; copy originals without transformation; calculate and recheck hashes. Detect duplicate/ambiguous IDs before any linking. Never alter source bytes.
2. **Identify and probe:** run one pinned local identification/probing backend; optionally run pinned DROID for format IDs; preserve the raw and normalized probe record, tools/build/signature versions and structured error class. Treat absent values honestly.
3. **Human review:** present record plus technical evidence; allow explicit stream/channel listening where available; add manual transcript links and immutable corrections; record acceptance/rejection reason independently from preview and rights status. Unknown permission never becomes a grant.
4. **Portable handoff:** build a staged directory/package with relative references and checksum manifests, validate it, then expose a completed export. Do not connect to or mutate an unspecified catalog. Add an adapter only after the catalog owner defines field mapping, error handling and import semantics.

Checkpoint each item after a complete stage so reruns are idempotent. A local transactional store such as SQLite can record state, but record transaction atomicity does not make a database row and a filesystem copy one atomic transaction. Serialize writes and fault-test the real filesystems (S15–S16). For portable integrity, BagIt’s relative payload checksum manifest is a fit, but separately validate the custom museum metadata and do not present BagIt checksums as a signature/authenticity system (S14).

## Validation plan and execution record

### Proposed checks

- Build a small cleared fixture matrix: renamed extensions; WAV/BWF, FLAC, MP3, AAC/MP4, OGG/Opus, AIFF/CAF as selected and enabled; absent/contradictory duration; malformed/truncated/zero-byte/unreadable; known container with a decoder absent; multiple audio streams; mono, stereo with distinct synthetic signals, and multichannel content. Record identification/probe/preview outcomes and the exact software feature/plugin versions.
- Compare at least two candidate paths on the same inputs; confirm stream/channel choices, duration provenance, output stability and meaningful failure states. Include release-known Symphonia edge cases from S08, and test FFmpeg JSON decoding/build metadata plus selected FATE cases when a reproducible build is available (S05, S08). Do not use protected donor material.
- Provide transcript absent, uniquely linked, ambiguous, unmatched and corrected versions; spreadsheet blank/duplicate/conflicting ID and permission cases. Confirm automatic filename matching is never silently accepted and unknown permission never exports as public permission.
- Verify original SHA-256 before and after copy, probe, preview and restart. Interrupt after each checkpoint, copy, manifest write and final checksum; resume twice; assert no duplicate catalog items/links, silent overwrites, false-complete packages or lost transcript versions. Test changed source bytes as a new version.
- Validate every completed package checksum and its independent JSON/CSV schema. Check that all included media references resolve within the package and that a catalog import can be mapped without reading the original workstation paths. Treat rejected-media export policy as a fixture decision.
- Measure time, memory, cancellation and resume with representative file sizes at 40 and 500 entries and bounded concurrency. Set acceptance thresholds with the museum; no performance claim is made here.
- Complete the workflow by keyboard, including playback/channel selection, review decision, transcript correction, error recovery, resume and export. Test focus order, accessible names, stable textual statuses and concise progress with the platform screen reader. Confirm “unreadable/probe failed,” “preview unsupported,” “preview failed,” “duration unavailable,” and “no transcript” are distinguishable without color or icon cues.
