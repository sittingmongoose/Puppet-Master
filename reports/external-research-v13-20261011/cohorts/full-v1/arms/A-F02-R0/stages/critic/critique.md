## Assessment

The proposal substantially covers the brief and responds clause-by-clause to P1–P8 without choosing a codec stack or catalog API the museum has not specified. Its distinctions among original readability, identification/probe, preview support, transcript presence, rights, and acceptance are especially useful. It preserves the no-cloud, no-permission-inference, no-original-mutation, and no-required-transcoding constraints. I found no material wrong claim in the independently checked consequential evidence and no recommendation to narrow the brief.

One **material incomplete** item remains: the restart proposal does not yet specify the recovery invariant for a partially copied item or handoff. It correctly says a SQLite transaction cannot make a filesystem copy atomic, and it proposes crash testing, but it leaves the interim/reconciliation behavior unspecified. This should remain an explicit design gate for the eventual integration, not be reported as an implemented or already-safe mechanism.

## Brief obligation coverage

- **Format identification / metadata / duration:** compares FFprobe, Symphonia, GStreamer and optional DROID; distinguishes identification from decoding; preserves raw values, source fields, tool versions and duration provenance. No missing duration is normalized to zero.
- **Channels and speakers:** exposes streams and channels, uses explicit selection, leaves unknown layouts as channel numbers, and disallows silent mixing or speaker inference.
- **Transcript association and correction:** avoids automatic stem matching, preserves exact row/source identity, and represents absent, unmatched, ambiguous, linked and corrected versions separately from audio status.
- **Safe restart:** has item checkpoints, hashes, idempotency intent, staged export and proposed injected-stop testing. **Not yet sufficient as a fully described restart protocol**; see MI-01. This is proposed design, not proven behavior.
- **Portable catalog handoff:** includes payloads and relative references in a documented manifest, with a versioned JSON/CSV starting point and no assumed API. It does not mutate a collection or connect to an unspecified catalog.
- **Warnings / absent transcript / accessibility:** explicit non-color text differentiates unreadable/probe failure, unsupported preview, preview failure, unknown duration and absent transcript. Keyboard and platform screen-reader checks are proposed.
- **Scale and constraints:** plans qualification at 40 and 500 items; selects no codec or API in advance; does not alter originals, guess rights, send audio to cloud transcription, or require universal transcoding.
- **Research and comparison:** compares alternatives with build/plugin/features, error handling, packaging, licensing and test-corpus conditions; uses caller code, tests, release/fix history, and a maintainer discussion for duration/reproducibility. It states that no code, media, UI, package, decoder, or workload validation ran.

## Primary evidence and execution boundary

Independent source checks are recorded with stable critic IDs C01–C18 in [source-map.json](source-map.json), navigable by [sources/index.md](sources/index.md). They confirm the consequential source-map claims: ffprobe JSON auto-omits invalid/non-applicable fields; FFmpeg’s default audio selection favors channel count then lower stream index; the tagged filter documentation gives `channelsplit` a stereo input-layout default and errors for absent channels; Symphonia 0.6.1’s Cargo defaults are feature-gated; its sample caller selects a default audio track and contains example-level panic/skip behavior; GStreamer reports distinct invalid-URI/error/timeout/busy/missing-plugin outcomes; BagIt’s manifests cover relative payload files and do not protect against active attack; SQLite allows one simultaneous writer and database transactions do not include package file operations; WCAG 4.1.3 expressly applies to content implemented using markup languages; and the National Archives’ current page states approximately 70% PRONOM signature coverage. C15 records the DROID branch-pin limitation rather than pretending its moving branch is immutable.

The FFmpeg release page currently lists source 9.0.2, while upstream says it supplies source and compiled packages are linked from outside. The proposal appropriately conditions support on the exact shipped build. The FFmpeg legal page also makes licensing depend on enabled components and build/distribution facts; no legal conclusion for an eventual package is established here.
