# Independent discovery — C-P04 export-worker architecture

**Stage:** investigator, run C-R2-P02-treatment. **Basis:** the released brief only; the exact plan had not been released when this discovery was written. **Research access window:** 2026-10-12 02:38:59–02:41:16 UTC. **Executed checks:** primary-source web retrieval and reading only. No converter, downloaded code, synthetic worker, application integration, or stress test was executed. This is a research recommendation, not a runtime selection or production validation.

## Preliminary architecture recommendation

Use a parent-owned job coordinator and a **separately supervised process per export** as the default contract for third-party native converters. Define a versioned, language-neutral protocol and a data-only converter manifest. Keep discovery separate from execution: enumerate approved external manifests without loading code; validate the manifest and the saved preset; then make a short, resource-limited preflight request in an empty job sandbox to confirm the worker's protocol version and capabilities. Reject a missing format, required option, unsupported snapshot contract, output cardinality, or protocol version before passing the document or creating an export job. LSP 3.17 supplies a useful established pattern for capability exchange during `initialize`, token-correlated progress, and request cancellation, but it is an analogy, not an existing converter standard; its own cancellation can be ignored or impossible for a synchronous peer [S01].

The coordinator should create a stable document snapshot with a digest, make the worker's input read-only, and give it access only to that snapshot plus a private, quota-limited output directory. Do not run a third-party converter with ambient home-directory access. Give every job a distinct process group / OS job / sandbox and bounded pipes. A worker can report progress and a structured terminal status, but only the coordinator can declare success: require the worker's declared output manifest, exact expected paths and cardinality, successful reads and any format-specific validation, and completed transfer to the selected destination. Keep generated bytes private until verification; after cancellation, failure, timeout, or resource-limit termination, clean or quarantine staging and never publish it. Exit code zero and process exit are inputs to verification, not proof of artifact integrity.

Use host controls in addition to the process boundary. Linux cgroup v2 offers per-process-tree CPU, memory, PID and block-I/O controls when exposed and delegated. For filesystem confinement, Landlock can add a per-worker ruleset when supported and enabled; apply it before untrusted code starts, check the ABI, close inherited handles that carry broader access, and fail closed or clearly downgrade when unavailable. Windows Job Objects group descendants and apply CPU / committed-memory limits; AppContainer separately scopes file, registry and network access. macOS App Sandbox is an entitlement and file-access boundary; Apple documents XPC as preferred for privilege separation, and child sandbox inheritance does not carry dynamic file access acquired after launch. None of these labels alone is a cross-platform resource policy. A Wasmtime/WASI adapter is a useful optional runtime for compatible converters: filesystem access begins with no preopens and can be granted to specific directories, while linear-memory caps and fuel can be enabled. Its documented defaults include unlimited linear-memory growth and fuel disabled, and a per-linear-memory cap is not a whole-process RSS cap [S02–S10, S19–S20].

Keep UI responsiveness and fairness in the coordinator. Reserve interactive capacity first; admit exports through bounded per-job resource budgets and a queue with aging / weighted fair service, rather than letting each converter schedule itself. Separate the small job's queue wait from execution time, prevent repeated large arrivals from resetting an older job's priority, and make the fairness policy explicit and measurable. Kernel CPU weights distribute CPU among active eligible work but do not implement app-level admission, aging, I/O fairness across all devices, or a finite wait guarantee [S02].

## Contract and lifecycle findings

- **Discovery and versioned capabilities.** Treat a converter ID, executable/package digest or signed build identity, protocol version, supported input/output media types, option schema version, resource requests, and declared output set as separate stable fields. Manifest metadata can be inspected without installing a plugin into the editor. A constrained `hello`/`capabilities` exchange should confirm, not silently expand, manifest claims. Persist the exact converter identity and preset schema/version with the saved preset. An update must keep the old executable available or produce an explicit incompatibility/migration prompt; never reinterpret saved options against new defaults. LibreOffice's command-line example separates output extension, API filter name and filter parameters, illustrating why extension alone is not a stable format contract [S15].
- **Snapshot and filesystem.** Snapshot once before dispatch; use a content digest and an immutable/read-only handle or materialized read-only copy. The host owns the snapshot lifetime. Worker writes go only to a per-job scratch tree; output names are relative, normalized, bounded, and checked against traversal, links, duplicates and undeclared files. On macOS, a child inheriting the App Sandbox gets static entitlements only; for a document selected after launch the parent must pass its data or a bookmark, so a brokered snapshot/handle is safer than assuming path access [S09–S10].
- **Progress, cancellation, errors.** Make lifecycle states explicit (`queued`, `preflight`, `running`, `cancelling`, `verifying`, `transferring`, and terminal success/failure/cancelled/timeout/resource-limit). Correlate progress with a job ID and report phase plus optional bounded estimates; progress is advisory and must not create a success state. Cancellation first sends a cooperative request, then after a bounded grace period terminates that job's entire process group and waits for teardown. On Linux, cgroup v2 `cgroup.kill` can kill the subtree with SIGKILL and handles concurrent forks, when the job has its own non-root domain cgroup [S02]. Make terminal-state races coordinator-serialized and cancellation idempotent. Capture exit code/signal, structured worker error, bounded stderr, verifier/transfer error, and cleanup result. Keep job processes isolated so terminating one cannot terminate another.
- **Declared outputs and destination.** Require a worker result describing every output (relative name, media type, byte count and digest, plus whether an output is optional); compare it against the pre-negotiated output contract, reject missing / extra / duplicate / escaping paths, and open/read each file before transfer. For formats with a safe parser, add a format-specific integrity check. Only publish after validation. Linux `rename` atomically replaces a path on one mounted filesystem; `EXDEV` is returned across mount points, and the manual warns NFS retry ambiguity. Windows `ReplaceFileW` requires all files on the same volume and documents partial-failure cases; its `REPLACEFILE_WRITE_THROUGH` flag is unsupported. Thus stage beside the target when possible; otherwise copy to destination-side staging, verify there, and publish atomically only if the destination adapter offers such a primitive. Remote/cloud targets need an explicit commit/verification contract. Report success only after the requested transfer/commit completes; do not promise universal cross-volume atomicity or crash durability without testing the filesystem/adapter and sync path [S16–S18].

## Alternatives and host guarantees

1. **Native worker process plus OS sandbox (recommended baseline).** Broad converter compatibility, separate address space, killable job and independent process-tree accounting; overhead and per-platform policy work remain. A plain subprocess under the editor's user identity is not a security boundary. Pair a per-job process group with least-privilege credentials, scrubbed environment, no network unless capability-approved, a private input/output view, and host-specific limits.
2. **WASM/WASI runtime sandbox (optional adapter).** Strong, portable capability-shaped filesystem access and deterministic instruction fuel for compatible guests. It constrains wasm linear memories individually, not all host allocations or native components, and documented controls are opt-in. Native converter reuse, GUI/library dependencies, large-format ecosystem and host-call correctness need a compatibility spike. If adopted, also supervise the runtime process and set host limits.
3. **Cooperative in-process interface (trusted-only fallback).** Lowest IPC and memory-copy cost, but a fault can corrupt the editor, a hung callback blocks or complicates cancellation, and the host cannot reclaim a worker's private allocations independently. Reserve for first-party/trusted converters with bounded APIs; do not expose it as the safety promise for third-party converters.

On Linux, cgroup v2 controllers must exist, be enabled top-down and be delegated; `memory.max` defaults to `max`, can invoke the OOM killer, and usage can exceed it temporarily. `cpu.weight` defaults to 100 and affects fair-class/BPF schedulers, while `cpu.max` is a bandwidth cap. `cgroup.kill` exists only on non-root cgroups and is unavailable for threaded cgroups. Landlock first appeared in Linux 5.13, must be built and enabled at boot, and applications should check its ABI because supported filesystem/network rights vary. On Windows, job assignment normally includes `CreateProcess` children, but breakaway or `Win32_Process.Create` changes that; job memory limits count committed virtual memory. Use `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` / `TerminateJobObject` and disable breakaway unless required. AppContainer limits file/registry/network/process access to granted resources. On macOS, App Sandbox controls access entitlements and selected documents; the reviewed Apple material does not establish a per-converter hard memory/CPU quota. Keep process isolation and non-destructive staging everywhere; mark enforceable CPU/memory/IO guarantees conditional on OS version, policy permission and host controls. WASI fuel/memory limits are conditional on the selected runtime/version and guest staying within its WASI surface [S02–S05, S09–S10, S19–S20].

## Converter history and preset risk

Pandoc is a concrete external-filter pattern: a JSON filter is an executable pipe that reads/writes the document AST; Lua filters are embedded and described as faster. Pandoc's manual warns that filters/custom writers can perform arbitrary filesystem actions and that its `--sandbox` applies only to readers/writers and can leave filter/PDF-engine risks. This supports preserving the cheap cooperative option for trusted code while isolating third-party executables [S11]. More importantly for saved presets, Pandoc 3.8.3 records real output behavior regressions introduced in 3.8 and fixes them: SVG-to-PDF with WeasyPrint and Typst smart-quote behavior (issues #11275 and #11256). Its release is tagged 3.8.3 at commit `568dab1`. Treating upgrades as potentially semantic is evidence-based; keep build/schema identity and require explicit migration or revalidation [S12–S14]. The docs.rs API pages observed here identify Wasmtime 49.0.2; these are runtime examples, not a decision to use that release [S06–S07].

## Validation plan (proposed, not executed)

1. **Discovery/preflight:** synthetic manifests/workers for supported and unsupported media/options/schema versions, missing executable, duplicate IDs, malformed handshake, unknown required capability and protocol mismatch. Verify rejection occurs before document bytes or output handles are exposed.
2. **Snapshot/isolation:** mutate the live document during an export; verify a digest-pinned worker reads the original snapshot and cannot modify it. Try sibling-job scratch access, home-directory reads, traversal/symlink output, network by default, and inherited handles; verify denials on each supported host.
3. **Failure/cancellation:** crash before/after writing, exit 0 with missing/truncated/extra output, hang in handshake/run/cleanup, ignore cooperative cancel, fork descendants, flood stderr, exceed CPU/memory/IO/disk quotas, and cancel while another job runs. Check a single job is torn down, the editor and peer job remain usable, and no unverified staging path is published.
4. **Transfer/commit:** permission denied, full destination, disk or network disconnect, same-volume replace, cross-volume copy, existing destination, interrupted transfer and retry. Compare hashes after destination read-back; verify adapter-specific atomicity and crash behavior before claiming them.
5. **Fairness and presets:** reserve an editing heartbeat under saturated converter workloads; enqueue a short job behind repeated large jobs and measure bounded queue wait/aging without starving long jobs. Save an old preset, change converter binary/defaults/schema, then verify the old exact build is used or the user sees a compatibility/migration choice before work.
6. **Matrix:** run the synthetic suite under declared Linux/cgroup, Windows Job+AppContainer, and macOS sandbox configurations; record unavailable controls and downgrade guarantees rather than silently running unsandboxed. No production integration or stress matrix is claimed executed here.
