# C-P03 — Software planning brief

We are planning an import component for a desktop environmental-observation notebook. Field volunteers bring delimited files from several loggers and occasionally edit them in a spreadsheet. Files may be re-imported, partly overlapping, truncated, or revised to correct measurements. Headers, unit labels, date formats, and missing-value conventions can differ. Research a reliable intake design that shows users what will change before committing and keeps enough lineage to explain an imported value later.

The proposal should cover incremental parsing, schema interpretation, duplicate and revision handling, preview, and transactional application to local storage. A malformed late row must not leave a silently partial import. Volunteers need to correct an interpretation, rerun it, and understand whether a previous import will be replaced, supplemented, or left intact. Explore maintained parsing and storage mechanisms, relevant format documentation, callers or tests, and useful failure history without nominating a winning library in advance.

Investigate both detection and explicit user configuration. Compare at least two ways to identify overlapping observations when timestamps or row positions alone are insufficient. Explain handling of ambiguous time zones and changed units without inventing missing values. Responsiveness matters for a file larger than memory, and cancellation must have defined effects.

Do not rewrite the source file, send observations to a service, silently coerce ambiguous values, or discard an earlier accepted observation merely because a newer file has the same name. We need a research-backed plan and validation proposals, not a database deployment. Use synthetic examples if helpful, reporting their actual executed coverage separately from proposed stress, restart, and corruption tests. Leave unknown logger conventions explicit while still researching available parser and transaction behavior.

Complete all substantive research and planning obligations within a maximum of 60 elapsed minutes. Finish earlier when the complete output is ready. There is no minimum research duration, no requirement to consume the allowance, and no credit for waiting. The deadline includes arm-specific setup, provider queueing after admission, tools, native retries, handoffs, revision and delivery. Output quality is assessed independently of elapsed time.
