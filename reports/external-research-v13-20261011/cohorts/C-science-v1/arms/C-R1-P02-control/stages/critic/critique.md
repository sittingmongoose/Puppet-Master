## Obligation and plan coverage

- **Original brief:** The draft addresses separate devices and uncertain clocks without using wall-clock metadata as authority; distinguishes inspection, decoding, and encoding; preserves stream identity and multi-audio selection; proposes exact source-clock boundaries and uncertainty reporting; separates stable transcript annotations from timing evidence; specifies impact previews and revision pin/rebase behavior for excerpts and comments; provides original, proxy-review, and external-original package modes; and proposes synthetic plus licensed public-fixture tests. It explicitly states that no media were uploaded, changed, or processed.
- **Revealed plan paragraph 1:** All clauses receive a clear disposition. Millisecond-only time is rejected as canonical storage; imported timestamps remain evidence; immutable sources and explicit stream selection are retained. The advice about hash identity is appropriately bounded: a digest identifies bytes, not the intended stream or channel.
- **Paragraph 2:** Inventory before optional decode is separated from decode/encode work. Constant offset, affine drift, and piecewise drift are compared with assumptions and costs. Alignment revisions do not silently mutate source anchors; transcript text correction does not become timing evidence; approved-excerpt behavior is exposed as an owner decision with a sensible pinned default.
- **Paragraph 3:** The draft makes the portability boundary explicit. A reference package depends on separately available originals; proxy review is not represented as an original-bearing package; self-contained media are deduplicated by unique source. Digest, path containment, stream/role identity, unavailable media, and explicit relinking are all considered. The storage trade-off is direct.
- **Paragraph 4:** Both alignment model and playback comparisons are present. The draft also covers unsupported streams, transcript revisions, ambiguous timing, and each named validation area: drift, VFR, relinking, excerpt revision, and interrupted preview generation.
- **Repeated deadline clause:** Treating it as a process constraint rather than a product feature is correct. The research claims no minimum runtime and distinguishes future work from actual checks.

## Source and validation assessment

The evidence supports the main operational caveats. FFmpeg documents that input seek commonly lands at a prior seek point; with accurate seek during transcoding the extra segment is decoded and discarded, while stream copy preserves it. FFmpeg also documents wall-clock timestamps as opt-in (default 0) and output timestamp shifting under the auto mode. These conditions support the draft’s warning against promising exact rendered cut points or inferring alignment from wall-clock defaults. The current ffprobe reference supports stream, packet, frame, and stream-specifier inspection; the draft correctly says an inventory is not proof of full decode behavior.

Kdenlive’s 26.08 manual supports referenced source media, stored proxy references, project-version upgrades/backups, and backward-compatibility caveats. Its proxy controls are optional; reduced proxies are used for editing and originals for full-resolution render. ELAN’s manual supports manual synchronization through offsets and anchors, explicit moved-media update, the top file’s master/default-audio behavior, and a separate annotation file. These are useful workflow precedents, not proof that either tool provides the proposed app’s exact VFR clock or portable package semantics.

OTIO’s bundle documentation specifies a flat media directory with unique basenames and relative references; the reader parses the timeline without decoding or unzipping the media. That supports the storage and scope limitations stated in the draft. RFC 8493 treats payload as opaque, provides checksum manifests, and requires readers not to access outside the bag; it does not supply timeline semantics. FATE is an FFmpeg regression suite with selectable tests and sample files, not an end-to-end validation of this app. MLT release notes provide useful issue-to-fix history, but a release fix does not prove all camera variants behave correctly.

The draft’s validation plan is appropriately labeled proposed. It includes deterministic synthetic timing oracles, stream selection, VFR and timestamp edge cases, source immutability, alignment and annotation revision effects, interrupted derivative jobs, package movement, missing/corrupt files, traversal protection, and future real-media fixtures with license and hash records. Checks actually run are limited to the investigator’s documented source research; I independently checked primary documentation during this critique. No fixture generation, sample download, media probe, executable witness, application test, or integration test was run.

## Final assessment

Accept the draft as a sound planning proposal, with the disclosed frozen-discovery issue-number correction kept attached to the record. Keep the MLT “latest” statement time-qualified, and pin the actual releases before implementation. The unresolved first-release choices (constant versus affine drift, excerpt pin/follow default, package default, supported-input matrix, and whether previews are evidence artifacts) are properly identified as owner decisions rather than hidden assumptions.
