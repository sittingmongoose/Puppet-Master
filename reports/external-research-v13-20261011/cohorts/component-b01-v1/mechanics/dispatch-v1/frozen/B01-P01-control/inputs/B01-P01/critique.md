# Source-backed common critique — both arms

C1 CHANGE: Correct the pacing contract in Architecture. S2's loop sleeps only after SQLITE_BUSY or SQLITE_LOCKED, not after every successful batch. `pages` bounds each SQLite step, not elapsed-time completion or GUI yielding by itself. Keep incremental online backup, but remove the fixed rate promise and propose measured responsiveness with a worker/callback strategy. S1's short sleep description must be read with S2's actual governing branch.

C2 CHANGE: Do not promise monotonic progress against an immutable initial page count. S3 `test_modifying_progress` observes remaining counts 1,1,0 with an intervening committed write, and S4 describes restart behavior under concurrent changes. Expose current copied/remaining values as provisional, tolerate resets/changed totals, and distinguish a complete backup from an ETA. Keep the useful callback and cancellation plan: S2 explicitly finishes the handle when the callback raises; test exceptions in the future application, rather than claiming cancellation has been proved end to end.

C3 CHANGE: The DB snapshot does not transactionally freeze attachment files. This is an unsupported cross-system inference, consequential to restore. The brief requires uninterrupted editing and a restorable bundle. Propose immutable content-addressed attachment generations retained until the backup releases them, or a brief attachment publication lock plus retained old versions; validate references against the copied database. Explain residual crash/deletion risks and safe reclamation. Digests alone detect mismatch and do not establish a consistent generation.

C4 KEEP/CONDITION: Retain online backup and worker-owned connections, bounded-memory copying, no overwrite, privacy, staged cleanup and restoring into a new workspace. Retain rejection of copying only an open main file (S5) while preserving stopped-app complete-file-set copying as a conditional alternative. Retain logical SQL export with its reconstruction costs. Do not treat WAL as inherently unusable or source-supported database consistency as invalid simply because attachments require a separate protocol.

Coverage: C1/C2 cover progress, cancellation and concurrency; C3 covers external snapshot and restore; C4 covers alternatives/history, memory, ownership, collisions, privacy and validation. No actual application tests ran. Disposal of every finding must be visible in the complete final; uncertainty about workload-specific throughput is legitimate and cannot be replaced by an invented benchmark.
