# Source-backed common critique — both arms

C1 CHANGE: The claim that standard extraction makes no path modifications is false for the pinned CPython. S2 `_extract_member` strips drives and removes empty, dot and parent components; Windows names pass through `_sanitize_windows_name`. S1 documents those transformations and still warns to inspect untrusted archives. Correct the factual rejection while retaining the application's stricter path policy, resource limits and private staging. A source-backed capability does not by itself prove a complete safe importer.

C2 CHANGE: `zipfile.Path` does not inherit extraction sanitization. S1's Path note explicitly assigns validation to the caller, unlike extract/extractall. Keep it only as an archive navigation API with explicit name checks; do not use its apparent directory structure as an extraction security boundary.

C3 CHANGE: The collision policy is internally inconsistent with the brief's rejection of ambiguous collisions. S2 opens output with `wb`; later writes can overwrite earlier data. A final checksum cannot prove that a silently replaced selection was intended. Build the destination namespace before writing, reject duplicates/collisions for this release or obtain an explicit unambiguous rename mapping, then stream each selected ZipInfo separately. Preserve useful nested folders, selected empty directories and noncolliding names. Include Windows case/name transformations and decoding uncertainty in the preview policy.

C4 KEEP/CONDITION: Keep actual byte quotas, EOF/CRC handling, owned staging cleanup, cancellation, no execution, no overwriting existing projects, explicit unsupported-content diagnostics and the distinction between product encryption policy and Python capability. Retain custom streaming versus inspected standard extraction as real alternatives. S1's resources/interruption/default-behavior sections govern their risks; do not overstate that declared sizes or filename filtering suffice. A private tree reduces substitution risk; no untested cross-platform race/durability guarantee is justified.

Coverage: C1/C2 address governing library exceptions and confinement; C3 covers collisions/selection/platform behavior; C4 covers resources, failures, negative constraints, useful structure, alternatives/history and validation honesty. The common critique inspected sources and upstream test text only; no importer, Windows test or penetration test ran. Resolve all findings with evidence, retaining supported design meaning rather than replacing the proposal with a safety checklist.
