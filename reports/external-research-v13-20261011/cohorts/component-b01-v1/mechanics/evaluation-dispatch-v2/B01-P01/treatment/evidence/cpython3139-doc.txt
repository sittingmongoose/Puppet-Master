25: SQLite is a C library that provides a lightweight disk-based database that
26: doesn't require a separate server process and allows accessing the database
27: using a nonstandard variant of the SQL query language. Some applications can use
28: SQLite for internal data storage.  It's also possible to prototype an
29: application using SQLite and then port the code to a larger database such as
30: PostgreSQL or Oracle.
31: 
32: The :mod:`!sqlite3` module was written by Gerhard Häring.  It provides an SQL interface
33: compliant with the DB-API 2.0 specification described by :pep:`249`, and
34: requires SQLite 3.15.2 or newer.

513: .. data:: threadsafety
514: 
515:    Integer constant required by the DB-API 2.0, stating the level of thread
516:    safety the :mod:`!sqlite3` module supports. This attribute is set based on
517:    the default `threading mode <https://sqlite.org/threadsafe.html>`_ the
518:    underlying SQLite library is compiled with. The SQLite threading modes are:
519: 
520:    1. **Single-thread**: In this mode, all mutexes are disabled and SQLite is
521:       unsafe to use in more than a single thread at once.
522:    2. **Multi-thread**: In this mode, SQLite can be safely used by multiple
523:       threads provided that no single database connection is used
524:       simultaneously in two or more threads.
525:    3. **Serialized**: In serialized mode, SQLite can be safely used by
526:       multiple threads with no restriction.
527: 
528:    The mappings from SQLite threading modes to DB-API 2.0 threadsafety levels
529:    are as follows:
530: 
531:    +------------------+----------------------+----------------------+-------------------------------+
532:    | SQLite threading | :pep:`threadsafety   | `SQLITE_THREADSAFE`_ | DB-API 2.0 meaning            |
533:    | mode             | <0249#threadsafety>` |                      |                               |
534:    +==================+======================+======================+===============================+
535:    | single-thread    | 0                    | 0                    | Threads may not share the     |
536:    |                  |                      |                      | module                        |
537:    +------------------+----------------------+----------------------+-------------------------------+
538:    | multi-thread     | 1                    | 2                    | Threads may share the module, |
539:    |                  |                      |                      | but not connections           |
540:    +------------------+----------------------+----------------------+-------------------------------+
541:    | serialized       | 3                    | 1                    | Threads may share the module, |
542:    |                  |                      |                      | connections and cursors       |
543:    +------------------+----------------------+----------------------+-------------------------------+
544: 
545:    .. _SQLITE_THREADSAFE: https://sqlite.org/compile.html#threadsafe
546: 
547:    .. versionchanged:: 3.11
548:       Set *threadsafety* dynamically instead of hard-coding it to ``1``.

670:    .. method:: commit()
671: 
672:       Commit any pending transaction to the database.
673:       If :attr:`autocommit` is ``True``, or there is no open transaction,
674:       this method does nothing.
675:       If :attr:`!autocommit` is ``False``, a new transaction is implicitly
676:       opened if a pending transaction was committed by this method.
677: 
678:    .. method:: rollback()
679: 
680:       Roll back to the start of any pending transaction.
681:       If :attr:`autocommit` is ``True``, or there is no open transaction,
682:       this method does nothing.
683:       If :attr:`!autocommit` is ``False``, a new transaction is implicitly
684:       opened if a pending transaction was rolled back by this method.
685: 
686:    .. method:: close()
687: 
688:       Close the database connection.
689:       If :attr:`autocommit` is ``False``,
690:       any pending transaction is implicitly rolled back.
691:       If :attr:`!autocommit` is ``True`` or :data:`LEGACY_TRANSACTION_CONTROL`,
692:       no implicit transaction control is executed.
693:       Make sure to :meth:`commit` before closing
694:       to avoid losing pending changes.

2655: Transaction control
2656: ^^^^^^^^^^^^^^^^^^^
2657: 
2658: :mod:`!sqlite3` offers multiple methods of controlling whether,
2659: when and how database transactions are opened and closed.
2660: :ref:`sqlite3-transaction-control-autocommit` is recommended,
2661: while :ref:`sqlite3-transaction-control-isolation-level`
2662: retains the pre-Python 3.12 behaviour.
2663: 
2664: .. _sqlite3-transaction-control-autocommit:
2665: 
2666: Transaction control via the ``autocommit`` attribute
2667: """"""""""""""""""""""""""""""""""""""""""""""""""""
2668: 
2669: The recommended way of controlling transaction behaviour is through
2670: the :attr:`Connection.autocommit` attribute,
2671: which should preferably be set using the *autocommit* parameter
2672: of :func:`connect`.
2673: 
2674: It is suggested to set *autocommit* to ``False``,
2675: which implies :pep:`249`-compliant transaction control.
2676: This means:
2677: 
2678: * :mod:`!sqlite3` ensures that a transaction is always open,
2679:   so :func:`connect`, :meth:`Connection.commit`, and :meth:`Connection.rollback`
2680:   will implicitly open a new transaction
2681:   (immediately after closing the pending one, for the latter two).
2682:   :mod:`!sqlite3` uses ``BEGIN DEFERRED`` statements when opening transactions.
2683: * Transactions should be committed explicitly using :meth:`!commit`.
2684: * Transactions should be rolled back explicitly using :meth:`!rollback`.
2685: * An implicit rollback is performed if the database is
2686:   :meth:`~Connection.close`-ed with pending changes.
2687: 
2688: Set *autocommit* to ``True`` to enable SQLite's `autocommit mode`_.
2689: In this mode, :meth:`Connection.commit` and :meth:`Connection.rollback`
2690: have no effect.
2691: Note that SQLite's autocommit mode is distinct from
2692: the :pep:`249`-compliant :attr:`Connection.autocommit` attribute;
2693: use :attr:`Connection.in_transaction` to query
2694: the low-level SQLite autocommit mode.
2695: 
2696: Set *autocommit* to :data:`LEGACY_TRANSACTION_CONTROL`
2697: to leave transaction control behaviour to the
2698: :attr:`Connection.isolation_level` attribute.
2699: See :ref:`sqlite3-transaction-control-isolation-level` for more information.
2700: 
2701: 
2702: .. _sqlite3-transaction-control-isolation-level:
2703: 
2704: Transaction control via the ``isolation_level`` attribute
2705: """""""""""""""""""""""""""""""""""""""""""""""""""""""""
2706: 
2707: .. note::
2708: 
2709:    The recommended way of controlling transactions is via the
2710:    :attr:`~Connection.autocommit` attribute.
2711:    See :ref:`sqlite3-transaction-control-autocommit`.
2712: 
2713: If :attr:`Connection.autocommit` is set to
2714: :data:`LEGACY_TRANSACTION_CONTROL` (the default),
2715: transaction behaviour is controlled using
2716: the :attr:`Connection.isolation_level` attribute.
2717: Otherwise, :attr:`!isolation_level` has no effect.
2718: 
2719: If the connection attribute :attr:`~Connection.isolation_level`
2720: is not ``None``,
2721: new transactions are implicitly opened before
2722: :meth:`~Cursor.execute` and :meth:`~Cursor.executemany` executes
2723: ``INSERT``, ``UPDATE``, ``DELETE``, or ``REPLACE`` statements;
2724: for other statements, no implicit transaction handling is performed.
2725: Use the :meth:`~Connection.commit` and :meth:`~Connection.rollback` methods
2726: to respectively commit and roll back pending transactions.
2727: You can choose the underlying `SQLite transaction behaviour`_ —
2728: that is, whether and what type of ``BEGIN`` statements :mod:`!sqlite3`
2729: implicitly executes –
2730: via the :attr:`~Connection.isolation_level` attribute.
2731: 
2732: If :attr:`~Connection.isolation_level` is set to ``None``,
2733: no transactions are implicitly opened at all.
2734: This leaves the underlying SQLite library in `autocommit mode`_,
2735: but also allows the user to perform their own transaction handling
2736: using explicit SQL statements.
2737: The underlying SQLite library autocommit mode can be queried using the
2738: :attr:`~Connection.in_transaction` attribute.
2739: 
2740: The :meth:`~Cursor.executescript` method implicitly commits
2741: any pending transaction before execution of the given SQL script,
2742: regardless of the value of :attr:`~Connection.isolation_level`.
2743: 
2744: .. versionchanged:: 3.6
2745:    :mod:`!sqlite3` used to implicitly commit an open transaction before DDL
2746:    statements.  This is no longer the case.
2747: 
2748: .. versionchanged:: 3.12
2749:    The recommended way of controlling transactions is now via the
2750:    :attr:`~Connection.autocommit` attribute.
2751:

2753:    https://www.sqlite.org/lang_transaction.html#implicit_versus_explicit_transactions
2754: 
2755: .. _SQLite transaction behaviour:
