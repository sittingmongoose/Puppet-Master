## Recommendation

Build comment anchoring as a domain component beside the layout merger. Give each shape, connector, group and thread a never-reused application ID and creation generation. Keep original target identity and context immutable in a thread record. Store current attachment/resolution separately, with revision and event provenance. Let a sync engine merge layout operations; let a resolver decide only identity-preserving cases automatically. The engine’s deterministic state is not proof that a reviewer meant to follow a replacement object.

Loro’s Rust movable tree merits the first prototype because its API represents create/move/delete directly, exposes TreeIDs and can enumerate deleted nodes. It could represent groups and hierarchy. Store geometry as entity data with explicit immutable application IDs and use a separate stable collection for connectors/comments; verify exact deletion, node metadata, snapshot and cross-language behavior against a pinned crate. Yrs is attractive for shared text/sequence anchors and Yjs interoperability. Automerge is attractive for Rust local-first per-field merge and inspectable conflicts. None supplies floor-plan comment intent policy. Compare them before selecting one; this is not a library lock.

The following labels distinguish evidence-based correction from decisions that require product ownership:

- **Keep/refine:** the principle fits, with the stated boundary or data needed to make it safe.
- **Reject as automatic behavior:** preserve the idea’s user value, but do not silently infer it.
- **Optional improvement:** useful behavior not required to honor the plan.
- **Owner decision:** policy remains open; preserve enough state so the choice can be made later.

## Merge engines versus referential-intent mechanisms

| Approach | What it can merge/guarantee | What it cannot decide for this component | Main tradeoff / evidence |
|---|---|---|---|
| **Loro movable tree + app data** | Rust API supports create, move, ordered sibling placement and delete with TreeIDs; deleted nodes remain enumerable. A tree CRDT is a direct fit for groups/parent-child structure. | Whether an existing review comment should move to a replacement, split child, or object now hidden by an ancestor delete. Fractional position is not the identity of a shape or a comment. | Strong initial prototype candidate; verify deleted node metadata, tree snapshot import/export, delete/move conflicts, cycles and concurrent ordering at a pinned Rust version. API 1.16.2 reviewed; JS release 1.16.4 includes tree snapshot regression fixes, not evidence of the same Rust defect. [LORO-RUST-TREE-1.16.2; LORO-TREE-DOC-CURRENT; LORO-MOVABLE-TREE-ARTICLE-2024; LORO-RELEASE-JS-1.16.4] |
| **Automerge map/list CRDT** | Offline changes merge through a change graph; concurrent values remain queryable as conflicts; list entries have operation identity. Rust crate is available. | Same-property intent, delete-vs-new-value semantics, and comment reassignment. A deterministic winner is not a human decision; a later write can hide conflict values. | Fine-grained maps keyed by entity ID suit mutable shape fields; retain alternatives explicitly before resolving. Full change history improves historical inspection but costs storage and can reveal deleted content. [AUTOMERGE-RUST-0.12; AUTOMERGE-DATA-CURRENT; AUTOMERGE-CONFLICT-CURRENT; AUTOMERGE-MAP-MERGE-CURRENT; AUTOMERGE-HISTORY-MODEL-CURRENT] |
| **Yrs/Yjs shared types** | Rust/JS-compatible shared Map/Array/Text updates; state-vector synchronization; sticky/relative sequence positions track sequence selections across insertions. | A sequence position does not identify a floor-plan shape. Resolution can fail for a deleted/unavailable type. GC and offset-unit choices affect recoverability and cross-runtime behavior. | Good for text/range subcomponents or Yjs interop; do not use text-position tracking as the domain anchor. Test UTF-8/UTF-16 and delete/undo across replicas. Public history includes a Yrs delete-set/GC regression fixed by PR #614 and a Yjs relative-position/undo bug reported fixed in 13.6.21. [YRS-STICKY-INDEX-0.28; YRS-DOC-OPTIONS-0.28; YRS-DELETE-SET-ISSUE-607; YRS-DELETE-SET-PR-614; YJS-RELATIVE-UNDO-ISSUE-657; PYCRDT-STICKY-UTF16-ISSUE-382] |
| **Revisioned central command sequencer** | One authority can serialize accepted layout commands, reject stale/invalid moves and assign a canonical revision. Rejected commands can remain in a review queue. | An offline edit cannot be accepted immediately; authority ordering still does not infer author intent for an anchored comment. | Easier server audit/cycle checks, weaker disconnected convergence and needs membership, auth, retry and conflict-queue policy. Alternative, not selected or implemented. |
| **Custom event log / snapshot three-way merge** | Stores explicit domain operations and causal bases; custom reducer can represent pending delete/edit branches without exposing a resurrected shape. A snapshot can be read-only and deliberately projected. | No off-the-shelf intent rules; replay order, schema migration, event authorization, merging and redaction all become product code. | Good audit control if requirements justify it, but higher implementation and long-term compaction/privacy cost. A plain snapshot merge is simpler, yet requires manual same-object conflict resolution. |

The component should store at least two independent facts: (1) the merged layout state and all unresolved competing operations, and (2) the immutable comment target plus current attachment outcome. A comment may remain valid even when the layout merger says its target is absent. A shape may be visible even when a thread’s relation to it is unresolved.

## Resolution model and data shape

Conceptual fields; names and serialization are implementation proposals, not a public API commitment:

```text
Thread {
  thread_id, author_id, created_at, created_at_revision,
  original_anchor: {
    kind: shape | connector | object_region | canvas_region,
    target_ids: [{id, generation}],
    local_point_or_region, coordinate_frame_id,
    original_transform, original_geometry_summary, original_label_summary
  },
  replies: [...],
  resolution_events: [
    {status, revision, reason, actor, candidate_target_ids, confirmed_by}
  ]
}
```

The creation target is immutable. `resolution_events` append instead of rewriting the original anchor. A live target with the same ID/generation may follow movement/group transforms automatically. A concurrent position-property conflict may show both positions or a deterministic current position while retaining the alternative branch and presenting a conflict marker. A deleted target remains a tombstone and a thread remains reachable in review navigation. A new ID—even when its image and bounds exactly match—does not inherit a comment automatically. A user-confirmed `replaces` relation may be shown as an offered mapping; it is not sufficient by itself to transfer discussion unless an authorized person confirms.

For a region, keep world/plan-frame geometry and the object IDs selected at creation separately. On split, compare the recorded region against child mappings only to prepare optional candidates; do not commit a mapping automatically. On group changes, compose stored transforms and preserve the leaf ID. On connector changes, keep connector ID separate from endpoint IDs so endpoint breakage does not erase the connector’s thread. If transformations are unavailable or the coordinate frame version changed, preserve the creation snapshot and mark the current placement uncertain instead of recalculating from screen pixels.

## Covered, rejected and uncertain points

**Already covered by the released plan:** persistent shape IDs, ID-based connector endpoints, child IDs surviving grouping, offset transformation during move/resize, operation-log merging while disconnected, keeping last geometry, delayed edits on deleted objects, acknowledgement-based retention, compaction to an anchor summary, export of current geometry/comment text/unresolved state, and the listed synthetic checks. This review preserves each objective while making its conditions explicit.

**Rejected as automatic behavior:** restoring a deleted visible shape when a delayed edit arrives; attaching a comment by nearest coordinates or a region’s rectangle fallback; transferring a thread to a same-looking replacement; hiding/removing the thread because its anchor cannot resolve; treating library convergence, an actor ID, or a screenshot as proof of user intent, authorization, or full review context.

**Uncertain / decisions for product owner:** selected CRDT or central-server hybrid; exact replacement/split workflows and who may confirm them; whether group deletion cascades, detaches children, or leaves hidden descendants; region anchors across plan/frame changes; conflict UI and merge authority; participant/device roster and offline-age fence; tombstone/history retention duration and privacy erasure requirements; permitted author/reply content and identities in an external snapshot. Keep sufficient original evidence until these decisions are made; do not silently choose for the owner.
