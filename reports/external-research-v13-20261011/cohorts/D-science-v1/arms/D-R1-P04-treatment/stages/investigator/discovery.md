# Independent discovery — D-R1-P04-treatment investigator

## Question and scope

The target is a comment-anchor/reconciliation component for offline-first floor plans. Shapes, connectors, groups, regions, comments, layout synchronization, and review-intent resolution are separate concepts. The research below is an independent finding set from the brief; the exact plan has not been read or inferred. The sources index and source IDs are in `sources/index.md` and `source-map.json`.

## Most promising mechanisms and alternatives

**Loro (Rust crate 1.16.2 API reviewed)** deserves first evaluation because it offers a movable-tree CRDT with ordered siblings, persistent TreeIDs, and node-associated maps. The same target ID is moved rather than removed/recreated by ordinary move calls. Its API can enumerate deleted nodes and `contains` includes deleted IDs; deleting a parent makes its descendants disappear from the visible tree without actually deleting them. This is a close structural fit for grouping and durable shape identity, but product code still needs explicit comment references, tombstone/context policy, connector endpoints, and semantics for replacement. Loro’s fractional-index ordering has same-position/interleaving caveats; its maintainer documents edge cases involving delete-vs-move, competing parents, cycles, and deleting an ancestor while a descendant moves. Proposed initial prototype: separate layout geometry from tree parent/order, and keep thread records keyed to immutable application IDs (with Loro TreeID as a library-level correlation), not rendered coordinates. Sources: `LORO-RUST-TREE-1.16.2`, `LORO-TREE-DOC-CURRENT`, `LORO-MOVABLE-TREE-ARTICLE-2024`.

**Yrs (Rust port of Yjs)** is a maintained general-purpose shared-type CRDT with StateVector-based incremental synchronization and a Rust API. Its `StickyIndex` follows a reference inside sequence-like shared types, and Yjs `RelativePosition` specifically supports comment ranges in collaborative text. These mechanisms can anchor sequence/range selections, but they do not encode shape identity or geometry and can return no usable position when an underlying type/reference is deleted or unavailable. Yrs defaults to byte offsets and attempts commit-time GC (`skip_gc=false`); mixed-language consumers must agree on offsets and GC policy. Sources: `YRS-STICKY-INDEX-0.28`, `YRS-DOC-OPTIONS-0.28`, `YJS-RELATIVE-POSITION-CURRENT`, `YJS-GC-INTERNALS-MAIN`.

**Automerge (Rust crate 0.12.0)** is an offline-capable data-structure CRDT with a change graph and per-field conflicts; a map of immutable app-ID-keyed entity records plus a separate ID order list is a candidate schema. Concurrent same-field updates converge to a deterministic displayed value while `getConflicts` exposes other values; assignment later can hide the conflict. A map delete concurrent with a new value can yield the new value, so no engine default should be mistaken for a product-level delete-wins or comment-intent rule. Its docs say complete operation history is retained; this has audit value and storage/privacy cost, and can expose deleted content to later collaborators. Sources: `AUTOMERGE-RUST-0.12`, `AUTOMERGE-DATA-CURRENT`, `AUTOMERGE-CONFLICT-CURRENT`, `AUTOMERGE-MAP-MERGE-CURRENT`, `AUTOMERGE-HISTORY-MODEL-CURRENT`.

A **centralized revision/command sequencer** is a competing approach: validate or serialize structural operations on a server, retain rejected operations and revisions for review, and define explicit policy for offline commands. It simplifies authority and audit, but reconnecting peers still need to see conflicting intent and it weakens fully offline convergence. A **custom append-only event log with deterministic replay** gives rich causal audit and app-specific merge rules, but requires more implementation, compaction, version migrations, and a privacy/retention plan. A plain snapshot three-way merge is simpler but pushes same-shape semantic conflicts to a person. These are architectural alternatives, not implemented or benchmarked here.

## Component model to carry into plan review

- Give every shape, connector, group and thread an immutable application UUID plus a creation/generation ID. Geometry, layer order and parent/group are mutable fields. A move/group/ungroup changes placement; it must not mint a new entity ID. A replacement that merely looks the same is a new ID with an optional explicit `replaces` relation, never an identity match by visual similarity.
- A thread keeps the original target kind and ID(s), creation revision/frontier, creator/time, local-frame selection or region geometry, and a minimal original context snapshot (labels/geometry/endpoint IDs) for explanation and export. Keep current resolution in a separate append-only field/event: `attached`, `moved-with-target`, `deleted`, `partially-missing`, `unresolved`, or a user-confirmed reattachment. Never overwrite the original anchor with a guessed destination.
- Safe automatic handling is limited to a known still-live stable ID: transform the current display location with the current object/group transform, keep the thread accessible if hidden/collapsed, and show old/current context. A tombstoned target remains available in the review list. Missing/replaced targets, a region spanning changed/deleted objects, competing edits to the same field, and a connector with a missing endpoint require explicit resolution or remain unresolved. Coordinate similarity may rank a suggestion for a user but cannot reattach automatically.
- Store explicit product deletion intent separately from CRDT-internal tombstones/GC. A user-approved restore is a visible command with provenance; an old disconnected update must not silently clear it. Keep tombstones until known replicas have crossed a checkpoint/retirement fence, or force an explicit rebase/document-generation change before pruning them. Comment threads survive layout deletion and export whether their targets resolve or not.
- Layout merge and comment-intent reconciliation are separate passes. First exchange/apply idempotent updates and identify all conflicting values/moves/deletes. Then resolve only well-defined identity-preserving changes automatically; preserve the competing branches and causal evidence for author/owner choice otherwise. Stable IDs plus revision/frontier and operation IDs explain why a thread moved or became unresolved.
- For a read-only outside snapshot, render a deliberately projected/exportable bundle: snapshot revision, read-only layout, thread text/author representation per permission policy, original target context and current-resolution reason including unresolved anchors. Do not send a raw CRDT history if it contains unrelated/private/deleted data. History, tombstones and original-context snapshots grow storage and may retain sensitive geometry/comments; retention and export redaction are product decisions.

## Useful public history and actual callers/tests found

- Yjs issue #657 reproduces a relative-position conversion error under deletion/undo (Yjs 13.6.18); maintainer says fixed in 13.6.21. This makes undo/redo plus cross-replica anchor resolution a required synthetic case (`YJS-RELATIVE-UNDO-ISSUE-657`).
- Yrs issue #607 reproduces a nested Map/Array delete-set divergence after GC in yrs 0.25.0. PR #614 merged the fix at commit `48b1a7b` and adds Rust Map and XML regression tests. I inspected the reproducer and test diff but did not run either (`YRS-DELETE-SET-ISSUE-607`, `YRS-DELETE-SET-PR-614`).
- The open pycrdt issue #382 reports UTF-16 `StickyIndex` offset conversion trouble for non-BMP text, while Array indices are unaffected. This is a binding-specific condition, not evidence that native Rust Yrs has the same bug (`PYCRDT-STICKY-UTF16-ISSUE-382`).
- The Loro 1.16.4 JavaScript release changelog records tree snapshot export/import fixes after move/delete. It is a cross-language regression signal, not proof that Rust 1.16.2 has the same failure (`LORO-RELEASE-JS-1.16.4`). Yrs repository lists maintained downstream callers/bindings and distinct FFI/WASM test directories (`YCRDT-REPO-CALLERS-MAIN`).
