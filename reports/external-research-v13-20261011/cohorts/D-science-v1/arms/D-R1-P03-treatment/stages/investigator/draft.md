# D-P03 backup and restore — investigator proposal

## Recommendation

Keep the plan's manifest, temporary restore directory, preview, record identifiers, and whole-package passphrase option. Correct the implied consistency guarantee and filename-based attachment merge before implementation. The first deliverable should be a self-contained whole-workspace export using an app-owned versioned manifest and an engine-aware snapshot adapter, plus a read-only preview and isolated staged restore. Publish an archive as complete/current only after the expected inventory, bytes, and snapshot semantics all verify. Apply only after semantic validation and explicit confirmation; preserve the live workspace and a rollback copy. Make archive format, persistence-engine adapter, and encryption implementation owner decisions informed by compatibility/prototype evidence.

A verified container is level 1 evidence; successful extraction is level 2; schema/reference/media validation is level 3; opening and using the staged workspace is level 4. User-facing status must name the level achieved and must not translate any lower level into “restored and usable.”

## Complete brief-scope treatment

1. **Portable archive of records, attachments, and preferences:** use one versioned manifest and generation identity; preserve stable IDs, content bytes, and explicit relationships. Candidate packaging: conservative ZIP/ZIP64 or tar plus separately selected compression. Both need path, duplicate-name, large-file, encoding, symlink, and interruption tests; neither supplies application snapshot semantics. Archive/engine/encryption selection remains an owner decision.
2. **Interrupted backup, removable storage, newer app schema:** build privately and publish only after completeness checks; prior verified archive remains current after failure. Target-volume temp and sync behavior must be measured on removable filesystems. Preview stops on unknown newer schema pending an explicit migration decision.
3. **Included/excluded inventory and member damage:** record positive inventory and explicit exclusions/reasons; missing expected members fail completeness. Report archive parse/CRC, manifest digest, authenticated decrypt, semantic workspace, and app-use results as separate states. Partial results cannot masquerade as complete protection.
4. **Empty restore and deliberate merge:** empty restore uses isolated build/migrate/validate then guarded promotion. Merge is simulated against a candidate and requires per-conflict choice. Preserve live workspace and rollback through verification; direct overwrite is not the default.
5. **Identity and referential integrity:** records and attachments have stable identities distinct from names. Store bytes by safe generated ID/content hash; names are metadata. Validate references; missing attachments remain visible, and duplicate names with different bytes never overwrite. For SQLite, use integrity_check and foreign_key_check separately plus app checks (S03).
6. **Migration and atomicity:** version archive independently from app schema. Apply known migrations sequentially to staging; validate before merge. Unknown/newer versions fail closed. SQLite user_version is app-controlled, while engine checks have separate scope/defaults; choose actual engine and migration registry before implementation (S03). A DB transaction alone is not atomic across separate media and preferences files.
7. **Passphrase protection:** whole-package encryption can protect names and payloads. Offer an explicit warning and optionally a generated phrase. A forgotten passphrase is unrecoverable in a passphrase-only design unless a separately designed/approved recovery credential exists. Do not imply account reset, upload, escrow, or recovery. Correct decryption still does not prove workspace usability.
8. **Whole versus incremental:** favor self-contained full snapshots for v1. Revisit incremental/content-addressed storage only if measured time/space needs justify parent/retention complexity. If adopted, record parent IDs and refuse complete status when a dependency is missing or unverified.
9. **Explicit prohibitions and terminology:** never delete the live workspace before candidate verification; never silently overwrite a same-named attachment; never upload archives; never promise recovery after passphrase loss. Use “archive verified,” “extracted,” “workspace validated,” and “opened/usable” only for the respective gates.

## Owner decisions and unresolved applicability

Recommended defaults are full self-contained backups, staged restoration, generated stable IDs, no symlink restoration, and preview-required merge. Decisions still needed before implementation:

- Which record database/storage engine and application snapshot/quiescence API exist? Are preferences in the same transaction domain? Can attachment files change during capture?
- Which container and supported portability matrix (OS, removable filesystems, legacy tools, max size/ZIP64, Unicode and metadata rules)?
- Which crypto format/library and whether protection is optional or default? Is public envelope version leakage acceptable? Is there a separately held recovery key, and who owns it? No recovery scheme is assumed.
- What counts as merge update versus conflict, can an imported duplicate receive a new ID, and how are all references rewritten? Which migrations are supported and for how long?
- What platform crash/durability level and app-level checks define “usable” after promotion?

Archive output format, encryption layer, all-SQLite guidance, and filesystem rename semantics are conditional on these choices. The WAL-reset notice and Rust ZIP advisory are applicability evidence; they do not establish which dependency the product will use.

## Validation plan — proposed; none of these checks executed

| Area | Proposed witness and acceptance boundary |
|---|---|
| Capture consistency | Concurrently update a record, preference, and attachment during snapshot. Accept one coherent generation, or detect/retry/fail; no mixed generation becomes current. If SQLite/WAL is selected, compare native online snapshot to a controlled known source and test bounded BUSY/LOCKED and fatal I/O paths. |
| Completeness/publication | Inject cancellation, process termination, disk full, read denial, and removable-device disconnect during source read, container write, finalization, verification, sync, and rename. Existing verified destination survives; temp/partial state is not current. |
| Inventory/integrity | Remove, add, reorder, truncate, or alter a member and separately alter its manifest digest; test header/CRC failure, SHA-256 mismatch, missing expected attachment, exclusion reasons, duplicate entries, and a well-formed but semantically invalid workspace. Verify which gate fails. |
| Extraction safety | Archives with absolute/parent/drive/UNC paths, earlier symlink then traversal file, hardlinks/special files, duplicate normalized names, case-only and Unicode-normalized collisions, oversized counts/member sizes, and long UTF-8 names must be rejected or safely represented without writes outside stage. If Rust zip is used, include the S05 sequence as a regression and qualify to a fixed supported release. |
| Identity/references/preview | Same filename/different bytes; same ID/equal or different content; duplicate title/different ID; missing attachment target; dangling relationship; import-as-new and reference remap. Preview enumerates exact effects and leaves live files unchanged. |
| Schema/migration | Every supported archive schema migrates in order on a cloned fixture; migration failure/termination leaves source and live workspace unchanged; unknown newer schema blocks apply. Validate DB structure and FK separately plus app invariants. |
| Restore/apply atomicity | Test empty restore and merge choices; fail each step across DB/preferences/attachments; terminate before/during/after commit and restart. Recovery selects one known-good workspace or offers rollback, never silent partial state. Confirm old workspace remains recoverable until candidate passes app open/read/use checks. |
| Encryption/diagnosis | Round-trip supported passphrase/generated phrase; wrong passphrase, bit flip, truncation, deleted final auth chunk, altered public envelope version, unsupported inner archive, and member mismatch. Verify honest diagnostic boundaries, no secret leakage to logs, and explicit no-recovery warning for lost passphrase. |
| Usability | Open candidate with supported app build, read representative records/preferences, resolve known attachment references, and exercise a safe workflow. This is a future application test, not established by archive parsing or SQLite checks. |
