# Independent discovery — D-P05 software planning brief

## Scope and state
This discovery is based only on the released brief. The exact plan has not been opened or inferred. No platform has been selected. The implementation choice depends on the private-data boundary, source platform, permission-change latency requirement, editorial version model, and owner-approved retention rules.

## Preliminary recommendation
Model retrieval, authority, and citation identity as separate concerns. Rank candidate passages for relevance; obtain current policy status and permission from their authoritative owners; never derive either from rank. Start with lexical retrieval over title, headings, exact identifiers, and body text. Use a hybrid lexical-plus-vector candidate path only if a representative judgment set shows meaningful recall improvement without unacceptable precision, latency, or cost. OpenSearch, Elasticsearch, PostgreSQL full-text search, and Typesense illustrate distinct maintained choices, not a product selection. OpenSearch and Elastic document their hybrid pipelines and filters; PostgreSQL offers a local lexical baseline; Typesense demonstrates scoped search parameters through generated keys. Azure AI Search demonstrates query-time permission filtering, but the reviewed push ACL path is marked preview and requires re-ingestion when ACLs change. These features do not combine into a full citation/version/authorization solution by themselves.

A citation should bind to a source-system document ID plus an authoritative immutable edition ID (and a canonical-content digest where suitable), then identify the selected passage with a stable authored block ID when available and a normalized quote selector plus prefix/suffix and position fallback. Record the section label/path, locator scheme and extractor version. Opening a citation first resolves and authorizes the exact cited edition; separately show whether a newer edition exists. Quote matching is a locator, not proof that an edition is identical. Web Annotation explicitly cautions that duplicate text can match multiple spans and that position offsets are brittle. Stable heading/fragment paths are useful when authored but can move. Fuzzy/semantic re-anchoring can suggest a current passage only as an explicitly different candidate; do not silently redirect a historical citation.

Permission metadata can trim candidates before retrieval, but the critical invariant is that no unauthorized title, snippet, cached text, or passage is returned after revocation. Check current authorization before disclosing metadata or fetching content; fail closed if identity, policy resolution, or freshness is uncertain. Invalidate per-user and per-document caches on permission changes, with bounded TTL as a secondary limit, and avoid cache keys that omit identity and policy/version generation. Store only opaque hit IDs until authorization succeeds. The preview Azure API's documented behavior is instructive: it appends permission filters, returns no protected results without a query token, and errors rather than returning partial results when ACL resolution fails; its indexed ACL values still remain stale until re-ingestion/update. A search hit removal cannot retract a quote or exported copy already pasted elsewhere.

During updates, maintain source revision, indexed revision, index generation, ACL generation/check time, and an explicit freshness state. A visible old-edition hit must be conspicuously marked as historical/stale and never presented as current policy; it should be suppressed if authorization against the current permission source cannot be confirmed. A safer initial behavior is to suppress results while authorization/index state is stale, show an indexing state, and offer an authorized route to the source's current document. For whole-index rebuilds, a versioned index plus atomic alias swap is one maintained pattern; for document-level updates, publish a new immutable edition and its index record before atomically switching the current pointer. Retain old editions only under an owner-approved retention policy and preserve their authorization checks. On removal, show an unavailable/withdrawn tombstone only if even that metadata is permitted; do not resurrect or silently substitute a nearby passage. If the exact edition is retained and the caller remains authorized, offer it with its original date/status. Decide whether deletion, supersession, legal hold, and access removal are distinct states with the policy owner.

## Search and evidence leads
- [S01–S02] PostgreSQL 18 full-text types and GIN: normalized lexemes and indexed text provide a useful local lexical baseline; GIN update work is deferred into a pending list, which can make searches slower until cleanup. Plan and measure update freshness/latency rather than assuming index updates are instantaneous.
- [S03–S04] Elastic hybrid and OpenSearch hybrid docs: hybrid retrieval combines lexical and vector branches; RRF is a candidate rank-fusion method. OpenSearch requires a search pipeline and exposes pre- versus post-filter semantics. Rank-fusion behavior is version-sensitive; post-filtering must not be used as an authorization control.
- [S05–S06] OpenSearch DLS and issue history: DLS is read filtering, not write protection; role combinations, exact keyword mappings, and query shape matter. Hybrid bug #1490 on multi-shard dfs_query_then_fetch was handled by merged validation that rejects the unsupported search type, not by making that combination work. The Aug 2026 resolver HLD remains an open design proposal and lists pipeline/composability/latency caveats.
- [S07] Typesense 28.0: scoped search keys can enforce embedded filters and parent-key revocation invalidates descendants. This depends on server-side key creation, correct per-document ACL metadata, protected key handling, and a current permission-update path; a scoped filter alone is not authoritative identity or version management.
- [S08–S09] Azure AI Search ACLs: query-time filtering can fail closed, but freshness is bounded by sync/re-ingest; preview APIs are not a production recommendation. Preview history matters: earlier 2025 preview versions could return all documents with only service credentials; the documented behavior changed in Nov 2025 to require a user token for protected content.
- [S10] W3C Web Annotation: combines a source and edition/time state with a specific passage selector. Quote selectors can themselves leak copied text; position selectors preserve less text but are brittle.
- [S11] Microsoft Graph driveItemVersion: illustrates an exact version-addressed fetch. Its download URL is unauthenticated, short-lived, and may remain usable after permission removal, so it is not a safe durable citation URL.
- [S12–S13] Elastic DLS and atomic aliases: search filters have role-combination caveats and may expose aggregate information; versioned indexes can be atomically swapped without downtime. Neither mechanism replaces source-authoritative ACL freshness.
- [S14] OpenSearch relevance workbench: hybrid parameters require query sets and judged results; there is no one-size-fits-all ranking. A synthetic corpus can smoke-test mechanics, not represent organizational relevance.
- [S15] Git object addressing: commit:path identifies an edition-specific blob for versioned repositories; a line number alone is not durable. Applicability is limited to content actually stored and retained in a repository.
- [S16] No executable product checks were run in this discovery. Future checks should include synthetic repeated quotes/headings, moved/removed passages, two editions, stale ACLs, revoked access, cache reuse across users, index rebuild interruption, and failing policy resolution. Real-corpus relevance, authorization integration, private-data handling, retention, and policy authority remain proposed owner validations, not completed checks.
