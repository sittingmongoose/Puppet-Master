# Brief-only discovery — investigator

Run: B12-P01-treatment. Stage: investigator. Research basis: the exact released brief only. The tentative plan has not been read. Source review completed 2026-10-12; the source identities and locators below are frozen in source-map.json and sources/index.md.

## Obligations traced from the brief

The component must represent packages holding short audio/video clips, multiple subtitle/transcript tracks and descriptive metadata. It must preserve track language, timing, overlaps, clip associations and meaningful text formatting on supported round trips, and report unsupported content rather than silently discard it. Import must handle missing files, duplicate names, malformed text, large attachments and unsafe paths. The research must address internal representation, compatibility policy, practical interchange alternatives, timelines/tracks, package path/resource boundaries, preview/diagnostics, selective import, cancellation with recoverable partial work, export inclusion/loss explanations and retention of originals. It must stay local, avoid paid cloud conversion, avoid replacing the playback engine, avoid automatic network fetches, and make no universal format-support claim. The proposal must distinguish research/checks already run from future validation.

## Discovery findings and candidate approaches

1. Separate package identity, logical media/lesson structure, track and cue identity, and physical resource names. Give clips, tracks and resources stable IDs; a filename is a display/path attribute, not a key. Model a clip-to-resource relationship explicitly, then tracks with language tag, user-facing label, role/type, stable order, source lineage and cues. Keep language tag and original language label separately (BCP 47: SRC-RFC5646). Preserve unknown metadata/extension fields with source format/version and raw source bytes or a source-preserving representation. This makes round-trip fidelity measurable and allows unsupported features to remain recoverable instead of being silently normalized away.

2. Represent time with an exact rational or integer-tick value plus an explicit per-clip timebase/offset. Retain each source timestamp expression and frame/tick parameters alongside normalized time so conversion is reversible and drift can be detected. Preserve cue sequence and permit intersecting cue intervals across and within tracks. WebVTT requires nondecreasing cue starts and end-after-start, but does not require non-overlap; its examples include simultaneous cues (SRC-WEBVTT-2026-CRD). TTML profiles/time expressions can introduce frame-rate, tick and media-time distinctions (SRC-TTML2-REC-2018; SRC-TTML2-CR-2020). Do not infer cue overlap is corrupt. Distinguish valid temporal overlap from rendering collisions and report actual clipping/repositioning separately.

3. Treat meaning and visual formatting as structured content, not flattened plain text. Preserve cue markup/spans, speaker/language annotations, explicit line breaks and supported position/alignment settings. WebVTT explicitly forbids Unicode normalization during processing, permits richer voice/language spans and cue settings, and has user-agent-specific styling limits; its three-line regions can clip a cue when exceeded (SRC-WEBVTT-2026-CRD). Thus a normalized view can use rendered text, but export must retain original text/markup and disclose unsupported style loss. TTML2 supports broader profile-based timed text and styling but profiles/time models raise implementation complexity and require profile-specific tests. SRT is a useful familiar plain-text fallback, not a lossless interchange for multiple tracks or all formatting: FFmpeg's released SubRip muxer accepts a single subtitle stream (SRC-FFMPEG-SRT-N9.0.2; SRC-FFMPEG-SRT-HISTORY).

4. Plausible alternatives occupy different layers. WebVTT is a strong simple per-track timed-text sidecar, not a full multi-clip package. TTML2 is richer interchange when target tools share a profile. Matroska can hold multiple media/subtitle tracks in one clip and records language, default/forced and other flags, but its default flag is only a player-selection hint; a single container is not a whole lesson/package model (SRC-MATROSKA-ELEMENTS; SRC-MATROSKA-NOTES). ELAN EAF is a useful unfamiliar language-learning model: tiers can be independent, time-alignable, subdivided, symbolic, and parent-related; media descriptors link out and annotation data remains in the EAF (SRC-ELAN-EAF3; SRC-ELAN-MANUAL-MEDIA; SRC-ELAN-MANUAL-TIERS). Praat TextGrid supplies multiple interval and point tiers useful for phonetic/word alignment, but is an annotation file rather than an asset package and its text formats have encoding/version edge cases (SRC-PRAAT-TEXTGRID; SRC-PRAAT-TEXTGRID-FORMAT). EPUB 3.3 provides a mature ZIP package/manifest model and SMIL media overlays synchronizing narrated audio with structured text, but it is book-oriented and larger in scope than clip lessons (SRC-EPUB33-REC-2026).

5. If the later plan proposes a custom local package, a ZIP envelope with a versioned manifest and resource table is a practical candidate, not an assumed choice. Keep paths relative to the package root and use stable resource IDs; reject ambiguous manifest JSON duplicate keys because RFC 8259 says member names should be unique for interoperable behavior (SRC-RFC8259). Inspect the central directory and manifest before extraction. The CPython 3.14.8 documentation exposes duplicate ZIP member names as a real case, warns that path convenience APIs differ in sanitization, and says untrusted archives require prior inspection (SRC-PY-ZIPFILE-3.14.8). Do not rely on filename sanitization alone. Reject absolute, parent-traversing, drive/UNC, NUL/control and ambiguous separator names; detect case-fold/Unicode-normalization collisions for the destination platform; reject symlinks and unsupported entry types. Resolve every selected output under a private staging root without following links. Apply explicit entry-count, per-resource and aggregate expanded-size, compression-ratio, path-depth/name-length and parse-work limits. Show source and expanded sizes and why an item exceeds limits. These proposed limits need owner-approved values based on supported platforms and real teacher packages.

6. Use a preflight/selection/transaction flow. Preflight should identify package version, assets, clips, track languages/roles, supported features, missing references, duplicate exact names and destination collisions, invalid text/encoding, unsupported compression/types, media probe summaries and size estimates. Preview should present a clip/track tree, local media availability, a timeline that exposes overlaps, readable text/style, and diagnostic severity with exact source location (resource, entry, track, cue/line/column) and next action. Never turn a parse failure into silent replacement characters: strict-decode supported encodings, keep original bytes and report offset/encoding decisions; RFC 3629 defines validity, and WebVTT prohibits normalization (SRC-RFC3629; SRC-WEBVTT-2026-CRD). For malformed but recoverable records, isolate/skip only the failing record when safe and offer original retention; otherwise block that selection.

7. Import only selected clip/track/resource dependencies. Stage selected bytes with content hashes and a durable transaction journal; cancellation must leave an explicit resumable/discardable import session, not a half-committed lesson. Resume must verify source identity/hash and recheck quotas and paths; commit selected records atomically only after final dependency validation. Missing resources may be unselected or diagnosed while unrelated selected clips proceed. Export preview must enumerate selected clips/tracks/metadata/attachments and planned transformations, report included/omitted/modified/unknown features by ID, and require an explicit lossy choice where conversion drops meaning. Keep original package and source track representation immutable and available until user-initiated cleanup.

8. A local preview can avoid a playback rewrite: reuse the existing local playback service if one is available, otherwise make transcript/timeline/metadata preview useful without playback and keep media preview behind an adapter. Do not fetch remote-linked files. The EPUB and EAF models include linked/external resources; the app should surface those references as unresolved links and never fetch them automatically (SRC-EPUB33-REC-2026; SRC-ELAN-EAF3). A preview should have a clear unsupported/needs-location state, never make a remote fetch seem like a failed local import.

## Current-source implementation observations

FFmpeg n9.0.2 WebVTT demuxer converts cue starts/durations to integer milliseconds, ignores STYLE and REGION chunks in its main loop, and stores cue identifiers/settings as packet side data; malformed cue timestamps break parsing rather than yielding an import report (SRC-FFMPEG-WEBVTT-N9.0.2). This is useful implementation evidence that an adapter's effective preservation depends on the exact code path, beyond what the format permits. The 2025 FFmpeg developer-list discussion reflects disagreement about strict rejection versus permissive parsing; it is a review/history signal, not a settled compatibility rule (SRC-FFMPEG-WEBVTT-HISTORY). FFmpeg's CLI auto-selects one stream of each type in many output situations and may choose the first subtitle stream; explicit maps are needed for user-selected export. Metadata/disposition defaults are conditional and can change when filter graphs or mappings are used (SRC-FFMPEG-CLI-DOCS). A generic conversion command is therefore not itself a compatibility policy.

## Decisions still needing product-owner input

- Supported platforms, per-file and per-package size limits, temporary disk budget, and whether imports may resume after app restart.
- Whether selection granularity includes individual cues/resources or is at clip/track level; whether one invalid selected item blocks its clip or only that item.
- Required authoring tools and target players, and which formats are launch commitments versus experimental adapters.
- Whether preserving original binaries means retaining whole packages, individual source files, or both; retention and deletion UX.
- Whether a local playback service exists and what media/codecs it already supports; this discovery does not inspect the application or assume a playback engine.
- Default export inclusion rules and how metadata, roles, translations, speaker labels and style fallbacks should map to each target format.
