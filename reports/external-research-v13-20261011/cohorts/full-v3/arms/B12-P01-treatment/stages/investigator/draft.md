# Investigator proposal — multilingual media-package import and export

Run: B12-P01-treatment. This proposal evaluates only the released plan at revealed-plan.md against the full assigned brief. It is a component design, not implementation evidence. Source IDs resolve through source-map.json and sources/index.md.

## Recommendation

Keep a versioned, local ZIP bundle as a first-party exchange envelope, but replace filename conventions and eager extraction with an explicit manifest, stable resource IDs, bounded preflight and a resumable staged transaction. Make the normalized model richer than plain text plus floating-point cue times. It must represent clips, tracks, language, time bases, overlapping cues, text spans, source provenance and opaque unsupported data while retaining the original package/source files for any transformation that cannot be reversed.

For a bounded first implementation, propose full read/write support for this application bundle plus a declared WebVTT subset and an explicitly lossy SubRip/SRT fallback. Export one sidecar per selected track where the target format is one-track-per-file. Keep TTML, Matroska, ELAN EAF, Praat TextGrid and EPUB as evaluated adapters with different value and cost; do not promise them for launch until teacher-tool and player demand, exact profiles and local dependencies are confirmed. There is no reliable universal round trip across these models. The compatibility contract must say which format version/profile and feature subset is handled, what is preserved opaquely, and what a conversion changes.

The stage has no evidence about target applications, distribution platforms, existing playback service, or realistic package-size distribution. Therefore numeric caps, supported-profile commitments, media codecs and retention policy are owner decisions. In particular, this proposal does not assume a specific player rewrite or remote service.

## Proposed internal representation and versioned package

### Data model

- Package: stable package ID, schema version, title/description/creator metadata, source provenance, declared capability profile and ordered lists of clips, tracks and resources.
- Clip: stable clip ID, display name, resource ID, declared media type, optional measured duration and stream details, clip-relative origin/offset, source timebase and source provenance.
- Track: stable track ID, clip ID, language tag and original tag/label, semantic role (subtitle, transcript, translation, caption, description or unknown), title/speaker, default/forced/accessibility flags when known, display order, source format/version/profile and preserved unknown fields.
- Cue: stable or source-derived ID, source sequence, exact begin/end representation, canonical rational time, original time expression/timebase, structured text nodes, explicit breaks, speaker/language spans, supported style/position fields and source locator. Preserve overlapping cues.
- Resource: stable resource ID, safe package-relative path, original filename, media type evidence, compressed/uncompressed length, content digest, required/optional relationship and provenance. Resource identity is independent from filename.

A native package may use manifest.json, media/<resource-id>.<ext>, tracks/<track-id>.<format>, and originals/<source-id>.<ext>. The exact extension/layout is a schema decision; no consumer should infer semantic identity from folder/base/filename. The manifest should reference every required resource and declare unknown feature/version policy. Parse JSON with duplicate-key detection. On unknown package schema major version, do not import under a guessed interpretation; preview and retain the package intact.

### Compatibility contract

| Level | Promise | Example |
|---|---|---|
| Native bundle exact source retention | Original files remain byte-identical when copied; IDs, associations, times and supported features remain semantically identical | Preserve source VTT/SRT/EAF and original media while editing in native model |
| Supported profile round trip | Listed model features survive semantic import/export under a named version/profile | VTT cues/times, text spans and supported cue settings; explicitly state unsupported STYLE/CSS subset |
| Lossy conversion | Export proceeds only after explicit review; report per-feature change and keep the source | VTT/TTML/ELAN to simple SRT sidecar |
| Unsupported content | No silent interpretation; retain as opaque original, diagnose, skip or block selected object based on dependency/safety | Unknown codec, unknown manifest major version, malformed track |

“Supported” must be feature-level and versioned, not a file-extension check. For untrusted malformed text, strict decode supported encodings and report encoding choice/byte offset; preserve original bytes. WebVTT processing must not normalize Unicode (SRC-WEBVTT-2026-CRD), and invalid UTF-8 is not validly repaired by replacing bytes without notice (SRC-RFC3629). For legacy encodings, offer a named encoding override and retain its provenance.

### Interchange alternatives

- WebVTT: recommended first timed-text adapter for web-style sidecars. Good cue timing, overlap examples, line breaks, voice/language spans and some cue position/style. One file has one data kind, it is not a multi-clip package, and rendering/style support varies; the latest published W3C text inspected is a 2026 Candidate Recommendation Draft, not a Recommendation (SRC-WEBVTT-2026-CRD). Bind support to the chosen stable/tested subset and exact targeted player/browser versions.
- SubRip/SRT: practical simple text sidecar when broad legacy tooling is the goal. It cannot carry this package model, and the FFmpeg implementation accepts one subtitle stream, so write a per-track file with a companion manifest. Treat encoding, cue ordering, overlaps and formatting as tool-compatibility questions, not a universal standard guarantee (SRC-FFMPEG-SRT-N9.0.2; SRC-FFMPEG-SRT-HISTORY).
- TTML2: consider when a teacher/export partner names a profile. The 2018 Recommendation and later second-edition Candidate Recommendation differ in status; time expressions and profiles depend on parameters. Richer style/time support comes at parser, renderer and interoperability cost (SRC-TTML2-REC-2018; SRC-TTML2-CR-2020).
- Matroska: useful optional container when the goal is one clip with several audio/subtitle streams, flags and attachments. Track language/default/forced flags are useful metadata, but player default selection is a hint and the container does not replace a multi-clip lesson manifest. If using FFmpeg, pin the release and explicitly map selected streams because default stream and metadata behavior is conditional (SRC-MATROSKA-ELEMENTS; SRC-MATROSKA-NOTES; SRC-FFMPEG-CLI-DOCS).
- ELAN EAF: valuable for interlinear/transcription workflows that need tiers, parent relationships, symbolic association/subdivision and multiple linked media descriptors. Importing to flat subtitle tracks cannot represent all tier semantics; preserve source and show a limitation unless native model gains these relationships (SRC-ELAN-EAF3; SRC-ELAN-MANUAL-TIERS).
- Praat TextGrid: valuable for phonetic and word-boundary annotation with interval and point tiers, but a separate annotation file rather than media package, with text encoding and format invariants to handle (SRC-PRAAT-TEXTGRID; SRC-PRAAT-TEXTGRID-FORMAT).
- EPUB 3.3: useful precedent for ZIP resource manifests and synchronized narration overlays, but publication packaging and reading-system rules exceed a clip lesson’s needs. Do not fetch its remote resources automatically (SRC-EPUB33-REC-2026).

A distribution adapter such as FFmpeg can be a local implementation dependency, never a policy oracle. Its n9.0.2 WebVTT reader skips STYLE/REGION/NOTE blocks and converts time to millisecond ticks; errors can terminate its read loop without the diagnostics this component needs (SRC-FFMPEG-WEBVTT-N9.0.2). The 2025 developer discussion shows the compatibility tradeoff between rejecting nonconformant input and accepting common malformed input but is not a resolved policy or merged-fix guarantee (SRC-FFMPEG-WEBVTT-HISTORY). Define parser strictness, recoverable cases and diagnostics independently.

## Import, preview, cancel and export behavior

1. Choose a package locally. Record source path, byte size and a package fingerprint. Do not resolve or fetch embedded URIs.
2. Scan the ZIP directory. Reject unsupported encryption, unsupported entry type, invalid directory structure, duplicate critical manifest entries and configured quota excess. Keep duplicate members addressable by entry identity, not name (SRC-PY-ZIPFILE-3.14.8). Check JSON duplicate keys (SRC-RFC8259), manifest version, unique IDs and referential integrity.
3. Parse manifest and small text resources under limits. For media, inspect bounded headers/metadata and store a quarantined content reference; do not trust extensions. Never execute packaged scripts. Do not exhaustively decode every large attachment before the user chooses it.
4. Build a preview with resource rows showing original name/path, duplicate/collision status, role/type evidence, compressed and expanded sizes, language/clip/track association, local/missing status, supported/opaque features and dependency links. Show malformed input locations (archive entry, track, cue, line/column/byte offset) and explain whether a safe partial import is available.
5. Let the user select clips, tracks and optional resources. Required associations cannot silently disappear; allow a missing-file placeholder if the lesson should be retained without the asset. Explain which unselected items are excluded and what source package is retained.
6. Create a recovery session with package fingerprint, user choices, journal, staged resource IDs and hashes. Stream into unique safe destinations while enforcing actual expanded-byte quotas, CRC/integrity, cancellation and disk-space checks. Never write outside the staging root. On cancel, pause/retain session and offer Resume or Discard. On resume, revalidate source fingerprint, staged checksums, path rules and all limits.
7. Revalidate model references and selected dependencies immediately before commit. Commit one consistent lesson record and resource set; existing lesson state must remain unchanged on failure. Mark committed only after file and database states are recoverable. Store a recovery report for crash/disk interruption; never expose staging records as completed lessons.
8. Export first to a temporary sibling output, validate manifest and files, compute a loss report, and atomically publish after acceptance. Name every included clip/track/resource, every omission/unsupported feature and each conversion (language mapping, style flattening, timestamp rounding, cue sort, overlap handling, subtitle sidecar count). Never overwrite originals. If destination replacement is requested, use an explicit backup/replace policy.
9. Display diagnostic states: blocking (unsafe/corrupt/unsupported selected dependency), actionable warning (missing link, malformed but isolated cue, likely target incompatibility), information (unselected attachment or unsupported but preserved feature). Exact severity rules must be stable and documented. Preview text must be rendered inert; support keyboard navigation and accessible association between warning and item.

## Failure handling and diagnostics

- Missing manifest/resource: identify the referring ID and any dependent track/clip; allow unrelated selected work when the dependency graph proves it independent.
- Duplicate member path: show all entry indexes and metadata; do not allow “last one wins.” Let the user omit/choose one only if no manifest ambiguity remains; otherwise preserve source and block that selection.
- Destination collision: retain original display names but write by stable generated resource ID; if a target cannot represent two names distinctly, stop export or request an explicit rename.
- Invalid UTF-8 or unknown encoding: identify byte offset; offer documented legacy encodings when known; never silently replace/normalize content.
- Bad cue timing: preserve raw source and identify the offending cue. Valid overlap is retained; zero/negative duration or impossible timestamps follow the adapter’s stated policy.
- Oversized item: report actual/compressed bytes, ratio, and which limit was reached. Allow omission if optional; do not bypass safety limits through per-file selection.
- Unsafe path/link/special file: never import the entry. Show a safe path diagnosis; permit retaining the original archive as an opaque original only under bounded source-retention limits.
- Cancellation/error/crash: journal which components were read/staged/validated, session identity, last safe point and resume/discard choices. Existing lessons remain unchanged.

## Owner decisions and assumptions to resolve

1. Platforms and filesystems; maximum package and per-resource compressed/uncompressed sizes, file count, path depth/length, parser work and staging disk space.
2. Required importing/exporting authoring tools and player/browser matrix. Decide whether WebVTT and SRT form an initial compatibility commitment; identify exact test versions. Prioritize ELAN, Praat, TTML and Matroska only from user workflow evidence.
3. Whether whole source packages and individual original track files are both retained; location, storage cap, backup, deletion and privacy behavior.
4. Whether resume must survive process restart or OS reboot, how long import sessions remain, and whether user can keep a recoverable session after app upgrade.
5. Existing playback service, local metadata-probe library, parser libraries and license/platform distribution limits. These determine safe preview reuse; no playback-engine rewrite is proposed.
6. Export inclusion defaults, language/role mapping, marker for original/default/forced tracks, and choice when a target lacks fields.
7. How a malformed cue inside an otherwise readable track affects selection; whether user may keep a missing media placeholder; conflict resolution when duplicate manifest paths/IDs make identity ambiguous.
8. Privacy requirements for source paths/metadata and whether original packages can contain untrusted or regulated content.

## Proposed future validation (not run)

- Schema contract: unique package/clip/track/resource/cue IDs; duplicate JSON key rejection; valid references, unknown-field retention, major/minor version behavior, non-UTF8 manifest rejection, and deterministic package writing.
- Round-trip corpus: authored representative WebVTT (overlap, RTL, language tags, speaker spans, line breaks, regions, styles), SRT from each named teacher tool, TTML profile samples if adopted, and malformed/legacy files. Compare semantic times, timebase, order, language, style spans, clip associations, metadata and attachment bytes. Verify original-byte preservation separately from normalized semantic equality.
- Archive adversarial corpus: absolute/parent/drive/UNC/backslash paths; duplicate names; case-fold and Unicode normalization collisions; symlink/special entries; encrypted/unsupported methods; corrupt central directory/CRC; ZIP64; high-ratio and declared-size mismatch archives; too many/deep/long names; missing resources. Prove no writes escape staging root and every configured quota applies to actual stream bytes.
- Timing tests: overlapping same-track and cross-track cues, adjacent/equal start boundaries, source timebase changes, frame and tick expressions, offsets, millisecond export rounding and overflow. Confirm no overlap is silently deleted/reordered and UI warnings match actual target clipping.
- Parser robustness: fuzz bounded text parsers and malformed encodings; ensure diagnostics contain stable source coordinates and parser work limits terminate safely. Check all unsupported fields survive opaque retention and are listed in export reports.
- Transaction/recovery: cancel before scan, after preflight, mid-copy, after validation and during commit; process kill/restart; changed source file; disk full; duplicate resume; discard; successful resume. Assert no half-visible lesson, no orphaned committed resource, existing lesson hashes unchanged on failure and exactly-once commit.
- Export behavior: preview and emitted manifest/files must agree; inspect every included/omitted/rounded/reformatted item; verify existing source originals remain byte-identical; test one SRT sidecar per track and explicit stream mapping for any FFmpeg adapter.
- Network and preview: use a test network monitor/deny rule to prove no remote requests; hostile markup must render inert; missing linked media produces a stable unresolved state; keyboard/screen-reader traversal associates diagnostics with each resource.
- Resource/performance tests: large valid media near each proposed threshold, slow removable/network filesystems if supported, cancellation responsiveness, peak memory and staging cleanup/recovery.
  
These are future proposals only. No code, parser, package sample, media file or UI was executed in this stage.
