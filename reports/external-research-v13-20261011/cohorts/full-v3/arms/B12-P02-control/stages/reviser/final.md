# Final proposal: cancelable local document-preview jobs

**Run / stage:** B12-P02-control / reviser  
**Scope:** the complete brief and one-shot released plan, identified by its recorded SHA-256 in source-map.json.  
**Status:** proposed component contract; no application, renderer, benchmark, or platform sandbox was implemented or exercised.

## Recommendation

Build an app-owned asynchronous scheduler and worker supervisor. Keep file reads, parsing, rasterization, cache I/O, and child-process waits off the UI thread. Treat every preview as derived data whose validity is checked at cache publication and again at the final display boundary.

Separate caller identity from shared work identity. Each caller gets a RequestId with its own cancellation right, view generation, priority, and event stream. Equivalent requests may share an internal RenderId only when document identity/revision, preview variant/options, handler/version, and cache key match. Canceling one subscriber detaches only that subscriber. Shared work continues while another valid subscriber or explicit import-preview interest remains. Promote shared work when any subscriber becomes visible. Remove queued shared work when no valid interest remains; request cancellation for active work under the worker policy. This avoids both cancelling another caller’s needed result and consuming a slot for work with no remaining interest.

Use bounded queues for current-visible work, near-visible prefetch, and background import previews. Prefer visible work while guaranteeing background service. Weighted scheduling such as three foreground dispatches per background dispatch, oldest-background aging, and one background slot when at least two slots exist are candidate policies, not measured service levels. With one slot, dispatch background work after each bounded foreground burst. A single app-owned dispatcher must choose classes before a semaphore caps active renderers. Two workers may be a starting cap for measurement, not a universal limit. Bound queued descriptors, active processes, input/decoded bytes, page and pixel dimensions, output bytes, progress buffering, per-job CPU/wall time, scratch space, and cache size. Queue handles and keys, not whole documents. If the preview queue is full, shed regenerable preview requests without deleting durable import records.

Run expensive or unreliable format handlers in app-owned, unprivileged worker processes when the selected platform can supervise them. Process isolation aids crash and hang recovery; a child process alone does not sandbox a hostile parser. Use one request per worker where freshness and failure containment justify the start-up cost. Reuse a small pool only after measuring start-up, memory, and reset behavior. Apply a bounded deadline and a no-progress watchdog for handlers that emit heartbeats. Cancellation first sends a job-scoped message and allows a measured bounded grace period. The supervisor then terminates the worker tree, awaits/reaps it, discards partial output, and releases accounting exactly once. Shutdown closes admission, removes queued work, requests cancellation, and force-stops/reaps remaining workers by a deadline. It never waits indefinitely for the active slots.

A platform that cannot demonstrate the required worker termination or sandbox policy cannot claim that guarantee. Disable the affected handler, or have the owner approve a clearly reduced policy. The design requires no GPU, upload, elevation, or newly installed machine-wide service.

## Identity and integration contract

A request contains stable library/item identity, an immutable source revision or digest, a read-only file capability, page/region and preview options, priority, view generation, and a deadline/resource profile. A result echoes the render key and source revision.

- **RequestId / subscription:** one caller’s interest, cancellation right, priority, view generation, and event stream.
- **RenderId:** internal execution shared by equivalent requests.
- **View generation:** monotonically increases on selection, close/reopen, or relevant option changes.
- **Cache key:** document identity and content revision, page/region and pixel size, renderer/handler ID and version, render/color options, and cache schema.
- **Request limits:** page/pixel dimensions, input/output bytes, CPU/memory/time profile, and permitted read-only capability.

Suggested surface: submit(request) returns RequestId; cancel(RequestId); cancel_obsolete(view_id, generation); subscribe(RequestId); shutdown(deadline) returns a report. The renderer never mutates the view model or commits cache entries.

On selection change, advance the generation and clear the prior document’s current-preview slot or display a neutral placeholder. A result is current only if complete, within limits, revision-matched, uncancelled, and still matches the selected item, options, and generation at the final UI handoff. A valid non-current result may populate cache; it cannot appear as the current document. The UI drops stale progress as well as stale images.

The supervisor owns exactly one terminal transition: accepted, queued, starting, running, cancel-requested, succeeded, cancelled, failed, timed-out, or shutdown-aborted. Every RequestId has one terminal outcome despite completion/cancel races. Events carry RequestId, applicable RenderId, revision, generation, state, optional completed/total units, stage, and UI-safe error category. Coalesce/throttle intermediate events and preserve terminal events.

## Cancellation, recovery, and retry policy

Queued cancellation removes the entry and reservation immediately. Running cancellation is cooperative first; a token or message does not prove work stopped. After grace, terminate the worker tree with the platform backend, wait/reap, reject partial output, and release its slot. Child exit, malformed protocol, output-limit breach, deadline, or watchdog expiry fails that attempt. Restart a reusable worker with bounded backoff so later requests can run.

Replace the plan’s two-retry allowance with this **provisional policy**, which is not sourced or measured:

1. Permit at most one fresh-worker retry for process-start failure before request acceptance or unexpected worker loss before valid output. Both attempts share the original deadline and cumulative CPU, memory, input, and output budgets.
2. Do not retry the same request after cancellation, source change, unsupported format, deterministic parse error, malformed protocol, invalid output, resource-limit breach, or no-progress timeout. A timeout kills/reaps the worker and fails that request; a later request may use a restarted worker.
3. After a second worker-loss event for the same document revision and handler version, suppress automatic execution of that tuple for the remainder of the app session. Other documents remain eligible.
4. Candidate handler circuit: key by handler ID/version, platform, and sandbox profile. Open after three crash/hang outcomes within ten minutes across at least two distinct document revisions. While open, return a typed unavailable result. Permit one half-open request after a 60-second cooldown; success closes the circuit, failure reopens it. After three failed probes, keep it open until handler-version change or explicit owner reset.

All retry and circuit values are policy hypotheses. Validate them with deterministic crash/hang fixtures and obtain owner review. They do not extend the job deadline or permit a timed-out render to succeed.

## Platform containment and native adapters

- **Linux.** Landlock can restrict filesystem actions without root when enabled and used with no_new_privs; supported rights vary by runtime ABI. Documented TCP bind/connect restrictions require ABI 4; UDP bind/connect-send restrictions require ABI 10. A no-network claim needs an ABI-10 policy that handles all four rights with no allow rules, an allowlist of inherited descriptors, and no inherited network sockets. Files opened before restriction remain accessible; a deliberately passed selected-document handle is an explicit capability exception. Landlock’s documented rights are not a general firewall. If the complete policy cannot be established, fail closed or select another qualified backend; an ABI probe alone is insufficient. [SRC-07](sources/README.md#src-07)
- **Windows.** Job Objects can terminate associated processes and enforce some process limits. Children created through CreateProcess join by default, subject to WMI and configured breakaway exceptions. Nested jobs begin with Windows 8 / Server 2012. Verify the actual launcher and outer-job policy. AppContainer or another deliberately configured filesystem/network sandbox is separate from Job Object supervision. [SRC-06](sources/README.md#src-06) [SRC-08](sources/README.md#src-08)
- **macOS.** Apple’s XPC overview describes bundled services managed by launchd, with crash restart and per-client lifecycle. Current XPCSession cancellation discards unsent messages and invalidates its connection. The low-level xpc_connection_cancel documentation explicitly says cancellation is asynchronous and non-preemptive; it does not interrupt an executing event-handler block. These APIs do not establish bounded termination of a stuck request. Keep XPC as a candidate only with a packaged one-request worker lifecycle whose process can be forcibly ended, awaited, and replaced on each supported macOS release. Until demonstrated, a handler requiring hard cancellation or hostile-parser confinement is unavailable there. Signing, sandbox policy, and selected-file handoff also need package review. [CRIT-SRC-01](sources/README.md#crit-src-01) [REV-SRC-01](sources/README.md#rev-src-01) [REV-SRC-02](sources/README.md#rev-src-02) [SRC-09](sources/README.md#src-09)
- **Native preview APIs.** Quick Look and Windows Shell may be optional adapters for supported formats. Quick Look offers asynchronous representations and cancellation. Windows documents Shell handlers out of process by default, with registry opt-out and Shell-managed caching. Probe actual handlers, cancellation, cache, and version behavior on supported OS releases. Keep app identity and display gates in control. [SRC-10](sources/README.md#src-10) [SRC-11](sources/README.md#src-11)
- **Linux thumbnail service.** The cited freedesktop standard defines a per-user XDG cache and metadata convention. It does not define a generic generation service or API. Remove “Linux user thumbnail service” as an established alternative. A named implementation/protocol can be considered after its identity, lifecycle, and security are sourced. The standard’s URI and whole-second mtime, with size as an optional check, cannot be the strong content revision key. [SRC-13](sources/README.md#src-13)

## Cache, persistence, and progress

Use an app-private derived cache unless an owner chooses interoperable platform cache behavior. Prefer an immutable imported copy or content digest. For linked mutable files, filesystem notifications are hints; revalidate source revision before publication and display. If the product cannot cheaply provide a trustworthy revision, the owner chooses digest/snapshot cost or a documented weaker metadata policy. Path and mtime, even with size, can collide. [SRC-13](sources/README.md#src-13)

Commit only complete output that matches the request, decodes within byte/dimension limits, and still matches the source revision. Write to a private temporary artifact on the cache filesystem, validate it, then publish. Same-filesystem rename is a useful atomic-publication pattern. Coordinate cache metadata and artifact recovery; do not overwrite a valid same-revision preview before validating replacement. Clean orphan temporaries at startup. SQLite’s cited atomic-commit explanation covers rollback-journal mode. WAL needs separate review and testing on the selected filesystem. A crash during file/metadata coordination must leave a valid reusable artifact or rebuildable cache miss. [SRC-12](sources/README.md#src-12) [SRC-13](sources/README.md#src-13)

Renderer queue state, process identity, priority, view generation, progress, and partial files are volatile. Do not resume old render requests after restart. On startup, clean orphan temporaries, validate complete cache entries, and request previews only for current views/import flow. The reference manager’s durable import record remains authoritative. Whether an accepted import resumes exactly after restart is an owner decision.

Progress is an event stream, not display authority. Report queued, starting, opening, parsing, rendering, encoding, completed, and typed terminal states. Page counts supply completed/total units only when meaningful; unknown totals remain indeterminate, with no invented percentage or time estimate. Include RequestId and view generation, throttle/coalesce intermediate events, preserve terminal events, and reject stale events at the UI boundary. Watchdog heartbeats remain separate from user-facing progress.

## Open owner decisions

1. Minimum supported Windows/macOS/Linux versions, packaging/signing, and permitted process/sandbox backend per version.
2. Supported formats, bundled handler versions/licenses, custom or OS-installed handler policy, and unsupported-format presentation.
3. Immutable app-owned documents versus mutable linked files; digest/snapshot costs and revision policy.
4. Whether accepted imports resume exactly after restart or remain durable and reissue preview requests. Preview jobs stay ephemeral.
5. Visible latency, memory/CPU/disk/output limits, queue bound, cache budget, cancel grace, overall deadline, shutdown bound, and background-service target.
6. Required hostile-parser isolation on each OS. If the policy or force-stop cannot be established, decide whether to disable the handler or approve a reduced guarantee.
7. Whether Quick Look/Shell providers are acceptable and how effective handler identity/version is captured; whether their caches are used.
8. Whether a generic icon may show during refresh and whether a same-document/revision low-quality preview may remain. A prior document image must never be represented as current.
9. Cache privacy/interoperability, SQLite journal mode/filesystem, and owner approval of proposed fairness/retry/circuit/deadline values.

## Validation plan (proposed, not run)

1. Exercise state transitions and prove one terminal result despite cancel/complete/shutdown races. Test queued removal, coalescing, promotion, one subscriber canceling while another remains, and cancellation after all interest disappears.
2. Reorder completions during rapid selection, edit, reopen, close, and option changes. Assert no mismatched item/revision/generation is displayed or committed as current.
3. Under sustained foreground arrival, prove bounded background service at two slots and one slot. Measure visible latency and import completion across concurrency settings; tune weights, aging, and reservations.
4. Use fake handlers for large, malformed, encrypted, truncated, unsupported, huge-dimension, and changed linked documents. Enforce input, output, pixel, memory, scratch, CPU, and time bounds.
5. Inject start failure, crash before/after output, hang before/after heartbeat, malformed IPC, descendant escape, full disk, shutdown, and termination failure. Verify retry eligibility, shared budgets, circuit transitions, complete reap, worker replacement, and orphan cleanup.
6. On Windows, test CreateProcess association, WMI path if used, breakaway, outer jobs, and nesting on every supported OS.
7. On Linux, test ABI discovery and each required filesystem/TCP/UDP right, sockets/descriptors, missing ABI, selected read-only input capability, and fail-closed behavior.
8. On macOS, test the signed packaged helper topology with a permanently hung handler: bounded termination, wait/reap, restart, shutdown, file handoff, and sandbox-denied access. Disable a handler if required guarantees fail.
9. Kill the app during temporary-file write, rename, and metadata commit on the selected filesystem and journal mode. Test WAL separately if selected.
10. Verify progress ordering, unknown totals, throttling, terminal-event retention, stale-event rejection, and heartbeat separation. Confirm no document/preview upload and no elevation.

These are future validations. No implementation or renderer was built, deployed, or benchmarked. No downloaded code or test suite was executed.
