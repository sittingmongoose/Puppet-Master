# Independent critic review — portable project archive export

**Run/stage:** B03-P02-control / critic  
**Reviewed:** the full brief, investigator discovery and draft, source map and index, exact released plan and reveal record. The reviewed plan SHA-256 and byte count match its reveal record: e5275189d516b10c2c700e04fae2df35e229bb7afd3fc3b364d22778f6e461dc / 2,354 bytes. No target application repository was supplied.  
**Purpose:** critique of the investigator package, not an endorsed product design or implementation.

## Overall assessment

The investigator identifies the central flaw correctly: a revision marker and one pass over task records cannot promise one coherent view of tasks, comments, relations, custom-field definitions and attachment references during concurrent changes. The package also handles the brief's explicit non-mutation, inaccessible-link, omission, local-reading, fidelity and future-importer boundaries well. The original brief's research-and-validation obligations are substantially covered, and the package keeps proposed checks separate from work actually done.

The package needs revision before it can serve as an unqualified final proposal. Three recommendations exceed what the evidence establishes: making NDJSON the required record layout, preferring content-addressed attachment paths, and asserting constant memory without a measurable bound on per-entry metadata. The draft also carries forward the investigator stage's earlier absolute deadline as if it applied to this critic stage. The archive-format decision, redacted reference allowlist, missing-byte status and target storage snapshot API remain honestly unresolved product or engineering inputs.

## Independent source checks and limitations

I independently reopened the governing primary references and pinned GitLab code/test files recorded in my source map. The core source claims are accurately qualified:

- SQLite documentation distinguishes WAL snapshot isolation from the current rollback-mode default; the Online Backup API describes a snapshot from backup commencement and possible restart/cost when source writes occur. The source map correctly limits these claims to SQLite.
- PostgreSQL 18 Repeatable Read is a stable snapshot under that DB's transaction semantics, not a portable claim about the unspecified tracker.
- RFC 8259 supports UTF-8 and the warning about unique JSON object member names; it does not define NDJSON. RFC 3339 distinguishes -00:00 from Z/+00:00, and the source notes its RFC 9557 update.
- ZIP APPNOTE supports streamed file data using descriptors and records the central directory/end structures at the archive end. This supports container-aware completion and also means per-entry metadata grows with entry count; it does not prove a particular reader matrix.
- The pinned GitLab 19.2 schema is an explicit project-specific relation/attribute allowlist. TreeSaver passes the current user and closes its writer; the serializer batches relations at 100 and catches/logs/skips a relation-batch error. That is a useful caution, not a behavior to copy into an unqualified complete archive.
- The service and task caller demonstrate authorization, orchestration, path checks, component savers, error handling and cleanup. The tests are evidence of intended assertions only and were not run here.
- The OWASP page supports traversal, symlink and expanded-size risks when archives are extracted. It does not establish that exporter output must use content-addressed paths.
- GNU tar's exact page returned a browser retrieval error during this review. The GitLab issue link redirected to a page shell without the issue body, and the MR page returned a browser retrieval error. I rely on the investigator's clearly caveated carried source-map descriptions for those three items only; none is required for the central conclusions. The living GitLab docs and two first-party history posts were opened; their release/product contexts remain nonbinding examples.
