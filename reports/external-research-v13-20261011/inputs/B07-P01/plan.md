# Draft plan: Supplier spreadsheet reconciliation

The draft separates parsing, review and commit. A saved mapping profile identifies headers, supplier identity and expected number conventions. Parsed rows retain their source line and original field text. The preview classifies proposed inserts, updates, duplicates and errors before a transaction applies approved changes. Staff notes are never mapped by default, and formula-like text is treated as data rather than executed.

Identity currently combines supplier identifier with product code. Discontinued items remain in the catalog, but the proposal assumes a matching code still refers to that item unless staff explicitly select a replacement. Quantities are interpreted as absolute stock values; whether suppliers actually send deltas is an open business question. A file hash prevents a second commit of identical bytes, though equivalent resaved files and interrupted retries need further treatment.

The parser chooses locale settings from the saved profile and flags values that do not match. The draft has not established which apparently valid values remain ambiguous or how duplicate rows should be resolved. Commit is all-or-nothing for approved rows, with rejected rows exported in a local review report. At eighty thousand rows, preview memory and transaction duration need investigation. Proposed validation covers reused identifiers, header drift, locale ambiguity, duplicate rows, canceled previews and interrupted commits. No supplier file has been processed. A recommendation should preserve original values and make replacement/delta decisions explicit rather than hiding them inside parsing.
