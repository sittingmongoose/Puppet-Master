# Extension isolation for a diagram editor

A desktop diagram editor wants third-party extensions that can inspect selected objects, offer a transformation and return proposed changes. The host must stay responsive when an extension loops, crashes or produces an invalid result. Research a component boundary, capability model and update workflow appropriate for extensions maintained by small independent teams.

Extensions may need read access to the active diagram and optional access to a user-selected file. A transformation can add objects but must not silently overwrite edits made while it was running. The proposal should explain how users see permission requests and failed operations without requiring them to understand sandbox internals. Assume Windows and Linux distribution; the host language and extension language are undecided. Do not grant blanket filesystem or network access by default, equate a separate process with a complete security boundary, apply partially validated results to the live diagram, or make the host execute an extension's custom installer. Existing built-in commands should remain available if extension loading fails. Compare viable execution and data-exchange alternatives, including their actual isolation limits and development burden. Recommend a phased integration and validation plan, without installing untrusted extensions or claiming a production security audit.

Produce a research-backed software proposal, not an implementation. Explore relevant primary documentation, repository code, callers/tests, and issue-to-fix or release history where consequential. Compare feasible alternatives without assuming a winning product. Distinguish proposed validation from work actually executed. The exact draft plan is withheld during brief-only discovery and released once at the declared comparison point.

Complete all substantive research and planning obligations within a maximum of 60 elapsed minutes. Finish earlier when the complete output is ready. There is no minimum research duration, no requirement to consume the allowance, and no credit for waiting. The deadline includes arm-specific setup, provider queueing after admission, tools, native retries, handoffs, revision and delivery. Output quality is assessed independently of elapsed time.
