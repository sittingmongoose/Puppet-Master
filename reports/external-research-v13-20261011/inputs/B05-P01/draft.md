# Asset-validator subprocess proposal — investigator draft

## Launch and ownership
Run the configured executable with `create_subprocess_exec(program, *args)` instead of interpolating a shell command. Arguments and environment come from explicit settings; secrets are redacted from diagnostic displays. The supervisor owns the returned Process, log sinks and temporary validation output. Windows uses a compatible Proactor event loop [S1]; the component has no arbitrary process-tree containment or OS sandbox claim. Validation success requires exit code zero and the product's output checks. Launch failure, timeout, user cancel and nonzero exit have separate terminal states.

## Output and memory
Capture stdout and stderr using PIPE. Set `limit=1048576` and await `proc.communicate()`. This limit is a hard cap on the complete stdout/stderr returned bytes, so memory remains at most 2 MiB even when a tool writes indefinitely. Once communicate returns, write both complete byte strings to disk and retain each last 1 MiB in the UI. Use replacement decoding only for display, while raw log bytes remain available within quota. Mark truncated disk logs explicitly; do not let a log-write failure silently become a validation pass.

For a future live-view option, read stdout first to EOF and then stderr. Since the supervisor is asynchronous, the other pipe cannot block the child. Calling only wait while pipes are undrained was rejected because the docs warn of deadlock [S1]. Redirect-to-file is another useful alternative with low buffering and less live feedback. A concurrent stream reader/spooler gives better incremental logs but adds cancellation, quota and EOF coordination. Small known-bounded output can use communicate conveniently.

## Timeout and cancellation
Wrap `proc.wait()` in `asyncio.wait_for(..., timeout=120)`. If it raises TimeoutError or the UI cancels the wait task, asyncio automatically kills the process and closes its pipes, so record the terminal timeout/cancel immediately. Explicit terminate/kill calls are only needed if the executable ignores timeout. S2 exposes terminate and kill separately and communicate waits after reading streams; S3's issue-linked cancel-wait regression is relevant context, not an application test already run.

On normal completion, close sinks, record exit status and make logs accessible. Partial validation outputs remain private and are removed on error/cancel. Restart recovery lists stale owned temporary files and removes only those proven to belong to this component. Do not wait forever for detached descendants that inherit a pipe; either disallow that tool behavior in the supported contract or implement a separately reviewed process-group layer. A direct-child API is not a process-tree kill guarantee.

## Alternatives, history and validation
The initial shell-command proposal was rejected for argument injection/quoting complexity; explicit argv remains the default. Keep communicate for genuinely small output, concurrent stdout/stderr pumps for streaming, and file redirection where live logs are unnecessary. Proposed tests cover simultaneous large writes to both pipes, missing executable, broken stdin pipe, nonzero exit, timeout/cancel, escalation, log quotas, invalid encoding, early pipe EOF and Windows compatibility. Docs/code and upstream test text were inspected; no asset tool, timeout witness, leak test, Windows run or throughput test executed. Future tests must inspect the child outcome independently of the canceled awaiting task and distinguish UI truncation from complete-log retention.
