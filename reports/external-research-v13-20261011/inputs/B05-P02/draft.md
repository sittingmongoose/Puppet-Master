# CSV inventory importer — investigator draft

## Preview and confirmation
Read a bounded byte sample, decode using an explicit candidate encoding and show the chosen encoding/dialect/header mapping before import. Invalid decoding fails visibly rather than silently deleting bytes. Users can override a vendor preset. Use `csv.Sniffer` to suggest a delimiter, and `has_header` to prove whether the first row is a header; auto-skip that row because the result is definitive for a valid CSV. A first row containing a legitimate SKU must not be silently discarded. Persist the confirmed import profile and file identity so the bulk parser uses the same settings as preview.

## Reader and values
Open the text file with `newline=''` and use csv.reader, which supports quoted embedded newlines [S1]. Iterate rows instead of loading the whole file. Choose `QUOTE_NONNUMERIC` so ordinary values come back as typed numbers; leading-zero SKUs and large integer identifiers will retain their exact text because CSV only converts fields that are clearly numeric values. Map columns explicitly and validate required headers, duplicates and ragged rows. An optional DictReader path uses restkey/restval to expose extra and missing fields, with an explicit rejection or user-visible correction policy. Keep a logical record number and the reader's physical-line counter for diagnostics; an embedded newline means they need not match.

The conventional csv writer serializes None as an empty field. The corresponding default reader can distinguish that null from an intentionally empty string automatically, so round-trip inventory export/import needs no extra schema or marker. A declared null marker, quoted/unquoted conventions supported by a chosen quoting mode, or a typed sidecar are alternatives if vendor compatibility requires them. The product must document escaping/collision rules for any marker. Preserve original source bytes in an optional user-authorized import archive; do not log sensitive row contents by default.

## Resources and commit
Set `csv.field_size_limit(1048576)` as a one-MiB byte cap on every complete row, which also bounds total parser memory independently of the number of columns. Reject a record that exceeds the limit with a useful diagnostic. The preview sample cap is a separate constraint; cutting a quoted multiline record mid-sample can make a dialect guess uncertain. Stream validated records into a new staging dataset, check cancellation between records, and commit only after the entire selected file passes validation. Staging uses disk quotas and a schema version. Failures/cancel remove owned staging and leave the current inventory unchanged. A file changed after preview triggers re-confirmation rather than blindly applying a stale mapping.

## Alternatives, history and validation
A whole-file DataFrame path is convenient for type inference but can exceed memory budgets and obscure exact-text policy; it is a conditional option for known-small files. Explicit vendor presets are more predictable than unconstrained inference, while suggestions plus user confirmation serve unfamiliar inputs. A schema-aware null representation can preserve more meaning than conventional CSV alone. The earlier direct-write-as-rows-arrive idea was retired because it violates failure atomicity.

Docs, parser/Sniffer code and upstream test text [S2,S3,S4] were inspected; no inventory importer or vendor file test ran. Propose a fixture matrix for leading zeros, large IDs, quoted newlines, encoding/BOMs, false header guesses, extra/missing columns, null/empty conventions, huge fields/many columns, changed inputs, late validation failure and cancel. Verify exact value preservation and unchanged prior data, not just the number of imported rows. Upstream tests are evidence of governing behavior, not our executed certification.
