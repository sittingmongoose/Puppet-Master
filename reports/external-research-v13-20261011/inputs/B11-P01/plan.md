# Tentative exact plan: Durable references to local project attachments

Our tentative plan is one project-local attachment table: record ID, display name, absolute path, size, modification time, and a digest computed when first linked. Opening a reference tries the saved path first. If it fails, scan the project folder and recently chosen attachment folders for a file whose size and digest match; choose the newest match automatically. A removable drive is stored by its current mount path. We will watch the listed folders while a notebook window is open and rewrite paths after rename events.

Each editor window keeps the table in memory and replaces the table file when the user changes a reference. Export includes the table and a readable list of attachments, with an optional explicit copy operation. The UI shows available or missing, plus a Browse button for manual repair. We expect this approach to work similarly on all supported desktop systems; platform-specific identity features can be added later if they justify their complexity. Keep references local, preserve record IDs in project exports, and do not introduce privileged services or silent copying. This is a proposal to examine, not implementation evidence.
