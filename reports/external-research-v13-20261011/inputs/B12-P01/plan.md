# Tentative exact plan: Multilingual media-package import and export

We propose a ZIP package containing a single metadata document, a media folder, and one text file for each subtitle track. On import, extract into a temporary directory, flatten media filenames, convert every recognized track to plain text plus floating-point seconds, and store one start/end pair per cue. Sort cues by start time; treat overlap as a warning rather than refusing the package. Unrecognized fields stay only in the imported originals. The user chooses tracks and media to keep before a final database transaction.

Export writes the same internal package and can generate a simple subtitle file for other tools. Track language comes from a filename suffix; clip association comes from matching base filenames. A canceled import deletes the temporary directory, while existing lessons stay untouched. The preview displays text, time ranges and a list of warnings. We will set a maximum compressed package size and reject absolute paths. Examine the representation, compatibility, error/cancellation handling and round-trip promises; retain original files when transformation is lossy and never fetch remote media automatically. No proposed parser or resource limit is implementation proof.

Complete all substantive research and planning obligations within a maximum of 60 elapsed minutes. Finish earlier when the complete output is ready. There is no minimum research duration, no requirement to consume the allowance, and no credit for waiting. The deadline includes arm-specific setup, provider queueing after admission, tools, native retries, handoffs, revision and delivery. Output quality is assessed independently of elapsed time.
