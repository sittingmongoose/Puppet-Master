## Candidate materialization boundary

Release brief.md, plan.md, draft.md and source-index.json to both arms. Do not add hidden rubric answers, findings, preparation scripts or another arm's semantic conclusions. Rubrics contain only obligations derived from the actual brief/plan and are evaluator preparation; the final proposal must be complete and source grounded.

- B01: release the exact same critique.md to both. Control rewrites a fresh complete final; treatment authors targeted evidence-backed amendments plus retained supported prose and assembles a complete self-contained final. Neither deterministic copying nor hashes establish truth.
- B04: control receives critique.md; treatment receives critique-compact.md. Both receive the same raw base and accessible primary evidence and revise into a complete final. findings.json is immutable prep/evaluator equivalence evidence, **not an extra candidate answer**. The full and compact critiques preserve every finding, source/counterevidence, requested change, supported keep/condition/uncertainty and obligation coverage. Semantic equivalence was reviewed by this preparer, not by an independent evaluator; automated ID/coverage checks prove only the mechanical part.
- B05: both independently review and finalize. Shared source-index.json exposes public URLs, pins/hashes and exact locators only. Control has ordinary independent source lookup; do not mount/copy/release treatment-cache, navigation or preparer's cached source pool to control. Treatment gets its exact treatment-cache/navigation.json, complete primary bodies, initial neighborhoods and `source_reader.py` on-demand adjacent expansion. Both can retrieve and inspect further primary sources independently. Cache acquisition is a support cost, not a free discovery or reusable truth judgment. Cache-assisted grading conclusions are never shared between candidates.
- B08: both independently inspect and finalize, with identical primary evidence and permitted execution tools. Treatment binds consequential propositions to subject/domain/version/units and an independent oracle or discriminating counterexample as the method says. No answer critique or result witness is included. Drafts retain supported conditional derivations and at least one consequential challengeable generalization. A few examples or a replay of the author's formula do not prove a universal proposition.

Shared filesystem permissions are not an isolation mechanism. `source_reader.py` mechanically refuses B05 control cache use, but a model with arbitrary filesystem tools could bypass it. Root must scope assignments/materialization and record observed method compliance. This is an explicit access contract, not a claim of enforced sandbox isolation.

## Sources and exact context

CPython sources target **3.13.9**, commit `8183fa5e3f78ca6ab862de7fb8b14f3d929421e0`; they are intentionally version-scoped, not represented as latest Python. Documentation, governing implementation and regression-test text are retained together. SQLite backup/WAL primary pages are live bodies frozen by retrieval hash. HTTP semantics target numbered RFC 9110 and RFC 9111, June 2022, with their original notices. Full bodies, literal line locators, initial exact neighborhoods and SHA-256 hashes allow checking governing exceptions instead of relying on isolated quotations. Upstream tests and issue-linked regression text were read, not run as this application's validation.

The source pool in this helper supports fixture provenance/reconstruction. Individual case caches are the frozen candidate-facing evidence. CPython's LICENSE is retained under sources/cpython/LICENSE; sources carry their public original author/notice text. These are public primary-source author contacts, not private account routing. Root may deduplicate exact source bytes during retention/publication while preserving each case's exact manifest resolution and the cache-access boundary. Do not delete a scientific body before verifying its retained equivalent.

Read an exact interval, with one-based inclusive line numbers:

```bash
python3 helpers/component-fixtures-v1/source_reader.py --case B05-P01 --arm treatment --source S2 --start 171 --end 203
python3 helpers/component-fixtures-v1/verify.py
```

The reader does no summarization, inference, semantic merging or model call. It verifies the full body hash before emitting the chosen lines. It can expand to any adjacent interval or the full cached body. Independent remote lookup remains authorized. The verifier checks all case hashes, declared raw identity, time contracts, cache gate, source/neighborhood byte equality and B04 finding IDs/coverage references; it **does not grade source correctness**.
