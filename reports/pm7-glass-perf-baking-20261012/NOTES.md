The Glass baking lane reduces repeated CPU work and prevents obsolete image callbacks from replacing the current surface. It preserves full-resolution optics, wallpaper cover and layout anchoring, all material constants, RGB dispersion, rim alpha and specular equations. Source scope is maps/cache, wallpaper decoding, frost/ring baking, mount and teardown in `Concepts/liquid-glass/opus-5.5/src/glass.js`; the scheduler and native lens lifecycle stay with their respective lanes.

A Map now holds one newest bake job per element instead of distinct `[element, kind]` arrays in a Set. A single shared decode/frost/bake batch consumes those jobs; identity, theme, viewport, element signature, connection and epoch guards reject stale work. Ring callbacks also check current layout/size before publishing. Null decode/encode results permit later retry. Removed surfaces release their URLs through `unmount(e)` and stop unnecessary queued work. Glass-off cancels pending work and native lens motion but retains connected settled ring/spec/frost images, preserving the baseline's immediate return paint. Conditional `suspendLensMotion()` and `pruneLensFilters()` hooks join the lens lane safely; runtime calls `unmount(e)` when it prunes disconnected surfaces.

The computed wallpaper data URL is resolved once per source theme/wall choice (or inline override), with one fresh read before loading. Surface signatures use a compact revision of the exact URL. Same-length wallpapers cannot collide. Concurrent requests share one Image and at most two completed decodes remain cached. Completed frost pairs are cached by exact wallpaper URL and viewport, limited to two pairs and 32 MiB of encoded blobs; an oversized displayed pair is not retained for reuse. Both levels publish together only if their context is current, and evicted/replaced URLs are released.

Optical maps use a count/byte-aware LRU of at most 80 entries and 64 MiB of estimated raw arrays plus string storage. SDF output and encoding scratch are reused; repeated exact distances/normals share the same transcendental results. No approximation is introduced. The unused sheet displacement PNG and unused rim array are skipped, and the ring loop visits the same alpha-eligible pixels directly. Active surfaces keep their own required image references when a reusable map is evicted.

Validation covers 43 distinct newly authored cases (47 executions, all passed): initial 35 cases, six extra edge cases, then two new off/on transition cases with four affected checks repeated. Frozen native JS/Float32/pre-encoded RGBA values match for seven sheet geometries, six lens geometries and three ring sampling fixtures. Frost drawing/filter parameters match. Maps were mechanically compared to the first passing source after the final teardown correction; only comment indentation differs. Syntax, whitespace and generated-page checks pass. All generated bytes outside the Glass script match the frozen presented v2.2 page exactly. Detailed evidence paths and SHA-256 values are in `result.json`.

Controlled operation counts demonstrate the avoided work, rather than elapsed browser performance: 100 geometry updates to one sheet queue/encode 1 final ring instead of 100 and reduce computed wallpaper reads from 101 to 2; 20 concurrent wallpaper requests create 1 Image instead of 20; 10 concurrent frost requests encode 2 PNGs instead of 20. For the 800 × 450 map fixture, atan/asin calls each fall from 75,628 to 145, pow from 453,768 to 2,280, and exp from 302,512 to 290; every compared output byte stays equal. That ring has 19,536 alpha-eligible pixels out of 360,000.

These deterministic Canvas/Image/timer doubles do not establish real Chromium encodes or Gaussian-blur pixels, GPU timing, completed-frame rate, or visual approval. The sole profiler owns those checks. Cold full-resolution sampling/encoding still takes synchronous work, and connected offscreen sheets retain baseline eligibility. No optical quality, wallpaper art, CPU-tier policy, settings, canon or landing decision was changed. The pushed commit is pinned in external `baking/handoff.json`; this report pins the exact source and external focused harness bytes.
