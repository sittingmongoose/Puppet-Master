## How validation got cheaper

`MemoValidator` is a subclass of the exact validator class GO ran (`StrictValidator` over the same runtime schema, registry, base URI and format checker, rebuilt from a pickled dump of the root). It changes nothing in the keyword functions.

1. **Valid subtrees are reused.** A `descend` or `iter_errors` result is reused only when it was *no errors*, keyed by:
   - the schema node,
   - the instance value, hash-consed exactly with type tags so `1`, `1.0` and `true` stay apart (no probabilistic hash),
   - the base URI,
   - the clause-cut context and the date-time profile.
2. **`is_valid` also remembers refusals.** Every refusal stream itself is recomputed by the reference keyword code.
3. **The interning frame is reset per top-level validation,** so an in-place edit between validations can never hit a stale entry. There is a standing trial for this.
4. **`$ref` lookups are memoized.** `referencing` re-crawls the whole registry on every lookup of a URI that is not registered at top level. In 51a5's summary region that cost 0.43 s per validation, and GO's reference validator pays it too. `Resolver.lookup` is a pure function of registry, base URI, dynamic scope and ref, so its result is reused.

## How the search got smarter

GO's `search_clause` is copied with its witness test unchanged: the single-field defect at the clause's own location is refused there; with only that clause cut the whole definition accepts (KILLED); restored, it refuses again. Otherwise the cut still refuses, at the clauses it names (COVERED_LATER). The same GO defects, siblings and constructions apply. GO2 additions, each marked in the source:

- **Reaching controls first.** Accepted controls that already take every union alternative and branch of the clause's reach are tried first. This is ordering only.
- **Donor construction (residual passes).** Branch entry from a real control:
  - the members on the way are created from real accepted sub-values ("donors") of every dumped root's seeds and of earlier passes' accepted controls;
  - an `if` is forced to the needed branch (const/enum, nested pins, `null`, removal), with the forced selectors protected;
  - one parent selector value is chosen so every conditional of the parent accepts the edited member;
  - a greedy repair keeps the candidate with the fewest remaining errors (union contexts included).
  A built control is used only if the reference-class validator accepts it and it actually takes the reach. The witness test on it is GO's.
- **Budget.** GC's per-clause cap of 900 counted validations, with GO's suite share (450) measured after the donor stage. There is no wall-clock bound. The cap is checked between attempts, as in GO's loop, so one GO construction can overshoot it:

  | 35d6 | 14,932 | 74 |
  | 51a5 | 2,585 | 207 |
  | c15ebf | 3,683 | 33 |

- **Parallelism.** At most 4 scoped processes at once, each under `systemd-run --user --scope -p MemoryMax=2G -p MemorySwapMax=0`. Each launch had 13–20 GB available. The work ran as long-jobs with checkpoints every 120 s. Search wall clock per root (sum over passes):

## The 12 "dangling-ref" clauses: a tool defect, now covered

GO recorded `PointerToNowhere: /$defs/CommandOutcomeRecord` for 12 clauses of 35d6 (15 occurrences). These are not unreachable and not an owner defect.

- **The spec says the ref resolves inside the embedded resource.**
  - JSON Schema 2020-12 Core §8.2.1: "The presence of "$id" in a subschema indicates that the subschema constitutes a distinct schema resource". Its absolute URI "also serves as the base URI for relative URI-references in keywords within the schema resource".
  - §8.2.3.1 (`$ref`): "Resolved against the current URI base, it produces the URI of the schema to apply."
  - So `#/$defs/CommandOutcomeRecord` inside the embedded `pm.storage_value.restore_point_create_result.v1` resolves within that resource, and that resource has `$defs/CommandOutcomeRecord`.
- **The validator agrees.** All 17 authored 35d6 seeds validate through the embedded `$ref`. A defect at `creation_result.value.original_command_outcome` is refused at `pm.storage_value.restore_point_create_result.v1/$defs/CommandOutcomeRecord/type` (standing trial `dangling_ref_reached`).
- **The cause was GO's tool.** GO's `deref()` (used by `null_at`/`scope_of` in every static proof, and by `gen`/`realize`) kept the enclosing document's resolver when it stepped onto a subschema with its own `$id`. So it looked the pointer up in `pm.restore_point.retained_read.v1`, which has no `$defs`.
- **The fix lives in GO2's process only.** GO2 switches base at an inline `$id` exactly as jsonschema's `descend` does. GO's file is unchanged; standing trial `inline_id_deref`.
- **Now:** KILLED 2 and COVERED_LATER 13 (all 15 occurrences). No `--decision` mail was needed.

## Two more defects found in the closure machinery

1. **The clause id of a `$defs` node can depend on the process.**
   - The frozen roots embed the same resource under one `$id` many times, for example 12 copies of the `restore_point_deleted/1.0.0` payload in 51a5.
   - When `referencing` crawls its registry, the last copy inserted wins. The insertion order follows the process's string-hash order. So a `$ref` into such a resource reaches a different copy's `$defs` in different processes, and both the walk and the validator's error locations name that copy.
   - Copies are identical apart from GO's location annotation: checked by sha256 of every copy, all identical. So verdicts never change; clause ids under `<copy>/$defs/` do.
   - The walk order changes too, so contiguous shard ranges are not a partition across processes. This surfaced as 74 clauses that one pass's range named and another's did not.
   - **GO2's fix.** Clause ids under a duplicated-`$id` copy's `$defs` (reached only through `$ref`) are mapped to one canonical copy: the registry document if there is one, else the first copy by location. Inline nodes of a copy are never mapped, because each is reached by its own instance paths. `close` (only, residual, carry), `merge-shards` and `verify` compare canonical ids. `merge-shards` joins reports by id and checks the union against the root's clause set.
   - **Checks.** Standing trial `duplicate_id_copies`. 69 entries were mapped this way in 51a5; `verify` judged 42 witnesses under a different copy and all passed.
2. **GO's VACUOUS rule only knew `min*: 0`.** Three 51a5 nodes have `required: []`. Validation 2020-12 §6.5.3: "Omitting this keyword has the same behavior as an empty array"; an empty list is always satisfied. GO2 adds checked VACUOUS rules for `required: []`, `uniqueItems: false` (§6.4.3) and empty `dependentRequired` (§6.5.4), with a standing trial on the validator's own keywords.

## One new checked proof: case exclusion

`case_excluded` is a GO2 addition, used only when GO's own proofs find nothing. For every reach of the clause there must be an ancestor object Q on the clause's own path and a member S of Q such that:

- in the reach's scope, S is required and pinned to finitely many values;
- for each value, the conditionals of Q that value decides pin members of Q;
- those pins contradict a conditional the reach itself passes below Q: a `then` whose `if` needs a present member in disjoint values, or an `else` whose `if` the pins make always true.

GO's selector-clash rule holds: no selector or pinned member prefix-related to the clause's location is used. Standing trial: a proved case, and a live case it must not claim.

It fired once, in 51a5, on `…/migration_admission/properties/receipt/$defs/migration_preflight_result/allOf/1/then/properties/reason_code/const`. `terminal_status` is required and pinned to `committed | rolled_back | blocked`, and all three branches pin `preflight_result.outcome` to `ready`. The clause's `then` needs `outcome: blocked`.
