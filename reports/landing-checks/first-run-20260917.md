## The branch-path rule, checked against an independent pass

The rule has to catch a failure that names a branch path anywhere, and several of these failures
name a document only in a nested field or only through a span id. Over the 29,131 failures of one
full run, with a pretend branch touching `Plans/00-plans-index.md`,
`Plans/assistant-chat-design.md`, `Plans/Decision_Log.md`, `Plans/storage_value_registry.json` and
`scripts/pm-plan-index.py`, the script and an independent regex pass over the raw reports both find
the same 5,611 failures, with nothing found by only one of them.

That pass caught a real defect on its first run: the key deliberately drops the measured
`actual`/`expected` values, and `current_snapshot_batch_doc_set_not_exactly_once` names its
documents only inside those lists, so the match missed it. The match now reads the failure as it
came. Commit `e305265c51`.

The failure sample order is deterministic: all 14 subchecks that `run-gates` and `audit-governance`
share produced byte-identical samples in two separate processes, once the absolute path of the
checkout is taken out of them.

## Gaps this run found

1. A full checkout is not the tracked tree. `tests/fixtures/governance/`,
   `tests/fixtures/pm7_shared/`, `tests/fixtures/usage_gui/cases/`,
   `tests/fixtures/usage_gui/presentation/`, `tests/test_pm_evidence_artifact_binding_modes.py`,
   `tests/test_pm_plan_migration.py` and the `tests/agent_packet_restrictions` symlink are
   gitignored and exist only in the shared checkout. Without them `json_syntax` and
   `pm7_gui_fixtures` fail on missing files, so a baseline recorded from git alone is not the
   baseline a landing meets.
2. Nothing schedules the nightly run. There is no cron entry, no systemd timer, no scheduled task
   and no workflow with a `schedule:` block; the nightly placement lives only in
   `Plans/Bootstrap_Planning_Migration.md` BPM-009 and the Decision Log. Until something schedules
   it, the refresh is a manual step in the rule.
3. `Plans/.plan_index/plan_units.jsonl` names `tests/test_pm_evidence_artifact_binding_modes.py` as
   an implementation surface for ATS-001, and it is one of the untracked files. That is the
   tests-tracking convention losing a test again.
