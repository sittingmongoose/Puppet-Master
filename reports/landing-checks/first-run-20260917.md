## The branch-path rule, checked against an independent pass

The rule has to catch a failure that names a branch path anywhere, and several of these failures
name a document only in a nested field or only through a span id. Over the 29,131 keyed failures of
the first full run, with a pretend branch touching `Plans/00-plans-index.md`,
`Plans/assistant-chat-design.md`, `Plans/Decision_Log.md`, `Plans/storage_value_registry.json` and
`scripts/pm-plan-index.py`, the script and an independent regex pass over the raw reports both find
the same 5,611 failures, with nothing found by only one of them.

That pass caught a real defect on its first run: the key deliberately drops the measured
`actual`/`expected` values, and `current_snapshot_batch_doc_set_not_exactly_once` names its
documents only inside those lists, so the match missed it. The match now reads the failure as it
came. Commit `e305265c51`.

The failure sample order is deterministic: all 14 subchecks that `run-gates` and `audit-governance`
share produced byte-identical samples in two separate processes, once the absolute path of the
checkout is taken out of them.

Two keyed totals appear in this bundle and they come from different runs. The cross-check ran over
the **first** full run, taken against the tracked tree alone, which keyed 1,003 + 28,128 = **29,131**
failures. The baseline was recorded from a **full checkout**, which keys 1,007 + 28,128 = **29,135**.
The four extra are what appears once the gitignored fixtures are in place: `pm7_gui_fixtures` stops
crashing on a missing file and reports three real findings instead of one traceback, and
`json_syntax` stops reporting a missing schema. The `failure_total` figures, 37,935, are the checks'
own totals and include the failures above the print caps that are never keyed.

## What the tests would notice

The suite is mutation-checked rather than counted. Nineteen deliberate single-line regressions were
introduced on copies and the suite re-run against each; **all nineteen fail at least one test**. They
are: hash masking removed; masking widened to 6 hex characters, which would merge `pds-20260906` with
`pds-20260917`; `actual`/`expected` type-tagging removed; the checkout prefix left in; `scrub` made
non-recursive; `canonical` left unsorted; the fingerprint cut to two hex characters; the span-id
pattern unquoted at either end; the span-stem match removed; the path boundary widened, and narrowed
to an exact end; the bucket cap made exclusive; the count-only bucket's count zeroed; growth skipped
for count-only buckets; the `fingerprints is None` guard dropped at its use site; buckets the
baseline never saw counted as growth; per-subcheck totals read from the sample instead of the check's
own count; the totals stopped from gating the result; the truncation flag pinned false; new
off-branch items counted as blocking; the resolved set reversed; the excused-by-kind count blanked;
and `main` never returning 2.

An earlier round of ten mutations reported here as all caught was wrong on one count: unquoting the
span-id pattern survived, because the test that looked like it covered the quotes was protected by
the `-S\d+` suffix instead. Two tests now exercise the quotes at both ends, and the end-to-end tests
drive `main` itself, which is where five of the survivors the independent review found were hiding.

## Gaps this run found

1. A full checkout is not the tracked tree. `tests/fixtures/governance/`,
   `tests/fixtures/pm7_shared/`, `tests/fixtures/usage_gui/cases/`,
   `tests/fixtures/usage_gui/presentation/`, `tests/test_pm_evidence_artifact_binding_modes.py`,
   `tests/test_pm_plan_migration.py` and the `tests/agent_packet_restrictions` symlink are
   gitignored and exist only in the shared checkout. Without them `json_syntax` and
   `pm7_gui_fixtures` fail on missing files, so a baseline recorded from git alone is not the
   baseline a landing meets.
2. Nothing schedules the nightly run. There is no cron entry, no systemd timer, no scheduled task
   and no workflow with a `schedule:` block; the nightly placement lives only in
   `Plans/Bootstrap_Planning_Migration.md` BPM-009 and the Decision Log. Until something schedules
   it, the refresh is a manual step in the rule.
3. `Plans/.plan_index/plan_units.jsonl` names `tests/test_pm_evidence_artifact_binding_modes.py` as
   an implementation surface for ATS-001, and it is one of the untracked files. That is the
   tests-tracking convention losing a test again.
