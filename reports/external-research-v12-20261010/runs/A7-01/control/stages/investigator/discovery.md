## Independent findings for obligations 1–8

### 1. Two CAD-to-slicer routes and a portable alternative

**Route A — CAD mesh export to 3MF, then open as model geometry.** Autodesk Fusion provides Save As Mesh for 3MF/STL/OBJ and allows a component to export its contained bodies [S04]. Autodesk describes its 3MF export as vertices/triangular faces with units, colors, and textures [S05]. The 3MF Core is a ZIP/Open Packaging Conventions package, with unit-qualified mesh, object resources, build items, optional metadata and thumbnail parts [S01]. It can represent component objects and transforms, which helps preserve separate parts and placement where both exporter and receiver honor them [S01]. The **inference** is to make this the default slicer handoff for a modest, cross-tool pilot: it supplies more explicit print-oriented structure than STL while remaining an additive-manufacturing format. It is still a mesh/model exchange, not the author's editable CAD history.

**Route B — neutral STEP exchange to a receiving CAD tool or directly to a slicer that imports STEP.** STEP is a published CAD exchange route in Fusion [S05]. PrusaSlicer 2.9 documents direct STEP import, but explicitly triangulates the STEP during import [S07]. Thus direct STEP-to-slicer gives a convenient way to preview geometry but crosses into mesh geometry at that slicer boundary; users who need CAD-level inspection should open STEP in a CAD receiver first. The **inference** is to include STEP as an optional geometry review path for assembly/shape-sensitive projects, not as a universal slicer setting or parametric design source. Fusion says exported designs lose associativity to the source [S05], so the original native file remains the editable authoring artifact when its app is available.

**Useful alternative — STL.** It remains the broad fallback for one simple surface mesh, but Autodesk confirms it is unitless; export/import defaults can create scale errors, and recommends selecting export units [S06]. 3MF provides an explicit model unit with default millimeter [S01]. The 3MF Consortium says STL lacks color/material/property information [S17], consistent with its triangle-only role in the vendor docs [S05]. **Inference/local choice:** allow STL only as a clearly labeled fallback plus declared units, overall dimensions, and a part list; do not make it the primary project handoff.

**Portable package mechanism — 3MF plus a small outer folder/ZIP manifest.** Core 3MF is already a portable ZIP/OPC container with optional JPEG/PNG package/object thumbnails and standard Title/Designer/Description metadata [S01]. Version 1.4.0 additionally recommends distinguishable roles such as .model.3mf, .project.3mf, .build.3mf, and .toolpath.3mf [S01]. **Inference:** deliver a geometry-labeled .model.3mf inside an ordinary folder/ZIP containing a human-readable project note and separate preview PNG; embed the same thumbnail and Description metadata when the producing and tested receiving tools support them. The external note/preview remains readable if a viewer ignores optional 3MF parts. Reserve .project.3mf or .build.3mf for a receiver/technician-produced, application-specific snapshot; do not label the author's geometry package as machine-prepared.

**Another formal portable-format alternative — AMF.** ASTM lists active ISO/ASTM 52915-20 AMF 1.2 and says standards-compliant electronic use depends on its XML schema [S13]. PrusaSlicer 2.9 still imports AMF but recommends 3MF [S07]; its 2019 release note says its 2.0 project workflow chose 3MF and retained AMF import [S14]. The 2022 issue below records an AMF from the same reported FreeCAD case loading with different placement [S11]. **Inference:** keep AMF as a useful import/legacy comparison in a pilot matrix, not the chosen exchange default; support and coordinate placement must be checked on exact builds.

### 2. Units, object/assembly relations, materials, and machine instructions

- **Units/geometry:** 3MF Core's model unit is explicit, defaulting to millimeters, and also permits micron, centimeter, inch, foot, or meter [S01]. STL is unitless; receiving defaults such as millimeters are application behavior, not a meaning encoded by STL [S06]. Require the author to state units and key dimensions in the note even when the selected file format carries a unit.
- **Objects/assembly:** 3MF has object resources, build items, and component references/transforms; the receiving manufacturing consumer must honor relative component positions [S01]. Fusion authoring components have names, origins, bodies, nested components and external references, which can become unresolved when a linked design or permission is missing [S19]. A neutral mesh should not be described as preserving the whole parametric assembly tree. **Inference:** preserve per-part names and transforms in 3MF where available, and list each part plus its intended relation in the note (separate, assembled, clearance/fit, adhesive, or interlocked). Confirm any ambiguous fit with the author.
- **Material intent:** Core base-material names are meant to convey design intent and help map to print materials; machine-specific names belong in printer-specific settings/PrintTicket. Core displaycolor is for rendering and does not make the printed color/material [S01]. Materials and Properties 1.2.1 can carry richer color/material/texture properties, but only when both sides implement that extension [S02]. The 3MF compatibility matrix distinguishes core support from optional Materials support and labels some feature support partial; the matrix is vendor-self-reported [S03]. **Inference:** put the intended substance/finish per part in the author note and core base-material name where available; do not imply color swatches or material names guarantee the receiver has that material loaded.
- **Application-specific process:** A 3MF PrintTicket can carry settings, but its format is governed by a consumer environment; if it is absent or unsupported, that consumer applies its own defaults [S01]. Prusa project 3MF files can additionally capture Prusa objects, settings, and modifiers for the corresponding Prusa workflow [S08]. A Prusa 3.0 public preview says cross-slicer third-party 3MF comes in as geometry only; its own 2.x/3.x settings compatibility is asymmetric [S10]. **Inference/local choice:** separate author design intent from machine instructions. The technician chooses and records printer, material preset/spool, nozzle, bed/build volume, supports, orientation, temperatures, and process settings for the actual receiving machine; that application-specific project is a distinct, labeled output. A saved slicer project is not an instruction approved for every printer.

### 3. Optional preview and metadata

Core 3MF allows package/object JPEG or PNG thumbnails and standard model metadata including Title, Designer, and Description [S01]. A thumbnail is explicitly optional and consumers may not surface it in the same way. The 1.2.1 Materials extension and its color/texture features are a separate optional capability [S02]. The current matrix shows implementation variation; it is not independent confirmation [S03]. **Recommendation inference:** retain the brief-authorized preview image and human-readable note when supported. Include a sidecar PNG and README-style note in the outer folder/ZIP as the reliable reviewer path, and embed the thumbnail/Description in 3MF where the exact exporter supports it. Do not exclude this scope: sources establish standard 3MF support for optional thumbnails and Description. Do not claim every file browser/slicer displays them or that metadata/extension support is universal.

### 4. Bounded importer/exporter history and pilot effect

A reported FreeCAD 0.20 to PrusaSlicer 2.4.2 compatibility case is directly relevant: the reporter said the 3MF import failed silently, while the AMF file loaded at an unexpected origin and the STL worked [S11]. A Prusa maintainer identified malformed relationship/path content (the discussion describes an unwanted leading slash/backslash) and closed the issue after an import-failure diagnostic change; the reporter said FreeCAD fixed its exporter output [S11]. Prusa commit 040a846 changed the importer success result so a file with neither loaded objects nor configuration is not treated as success [S12]. The specific first stable versions containing these fixes are not stated in the retrieved history. This is a historical, version-bounded case, not proof of a current defect. **Pilot effect/inference:** hold one malformed/empty file as an import-error test and test the exact CAD exporter/slicer builds in the selected receiving matrix. Verify visible geometry, dimensions/units, components/positions, and an explicit error on failure; do not silently replace the failed source with a different format without recording that choice.

### 5. Optional scope: preview image and reviewer note

The brief explicitly authorizes this as optional scope. Core specification permits package/object thumbnails and standardized document Description [S01]. **Disposition:** keep the option in the proposed package; include the note and sidecar preview for all pilot projects when available, embed standard parts/metadata opportunistically, and mark anything not exported/readable as optional support pending the matrix. No evidence-based exclusion is supported. The note should provide project/revision, author/source CAD app and export version, units and key dimensions, part list/names, assembly relation, material intent, known exceptions, and any receiving-tool test status. It must be visibly described as design/review context, not print approval.

### 6. Explicit owner decisions

These are brief-set owners, not open research questions:
- **Project author:** intended units and materials; resolves ambiguous part names/assembly/fit intent.
- **Workshop technician:** printer-specific slicer settings and the suitability of the selected physical setup.
- **Pilot lead:** the tested receiving-tool/version matrix and what compatibility wording is justified by actual results.

The compatibility matrix is a candidate discovery aid, not the pilot lead's selected or executed matrix [S03].

### 7. Negative constraints

This research did not operate a printer or generate machine output. The recommendation is only a planning proposal for ten noncritical decorative projects. Exclude safety-critical use; do not imply STL retains units, assemblies, colors, materials, or project properties; do not call an imported saved slicer configuration approved instructions for any other machine. Do not use a research-source lookup, schema capability, or proposed validation as an executed product check.

### 8. Validation boundary, proposed checks, and uncertainties

**Checks actually executed:** read-only public page searches/open/find; no product, format-file, CAD, slicer, or printer validation. Local product checks: NOT_RUN.  
**Proposed pilot checks (not executed):** (1) pilot lead selects a specific CAD-exporter and receiving-slicer matrix, with exact versions/builds; (2) round-trip ten representative decorative samples through 3MF and the agreed STEP route, recording imported dimensions against declared units, visible object/part names, count and relative positions; (3) check intended material names versus receiver mappings and optional extension survival; (4) display both embedded and sidecar preview/note in no-author-CAD review; (5) capture warnings, silent/no-geometry failure, and manual recovery paths using the historical invalid-file case as a boundary example; (6) technician performs an in-app G-code preview for selected machine settings, without this research operating a printer. A file-format conformance suite may supplement, not replace, these application tests [S15].

**Unresolved inputs:** which CAD tools and versions members actually use; which receiving tools/builds the pilot lead selects; what ten project files reveal about assemblies/materials; whether chosen apps embed/preserve/display thumbnails and Description; and whether to distribute source-native CAD files or only a STEP option. The source matrix has no build-level guarantees, and 3MF consortium compatibility entries are self-reported [S03]. AMF's full paid text was not reviewed [S13]. No validation conclusion is drawn from either.

## Preliminary recommendation (inference/local choice)

For the pilot, ask authors to export an explicit-unit, geometry-oriented 3MF when their CAD tool supports it. Deliver it with a readable note and sidecar preview in a small folder/ZIP. Use the 3MF 1.4.0 naming convention to distinguish a model package from a slicer project or machine build. Offer STEP as a secondary, CAD-review/receiving-slicer route where the pilot's selected version actually supports it; document that the slicer may triangulate it. Offer STL only with stated unit and dimensions. Keep AMF as a bounded legacy comparator. Treat embedded thumbnails, Description metadata, and rich Materials extension data as optional capabilities to retain when present and proven in the tested matrix. Let the technician establish printer-specific settings and the pilot lead state compatibility only for tested versions.
