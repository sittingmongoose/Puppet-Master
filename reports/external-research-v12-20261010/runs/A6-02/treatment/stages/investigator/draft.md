## Proposal and workflow comparison

Build a network-owned pilot catalog with one read-only adapter and mapping profile per collection. Use OAI-PMH where the collection supports it; otherwise use a documented public API or scheduled source export. Keep the fetched source record immutable, version each mapping, and produce a separate normalized/searchable view. Publish item links back to collection pages. Record each import, update, explicit deletion, invalid record and failed fetch. This gives the network one place to display statement plus origin even when feeds differ, while making freshness and mapping history visible.

## Rights assertions, scope and display

Do not reduce rights metadata to “reusable / not reusable.” Preserve the collection’s exact assertion and show the source beside it. Treat these as distinct:

1. A supplied rights statement is the institution’s statement about an item and may be a standardized RightsStatements.org URI, local policy text or another source value. It is a record of what that collection supplied, not a network verification.
2. A license is an instrument that grants permission subject to its stated terms. A CC license URI identifies particular conditions, such as attribution, share-alike, noncommercial or no-derivatives ([S11](https://creativecommons.org/share-your-work/use-remix/cc-licenses/)). Record the exact supplied license, version/URI and stated scope; the network must not issue a new license.
3. A public-domain assertion is separate from a license. CC0 is a rightsholder’s tool for waiving rights; the Public Domain Mark is an informational label for works believed to be already public domain. The PDM must not be used when status is uncertain or jurisdiction-specific ([S11](https://creativecommons.org/public-domain/), [PDM 1.0](https://creativecommons.org/publicdomain/mark/1.0/)). The catalog must display a supplied assertion without making its own legal finding.
4. Local access policy controls what this service displays, links or permits users to download. It is not itself a copyright status or a license. Store it as a separate, network/collection-owned policy decision, and never convert it into a rights statement.

Keep the subject of each assertion explicit: described cultural object/work, digital reproduction or WebResource, thumbnail/preview, metadata record, and access to the local catalog may have different values. EDM’s definition places edm:rights in aggregation and WebResource context; Europeana says it communicates terms for previews and digital objects. DPLA’s schema separates sourceResource.rights from object.rights ([S03](https://pro.dp.la/developers/field-reference), [S06](https://pro.europeana.eu/files/Europeana_Professional/Share_your_data/Technical_requirements/EDM_Documentation/EDM_Definition_v5.2.7_042016.pdf), [S08](https://pro.europeana.eu/index.php/page/europeana-licensing-framework)). Europeana’s CC0 for its metadata does not extend to the underlying objects. Do not claim that a museum network’s metadata terms authorize image reuse.

A universal permission badge on every visible thumbnail is rejected. It collapses distinct statements and scopes and makes image visibility look like permission. If an exact, source-supplied URI is valid, the UI may show that statement’s name and link as a source-provided status; do not relabel it as a network grant. Missing, malformed or conflicting values get a neutral status and visible explanation, not a green/red permission decision. A small icon may supplement the text only if its meaning is clear and it never replaces the supplied statement/source.

## URI, attribution, mapping, provenance and changes

Use a provenance envelope for every ingested record and statement. Minimum fields: collection ID and registrar; stable source-record ID and exact source URL; raw record snapshot/reference and capture time; source-reported modified time or datestamp; raw field path, literal and exact URI as supplied; stated subject/scope; source attribution text and linked agent/organization if supplied; source schema/feed and version; mapping profile ID/version; normalized value plus mapping relation/reviewer; ingest activity/result; and prior version/supersedes link. Keep source and derived values side by side. PROV-O offers Entity/Activity/Agent and wasDerivedFrom/wasAttributedTo relationships for this chain; it does not establish legal correctness ([S14](https://www.w3.org/TR/prov-o/)).

Retain source vocabulary URI and label. Do not discard identifiers after copying labels. For crosswalks use a relation with strength appropriate to evidence: SKOS exactMatch is high-confidence, transitive concept equivalence; closeMatch is weaker and non-transitive; owl:sameAs means the resources are identical and is not an approximate mapping ([S13](https://www.w3.org/TR/skos-reference/)). A network mapper owns the crosswalk and its release version. Automated enrichment can add linked terms, but it must remain marked as derived; Europeana’s enrichment docs say it adds terms to source metadata and dereferences supported vocabulary URIs ([S09](https://pro.europeana.eu/page/europeana-semantic-enrichment)). Preserve the original supplied field even when a more precise mapped field is available.

For standard RightsStatements.org or CC URIs, keep the original machine URI. The IIIF spec says HTTP URIs are machine-actionable and equivalent HTTPS human-readable pages may be used for user links; it says rights is informative, and requiredStatement or metadata should carry text shown to a user ([S12](https://iiif.io/api/presentation/3.0/)). Preserve original attribution wording plus source entity/URL and source context. A link back to a collection record is useful but is not enough provenance: the linked page may change or disappear, so the catalog needs captured source value, capture time and mapping version as well.

Missing or conflicting statements need explicit workflow:

- Missing: state “No reuse statement supplied by this source” and show source/last-seen time. Keep rights value null; do not invent CNE, UND, NKC, a license, a PDM or “all rights reserved.” RightsStatements.org distinguishes no status inquiry (CNE), an unsuccessful inquiry (UND) and reasonable cause to believe no copyright remains (NKC); these are not interchangeable unknown markers ([S10](https://rightsstatements.org/page/collection-other/1.0/?language=en)).
- Conflicting source values or scope: preserve each value, identifier, field path, source version and capture time; mark conflict, provide the source links, suppress any synthesized permission decision, and route to the registrar. Keep both until that owner corrects or explains them.
- Malformed or unsupported URI: preserve the raw input for staff and record a parse/validation warning. Do not rewrite to a different RightsStatements/CC URI by guess. If a safe user link cannot be established, display supplied text and source page.
- Stale source/unavailable feed: show the last captured value with its observation time and a stale/unavailable note. Do not represent it as freshly confirmed; do not scrape a restricted collection to refresh it.
- Changed assertion: write a new version and link it to its predecessor. Retain the previous value for audit/display history; do not silently mutate published metadata.

OAI-PMH update behavior is conditional, not a universal freshness guarantee. Store Identify’s deletion policy and datestamp granularity; use the declared granularity, follow resumption tokens and record set/metadataPrefix. Explicit deleted headers can drive tombstones when supported. With deletedRecord=no, absence from an incremental response cannot distinguish deletion from a missed/failed request; use full snapshot reconciliation and an owner-approved age/stale threshold. With transient support, deleted headers may disappear later; persist locally when first seen. Apply equivalent checks to APIs/files: stable ID, fetch status, source version, delete marker, outcome counts and retry policy. [S01]

A useful released behavior example is DPLA ingestion3’s pinned Issue 739 commit 608ea023de200df48e8241ed08e0fa49466646f9 (2026-06-17). Its NARA audit states that preprocessing had treated NaidsList roster files as delete instructions instead of NAC_DESC_Deletes files; requested deletes were not executed. The fix selected the explicit delete-file pattern and added a zero-valid-delete gate; non-interactive runs halt, and bypass is explicit. Its README says affected records may remain and leaves retroactive reprocessing to the team. This is evidence from a pinned public source/runbook, not an incident independently replayed here. Apply the lesson, not the NARA-specific filenames: count deletes, alert on zero/invalid outcomes, preserve logs, and require a named owner to decide backfill ([S16](https://github.com/dpla/ingestion3/commit/608ea023de200df48e8241ed08e0fa49466646f9)).

A second migration case is Europeana ESE → EDM. ESE flattens source object, web resource and aggregation properties; Europeana warns that default mapping can confuse original creation date with digitization date and original format with digital-file format, and recommends a better provider mapping when possible ([S07](https://pro.europeana.eu/page/ese-documentation)). For each of the five collections, inspect its own source schema and examples, name ambiguous fields, pin a mapping version, and obtain the metadata lead’s choice. Two records cannot validate five different source schemas; use a per-collection sample plus targeted edge cases, and keep the source payload for later remapping.

## Optional reuse-help link and downloadable record

Retain both as authorized optional scope; neither is mandatory, nor does the brief establish that all sources support it. Recommend the reuse-help link where a standard identifier is supplied: show the exact statement URI/name and link to the official RightsStatements.org/CC human-readable explanation. For local statement text, use the collection’s supplied help page if one exists; otherwise route copy/URL approval to its registrar. A neutral catalog explanation may clarify “this is the statement supplied by collection X” and distinguish the catalog’s access policy without paraphrasing or strengthening the source’s grant. IIIF requiredStatement supports user-facing attribution/copyright text; its rights URI may accompany it. [S10–S12]

Offer a downloadable JSON-LD or JSON source-attributed metadata record when each registrar confirms that the metadata fields may be publicly exported and the metadata lead approves a stable schema/export version and terms for network-created metadata. Include source collection, stable source ID/URL, exact supplied rights values/URIs and attribution, statement scope, capture/modified times, mapping version, source record link and explicit “unknown/conflict” state. Include a separate field for the catalog’s metadata-use terms, if chosen by the appropriate owner. Exclude image/video files, restricted values, credentials and hidden local-only fields. DPLA exposes JSON-LD/bulk exports, Omeka S exposes JSON-LD/API values and optional public output formats, and IIIF manifests are dereferenceable JSON documents; these show feasible patterns but do not prove the five source collections permit export ([S03](https://pro.dp.la/developers/field-reference), [S17](https://pro.dp.la/developers/bulk-download), [S20](https://omeka.org/s/docs/user-manual/importexport/), [S12](https://iiif.io/api/presentation/3.0/)).

Evidence-based exclusion is appropriate per source/field if a collection’s published terms or owner instruction restrict metadata redistribution, the record contains personal/restricted content, scope/attribution cannot be preserved, or the export would accidentally include the digitized object. In that case retain the option in product scope for eligible records, omit the disallowed fields or withhold that record’s download, explain which collection rule applies, and link to the source. Do not exclude the supported option globally merely because an aggregator lacks it.

## Method contrast

Research questions sharing a governing source were grouped: OAI dates/tokens/deletions; EDM/DPLA object and rights scope; RightsStatements/CC statement conditions; IIIF visible text/links; SKOS/PROV mapping history; Omeka import/export behavior. The same neighborhood was read once, then each distinct condition was applied to its own question. Compared with ordinary sequential clause-by-clause review, this avoids re-reading the same specification and leaves more time for source-version and exception checks without dropping an obligation. No separate competent-reference artifact or measured reference performance was an allowed stage input; this is a method-level contrast, not an empirical benchmark.
