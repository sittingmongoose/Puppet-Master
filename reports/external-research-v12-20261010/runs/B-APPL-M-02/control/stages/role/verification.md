# Python 3.13 pathlib inventory claims

Scope: target CPython 3.13 on POSIX; documentation reviewed is Python 3.13.16. `rglob('*')` is interpreted as converting the recursive iterator to a list. Citations refer to primary Python documentation.

1. **Supported, bounded.** For `Path.rglob('*')`, dot-prefixed names such as `.env` are not special or excluded by pathlib’s glob matching rules; unlike `glob.glob`, it behaves like `include_hidden=True`. This concerns pattern matching, not a promise that every entry can be read. [Python 3.13.16 pathlib, “Comparison to the glob module”](https://docs.python.org/3.13/library/pathlib.html#comparison-to-the-glob-module); [Python 3.13.16 glob, module rules](https://docs.python.org/3.13/library/glob.html#glob.glob).

2. **Rejected.** `Path.rglob` does not promise a sorted list: it yields matches in no particular order. Converting it with `list(...)` preserves that unspecified traversal order. Bounded wording: explicitly sort collected paths when a stable order is needed; sorting cannot stabilize which entries are observed during concurrent changes. [Python 3.13.16 pathlib, `Path.rglob`](https://docs.python.org/3.13/library/pathlib.html#pathlib.Path.rglob).

3. **Supported, with scope.** In 3.13, `recurse_symlinks=False` is the default; recursive `**` expansion does not follow symlinks. This does not mean every operation ignores symlinks: pathlib says it follows symlinks except while expanding `**`, so the symlink entry itself may still be returned. [Python 3.13.16 pathlib, `Path.rglob` and comparison](https://docs.python.org/3.13/library/pathlib.html#pathlib.Path.rglob).

4. **Rejected.** In 3.13, `Path.rglob` suppresses `OSError` raised while scanning, including `PermissionError` for directories without read permission. A denied subtree therefore is not guaranteed to raise; entries below it may be absent without a propagated exception. This scanning rule is version-specific; earlier releases suppressed such errors in many, but not all, cases. [Python 3.13.16 pathlib, `Path.rglob`; 3.13 change note](https://docs.python.org/3.13/library/pathlib.html#pathlib.Path.rglob).

5. **Rejected.** `glob.glob('~/project/*')` does not expand `~`; the module does not invoke a shell. Bounded wording: explicitly apply `os.path.expanduser` (or equivalent path expansion) before globbing, and confirm the runtime’s home-directory resolution. [Python 3.13.16 glob, module introduction](https://docs.python.org/3.13/library/glob.html#module-glob).

6. **Rejected / unsupported as a combined guarantee.** The `Path.rglob` contract states neither a complete point-in-time inventory nor a sub-100-ms duration. Separately, pathlib’s `Path.iterdir` documentation leaves membership unspecified when entries change after iterator creation; `glob.glob` likewise leaves inclusion of entries added or removed during a call unspecified. These are not an explicit mutation guarantee for `rglob`, but they provide no basis for asserting one. Also, `rglob` suppresses scan errors, and pathlib warns that recursive `**` visits every directory and large trees may take a long time. The glob docs warn recursive scans of large trees may take an inordinate amount of time. Inference: with mutation and inaccessible directories in scope, results can differ from a complete snapshot. No tree size, storage, filesystem, host, workload benchmark, or stabilized snapshot is supplied, so no latency or completeness guarantee follows. To evaluate a stronger requirement, specify snapshot/quiescence conditions, permissions and symlink scope, a representative deployment, and measured workload/threshold. [Python 3.13.16 pathlib, `Path.rglob`, `Path.iterdir`, and pattern language](https://docs.python.org/3.13/library/pathlib.html#pathlib.Path.rglob); [Python 3.13.16 glob, `glob.glob`](https://docs.python.org/3.13/library/glob.html#glob.glob).

## Acceptance checks

1. On target CPython 3.13, run as a non-root POSIX account against a controlled tree containing `.env`, `src/main.py`, a directory symlink to an external marker, and a mode-denied subtree. Check that `.env` and `src/main.py` match, the symlink may be listed but its target marker is not traversed through `**`, and scanning does not rely on `PermissionError` propagation. Record the denied subtree’s omitted contents as an applicability limit.
2. For any deployment-specific completeness and under-100-ms requirement, use a representative, stable/quiesced fixture and host/filesystem; define intended scope and symlink/permission policy; compare sorted output with an independent expected inventory; and measure repeated scans against a pre-agreed statistic and threshold. If unreadable contents remain in scope, fail the completeness check unless the policy explicitly accounts for their omission. Such measurements support only the tested deployment and workload, not a universal API guarantee.

These are proposed checks; neither was executed in this verification.
