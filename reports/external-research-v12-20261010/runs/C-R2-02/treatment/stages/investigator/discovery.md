# Investigator discovery — C-R2-02-treatment

## Scope and boundaries

I used only the assigned brief as the case question. It describes a synthetic planning problem in scholarly information retrieval: a university group wants a reproducible pilot to improve discovery of local observational studies and municipal reports about urban-heat interventions, while retaining each study’s identity and provenance. There is no supplied search export or known complete reference set. This is a discovery-method proposal, not a systematic review and not a conclusion about intervention effectiveness.

The full brief’s obligations are carried forward here: separate discovery coverage, screening workload, and identity accuracy; compare query/database changes with citation and repository discovery and a manual or expert-curated alternative; handle reports, versions, ambiguous titles, and geographic terms without automatic duplicate assumptions; specify what previous searches/implementations must disclose; and propose auditable sampling, comparison, provenance, uncertainty, and a clear split between work actually done and future validation. I preserve the brief’s prohibitions on invented recall, effectiveness conclusions from search yield, restricted-service scraping, private accounts, author contact, building a search product, and deletion of ambiguous records.

Intervention scope, language, jurisdictions, dates, inclusion rules, approved access, and later screening time are unresolved. These are protocol decisions, not facts to infer from the case. A comparison with no fixed eligibility and jurisdiction definitions is not interpretable.

## Discovery method actually used

I executed public-web desk searches between 2026-10-10 05:49 and 05:53 UTC for official OpenAlex, Crossref, Zotero, ASReview, PRISMA-S, and Cochrane documentation, ASReview release history, and prior urban-heat review/search strategies. I then opened and read the primary-source pages and the Québec public-health report listed in source-map.json. The browser response-observation times, exact source URLs, versions or missing version pins, locators, observed mechanics, conditions, and applicability are in the source map and sources/index.md.

No database/API query, municipal-portal search, repository crawl, title retrieval, screening, duplicate adjudication, or evidence-yield calculation was run. No source records about a selected intervention or jurisdiction were sought because the brief leaves those decisions open. These are proposed pilot actions below, not executed checks.

## Useful approaches and alternatives

### 1. Terminology/database search arm

Build an eligibility matrix before selecting terms. After scope decisions, have an information specialist and a subject reviewer define concept blocks for urban setting/heat, the eligible intervention or intervention family, outcome/study design if the brief’s later rules require it, and jurisdictional language. In each database, combine synonyms with OR within a concept and concepts with AND; use the platform’s controlled vocabulary where available, alongside title/abstract/free-text terms. Keep a broad terminology arm and a changed-term arm, with otherwise identical source, date, field, language, and eligibility limits. Candidate variants to test only after the concept set is approved include urban heat island/UHI, urban heat, heat mitigation/adaptation/resilience, and named intervention families such as urban forestry, shade, cool roofs/pavements, and blue-green infrastructure. These are candidate vocabulary, not final inclusion categories.

OpenAlex is a useful no-cost-to-start discovery/API candidate: its current works search can cover title, abstract, full text where represented, and keywords; supports field-specific search, phrases, wildcards/fuzzy forms, and a semantic option. The exact behavior matters: default relevance is not a neutral coverage order because citation count contributes to ranking; full text is only available for a subset; and a ranked top-N should not be treated as an exhaustive export. Freeze the request URL, date, response/cursor, selected fields, software/API version if exposed, and all pages. Compare field-scoped and broader queries on the same frozen scope. It is an alternative source and query engine, not a complete municipal-report index [S005].

Crossref REST is a complementary open metadata/identifier route. It exposes records deposited by Crossref members and trusted sources, supports the works/type/filter endpoints, and documents a report type and approved-date filters for report records. This can help locate DOI-bearing reports or resolve/verify cited items. Its governing condition is deposition/metadata representation: a local report absent from Crossref cannot be recovered with a report-type filter, and type/metadata quality is depositor-dependent. Use it as a supplement to—not a denominator for—the city-report arm [S006–S007].

Use terminology variation as an experimental arm, not an uncontrolled widening exercise. Translate the approved core strategy for each platform; do not copy database syntax between platforms. Record the exact string as run, fields, controlled vocabulary version, limits, interface, date/time, hit counts, and raw exports. One change per arm makes differences attributable. A PRESS-style librarian review should check conceptual coverage, Boolean/proximity logic, spelling, and platform translation before the pilot. Cochrane notes that search development is iterative and stopping rules have little formal evaluation, especially cautioning against stopping too early in scarce-evidence topics [S002–S003].

### 2. Citation, repository, and municipal-source arm

Citation discovery tests a different failure mode from lexical query expansion. Start from a deliberately varied seed set selected under the approved inclusion rules (not merely famous reviews); backward-check reference lists and forward-check citing records for each seed and relevant review. Where a public citation index is used, name the index, its date, each base record, direction (cited/citing), depth, and stopping rule. Preserve source-specific record IDs and the citation edge, not just the linked title. Check newly found eligible-looking items against all previous routes before adding them. Cochrane treats citation/reference checking as an adequacy check, not proof of completeness, and PRISMA-S asks that the base items and specific citation-search method be reported [S002–S003, S001].

For reports, repositories, and official implementation records, first define eligible jurisdictions and organization types. Create a finite source frame: official city/regional planning, sustainability, public-health, environment, and open-data repositories; regional or national institutional repositories; and any relevant public repository directory or aggregator identified by the information specialist. Search the source websites directly where possible, because generalized indexes may not represent their holdings. Do not assume that a report is absent because it lacks a DOI, abstract, or standard article title. Capture repository/portal, exact query, date, result page or result cap, item URL/identifier, owning body, and document/version clues. Check both common-language and official/local place names and translations, retaining each original spelling and the mapping used. Keep public access routes only; do not scrape restricted services or bypass access controls.

A useful manual alternative is a small, predeclared hand-search of named municipal/regional report portals and a source-list curated by an information specialist plus an internal local heat/planning subject expert. Make the source frame explicit and finite; log who suggested each site, why it belongs, what was searched, how far it was screened, and what was found. This alternative is more tailored to local reports but has a person/site-selection bias, so it must be compared against query and citation routes rather than declared superior. Do not contact authors; any expert curation here is internal/prospective.

### 3. Screening and record identity

ASReview LAB is an optional screening-workload aid, not a discovery route or recall oracle. Its v3.0.8 documentation says the “not relevant since last relevant” threshold is not set by default; once a chosen threshold is reached it asks the user whether to stop or continue. The tool’s guidance says the ideal threshold remains under study. If used, prespecify and report the model, feature extraction, seeds/prior knowledge, version/commit, labels, ranking, stopping rule, reviewer decisions, unseen-record audit, and export. A time-saving estimate or long run of irrelevant records cannot establish that another eligible local study was not missed [S009–S010]. ASReview releases v3.0.5–v3.0.8 include fixes to decision migrations, retry-safe project import, database locking, ranking-table persistence, and a corrupt record identifier in a saved ranking; this history makes version pinning and export/reopen checks prudent for any live pilot [S010]. The pilot can instead use conventional blinded title/abstract screening if tooling overhead is not justified.

Zotero’s duplicate view can help surface candidates, but should not decide study identity. Its current documentation describes title/DOI/ISBN matching, then year proximity and creator-list overlap under stated conditions; matching is confined to one library, and the page says false positives cannot be marked as non-duplicates. Zotero supports human selection and merge, but deleting or merging an ambiguous pair would destroy a distinction the brief explicitly asks to preserve. Treat any software flag as a reversible candidate edge. Keep the original source records and let adjudicators resolve identity [S008].

Use three linked entities:
1. **Source record**: the untouched record returned by one search source, with source ID, retrieval time, raw citation/title, and exported fields.
2. **Document/version**: a particular report/article/preprint/repository artifact, with DOI or report/contract number where present, repository accession, stable URL, issuing body, language, date, edition/version, and relations such as “preprint of,” “revised version of,” or “same study as.”
3. **Underlying study**: an observational investigation/data collection, with place, population/data, observation period, intervention, design, and its own stable local study ID.

Store raw and normalized titles separately; normalization is only for candidate generation. A similar title, shared institution, city, or year is not sufficient to merge. Maintain explicit candidate-pair states: same source record repeated; same document with metadata variants; distinct document versions of the same study; distinct studies with similar names; or unresolved. Record each field’s source and confidence. Keep ambiguous pairs linked but unresolved; never remove them to improve appearance. For versions that report the same underlying study, preserve every document and indicate which version is used for which evidence.

For identity adjudication, use a human-reviewed decision table. Two reviewers independently judge every proposed merge and a sample of pairs the software did not flag, using DOI/report number, authors/issuing body, date/version, place, study period/design, and content. A third reviewer resolves disagreements; absent evidence remains uncertain. Report precision among flagged pairs, missed duplicate/related-version rate in the audited unflagged sample, false merges, unresolved pairs, and agreement. Distinguish duplicate records of one document from multiple documents of one study. Identifiers and title similarity can propose links; neither substitutes for this adjudication.

## Reproducible pilot and comparison

1. **Decisions first.** Approve intervention definitions, target study designs and outcomes, what counts as local/observational, eligible report types, jurisdictions and geographic hierarchy, languages and transliteration/translation handling, date limits and date field, inclusion/exclusion rules, permitted sources/access, and the later screening hours available. Record owner, decision, date, and provisional/settled status. Any provisional decisions must be fixed across comparison arms.
2. **Protocol and source frame.** Write the eligibility matrix, term blocks and controlled vocabulary, source list, arm definitions, exact capture/export fields, dedup/identity rules, reviewer training examples, and stop rules. Have an information specialist review the database queries. Test the plan on a small set of independently identified “known” items only as a retrieval check; do not use that convenience set as a recall denominator.
3. **Freeze comparable searches.** Run a baseline terminology search and one changed-terminology/database arm over the same sources, years, languages, and scope. Run backward/forward citation discovery and the finite repository/manual arm independently. Save unmodified results, raw counts by source/arm, query strings, timestamps, API/export metadata, and software/API versions. Avoid mixing updates or later dedup decisions into the initial yield.
4. **Sample and screen.** For a small pilot, screen all retrieved records if feasible. Otherwise, use a reproducible random sample within each source × arm × document-type × language × year stratum, publish the random seed, and keep an oversample of records unique to each route so incremental yield is visible. Screen records blind to route when practical; double-screen a prespecified subset and all uncertain/likely eligible reports. At full-text stage, document access failures and reasons for exclusion. Preserve the unscreened remainder and label it as unassessed, not irrelevant.
5. **Measure three outcomes separately.**
   - **Discovery:** raw records, distinct documents, distinct underlying studies, eligible studies/documents found in the screened sample, unique eligible yield by route, and cross-route overlap. Report coverage as an observed yield under this protocol; do not call it recall or claim completeness.
   - **Screening workload:** records to title/abstract and full text, reviewer-minutes per stage, agreement/disagreements, records requiring manual report retrieval, and time per confirmed eligible study. Compare at equal reviewer-hours or equal screened records as well as total yield.
   - **Identity quality:** candidate links adjudicated, false merge rate, missed links in audited unflagged pairs, same-study multi-version counts, unresolved identities, and metadata-field provenance completeness. Counts of database hits alone establish none of these.
6. **Uncertainty and stopping.** Tag uncertainty separately for eligibility, document version, study linkage, geography, language, and access. Use two independent routes as triangulation, not as an exhaustive reference corpus. Stop each route only at a predeclared boundary (for example a fixed source/site list and page cap, or a prespecified consecutive-run rule), record the boundary and any remaining queue, and report uncertainty. In a sparse field, a long no-hit run is not assurance. Re-run neither queries nor silent updates without preserving the prior version and recording the delta.
7. **Report it so another team can replay it.** Follow PRISMA-S’s exact-query, other-methods, citation-search, source-by-source count, and deduplication disclosure. Preserve raw exports and hashes, query translation, controlled-vocabulary versions, source identity and applicable API/software version, source routes and site lists, date/access conditions, reviewer labels/adjudication, stop rules, and version relations in an open, navigable index. A prior effort’s headline hit count is not informative without these records [S001].

## Prior collection implementation: what it shows

INSPQ’s 2021 Québec “Urban Heat Island Mitigation Strategies” update is a close, primary-source comparator. It aimed to compile measures potentially applicable to Québec and explicitly combined scientific and grey literature with librarian assistance. Appendix 1 reports six scholarly database/platform searches on 2020-07-06; English/French terminology plus controlled and free-text terms; UHI × mitigation concepts; title/abstract/author keywords; and a 2009–2020 publication window. It reports 4,487 scientific records, 985 removed as duplicates, and two-stage selection; the final project includes 23 reviews plus 32 original articles selected to add material not already in the preferred review. Its grey route used Google, Google Scholar, and named public agencies, bilingual terms, quoted phrases, and an intitle operator; searches stopped when results no longer seemed relevant; the reported window was 2009–2021 [S004].

This documents a real, locally relevant, bilingual, mixed database/grey search and demonstrates why citation/report totals need route-level methods. The public appendix is unusually useful because it gives databases, fields, concept logic, languages, dates, and example strings. It does not, in the cited method passage, give a separate gray-route count/yield by portal or an auditable fixed stop boundary; “no longer seemed relevant” is judgment-based. The 4,487/985 figures are explicitly the scientific-search stream, so they cannot be read as total evidence collection coverage or as a local-report benchmark. Its inclusion rules and climate/geographic frame also cannot be transplanted to this case without owner decisions.

ASReview’s release history is a second implementation record, for screening state rather than source coverage: releases explicitly corrected prior-label ingestion, decision migrations, import retry behavior, database locks, ranking persistence, and record-ID serialization. This history supports a small export/reopen and decision-retention check before using active-learning prioritization, but says nothing about which records a search source contains [S010].

## Conclusions bounded by evidence

There is no known complete reference set. The pilot can compare discovery routes by unique, adjudicated eligible material observed per source and per reviewer-hour, and can estimate identity error rates on a clearly sampled audit; it cannot report corpus recall. Lexical/database changes, forward/backward citations, curated local portals, and an internal expert/librarian hand-search should remain distinct arms. Each can contribute differently. A high raw count may mean more noise, duplicate manifestations, or better recall; only independent eligibility and identity review can distinguish them.

The appropriate deliverable is a protocol and testable pilot, not an application, completed systematic review, or intervention-effect conclusion. Validation proposed above has not been run in this investigator stage.
