## Initial recommendation and product alternatives

Treat each submitted citation as an auditable contribution, not as a record to overwrite. Keep its exact submitted text and submitter credit immutable; assign an internal record ID even when DOI, arXiv ID, or other persistent identifier is absent. Maintain reviewed bibliographic fields separately with field-level provenance (value, lookup/provider or submitter, retrieval time, decision state, reviewer, and the prior value). A lookup or possible duplicate should create a review suggestion. Only the bibliography editor approves a merge or correction. A successful merge retains each contributor’s credit and original citation. These are local product recommendations, not features established in Zotero, JabRef, or Crossref.

## Identity, DOI-less entries and version relationships

Use two layers: **record identity** (one citable manifestation) and **work/version relationship** (several related records). DOI equality, when present, is evidence for a registered record; it is not a safe universal key for every scholarly version. Do not collapse records solely by title, author, year, or identifier. Generate duplicate candidates from a weighted set of title/creator/date/identifier evidence, show the compared fields and confidence/evidence, and leave the final decision to the editor. If evidence is insufficient, keep both and mark uncertain. A missing DOI does not make a submission invalid: store the text as submitted, assign a local ID, retain any stable URL or known arXiv/PMID/other identifier, and allow enrichment later.

Crossref offers a useful **analogous reconciliation model**, not a volunteer-facing merge tool: separate records can be linked with typed `isPreprintOf`/`hasPreprint`, `isVersionOf`/`hasVersion`, `isVariantFormOf`, and other relations. Crossref’s posted-content schema distinguishes preprints and can carry version numbers, status, DOI and a relation to an accepted manuscript/version of record [S16–S18]. In Crossref’s workflow, a title-plus-first-author match is a possible relation for review; Crossref notes deposited links can be missing. Its published matching dataset was explicitly limited to selected existing record types/subtypes through August 2023 [S19]. Therefore represent a preprint and later journal article as distinct candidate records linked by an approved typed edge; the edge is neither a duplicate merge nor proof every pair will be found. Crossref’s model is evidence for one provider’s practice, not a universal PID rule.

## Enrichment and a bounded failure history

A no-account lookup path is feasible: Crossref says its public REST API needs no signup, exposes member-deposited metadata, and supports DOI retrieval and search [S13–S14]. Requests/rate limits are governed by response headers; cache, identify politely only if the lead approves, and back off on 429s [S14–S15]. JabRef documents identifier discovery and a DOI/ISBN field-review dialog [S08]. These records support **lookup suggestions**, not automatic truth. Preserve the query and provider result with its date and fields; show alternatives and conflicts; let the editor apply an approved correction. Crossref’s coverage reflects its own deposits, and its docs warn limits/requests can fail; missing result is not evidence that a work does not exist.

A concrete, released import/export defect narrows validation: JabRef issue #15106 was reported against 5.15. With a BibTeX `pages` value `13905--13911`, RIS export put the entire range into both `SP` and `EP`; the report says a single dash worked. PR #15315 addressed en/em dash parsing, and official JabRef release notes list #15106 as fixed in v6.0-alpha.6 (commit `6d24100`), before the inspected v6.0-beta.1 (`3992b12`) [S10–S12]. This affected the exported start/end-page fields for the reported range encoding, not necessarily every citation or all RIS fields. A pilot should test both BibTeX double-dash and single-dash ranges against explicit RIS `SP`/`EP` expectations on its pinned release. This is an observed issue/release history, not a test run by this investigator.

## Export, constraints and initial validation priorities

Retain the optional downloadable-bibliography scope. Recommend an **opt-in RIS download** of the approved citation list, with title, creators, year, item/version label, DOI where present, and stable source/publisher URL; never include attachment files or paper content. RIS is documented as an import format by Zotero [S02] and supported by its bibliography/Quick Copy workflow [S05]; JabRef documents interchange and conversion [S09]. This is an authorized option, not a required default or proven app capability. Publish it only after pinned-version round-trip fixtures show DOI/URL, preprint/journal type labels, pages, Unicode, and multiple authors remain useful. If the relationship/provenance fields do not survive, keep them in the product ledger and accompany the public file with plain labeled links; do not claim RIS preserves the internal audit history. No evidence justifies excluding the option outright.

**Owner decisions, still open:** the bibliography editor approves each merge and metadata correction; submitters remain credited and their original citation text stays available; the group lead chooses public presentation style and acceptable lookup provider(s). Provider choice should include whether Crossref-only coverage is adequate, whether any email identifier is acceptable for polite access, and what to show on no-match/conflict. No source can decide these policy choices.

**Negative constraints preserved:** no paywalled paper downloads, no contributor accounts, no assumption one DOI uniquely identifies every version, and no silent preprint/journal merge. Product docs expose PDF/file retrieval routes; the proposed pilot omits those routes. Output contains citations and links only.
