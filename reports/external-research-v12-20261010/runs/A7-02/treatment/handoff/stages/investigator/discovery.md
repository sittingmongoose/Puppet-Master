# Discovery: volunteer reading-list citation curation

## Scope and evidence boundary
The brief describes a monthly, pilot-scale volunteer workflow: accept citations, reconcile duplicates, repair obvious metadata, retain the submitted citation, and optionally export to reference managers. This discovery compares Zotero and Paperpile workflows and uses OpenRefine as an analogous reconciliation pattern. Research consisted of read-only retrieval of public first-party documentation and public issue/fix/release history. No products were operated, no account was created, no metadata API query was issued, and no product implementation was validated. Product checks remain **NOT_RUN**; validation ideas below are proposals only. No article downloads or full-text inspection were used.

## Candidate workflows and tradeoffs
Zotero accepts identifiers such as ISBN, DOI, PMID, arXiv ID, and ADS Bibcode for item creation; its documentation warns that retrieved metadata may be incomplete or incorrect and should be checked [S01]. Its duplicate detector is documented as a library-local, field/heuristic process, and merge allows field conflicts to be chosen. The documented title/DOI/ISBN and year/creator rules are described in a page last updated in 2017, so exact current behavior must be checked against a selected released build before relying on it [S02]. Zotero distinguishes Preprint from Journal Article by publication/review status and provides fields that do not make a DOI mandatory [S03]. Its standardized imports include BibTeX, BibLaTeX, RIS, and CSL JSON; its export guidance warns that exports are not backups and can lose app-specific data [S04][S05]. Bibliography/Quick Copy supports formatted output and BibTeX/RIS; exporter preferences expose separate file, note, and tag toggles, which should be explicitly controlled for a shared export [S06][S07].

Paperpile imports RIS/BibTeX with “Skip duplicates” on by default; only the first occurrence of an intra-file duplicate is imported under that mode [S08]. Its duplicate help says it detects records by identifiers (including DOI, arXiv ID, ISBN, PMID/PMC ID) or exact metadata when no common identifier exists; users can dismiss a false match, and merge can consolidate fields, attachments, folders, and labels while moving originals to Trash. Different metadata without a shared identifier can evade detection [S09]. Export supports BibTeX, RIS, CSV, and JSON; the page calls RIS an industry standard and BibTeX widely supported, while warning its JSON is internal and not re-importable [S10]. Online search presents candidates for adding [S11]. The official indexed help result for Auto Update describes candidate selection, field-difference preview, Apply/close-discard, and per-record no-match/up-to-date outcomes; the page could not be opened directly in this session, and no interface was exercised [S12].

These products show useful workflows, not a product decision. Zotero's older published matching rules warrant version verification. Paperpile's default duplicate skipping is efficient but can conceal which submitter supplied a dropped citation unless our intake ledger remains authoritative. Neither application preserves the volunteer's exact raw citation and credit by itself as a guaranteed group-level audit contract. OpenRefine offers a useful model: reconciliation yields candidate links while retaining the original cell text, and the user selects among candidates; confidence scoring and provider behavior vary [S13][S14]. Its clustering feature is primarily syntactic, so it is not by itself a scholarly-identity resolver [S15].

## Identity, version, correction, and export model
Treat a submitted citation, a bibliographic work, and a citable version as related but distinct concepts. DOI is optional; a DOI-less record may still have a title, author, year, venue, URL, arXiv identifier, or other evidence. Crossref Simple Text Query may return several DOI candidates or no unique match when the citation is insufficient; its result is a lookup proposal, not authority to overwrite a record [S16]. Crossref records are deposited by members and may be incomplete; public REST access has documented usage limits and a polite-pool path [S17][S18]. Crossref's typed relations include `isPreprintOf`/`hasPreprint`, while DataCite guidance allows version relationships and explains that versions may use the same or different DOI depending on material change and stewardship choices [S19][S20][S21]. Consequently, do not infer that one DOI identifies every scholarly version, or silently merge preprint and journal article.

Proposed data flow: immutable submission entry with submitter credit, exact raw text, and intake time; one or more curated version records; explicit same-record/duplicate decisions separate from typed version relations; lookup proposals storing provider, query, retrieval time, returned identifiers, and field-by-field differences; and an editor decision record. Preserve both submitted values and corrected values with provenance. Show no-hit and ambiguous results without edits. A lookup result is not an authoritative correction until an editor approves it. The group lead chooses whether to permit Crossref, DataCite, arXiv, or another provider; use only approved public read-only routes and stay within documented limits.

Keep bibliography download optional and authorized. A pilot should offer RIS and BibTeX because both compared managers support them [S04][S08][S10]. Export citation metadata and links only; exclude full text, attachments, and unnecessary notes. Zotero exporter documentation exposes file/note/tag options, so turn off attachment/file and note export explicitly and review tag handling [S07]. The group lead chooses the primary format, citation style, and lookup providers. If actual common-reader round trips show a selected format cannot preserve required metadata safely, defer that format pending a decision rather than silently dropping fields.

## Released defect/fix example and applicability
JabRef issue #15106 reports that in JabRef 5.15, exporting a BibTeX page range containing double hyphen (for example `13905--13911`) to RIS put the entire range in both `SP` and `EP`; a single hyphen worked. The issue was closed via PR #15315. The PR changes range parsing to accept en/em dashes, and the fix appears in the JabRef `v6.0-alpha.6` prerelease dated 2026-05-14 [S22][S23][S24]. This is a concrete importer/exporter boundary regression: a malformed output may affect page fields on records with that input form, so inspect representative pages after export/import and preserve the source citation. It does not establish a general RIS failure or prove behavior in another product/version.

## Obligation coverage and open decisions
1. **Two workflows and an analogous mechanism:** Zotero, Paperpile, and OpenRefine are compared above, including strengths and limitations [S01–S15]. Alternative: use a plain reviewed CSV intake sheet with no automatic matcher; this is simpler but still needs an explicit provenance and export process.
2. **DOI-less items, preprint/journal versions, duplicates, and metadata preservation:** use optional identifiers, separate version records, typed relations, immutable raw submission, and editor-reviewed duplicate decisions [S02][S03][S09][S16][S19–S21]. Never merge merely on title or DOI.
3. **Optional export/enrichment and approval:** make both optional; retain lookup result separately from accepted values, show field diffs, and require editor action [S12][S13][S16].
4. **Released failure chain:** JabRef 5.15 report → PR #15315 → `v6.0-alpha.6`; impact is limited to described page-range conversion [S22–S24].
5. **Downloadable bibliography:** conditionally retain it as an authorized optional metadata-and-link-only RIS/BibTeX output; review field preservation and selected readers before enabling [S04][S05][S07][S10].
6. **Authority and credit:** editor approves merges/corrections; submitters retain credit and verbatim raw citation; group lead decides style and lookup providers. These are owner rules from the brief, not research conclusions.
7. **Negative constraints:** no paywalled/full-text downloads, contributor accounts, presumed universal DOI identity, or silent preprint/journal merging. No retrieval in this research path required a new account; the Crossref public API is documented as unauthenticated, but any provider still needs lead approval [S17][S18].
8. **Proposal and validation:** proposal is evidence-backed but unimplemented. Run the proposed checks only after owners select a workflow, build, format, and provider; record actual executions separately from research. The source review itself is not product validation.

## Proposed validation matrix (all NOT_RUN)
- Same DOI and same metadata; DOI absent but exact citation match; same title with different authors/years; duplicate within one batch; and DOI collision or provider ambiguity. Verify suggestions never auto-merge and false positives can be rejected.
- A preprint and journal version with shared title/authors but distinct types/identifiers. Verify two records survive and a typed relation can be stored without merging.
- DOI-less citation with arXiv ID, URL, or sufficient title/author metadata; no-result and multi-result lookup. Verify raw input remains byte-for-byte intact until editor acceptance and candidate provenance/field diffs remain inspectable.
- Correction and merge across multiple submitters. Verify each submitter credit and exact raw citation remain retrievable, and each field decision records editor, old/new values, and source.
- Round-trip RIS and BibTeX through the selected supported reader(s), covering DOI-present, DOI-less, Unicode authors, URLs, page ranges including double hyphen, tags, and two related versions. Compare item counts and every required field; explicitly confirm no file/attachment or full-text export.
- Test optional export disabled/enabled, approved provider configuration, rate-limit/backoff behavior, and group-lead-selected citation style. These are proposed checks, not execution claims.
