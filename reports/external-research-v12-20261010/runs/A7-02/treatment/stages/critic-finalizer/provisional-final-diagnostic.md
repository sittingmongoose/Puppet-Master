# Research proposal: volunteer reading-list citation curation

## Recommendation and evidence boundary

Use an app-independent, editor-reviewed citation ledger as the pilot’s record of truth. Keep one intake row for every submission, preserve submitter credit and the exact citation text, and store parsed/corrected fields, candidate matches, version relationships, and editor decisions separately. Similarity, a shared DOI, or a metadata lookup may suggest a review candidate; none authorizes an automatic merge or correction.

Zotero and Paperpile are both plausible curator tools. Zotero offers identifier-based item creation, item types that distinguish preprints from journal articles, and configurable exporter controls. Its duplicate help page is dated 2017, and its browser connector may save accessible PDFs, so any pilot must check a selected build and avoid connector/file workflows. Paperpile documents RIS/BibTeX import and export, online search, a duplicate-dismiss action, and a default import option that skips duplicates. Its metadata-update help page could not be opened directly in this research, so that interface remains uncertain. Neither product is documented here as guaranteeing the group-level preservation and audit trail the volunteers need. A reviewed CSV ledger is a lower-dependency alternative, but still needs deliberate provenance and interchange testing.

This is a planning proposal based on read-only public primary-source review. I did not install or operate a manager, create an account, call an API, import/export records, download a paper, or make a metadata correction. Product behavior and all proposed pilot checks remain unvalidated. The evidence index is [sources/index.md](sources/index.md), with exact URLs, version cues, locators, access records, conditions, and applicability in [source-map.json](source-map.json).

## Proposed pilot workflow

1. **Capture each submission.** Create a unique submission row with submitter credit, intake time/source when available, and the exact original citation text. Never discard a row because an importer skips it or a curator later judges it to be a duplicate.
2. **Parse without replacing the original.** Store title, creators, year, venue, page range, URL, and submitted identifiers as working values with field-level provenance. Normalization may help search; normalized strings are not identity decisions.
3. **Offer candidates with reasons.** Use whichever fields are present—identifiers, title, creators, date, venue, URL, and publication type—to surface possible duplicates or related versions. Show which fields support the suggestion and preserve “uncertain” and “no candidate” outcomes. Require editor review before a merge or authoritative correction.
4. **Represent record identity separately from version relations.** Keep distinct citable records for a preprint and a later journal publication when they are distinct states. If confirmed, record a typed relationship such as “preprint of” or “version of.” A relationship links records; it does not collapse them. A DOI can be absent, can be reused for some updates under a repository’s versioning policy, or can differ across versions [S19–S21].
5. **Keep lookup results as proposals.** Store provider, query basis, retrieval time, returned identifiers, and field-by-field differences. Keep the result even if rejected; apply only the specific field changes an editor accepts. No hit, ambiguity, or provider failure leaves the submission and curated values intact.
6. **Export only after an owner choice and a fixture check.** Keep the downloadable bibliography as an authorized optional capability. Consider RIS and BibTeX because both compared managers document those interchange paths [S04, S08, S10]. Do not assume they preserve every required field: test the chosen exporter/importer builds and target reader first. Export citation metadata and links only—no article files, full text, or unnecessary notes. For Zotero, do not use the browser Connector or direct-PDF save path for this pilot, and explicitly turn off file export. For Paperpile, do not upload PDFs or attachment paths alongside RIS/BibTeX. If a format loses a required field, revise the export profile or defer that format; do not silently lose data [S01, S07–S10].
7. **Record decisions and reversals.** For each accepted merge or correction, record the editor, time, evidence, old/new values, and rationale. Keep the submission rows available even after a curated citation is consolidated.

A minimal model would contain: `submission_id`, submitter credit, intake time, exact `raw_citation`, parsed values with per-field provenance, one or more `citation_version_id` records with type and optional identifiers, candidate-match decisions, typed version relations, provider query/result snapshots, editor decisions, and export profile/version. This schema is proposed, not implemented.

## DOI-less citations, duplicates, versions, and corrections

A missing DOI does not exclude a citation. Retain whatever the submitter provided and allow manual curation. If the group lead approves Crossref or another lookup provider, a citation query may produce multiple possible DOIs or insufficient evidence for a single match; Crossref asks users to evaluate multiple results [S16]. No query was issued here. A local “no candidate” state is a proposed interface requirement, not an observed response from a particular service. Do not manufacture an identifier to fill a blank.

Treat a submission, a bibliographic work, and a citable version as related but distinct concepts. A preprint and its journal-published form may have different publication status and different identifiers. Zotero documents separate Preprint and Journal Article types [S03]. Crossref supports typed preprint relationships [S19]. DataCite guidance says the steward may keep the same DOI for a minor change and recommends a new DOI plus a relation for a major version; its preprint guidance notes that separate manuscript versions may be assigned distinct DOIs [S20, S21]. These are registry/stewardship practices, not a universal DOI rule. Never presume one DOI uniquely identifies every scholarly version, and never silently merge a preprint with a journal article.

Duplicate tools find candidates using product-specific fields and rules. Zotero’s current help text is a 2017 description, scoped to one library [S02]. Paperpile documents identifier or exact-metadata matches, a way to dismiss a false positive, and possible misses when there is neither a shared identifier nor an exact enough metadata match [S09]. Neither rule defines truth for the group. Editors approve every merge after considering version/type, creators, dates, venue, and identifier evidence. Preserve all contributing submission IDs, credits, and exact strings after any consolidation.

Preserve submitted and curated values independently. For each correction, retain the original value, accepted value, source/provider, retrieval time, and approving editor. A DOI lookup, search ranking, OpenRefine score, imported field, or external deposited record is evidence to inspect—not an editor’s authorization. Crossref says its metadata is primarily deposited by members and may also include Crossref matching/enrichment; public access does not make a result authoritative for this group [S17].

## Optional enrichment and downloadable bibliography

Keep both enrichment and downloadable bibliography optional. The brief authorizes an optional bibliography download; it does not require a format or establish current technical compatibility. RIS and BibTeX are reasonable candidates because both managers document transfer paths for them [S04, S08, S10]. The exact interchange format and required fields remain owner questions. Confirm the default format with the owners rather than assuming the brief assigns that choice. The group lead chooses presentation/citation style and acceptable lookup providers.

If lookup is enabled, use only group-lead-approved public, read-only providers. Crossref’s REST documentation says public access requires no signup; public and polite access have different rate/concurrency limits and the documentation recommends identifying requests, caching, and backing off [S18]. Do not create contributor accounts or query unapproved services. A provider response remains a candidate snapshot; show field differences and require the bibliography editor’s explicit approval before changing a curated field. Paperpile Auto Update may illustrate a preview-and-apply pattern in its official indexed result, but the help page was not directly available during this review; independently verify it in a selected build or implement the group’s own decision contract [S12].

Make citation-only operation an explicit condition, not an assumed export default. Do not use Zotero’s Connector or save a PDF directly; its documentation says the Connector may save accessible or open-access PDFs [S01]. Do not upload PDFs with Paperpile’s RIS/BibTeX import [S08]. Turn off Zotero file export and review note/tag controls [S07]. Paperpile’s library-data export excludes PDFs, but this does not prevent separate PDF upload or download paths [S10]. The pilot publishes citations and links, not paper copies.

**Retention decision for optional export:** Retain the option because it is explicitly authorized and both compared products document RIS/BibTeX paths. Enable a chosen format only after a round-trip fixture confirms the group’s required fields, count, version relations, and attachment exclusion for specified builds/readers. If a format fails, defer that format or revise its profile; do not treat the optional route as mandatory and do not remove the authorized option without evidence.

## Released importer/exporter defect chain

JabRef issue [#15106][S22] reports a narrow BibTeX-to-RIS defect. The reporter names JabRef 5.15 on Ubuntu 24.04.4 LTS and says the then-latest development build also showed the problem. With `pages = {13905--13911}`, the reported RIS output placed the whole range in both `SP` and `EP`; the issue reporter said a single hyphen worked. These are the reporter’s claims, not a reproduction performed in this stage.

PR [#15315][S23] closes the issue, extends the page-splitting pattern to recognize en/em dashes, and gives an expected RIS result of `SP=13905`, `EP=13911`. It merged into `main` on 2026-03-13 as `d687c08`. The JabRef `v6.0-alpha.6` prerelease, tag `6d24100`, published 2026-05-14, lists #15106 as fixed [S24]. This establishes a report → fix → prerelease record for the described conversion. It does not establish behavior in a later stable JabRef release, another exporter, or another manager. Use this page range as a targeted proposed regression fixture; do not call the PR’s tests this stage’s validation.

## Authority, owner choices, and negative constraints

The brief assigns the following authority and rights:

- The **bibliography editor** approves merges and metadata corrections.
- **Submitters** retain credit and their original citation text.
- The **group lead** chooses presentation/citation style and acceptable lookup providers.

No decisions beyond those roles were made in this research. Owners still need to choose whether to use Zotero, Paperpile, or a CSV workflow; which interchange format(s) and output fields are needed; which target readers define compatibility; whether downloads are enabled for the pilot; which provider(s), if any, are approved; and how editor decisions are audited or reversed. The exact interchange format should be confirmed with the owners rather than described as an already delegated group-lead decision.

Binding constraints: do not download paywalled papers; do not create contributor accounts; do not presume a DOI uniquely identifies every scholarly version; and do not silently merge a preprint with a journal article. Because the group publishes citations and links rather than paper copies, keep this pilot citation-only and avoid article/PDF downloads or attachment export altogether. These restrictions were observed during this research: no paper download, account creation, API query, or live write occurred.
