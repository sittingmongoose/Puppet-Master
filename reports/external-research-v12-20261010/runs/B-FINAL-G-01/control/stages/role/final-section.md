### Staged asset mirror

Use rsync 3.2.7 on both peers to mirror a completed build’s asset-directory contents into an isolated staging root. The operator selects source and staging paths; display both resolved paths before preview. Preserve the exact controls <code>protected_dir=local-notes</code>, <code>publish_mode=explicit</code>, and <code>preview_required=true</code>. Use recursive transfer and a trailing slash on the selected source directory so its contents land directly under staging without an extra source-named level. ([rsync(1), “USAGE”](https://download.samba.org/pub/rsync/rsync.1), live upstream manual, unpinned.) The stage must be dedicated to this synchronization.

Use <code>--delete</code> only with recursive synchronization of the whole source directory into that stage. It removes extraneous receiver files only in synchronized directories, not sender files; wildcard-expanded individual files do not define the parent-directory deletion scope. Protect the staging root’s <code>local-notes</code> and descendants with a root-anchored exclude such as <code>/local-notes/***</code>, and omit <code>--delete-excluded</code>. Under default filter rules, an exclude hides matching sender paths and protects matching receiver paths from deletion; <code>--delete-excluded</code> changes ordinary rules to sender-side only. Do not add a later include or risk rule that defeats protection. Check the pattern against the application’s effective transfer root. ([rsync(1), “--delete,” “--delete-excluded,” and “FILTER RULES”](https://download.samba.org/pub/rsync/rsync.1), live upstream manual, unpinned.)

Before destructive transfer, produce a saved, inspectable preview using the same peers, paths, recursive options, filters, and <code>--delete</code>, adding <code>--dry-run --itemize-changes</code>. Require operator approval after confirming the listed deletions are expected obsolete assets inside staging and no <code>local-notes</code> path is listed; then repeat identical options without dry-run. The manual says a dry run makes no changes and itemized output is expected to match a subsequent run except for external source or destination changes and system-call failures. It is a point-in-time preview, not a lock: record path/version/filter identity, recheck source and stage immediately before execution, and cancel for a fresh preview if anything changed. No transfer command is run for this specification. ([rsync(1), “--dry-run”](https://download.samba.org/pub/rsync/rsync.1), live upstream manual, unpinned.)

On rsync success, mark staging complete but unpublished. Provide a separate explicit publish action; never publish automatically on transfer success. <code>--delay-updates</code> holds each updated file and then renames files rapidly to make updates somewhat closer to atomic; it does not commit a full directory tree atomically. Treat rsync completion and application publication as separate state transitions. On cancellation, interruption, or nonzero exit, show an incomplete stage, retain the exit status, diagnostic, and preview/run records, block publication, and require an explicit retry or cleanup decision. Do not promise rollback of staging changes or deletions. Sender-side I/O errors normally disable deletion unless <code>--ignore-errors</code> is enabled; do not enable it, and do not treat this safeguard as rollback. ([rsync(1), “--delete” and “--delay-updates”](https://download.samba.org/pub/rsync/rsync.1), live upstream manual, unpinned.)

### Critique dispositions

1. **Accept.** <code>--delete-excluded</code> removes the receiver-side protection provided by ordinary excludes; remove it and retain an effective exclude/protect rule. ([rsync(1), “--delete-excluded”](https://download.samba.org/pub/rsync/rsync.1))
2. **Reject.** Memory is not an inspectable deletion preview, and the original obligation requires one. The manual recommends a dry run to see proposed deletions. ([rsync(1), “--delete” and “--dry-run”](https://download.samba.org/pub/rsync/rsync.1))
3. **Accept.** Automatic publication violates <code>publish_mode=explicit</code>; delayed per-file renames do not establish whole-tree atomicity. ([rsync(1), “--delay-updates”](https://download.samba.org/pub/rsync/rsync.1))
4. **Reject.** A source trailing slash changes whether the source directory itself or its contents are placed at the destination. Keep it for direct children under staging. ([rsync(1), “USAGE”](https://download.samba.org/pub/rsync/rsync.1))
5. **Accept.** A dry-run/itemized preview can differ from the subsequent run after external tree changes or system-call failures; recheck and re-preview when inputs differ. ([rsync(1), “--dry-run”](https://download.samba.org/pub/rsync/rsync.1))
6. **Reject.** <code>--delete</code> removes extraneous files from the receiving side within synchronized directories. Sender-side removal is a distinct option, <code>--remove-source-files</code>. ([rsync(1), “--delete” and “--remove-source-files”](https://download.samba.org/pub/rsync/rsync.1))

**Remaining uncertainty:** The live manual is unpinned, and this role did not verify actual peer versions, application path/filter behavior, race controls, or publish/cancel implementation. All three checks remain proposed, not executed.
