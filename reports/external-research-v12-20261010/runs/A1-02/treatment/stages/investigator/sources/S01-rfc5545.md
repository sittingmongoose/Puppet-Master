# S01 — RFC 5545

- URL: https://www.rfc-editor.org/rfc/rfc5545.html
- Version: RFC 5545, Standards Track, September 2009.
- Access observation: 2026-10-10T04:00:20Z.
- Locators: §§3.2.19, 3.3.5, 3.3.10, 3.4–3.6.1, 3.6.5, 3.8.4.4, 3.8.4.7, 3.8.5.1–.3, and 3.2.20; exact web line ranges are in `../source-map.json`.

**Observed contract.** UID is the persistent globally unique calendar-component identifier. RECURRENCE-ID identifies one instance within UID; for a moved Friday instance, the recurrence ID remains Friday while DTSTART/DTEND hold the moved time. Its value type matches DTSTART. The recurrence set unions DTSTART, RRULE and RDATE, removes EXDATE values, gives EXDATE precedence, and deduplicates repeated inclusions; an unsynchronized DTSTART/RRULE pair is undefined. DATE-TIME supports floating, UTC, or local with TZID, not arbitrary explicit numeric offsets. Referenced TZID requires a matching VTIMEZONE. A TZID-local fold uses the first occurrence; explicit local gap values use the pre-gap UTC offset; RRULE-generated nonexistent local candidates are ignored and not counted. Without METHOD, do not infer a scheduling transaction. Unknown IANA/X-name value data must be preserved without interpreting it.

**Application.** This is the governing interchange behavior. It does not define the product's supported rule subset, duplicate-resolution UI, or whether a consumer accepts every legal exception/exclusion combination; test those separately.

Additional locator reviewed at 2026-10-10T04:04:04Z: §3.8.5.3, web lines 6585–6598. It confirms recurring local DATE-TIME instances keep the same local time across zone changes; DTSTART/DTEND yields the same exact duration for each recurrence, whereas DURATION yields the same nominal duration and a start-dependent exact elapsed length. A specific instance's duration may be changed in its exception.

Additional locators reviewed at 2026-10-10T04:07:07Z: §3.6.5 (web lines 3471–3478) requires the referenced VTIMEZONE to provide valid information for all recurrence instances; §§3.8.8.1–.2 (lines 7496–7558) allow IANA/non-standard properties to be ignored by a generic consumer. The user's no-silent-drop constraint is stronger, so this product should retain those raw properties even when it does not interpret them.
