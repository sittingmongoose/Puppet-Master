121: Configuring the build
122: Create a working directory and place the OTP jar file in it and call it otp.jar.
123: Since we download the OSM data from a free source, we don't want to put undue stress on the server.
124: Therefore we download it before building the graph, not during.
125: curl https://download.geofabrik.de/europe/norway-latest.osm.pbf -o norway.osm.pbf
126: Now create a file called build-config.json in the same folder and fill it with the following
127: content:
128: // build-config.json
129: {
130: "transitFeeds" : [
131: {
132: "type" : "netex",
133: "feedId" : "NO",
134: "source" : "https://storage.googleapis.com/marduk-production/outbound/netex/rb_norway-aggregated-netex.zip",
135: "sharedFilePattern" : "_stops.xml",
136: "sharedGroupFilePattern" : "_(\\w{3})(_flexible)?_shared_data.xml",
137: "groupFilePattern" : "(\\w{3})_.*\\.xml"
138: }
139: ],
140: "osm" : [
141: {
142: "source" : "norway.osm.pbf",
143: "osmTagMapping" : "norway",
144: "timeZone" : "Europe/Oslo"
145: }
146: ],
147: "osmCacheDataInMem" : true
148: }
149: Note the special section specifying how to find NeTEx XML files within the single ZIP archive that
150: OTP downloads.
151: Now you can instruct OTP to build a graph from this configuration file:
152: java -Xmx16G -jar otp.jar --build --save .
153: This should produce a file graph.obj in the same directory as your build-config.json.
154: Building the Norway graph requires downloading about 250MB of input data so stay patient at the
155: beginning particularly on a slow internet connection. The actual build takes approximately 10
156: minutes (without elevation data, as is configured above), and can be done within 16GB of heap memory
157: (JVM switch -Xmx16G). The Graph file it produces is about 1.1 GB. The server will take about 30
158: seconds to load this graph and start up, and will consume about 6GB of heap memory under light use.
