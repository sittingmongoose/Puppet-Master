445: 4.1.3.  The "metalink:pieces" Element
446: The "metalink:pieces" element acts as a container for a list of
447: cryptographic hashes of contiguous, non-overlapping pieces of the
448: file.  The cryptographic hashes MUST be listed in the same order as
449: the corresponding pieces appear in the file, starting at the
450: beginning of the file.  Metalink Documents MAY contain one or
451: multiple metalink:pieces container elements, if each "type" attribute
452: of metalink:pieces has a unique value.
453: metalinkPieces =
454: element metalink:pieces {
455: attribute length { xsd:positiveInteger },
456: attribute type { text },
457: metalinkHash+
458: }
459: 4.1.3.1.  The "type" Attribute
460: metalink:pieces elements MUST have a "type" attribute.
461: The Internet Assigned Numbers Authority (IANA) registry named "Hash
462: Function Textual Names" defines values for hash types.  See
463: Section 7.4 for security implications.
464: 4.1.3.2.  The "length" Attribute
465: metalink:pieces elements MUST have a "length" attribute, which is a
466: positive integer that describes the length of the pieces of the file
467: in octets.  The whole file is divided into non-overlapping pieces of
468: this length, starting from the beginning of the file.  That is, every
469: piece MUST be the same size, apart from the last piece, which is the
470: remainder.  The last piece extends to the end of the file, and it
471: therefore MAY be shorter than the other pieces.
522: 4.2.4.  The "metalink:hash" Element
523: The "metalink:hash" element is a Text construct that conveys a
524: cryptographic hash for a file.  All hashes are encoded in lowercase
525: hexadecimal format.  Hashes are used to verify the integrity of a
526: complete file or portion of a file to determine if the file has been
527: transferred without any errors.
528: metalinkHash =
529: element metalink:hash {
530: attribute type { text }?,
531: text
532: }
533: Metalink Documents MAY contain one or multiples hashes of a complete
534: file. metalink:hash elements with a "type" attribute MUST contain a
535: hash of the complete file.  In this example, both SHA-1 and SHA-256
536: hashes of the complete file are included.
537: ...
538: <hash type="sha-1">a97fcf6ba9358f8a6f62beee4421863d3e52b080</hash>
539: <hash type="sha-256">fc87941af7fd7f03e53b34af393f4c14923d74...</hash>
540: ...
541: Metalink Documents MAY also contain hashes for individual pieces of a
542: file. metalink:hash elements that are inside a metalink:pieces
543: container element have a hash for that specific piece or chunk of the
544: file, and are of the same hash type as the metalink:pieces element in
545: which they are contained.  Metalink Documents MAY contain one or
546: multiple metalink:pieces container elements, if each "type" attribute
547: of metalink:pieces has a unique value.
548: metalink:hash elements without a "type" attribute MUST contain a hash
549: for that specific piece or chunk of the file and MUST be listed in
550: the same order as the corresponding pieces appear in the file,
551: starting at the beginning of the file.  The size of the piece is
552: equal to the value of the "length" attribute of the metalink:pieces
553: element, apart from the last piece, which is the remainder.  See
554: Section 4.1.3.2 for more information on the size of pieces.
555: Bryan, et al.                Standards Track                   [Page 14]

569: 4.2.4.1.  The "type" Attribute
570: metalink:hash elements MUST have a "type" attribute, if and only if
571: it contains a hash of the complete file.  The IANA registry named
572: "Hash Function Textual Names" defines values for hash types.
573: metalink:hash elements MUST NOT have a "type" attribute, if they are
574: inside a metalink:pieces container element.  See Section 7.4 for
575: security implications.
753: 4.2.14.  The "metalink:size" Element
754: The "metalink:size" element indicates the length of the linked
755: content in octets.  This is the content length of the representation
756: returned when the IRI is mapped to a URI and dereferenced.  Note that
757: the "metalink:size" element MUST override the actual content length
758: of the representation as reported by the underlying protocol, and
759: those that do not match MUST be discarded by Metalink Processors.
760: This value MUST be a non-negative integer.
