89: Full object and composite checksum types
90: In Amazon S3, there are two types of supported checksums:
91: Full object checksums: A full object checksum
92: is calculated based on all of the content of a multipart upload, covering all data from the
93: first byte of the first part to the last byte of the last part. Be aware that if
94: you're using the AWS Management Console to upload objects that are smaller than 16 MB, only
95: the full object checksum type is supported.
96: Note
97: Objects that you upload using PutObject use the full object checksum type. You
98: do not need to specify a checksum type.
99: Composite checksums: A composite checksum is
100: calculated based on the individual checksums of each part in a multipart upload. Instead of
101: computing a checksum based on all of the data content, this approach aggregates
102: the part-level checksums (from the first part to the last) to produce a single,
103: combined checksum for the complete object. You may only use the composite
104: checksum type with certain checksum algorithms and only when using a multipart upload to
105: upload your object. For the algorithms that support each checksum type, see the
106: Multipart uploads section.
107: Note
108: When an object is uploaded as a multipart upload, the entity tag (ETag) for the
109: object is not an MD5 digest of the entire object. Instead, Amazon S3 calculates
110: the MD5 digest of each individual part as it is uploaded. The MD5 digests
111: are used to determine the ETag for the final object. Amazon S3 concatenates the
112: bytes for the MD5 digests together and then calculates the MD5 digest of
113: these concatenated values. During the final ETag creation step,
114: Amazon S3 adds a dash with the total number of parts to the
115: end.
116: Single part uploads
117: Checksums of objects that are uploaded in a single part (using PutObject) are treated as full object checksums. When
118: you upload an object in the Amazon S3 console, you can choose the checksum algorithm that
119: you want S3 to use and also (optionally) provide a precomputed value. Amazon S3 then
120: validates the precomputed checksum value before storing the object and its checksum
121: value. You can verify an object's data integrity when you request the checksum value
122: during object downloads.
