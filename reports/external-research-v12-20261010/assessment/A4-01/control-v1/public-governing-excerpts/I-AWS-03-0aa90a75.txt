47: Multipart upload initiation
48: When you send a request to initiate a multipart upload, make sure to specify a checksum type. Amazon S3
49: will then return a response with an upload ID, which is a unique identifier for your multipart upload.
50: This upload ID is required when you upload parts, list parts, complete an upload, or stop an
51: upload. If you want to provide metadata describing the object being uploaded, you must
52: provide it in the request to initiate the multipart upload. Anonymous users cannot initiate multipart uploads.
53: Parts upload
54: When uploading a part, you must specify a part number in addition to the upload ID. You
55: can choose any part number between 1 and 10,000. A part number uniquely identifies a part
56: and its position in the object you are uploading. The part number that you choose doesn’t
57: need to be in a consecutive sequence (for example, it can be 1, 5, and 14). Be aware that if
58: you upload a new part using the same part number as a previously uploaded part, the
59: previously uploaded part gets overwritten.
60: When you upload a part, Amazon S3 returns the checksum algorithm type with the checksum value
61: for each part as a header in the response. For each part upload, you must record the part
62: number and the ETag value. You must include these values in the subsequent request to complete
63: the multipart upload. Each part will have its own ETag at the time of upload. However, once the multipart upload is
64: complete and all parts are consolidated, all parts belong to one ETag as a checksum of
65: checksums.
66: Important
67: After you initiate a multipart upload and upload one or more parts, you must either complete or
68: stop the multipart upload to stop incurring charges for storage of the uploaded parts. Only
69: after you complete or stop a multipart upload will Amazon S3 free up the parts
70: storage and stop billing you for the parts storage.
71: After stopping a multipart upload, you can't upload any part using that upload ID again. If part
72: uploads were in progress, they can still succeed or fail even after you stop the upload. To
73: make sure you free all storage consumed by all parts, you must stop a multipart upload only after all
74: part uploads have completed.
75: Multipart upload completion
76: When you complete a multipart upload, Amazon S3 creates an object by concatenating the parts in
77: ascending order based on the part number. If any object metadata was provided in the
78: initiate multipart upload request, Amazon S3 associates that metadata with
79: the object. After a successful complete request, the parts no longer
80: exist.
81: Your complete multipart upload request must include the upload ID and a list of
82: part numbers and their corresponding ETag values. The Amazon S3 response includes an ETag that
83: uniquely identifies the combined object data. This ETag is not necessarily an MD5 hash of the
84: object data.
85: When you provide a full object checksum during a multipart upload, the AWS SDK passes the checksum to
86: Amazon S3, and S3 validates the object integrity server-side, comparing it to the received value.
87: Then, S3 stores the object if the values match. If the two values don’t match, Amazon S3 fails the
88: request with a BadDigest error. The checksum of your object is also stored in
89: object metadata that you'll later use to validate an object's data integrity.
90: Sample multipart upload calls
91: For this example, assume that you're generating a multipart upload for a 100 GB file.
92: In this case, you would have the following API calls for the entire process. There would be
93: a total of 1,002 API calls.
94: A CreateMultipartUpload call to start the process.
95: 1,000 individual UploadPart calls, each
96: uploading a part of 100 MB, for a total size of 100 GB.
97: A CompleteMultipartUpload call to complete the process.
98: Multipart upload listings
99: You can list the parts of a specific multipart upload or all in-progress multipart uploads. The
100: list parts operation returns the parts information that you uploaded for a specific multipart upload.
101: For each list parts request, Amazon S3 returns the parts information for the specified multipart upload, up
102: to a maximum of 1,000 parts. If there are more than 1,000 parts in the multipart upload, you must send
103: a series of list part requests to retrieve all of the parts. Note that the returned list of
104: parts doesn't include parts that haven't finished uploading. Using the list
105: multipart uploads operation, you can obtain a list of multipart uploads that
106: are in progress.
107: An in-progress multipart upload is an upload that you have initiated, but have not yet completed or
108: stopped. Each request returns at most 1,000 multipart uploads. If there are more than 1,000
109: multipart uploads in progress, you must send additional requests to retrieve the remaining
110: multipart uploads. Use the returned listing only for verification.
111: Important
112: Do not use the result of
113: this listing when sending a complete multipart upload request. Instead,
114: maintain your own list of the part numbers that you specified when uploading parts and the
115: corresponding ETag values that Amazon S3 returns.
116: Checksums with multipart upload operations
117: When you upload an object to Amazon S3, you can specify a checksum algorithm for Amazon S3 to use.
118: By default, the AWS SDK and S3 console use an algorithm for all object uploads, which you can
119: override. If you’re using an older SDK and your uploaded object doesn’t have a specified
120: checksum, Amazon S3 automatically uses the CRC-64/NVME (CRC64NVME) checksum algorithm. (This is
121: also the recommended option for efficient data integrity verification.) When using CRC-64/NVME, Amazon S3 calculates the checksum of the full object after the multipart
122: or single part upload is complete. The CRC-64/NVME checksum algorithm is used to
123: calculate either a direct checksum of the entire object, or a checksum of the checksums, for
124: each individual part.
125: After you upload an object to S3 using multipart upload, Amazon S3 calculates the checksum value for each
126: part, or for the full object—and stores the values. You can use the S3 API or AWS SDK to
127: retrieve the checksum value in the following ways:
128: For individual parts, you can use GetObject or HeadObject. If you want to retrieve the checksum values for
129: individual parts of multipart uploads while they're still in process, you can use ListParts.
130: For the entire object, you can use PutObject. If you want
131: to perform a multipart upload with a full object checksum, use CreateMultipartUpload and CompleteMultipartUpload by specifying the full object checksum
132: type. To validate the checksum value of the entire object or to confirm which checksum
133: type is being used in the multipart upload, use ListParts.
134: Important
135: If you're using a multipart upload with Checksums, the part numbers for each part upload
136: (in the multipart upload) must use consecutive part numbers and begin with 1. When using Checksums,
137: if you try to complete a multipart upload request with nonconsecutive part numbers, Amazon S3 generates an
138: HTTP 500 Internal Server error.
139: For more information about how checksums work with multipart upload objects, see Checking object integrity in Amazon S3.
