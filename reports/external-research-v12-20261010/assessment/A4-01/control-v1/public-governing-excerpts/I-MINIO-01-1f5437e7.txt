124: Issue body actions
125: Expected Behavior
126: When completing multipart upload checksum in format {checksum}-{numberOfParts} should be supported.
127: Current Behavior
128: When completing multipart upload checksum in format {checksum}-{numberOfParts}, InvalidArgument: Invalid arguments provided for checksum-bug/minio-checksum-bug/2024-05-04T17:52:34.793Z.mp4: (invalid/unknown checksum sent: invalid checksum) error is returned.
129: Various scenarios:
130: both s3 and minio allow completing without checksum
131: both s3 and minio fail on invalid checkum
132: both s3 and minio allow completing with checksum that does not contain number of parts, eg. ejt070PMd2pF/mFNTgP6LDtAo2px3L+i/l91VTgvRSc=.
133: only s3 allows completing when checkusm with number of parts as a suffix is provided, eg. ejt070PMd2pF/mFNTgP6LDtAo2px3L+i/l91VTgvRSc=-2.
134: Possible Solution
135: Fix somewhere in erasure-multipart.go.
136: Steps to Reproduce (for bugs)
137: Create multipart upload with ChecksumAlgorithm: "SHA256" (likely all other algorithms are also impacted)
138: Upload parts with checksum
139: Complete multipart upload with checksum combined with number of parts
