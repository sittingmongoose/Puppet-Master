## Governing locators and applicability

**C01** BagIt is a directory transfer/storage format with data/, bagit.txt and payload manifests; the standard has no native sequence of corrected asset states. RFC 8493 §§1.1, 1.3, 2.1; text lines 89–259. Evidence: E01-bagit-rfc8493. The payload is opaque; a local register can add version relationships. The lack of a native version model does not prohibit snapshots, ZIP serialization, or additional local metadata. This is BagIt 1.0, not a claim about every product using BagIt.

**C02** Each BagIt 1.0 payload manifest lists every payload filename exactly once, and completeness includes both listed-file presence and the actual payload file set. §2.1.3, §3; text lines 220–259, 462–475. Evidence: E01-bagit-rfc8493. Every manifest, not a union of manifests, must enumerate the payload in 1.0. Filenames are relative to the bag base and include data/; slash separators and special-character encoding rules apply. Older BagIt rules differ. The final proposes complete local packages, not unresolved fetch.txt holes.

**C03** A valid bag is complete and all payload/tag manifest checksums verify; missing paths, unlisted payload paths and byte mismatches are different failure observations. §3; text lines 462–475; §6.1.1.3 lines 650–657. Evidence: E01-bagit-rfc8493. A true unlisted payload violates 1.0 completeness. Normalization-equivalent paths need the RFC-recommended tolerant comparison, which the final expressly acknowledges. These checks do not catch an intended item omitted from both manifest and deposited content.

**C04** Fixity against a trusted reference does not establish intended exhibition completeness, authorship, live remote possession, or backup recoverability. BagIt §§1.1, 3, 5.4; PREMIS §1.5.2 p.59, special topic p.258; whereis description lines 34–36. Evidence: E01-bagit-rfc8493, E09-premis30, E10-annex-whereis. The governing standards concern reference bytes and preservation metadata. Registrar intent and custody/restore observations are separate controls. A whole archive digest can demonstrate archive-byte agreement with an established reference; the rejected plan had improperly promoted that to proof of expected contents and recovery.

**C05** bag-info.txt is optional human-use metadata, additional tags are permitted, and custom CSV field meanings are local. Manifesting an inventory protects its bytes, not its truth. §§2.2.1, 2.2.2, 2.2.4; text lines 261–290, 411–415; §2.1.2. Evidence: E01-bagit-rfc8493. Tagmanifest checks cover a listed tag; the RFC otherwise says to ignore custom tag contents. Putting CSV/README in data/ makes them payload bytes. Ordinary staff readability and registrar maintenance are proposed pilot checks, not established interoperability or catalogue integration.

**C06** BagIt 1.0 creation/validation tools MUST support SHA-256 and SHA-512; SHA-512 is a SHOULD default for new bags, and the gallery may choose the algorithm. §2.4; text lines 435–461, especially 455–459. Evidence: E01-bagit-rfc8493. The support obligation concerns tools. It does not require every bag to contain both algorithms, make SHA-512 a MUST, or prove any untested tool implements its default. Legacy algorithm support is separately recommended. No numeric hash length or unit is incorrectly substituted in the final.

**C07** Filename normalization, case and target-platform path rules can alter manifest lookup; actual filesystem and transfer-tool conditions matter. §§6.1.1.1–6.1.1.3, 6.1.2; text lines 583–679. Evidence: E01-bagit-rfc8493. The witnessed failure is a filename normalization change after manifest writing. It is not universal failure across all copies or proof of safety/failure on a single unchanged filesystem. The final avoids adopting the RFC’s dated numeric Windows length statement as a universal current limit and requests actual-platform fixtures.

**C08** OCFL uses stable local object IDs and continuous version directories with expected immutable earlier content. §§3, 3.3, 3.5.1, 3.7.1; released source lines 238–282, 377–402, 595–607. Evidence: E02-ocfl-spec, E16-ocfl-release-pinned-spec. The ID MUST remain stable and unique locally and SHOULD be a URI; no assertion of resolvability. Directory numbers are positive continuous integers with specified zero-padding rules. Immutability is the expected versioning model, not automatically enforced by ordinary disks. The final correctly says expected immutable.

**C09** OCFL inventories map digests to arrays of stored content paths and version states to arrays of logical paths; they record current and historical states. §§2, 3.4, 3.5.1–3.5.3, 3.7. Evidence: E02-ocfl-spec, E16-ocfl-release-pinned-spec. The inventory is UTF-8 JSON with required manifest/versions blocks. Digests connect physical and logical paths and can deduplicate unchanged content. Safe relative slash-separated paths prohibit empty, dot and parent segments and conflicts. The final does not mistake a logical asset ID for a checksum or OCFL object ID.

**C10** The OCFL root inventory is required; inventories in version directories are SHOULD; every inventory present requires its digest sidecar. §§3.6–3.7; HTML text lines 404–433; release-pinned source lines 556–593. Evidence: E02-ocfl-spec, E16-ocfl-release-pinned-spec. The condition is every occurrence of an inventory, not every directory whether it has an inventory or not. If a latest-version inventory is present it must match the root. Optional per-version inventories retain redundancy. This corrects investigator draft line 69 and the critic’s supported material finding.

**C11** Inventory sidecar digest is written after inventory edits, using the inventory digestAlgorithm. OCFL logs/ may hold local action records with format outside the specification. §§3.6, 3.8; text lines 404–414, 434–445. Evidence: E02-ocfl-spec, E16-ocfl-release-pinned-spec. A sidecar does not permit changing historic inventories without respecting version requirements. The optional logs directory is a designated object-root directory; arbitrary extra root files are not implied. The final does not claim the local CSV is an OCFL-native exhibition catalogue.

**C12** OCFL #538 was an inventory-referent ambiguity resolved by PR #547 and released in the 1.1.0 clarification; it was not a reported gallery loss or implementation failure. Change log v1.0→v1.1.0 historical inventory entry lines 34–35; issue body/milestone/dates; PR body, merged_at and merge_commit_sha; PR files[0].patch. Evidence: E03-ocfl-change-log, E04-ocfl-issue538, E05-ocfl-pr547, E06-ocfl-pr547-files. Issue opened 2021-04-02; PR merged 2021-06-10, merge commit 8b13af6edbac68fe1144ce0d398ac978627af314. The patch changes the inventory referent to that version’s inventory. Copying a whole object is a justified local preservation inference, not the PR’s empirical recovery finding and not a rule governing BagIt.

**C13** OCFL release tag 1.1 refers to 4b05472; 1.1.1 refers to c3f88b3 and is the latest listed release inspected. Official release bodies/tag_name/published_at; Git reference object.sha; latest release tag_name. Evidence: E07-ocfl-release11, E08-ocfl-release111, E13-ocfl-tag11, E14-ocfl-tag111, E15-ocfl-latest-release. Full commits: 4b0547244d54967d1404c8c1e7bdba403ac08fb7 and c3f88b31ab8c82c37a190a4f0e5b9bc3c9f01010. Releases published 2022-10-07 and 2024-11-22. The 1.1 URL now renders the 1.1.1 series; rules were also checked against the release-pinned source.

**C14** PREMIS 3.0 separates file/bitstream fixity from the fixity-check Event/date/outcome and permits backup-copy actions to be recorded in system logs. §1.5.2 printed pp.59–60, extracted physical lines 2838–2888; Event Entity p.137, lines 5713–5755; data model pp.6–7. Evidence: E09-premis30. The fixity container applies to File/Bitstream and its digestAlgorithm/value are required when that container is supplied. Event identifier/type/datetime are mandatory; outcome is optional generally. Events relate to objects and may relate to agents. A gallery log is expressly PREMIS-inspired, not formal conformance or a mandatory new platform.

**C15** git-annex whereis uses last-received location records and does not contact remotes; log may lack historic data and is about content currently at the paths. whereis Description lines 24–36; log Description/options lines 24–37. Evidence: E10-annex-whereis, E12-annex-log. Current official manuals, with no inspected release identifier. Private/forget/uncommitted history conditions are disclosed in the source maps. It is an optional alternative, not a selected production dependency or live custody guarantee.

**C16** git-annex fsck --from normally copies remote contents for checks; --fast skips expensive checksums/transfers and checks expected presence. Description lines 24–32; --from/--fast lines 34–42; --all lines 71–74. Evidence: E11-annex-fsck. This is remote fsck operation, not whereis. With ordinary parameters only selected/current-branch files are checked; --all expands version coverage. No selected annex execution is proposed as proof of every prior asset state. Current manuals remain version-sensitive and no product run occurred.

**C17** Use new full BagIt snapshots, stable local gallery IDs, a shallow role layout and SHA-512 as a conditional pilot recommendation. BagIt §1.1/§2.1.2; OCFL version/state model; PREMIS data model; original brief scale/owner clauses. Evidence: E01-bagit-rfc8493, E02-ocfl-spec, E09-premis30. Standards establish mechanics; inspectability and simpler full-snapshot restore are design inferences, trading duplicate bytes for fewer delta assumptions. No measured effort, storage, performance or revision threshold is claimed. Owners must decide volume, maintenance, toolchain, algorithm and depth. A reasonable local proposal need not be an externally benchmarked universal winner.

**C18** The retained CSV/README inventory is optional and useful without specialist repository software under readability and maintenance conditions. §§1.1, 2.1.2, 2.2.2, 2.2.4; original brief obligation 5. Evidence: E01-bagit-rfc8493. A plain-text CSV is a local representation, not an automatic BagIt/OCFL catalogue capability. The final explicitly retains its optional status and explains exclusion only on observed drift/maintenance facts. Staff-tool compatibility remains NOT_RUN. The main procedure is written for the recommended configuration with the option adopted; see limitation L03.

**C19** Validation is a bounded future source/destination/restore procedure using known reference manifests plus registrar intent, not an executed demonstration. BagIt §3; PREMIS fixity/event distinction; original brief obligations 3 and 8. Evidence: E01-bagit-rfc8493, E09-premis30, E10-annex-whereis. Missing, extra and renamed files and byte mismatches block acceptance; normalization-only differences are reviewed separately. Preserve suspect copies, do not regenerate their reference as proof, verify destination, restore into staging and open representative files. Sample opening proves only the selected files/use context, and the final does not generalize it to guaranteed recovery.
