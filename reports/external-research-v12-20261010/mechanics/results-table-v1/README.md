# Offline original-judgment results join

Run `python3 -B join.py` here. Optional `--runtime`, `--checkpoint`, and `--accounting` select read-only saved inputs. All output paths are fixed beside the utility. No framework, runner, provider call, Git operation, or input write occurs. `python3 -B checks.py` runs eight finite semantic checks and removes its fixtures. Python standard library only.

`table.json` contains exactly 80 assigned logical arms: A 16 pairs/32 full; B 12 pairs/24 bounded role; C 4 pairs/8 full; D 8 pairs/16 full. `current-extract.json` is the current row extract; `sourcehashmanifest.json` records every input actually consumed with absolute path and SHA-256. Row observations include exact RFC 6901 JSON pointers. An empty pointer identifies a whole source document. `checks.json` records the finite checks. Native Goal receipts belong solely to this utility assignment.

Assignment and lineage come from QUEUE_ORIGINAL; reservation/state provenance comes from QUEUE; reallocation and progress-count policy are recorded unchanged. Actual provider comes from a saved request whose clientRequestId exactly matches the declared attempt ID, never from a slot's M/G lineage. Returned checkpoint provider is separately retained. Requested tier is recorded only from its actual saved request field; missing non-Codex tier is UNKNOWN, never invented as vendor billing. A multi-stage arm may be MIXED. Original recipe/contrast IDs are assignment lineage, not an adjudication of selected successor compatibility.

Only `assessment/<slot>/<arm>-v1/assessment.json` is read, and only when at least one exact slot/arm evaluationTask in the supplied checkpoint is completed with hasPendingChildRuns false. An existing file with a running reviewer is UNASSESSED and is not read. A qualifying reviewer with no original file is ABSENT. A candidate with no declared attempts is UNSTARTED only without queue launch evidence; a launched queue arm omitted from the checkpoint is ABSENT_FROM_CHECKPOINT. No later dispute/disposition files, candidate scientific bodies, science freezes, or shared outcome roster are read. Original source_judgment remains exact, including FAIL. Source UNKNOWN is never upgraded by job counts, Goal counters, delivery, or native evidence. PASS and PASS_WITH_LIMITATIONS are grouped explicitly as the source-pass family; their exact labels remain separate in counts.

Delivery lifecycle is separate from original delivery labels under dimensions. A2 treatment final is the first ORIGINAL investigator attempt, with all declared stages quiet before completed delivery; A7 treatment uses critic-finalizer; B uses role; other full arms use reviser. Attempt task/thread/run IDs are retained. Schema aliases cover actual observed dimension containers. All original dimension blocks are retained with provenance, including unlabelled or conflicting blocks; absent/ambiguous labels remain UNKNOWN and schema mismatches are listed rather than regraded. Coverage blocks/axis labels remain independent from overall source judgment. Native counters in these raw blocks are never summed. Billing/effective fields are UNKNOWN unless an explicit corresponding telemetry field is present; generic receipts, requested options and token counters do not qualify.

Default resources are joined from the latest existing `accounting-extractor-v1/cohort3-thin-snapshot.json`, not recomputed by running the old extractor (which reads broader evidence). This accounting snapshot predates the current checkpoint. Its generation time, own checkpoint provenance, arm attempt inventory and exact resource pointers are exposed. Observed occupied-context totals retain that historical inventory. New checkpoint attempts without accounting lifetimes increase missing lifetimes and suppress complete totals; final/inventory disagreement suppresses latency. Missing values remain UNKNOWN. These are host-observed request-to-quiet-final latency/context occupancy, not inference time, billing or interchangeable vendor meters. Root native cumulative tokens are neither campaign aggregates nor summed usage. `sources_changed_during_join` detects concurrent edits during reading; rerun if nonempty. Root should rerun against its final evidence/checkpoint and selected final accounting JSON.

Counts stratify phase, original method/contrast, bounded role or final role, arm, actual provider and requested tier. Every assigned row stays in source and timely-source denominators. Delivery, assessment state and all dimension labels are counted separately. Timely-source numerators require source-pass family AND an explicit candidate-delivery timing boolean from the original assessment. Unmapped descriptive timing labels remain visible, but yield UNKNOWN eligibility; reviewer timeliness never stands in for candidate timeliness. Resource-observation counts are separate and never replace assigned denominators.

Paired latency ratios are treatment/control only where both original source judgments pass and both existing accounting latencies are observed. Each pair is labelled CONDITIONAL_BOTH_SOURCE_PASS_SURVIVORSHIP. Protocol eligibility remains UNKNOWN with both original protocol labels alongside; the utility does not adjudicate their compatibility. No incompatible-method averaging, aggregate speed claim, 20% win, vendor billing equivalence, or science regrading is produced.
