# Invocation clarification v1 — prospective mechanics only

Incident: topology-v1 generated assignments spell out freeze-investigator but leave confirm-frozen-active, author-intake, check-input, freeze-review and seal-final partly abbreviated. Role-v2 assignment carries the exact objective while the root short task says only to refer to the assignment. This records a mechanical invocation ambiguity, not a scientific finding or an attribution of a historical result.

`transform.py` is a post-prepare transformer, never a runner/scheduler. Root alone owns integration, displaying its returned JSON and any subsequent dispatch. It emits updated `args`, stage/config paths, applicable command templates and old/new hashes on stdout, and saves the same spec as `invocation-clarification.json`. Nothing is dispatched or activated by this program.

Root invocation (substitute the absolute unused prepared stage path):

```bash
python3 ER12_RUNTIME/mechanics/invocation-clarification-v1/transform.py --stage-dir /absolute/unused/prepared/stage
```

Every supported unused prepared stage, symmetrically control and treatment, has its unchanged `freeze.native_goal_objective` included as an exact JSON string in the short root task. Activation requires no case input. The original task is retained and the task directs the leaf to the appended assignment clarification; no second/replacement Goal is permitted. Unsupported activation stops inference and preserves exact diagnostics. Topology command clarifications apply only to topology assignments and stages. Existing Goal lifecycle, scopes, deadlines, reserves, identifiers, routes, Tier and non-task request arguments remain unchanged. No helper source is modified; the two inspected helpers are SHA-256 pinned in `helper-pins.json`.

Only complete prepared stages with request present, dispatch absent, future original deadlines and no output/receipt/record activity are accepted. Symlink stages/members and source work are rejected. Root must exclusively own the unused stage and must not dispatch concurrently. This is not a transactional scheduler or a repair of partial/dispatched history. Each transformation saves exact original request/freeze/input-map/assignment bytes read-only under a unique `.invocation-backup-<uuid>/`. Freeze request hash and changed carried assignment/input-map hashes and sizes are refreshed; existing carried hashes are checked before mutation. No external carried input is changed. Identical replay returns the saved spec with `idempotent: true` and does not rewrite files; changed transformed bytes fail closed. Dispatch rejection applies even to replay. Failed mutation retains the backup and restores the original four bytes. Backups cannot make an already-used historical stage eligible.

Command templates use absolute pinned helper/config paths and explicit stage names. For each native `--json` call, obtain a NEW direct native get_goal response immediately beforehand, require the original Goal active, and supply the complete exact unmodified response as one JSON argument. Templates deliberately contain runtime-data placeholders, not executable sample native receipts. The notification hash is exactly what root delivers. Native identity/provenance is validated by the existing helpers; this transformer attests no activation, completion, source truth or semantic success.
