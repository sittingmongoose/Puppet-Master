## Cause

The Projects search (`applyFilters`, base `TestPMConcept.html:70595-70643`) re-appends every card and toggles `hidden`
from the field's `input` event. Three things together left the hover on the hidden Tastebook:

1. A character typed into a text field starts no PMH frame. That is the typing-cost refinement in the return repair,
   kept because typing must stay free.
2. The scope's MutationObserver saw the re-appended cards, but started a frame only `if (proxyShown())`, which never
   happens in Basic's software path. It also never watched `hidden`.
3. The re-check's "page went away" test (`if (hover && !hover.getClientRects().length) want = null`) would have
   cancelled the new target as well, because the old hovered card had no box any more.

## Repair (`18-hover.js` only, +15/-6)

- The scope observer also watches `attributes: ['hidden']`. After any structural change in the hovered area (an element
  added, removed, moved or shown/hidden) it marks the scope dirty and, when the pointer is in the window or a proxy
  shows, runs one re-check frame (`recheckSoon`). This is the approved contract's "the next frame looks again at what is
  under the pointer" for a change the user caused with a key. It costs nothing for text-only rewrites, and typing that
  changes nothing structural still starts no frame.
- The "page went away" test applies to the wanted target (`want`), never to the old hover.
