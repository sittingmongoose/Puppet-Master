## 4. Supported corrections (cited)

### C1′ [CORRECTION, consequential] — L5 is already overtaken by events: nbformat 5.11.0 removed `validate()`'s repair kwargs; the no-repair path is now `isvalid()`/`normalize()` only, and the v5.10.4 pin becomes load-bearing
`inputs/UNRESOLVED_LEADS.md` L5 asserts [verbatim excerpt omitted; original artifact/source locator retained]. The proposal's own cited changelog (C5) contradicts this: **5.11.0** lists [verbatim excerpt omitted; original artifact/source locator retained] and [verbatim excerpt omitted; original artifact/source locator retained], and 5.11.1 lists [verbatim excerpt omitted; original artifact/source locator retained] and [verbatim excerpt omitted; original artifact/source locator retained]. Verified in code at C16 (`validator.py @ v5.11.1`):
- public `validate(nbdict, ref, version, version_minor, relax_add_props, nbjson)` — **no `repair_duplicate_cell_ids`/`strip_invalid_metadata` parameters anymore**; passing the proposal's T4 recipe as `validate(..., repair_duplicate_cell_ids=False)` (which is literally what v5.10.4's `validate` accepted) would be a `TypeError` on ≥5.11.0;
- internally `_validate(..., *, repair_duplicate_cell_ids: bool = True, …)` — **the repair default is still True**, so plain `validate()` still calls `_normalize(..., True)` which fills missing ids and rewrites duplicate ids in memory (warnings `MissingIDFieldWarning`/`DuplicateCellId`);
- `isvalid()` still calls the private `_validate(..., repair_duplicate_cell_ids=False)` — so the proposal's §3.2/N1 no-repair mechanism **survives, but only via `isvalid()` or explicit `normalize()`**, not via `validate()` kwargs;
- the future-minor relaxation (`current_minor < version_minor` → relax `additionalProperties` + `_allow_undefined`) is present unchanged at 5.11.1 ✓; the `MissingIDFieldWarning` [verbatim excerpt omitted; original artifact/source locator retained] text is unchanged at 5.11.1 (the warning's *threatened* hard error had not yet landed by 5.11.1).

Impact on the proposal: (a) N1 must pin the nbformat dependency and state the API surface it relies on (`isvalid`, `normalize`, `get_validator`) rather than assuming `validate(repair_duplicate_cell_ids=False)` exists; (b) T4's recipe must be restated as "use `isvalid()`-style no-repair validation at the pinned version"; (c) **mutation hazard the proposal never states**: `nbformat.reads()` itself calls plain `validate(nb)` (C4, `__init__.py @ v5.10.4`), which repairs id defects in memory by default — at *both* 5.10.4 and 5.11.1. A comparator that parses via `nbformat.reads()` and then compares the parsed object has already silently mutated a duplicate-id fixture, breaking T4's [verbatim excerpt omitted; original artifact/source locator retained] and T9's no-mutation guard. Concretely: parse JSON with the stdlib for comparison, or deep-copy before any nbformat validate/reads call, and assert non-mutation against the raw bytes. This strengthens, not weakens, the proposal's chosen nbformat-only path — but it must be written into N1/T4/T9.

### C2′ [CORRECTION] — §3.1's output-axis rule ([verbatim excerpt omitted; original artifact/source locator retained]) is under-specified for non-JSON mimetypes
Per C2: in the mimebundle definition, only `^application/(.*\+)?json$` values are unconstrained ([verbatim excerpt omitted; original artifact/source locator retained]); **every other mimetype value is typed `multiline_string` (string | array of strings)**, as is `stream.text` (the `error.traceback` is a plain array of strings). The proposal applies `\n`-join normalization only to cell `source` (§3.1.1). Counterexample: a `text/plain` mimebundle value of `["a", "b"]` in state A vs `"a\nb"` in state B are schema-equivalent representations of the same text, but naive structural comparison reports a fabricated output change; likewise `stream.text` list-vs-string. The corrected rule: apply the same multiline normalization to *all* `multiline_string`-typed fields (source, non-JSON mimebundle values, `stream.text`), report the normalization when representations differed, and keep raw-JSON structural comparison for the `application/(.*+)?json` pattern only. This is exactly the kind of false positive a discriminating fixture (extend T2) should pin.
