## 4. Supported corrections (cited)

### C1 — A v4 *code* cell has no `attachments`; the proposal's field inventory is contradicted by its own cited schema **[C]**

The proposal (Q2, "Separating source, outputs, metadata") asserts **[S]**: "A v4 code cell is a record with `source`, `outputs`, `execution_count`, `metadata`, `attachments` (4.1+)…", citing the v4.5 schema's "required lists and property maps". The cited property maps say otherwise: in both the v4.5 and v4.4 schemas, `attachments` is a property of `raw_cell` and `markdown_cell` **only**; `code_cell`'s properties are `id` (4.5+), `cell_type`, `metadata`, `source`, `outputs`, `execution_count`, with `additionalProperties: false` — so an `attachments` key on a code cell is schema-invalid under a strict 4.4/4.5 reading (captures 8–9). The correct introduction fact is narrower than proposed: nbformat CHANGELOG 4.1.0 — "Update nbformat spec version to 4.1, adding support for attachments **on markdown and raw cells**" (capture 10).

Design consequence (N2): the per-pair observation record should carry `attachments_changed` only for raw/markdown cells and treat its presence on a code cell as an identity/schema anomaly, not as an ordinary field. The rest of the record is unaffected.

### C2 — The proposal's "normative validation posture (current)" conflates the changelog's aspiration with current `validate()` behavior **[C]**

The proposal's Q1 bullet presents, as current posture, that auto-fixing arguments are "deprecated and removed from defaults" and quotes a `validate()` docstring sentence (see C3). Verified current state (captures 10, 11, 12, 14):

1. The kwargs were removed (CHANGELOG 5.11.0: "Remove deprecated kwargs from `validate()` function [#447]"), **but repair-on-validate is still the default behavior path**: in `validator.py` @ main, the public `validate()` calls `_validate(nbdict, ref, version, version_minor, relax_add_props)`, whose keyword-only default is `repair_duplicate_cell_ids: bool = True` (`_validate`'s own docstring: "the public `validate` always uses the defaults"). `_normalize` then, for `(version, version_minor) >= (4, 5)`, warns `MissingIDFieldWarning` and **generates** missing ids, and repairs duplicates with a `DuplicateCellId` warning — raising `ValidationError("Non-unique cell id '…' detected.")` **only when repair is disabled**.
2. This is not dead code: `test_repair_non_unique_cell_ids` @ main calls plain `validate(nb)` and asserts the `DuplicateCellId` warning plus a subsequently-valid notebook (capture 12).
3. Non-mutation is guaranteed only in `isvalid()`: `orig = deepcopy(nbjson)` … `finally: if nbjson != orig: raise AssertionError` (capture 11).
4. The public read path inherits this: `nbformat/__init__.py` @ main `reads()` calls `validate(nb)` with no repair-disabling argument (capture 14). Notably, PR #282's own diff of `nbformat/current.py` had introduced `validate(nb, repair_duplicate_cell_ids=False)` in reads/writes; at today's `main` the public `reads()`/`writes()` in `__init__.py` pass no such flag (capture 17, current.py patch; capture 14). **[I]** So on current main, reading a ≥(4,5) notebook with missing/duplicate ids through `nbformat.reads` warns-and-repairs in memory. This is an observable code-state fact from captures 11+14; I do not assert project intent.
5. Normative force preserved: the 5.5.0 changelog sentence is a statement of the security model and *intent* ("validation will fail instead of silently modifying an invalid notebook" — still future tense), and `iter_validate`'s Notes still say "To fix: For security reasons, this function should *never* mutate its `nbdict` argument" (captures 10, 11). The transition announced by the `FutureWarning` docstrings remains unscheduled.

Correction to the proposal: keep the 5.5.0 changelog quote as the *normative* statement, but state the current mechanism precisely — repair-if-asked has been `validate()`'s default all along (PR #282's diff shows the pre-existing positional default `repair_duplicate_cell_ids=True` being converted to the `_deprecated → True` sentinel, i.e. behavior unchanged when the kwarg is unset); the #282 fix landed in `isvalid()` (non-mutation assert), `normalize()` (copy-in/copy-out), and the then-`current.py` read path. Consequence for the prototype: its read/validate gate must be `isvalid()` or self-parsed JSON — never plain `validate()` — and its T3 non-mutation reference must mirror `_validate(..., repair_duplicate_cell_ids=False)`/`isvalid()`, not `validate()`. This *reinforces* the proposal's own adoption decision and leads #2/#3 (pin nbformat, parse JSON itself); it does not overturn the design.
