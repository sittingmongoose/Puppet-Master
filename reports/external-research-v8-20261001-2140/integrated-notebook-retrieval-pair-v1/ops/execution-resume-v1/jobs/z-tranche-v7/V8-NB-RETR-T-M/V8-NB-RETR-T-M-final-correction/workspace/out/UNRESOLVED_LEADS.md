Scope: items below are consequential to the corrected proposal in `out/FINAL_PROPOSAL.md` and were not resolvable from this case's admitted captures (including this stage's own re-captures of 2026-10-03). Everything else asserted in the final proposal is source-backed at a pinned version or explicitly labeled inference/product choice/proposed test. No test or arithmetic in the case has an execution receipt.

1. **nbdime multilevel pass ordering not fully traced.** `nbdime/diffing/snakes.py` (`compute_snakes_multilevel`) was not captured in any stage of this case; `generic.py` (captured in the research stage, sha256 prefix `8a4493e7…`) delegates the predicate list to it. The final proposal therefore asserts predicate *precedence* (low→high, `compare_cell_by_ids` highest) and the docstring-marked iteration roles (strict first, moderate second, approximate "third and last"), but not which pass executes first when the id predicate is present. Impact: none on the prototype design (it defines its own order, Q2 step 3); would matter only if the prototype ported nbdime's exact pass schedule.

2. **nbformat's announced hard-error transition for missing/duplicate cell ids is unscheduled.** `MissingIDFieldWarning`/`DuplicateCellId` are `FutureWarning` subclasses whose docstrings say "This will be turned into an error at later point." (sha256 `bcd6aa3e…`), and `iter_validate`'s Notes still read "To fix: For security reasons, this function should *never* mutate its `nbdict` argument…" (sha256 `3db1fe48…`). nbformat 5.11.1 also merged "#458 disable pendingdeprecationWarnings for now" (listed in the captured changelog; PR content not captured), a reminder that warning behavior is still moving. Dependency: the prototype parses snapshot JSON itself, uses only `isvalid()` on deep copies as the library gate, and pins nbformat (currently v5.11.1) rather than treating its read/validate layer as a stable behavioral contract across upgrades. Related verified-but-open fact: at current main, plain `validate()` — and therefore `nbformat.reads()` — still repairs ≥(4,5) notebooks with missing/duplicate ids in memory (`_validate` default `repair_duplicate_cell_ids=True`; `_normalize` docstring admits mutation); only the transition to non-mutating `validate()` is unresolved, not the current behavior.

3. **Validator backend variance.** nbformat selects `jsonschema` vs `fastjsonschema` via `NBFORMAT_VALIDATOR`; 5.3.0 made fastjsonschema the default (changelog, sha256 `414e10d3…`), and `tests/test_validator.py` parametrizes over both backends (sha256 `1d5990ad…`). Error-message shape and some edge behavior can differ. Product decision pending: pin one backend for the prototype's validation gate so report wording is deterministic.

4. **Rename inference beyond exact content equality.** The final proposal fixes the equivalence rule at exact sha256 equality (product choice). A similarity-threshold rule (à la Git's rename detection) was deliberately not specified because no primary source for it was captured in this case; if exact matching proves too strict in practice, that rule needs its own source-backed design pass. Low impact with two text files.
