# UNRESOLVED_LEADS — V8-NB-AMEND-C-L (final-correction stage)

Only consequential dependencies/uncertainty the corrected plan (`out/FINAL_PROPOSAL.md`) cannot close, each with its consequence and a lead. Leads 1–5 carry from the frozen stage (lead 1 updated where the critique strengthened it); lead 6 is added by correction C2. These are consequences of capture limits, not gaps in the deliverable.

1. **nbformat `validate()` repair-default boundary is not pinned to a tagged release.** Captured `main` tests (S3) show `validate()` still repairs missing/duplicate ids with warnings by default (`test_repair_non_unique_cell_ids` / `test_repair_no_cell_ids`), while the 5.5.0 changelog text (S2) says validation will stop silently modifying notebooks and 5.11.0 removed the deprecated kwargs (#447). Which tagged release first makes missing/duplicate ids a hard error through the public `validate()` is unresolved from these captures. Strengthened by the critique: the skipped `test_should_not_mutate` (S3) encodes the intended future raise, and #359 (S6b) records that in the then-current warning path `repair_duplicate_cell_ids` was set to `False` — the boundary demonstrably moved between 5.2.0, 5.5.0 and `main`. *Consequence:* the prototype must not claim "nbformat errors on these inputs" without pinning the version it vendors; nbformat's verdict is therefore treated as advisory and the prototype's own checks stay normative. *Lead:* read `nbformat/validator.py` at tagged releases 5.5.x–5.11.x and diff the repair default.

2. **nbdime #639's exact fallback when ids are absent/duplicate is unverified.** The changelog (S8) proves id-aware diffing exists since 4.0.0, but the fallback alignment policy for pre-4.5 or duplicate-id notebooks was not read from source. *Consequence:* §4.2(c)'s heuristic-fallback design cannot cite nbdime's exact algorithm, only its existence and history. *Lead:* read `nbdime/diffing/notebooks.py` at v4.0.4.

3. **Heuristic-alignment and rename-similarity thresholds are untuned product constants.** Git's default 50% similarity (S9) is a precedent from an unrelated corpus; the fixture set is too small to justify any threshold > 0 — hence the exact-hash rename default. `difflib.SequenceMatcher`'s ratio behavior was not captured/verified in this case. *Consequence:* near-rename and cell-fuzzy-match behavior stays behind an explicit flag until F1–F18 run. *Lead:* implement F2/F5/F9 first, then measure candidate thresholds on those fixtures only.

4. **The snapshot/manifest format is synthetic with no public normative source.** The brief's snapshots (declared minor version + manifest) correspond to no captured public standard; the capture contract in FINAL_PROPOSAL §3 is a product choice. *Consequence:* if the real capture format differs (e.g., stores hashes vs full contents), §3 and the N4 refusal rules need re-derivation. *Lead:* confirm the packaging format against the actual fixture snapshots before implementation.

5. **Proposed validation is unexecuted.** All F1–F18 checks, the end-to-end dirty-pair check and the no-mutation invariant are designed, not run; no execution receipt exists — including for everything in `inputs/CRITIQUE.md` and this correction stage. *Consequence:* the plan's correctness claims are limited to source-traced design rationale. *Lead:* execute FINAL_PROPOSAL §7 in the implementation stage and attach receipts there.

6. **(NEW, from critique C2) The validator's future-minor admission path is unread.** The captured v4.5 schema (S1) *defines* `unrecognized_cell`/`unrecognized_output` but admits them through neither the `definitions.cell.oneOf` nor the `definitions.output.oneOf` branch, yet S3 `test_future` shows a future declared minor passing at its own version. The mechanism (per-minor schema selection, or an explicit relaxation inside `validator.py`) was not read from source. *Consequence:* FINAL_PROPOSAL §4.2(e)'s forward tolerance is a prototype choice supported by behavioral evidence (S3), not by the captured schema text; if validation is ever delegated to nbformat on a future-minor notebook, behavior must be pinned first. *Lead:* read `nbformat/validator.py`'s version handling — how a declared minor above the known schema set is routed.
