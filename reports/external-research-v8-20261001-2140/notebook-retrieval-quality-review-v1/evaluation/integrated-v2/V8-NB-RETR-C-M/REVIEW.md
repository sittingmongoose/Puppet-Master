## Consequential source and design findings

1. **Stable release drift is confirmed, not hypothetical.** The final accurately labels its implementation sources `main` and leaves a release pin open. The public v4.0.4 notebook comparison source uses a 0.7 approximate threshold; its generic source lacks the configuration API and settings introduced on `main`. The recommendation cannot treat `main` defaults as verified stable-wheel behavior. [v4.0.4 notebook source](https://raw.githubusercontent.com/jupyter/nbdime/v4.0.4/nbdime/diffing/notebooks.py), [v4.0.4 generic source](https://raw.githubusercontent.com/jupyter/nbdime/v4.0.4/nbdime/diffing/generic.py), [main generic source](https://raw.githubusercontent.com/jupyter/nbdime/main/nbdime/diffing/generic.py).
2. **Future-minor validation does not establish matcher compatibility.** Relaxed validation admits unrecognized cells whose schema need not contain `source`; the proposed fallback and nbdime similarity predicates assume it. A future cell accepted by that relaxed schema can therefore fall outside the proposed comparison path. This is a static evaluator-derived counterexample, not an executed candidate test. [validator](https://raw.githubusercontent.com/jupyter/nbformat/main/nbformat/validator.py), [schema](https://raw.githubusercontent.com/jupyter/nbformat/main/nbformat/v4/nbformat.v4.5.schema.json), [nbdime notebook predicates](https://raw.githubusercontent.com/jupyter/nbdime/main/nbdime/diffing/notebooks.py).
3. **The parse boundary needs precision.** The final's non-mutation warning is correct: current public validation can repair IDs. Public `nbformat.reads` calls validation after parsing, so merely parsing with the library cannot be assumed non-repairing. The proposed guards are useful, but a pinned non-repairing entry point is not specified. [nbformat public read API source](https://raw.githubusercontent.com/jupyter/nbformat/main/nbformat/__init__.py), [validator](https://raw.githubusercontent.com/jupyter/nbformat/main/nbformat/validator.py).
4. **The corrected rename ambiguity fixture is reachable; the collision fixture is underspecified.** For T6, two disappeared paths and one appeared path yield two exact-content candidates. In T10, declared untracked paths are absent from the manifest, so the two path sets are disjoint. A name-normalization, case-sensitivity, malformed-manifest, or explicit remapping condition is needed to make a same-name collision reachable. These are analytic checks only.
5. **A source setting is not an end-to-end guarantee.** The configured whitespace-line option exists. On `main`, the approximate comparator computes normalized values but passes original values to the ratio function. The setting is accurately cited; the tradeoff prose overstates verified effective behavior if read as a guarantee. [nbdime notebook comparator](https://raw.githubusercontent.com/jupyter/nbdime/main/nbdime/diffing/notebooks.py), [generic comparator](https://raw.githubusercontent.com/jupyter/nbdime/main/nbdime/diffing/generic.py).
6. Several section references still use the proposal's earlier numbering. The relevant content is present, but some links now point to other sections.

All 13 candidate public source artifacts independently fetched over HTTPS match the final's full hashes or recorded prefixes. Important source conditions survive: JEP requiredness and notebook-local uniqueness, split recommendations, git's conditional/skippable preliminary pass, and the distinction between repairing and non-repairing validation. The issue/deprecation/removal/test investigation is supported as a scoped thematic chain; it does not establish that the open issue was closed or that public validation now never mutates. [JEP 62](https://raw.githubusercontent.com/jupyter/enhancement-proposals/master/62-cell-id/cell-id.md), [git diffcore](https://raw.githubusercontent.com/git/git/master/Documentation/gitdiffcore.adoc), [issue 235](https://github.com/jupyter/nbformat/issues/235), [PR 447 patch](https://github.com/jupyter/nbformat/pull/447.diff).
