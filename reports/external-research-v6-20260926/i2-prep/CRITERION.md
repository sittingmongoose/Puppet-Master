# C2 — prospective current/history criterion

TEST_ONLY_NEVER_PROMOTE. C2 applies prospectively to I2, not to D1. The closed D1 results remain Muse 15/15 and zcode 14/15, with its original false result. No D1 artifact is fed through C2 to assign a replacement score.

The current view must be faithful to the latest attempted record for each identity. Read the closed archive without constructing Store or publishing: derive identities/revisions from ordered request names, verify raw payload/marker snapshot identities, and parse those bytes with the pinned existing parser. Compare the host's recorded identity, status, complete parsed finding and change reason against that derivation. Use the latest attempt for each identity; an invalid/mutated/missing-snapshot latest attempt withholds that identity rather than restoring an earlier accepted record.

For each currently admitted finding compare **all** current JSON fields, IDs, titles, typed parts, order and exact text against the snapshot-derived record. Independently render the expected current Markdown through the pinned renderer and compare bytes. Compare the complete history projection against every attempted record, including rejected attempts. Unknown current fields, source quote changes, omissions or injected historical bodies fail fidelity. There are no source_fit, non_finding or condition exemptions. A current finding may legitimately quote or identify an old source: that text is preserved exactly when it belongs to its latest current record. No token scrub, marker disappearance test or semantic repair runs.

Outputs remain separate:

- `passed`: record lineage, all-field/current-render fidelity, recorded history fidelity and captured snapshot integrity.
- `structurally_complete`: no unresolved invalid/latest identity, missing required snapshot, unbound invalid record or recorded protocol failure. A faithful report that visibly withholds an invalid finding can pass fidelity while remaining incomplete. Both flags are required for maintained delivery admission, plus the live Store's final status and the native/output boundary checks.
- `synthetic_task_assertions`: optional development-only exact expected fields, designated proposition and required condition. A model-authored wrong new value can be faithfully rendered yet fail this synthetic oracle. A marker in metadata cannot satisfy the designated proposition. Stale rules inserted into source_fit/condition are also tested against complete expected fields. This is a small invented task oracle, not a general research truth validator, and is never staged to candidates or used as a research grader.

For research, a faithfully preserved latest record can still be wrong, unscoped, contradictory or lose a necessary condition relative to its sources. Independent semantic reviewers judge source/version applicability and temporal substantive losses across every field. The structural result does not auto-confirm upstream content. Native traces and the existing output inventory audit remain necessary for failed writes, pending inputs, illicit overwrites and actual chronology. Archive hashes do not prove an unobserved write never happened, protect against a malicious host rewriting all evidence, or provide power-loss durability.

The bounded artificial regressions cover legitimate old-source references, true stale fallback, wrong new value without an old marker, required-condition loss, invalid latest with an unaffected independent record, exact source quotations, stale rules embedded in other fields, missing/corrupt snapshots and field/order/identity/history tampering. Frozen D1 source and scores are unchanged.
