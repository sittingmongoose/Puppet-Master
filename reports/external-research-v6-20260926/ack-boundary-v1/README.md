## Cause and change

The frozen [I2 audit](../i2/checks/marker-order.md) found six correct marker Writes whose empty snapshots preceded their native terminals by 58.092–267.470 ms. Visibility caused premature acknowledgement; completion of those same Writes then appeared to be mutation. This successor changes only the receiver and its event adapter, leaving the frozen implementation and native drivers intact.

- [native_completion.py](tools/native_completion.py) consumes the existing Muse driver's flushed session response, binds its exact workspace/session/journal, and incrementally correlates call, lifecycle and result events. A valid completion proof needs successful terminal **and** exact result path/byte count; payload completion must precede marker start. See [observed route, source pins and limits](evidence/native-route.md). No inferred app API or transport was added.
- [completion_store.py](tools/completion_store.py) treats visible or attempted submissions as pending until that proof exists. It snapshots available completed bytes before any receipt, compares them with native Write arguments, then uses the pinned finding parser. Completed malformed inputs get `INVALID`; unfinished/failed operations get no fabricated acknowledgement and retain raw bytes/unavailability evidence at closure. Native operations are counted independently of acknowledged findings. Genuine source, provenance and snapshot mutations remain latched.
- Current selection follows native attempted order, independent of acknowledgement/completion order. Receipts retain their original arrival sequence and revision counter; `native_lineage_ordinal` supplies the distinct current-order evidence. Invalid or uncompleted latest revisions withhold older answers, while independent records remain visible. Older pending evidence remains incomplete history even when a later valid revision is current. These are structural rules, not judgments of source truth.
- Five derived files publish only when state or diagnostics change. Idle polls retain source/snapshot integrity checks. Journal appends read only their suffix; finalization verifies the consumed prefix. The existing 50 ms observation tick is scheduling only, never a completion signal.
- [host_receiver.py](tools/host_receiver.py) attaches the receiver to an already-launched driver; it cannot launch inference. The existing host must provide bounded stop/reap before cap/cancellation snapshots. Nonzero exit is explicit failure. Cleanup failure is preserved; an active writer is not falsely declared frozen. Independent submissions remain batchable.

The pinned I2 capacities remain 64 acknowledged attempts and 32,768 bytes per payload; this patch does not make them universal defaults. Invalid acknowledgements consume the limit; failed/pending native calls remain separately recorded and visible. The proposed short check has a smaller task allocation. No semantic prompt, parser/field meaning, evaluator admission/dispatch, C2 criterion or research strategy was changed.
