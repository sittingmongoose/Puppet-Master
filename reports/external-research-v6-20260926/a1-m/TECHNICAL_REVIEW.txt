Closure assessment
Acknowledgement now has a demonstrated event boundary
The receiver does not commit a visible request file merely because it exists. The bound native route correlates session, run, call, effect/task, exact path, expected byte count/hash, terminal completion and subsequent result. The payload result must precede marker start. The Store compares completed input bytes with the native arguments, saves the snapshots and state, and then issues the receipt.
In-flight data remains pending. A completed malformed marker remains invalid. Failed or unterminated operations remain incomplete and accounted for. Genuine post-acknowledgement mutation or changed native provenance remains a violation. This closes the demonstrated I2 producer/consumer race in the exercised offline paths without adding a delay-based approximation.
Current selection is not completion-arrival order
The successor retains acknowledgement sequence separately from native attempted order. The tests verify that late completion cannot reinstate an older revision as current and that an invalid or unfinished latest revision does not silently expose an older accepted answer.
