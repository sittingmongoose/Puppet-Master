# Discovery-to-Plan pilot

This is a small external prototype for finding useful unknowns, preserving them and turning supported findings into reviewable Plan improvements. Live Puppet Master canon remains in the PuppetMaster repository. It is not a production Rust/Slint research service.

The bounded pilot is closed: [final results](RESULTS.md) record all four attempts, actual landings, retained omissions, errors, time and captured cost bases. [Product decisions](DECISIONS.md) remain explicit and unapproved. The workflow has useful end-to-end evidence and a verified offline transport repair; complete research coverage and production reliability remain unestablished.

The first application landed two reviewed September terminal finding groups in five current owner/consumer documents. Later workflow findings produced a ConPTY conformance amendment, the remaining GUI retry consumer correction, and a command-block value alignment with a named fixture/checker. The patches and scoped verification are in `repairs/`. The retry residual belongs to the same historical finding family, and storage mapping is a rediscovered historical theme. Manual repairs, participant findings and evaluator-assisted landings are counted separately in `RESULTS.md`.

The research path is: product brief → external discovery → independent implementation/history investigations → external technical reconciliation → comparison with frozen Plans → concrete repairs or product proposals → decision → verified owner/consumer amendment. Discovery and technical study do not receive the Plan corpus. Research sources are evidence, never instructions.

Agents write ordinary Markdown. A note can have a title, a finding, source links and a follow-up question; none of those are rigid required fields. The application assigns lead IDs, retains original files and duplicate discoveries, and records where each lead advances. A short summary does not replace the full lead collection.

The shared source helper pins successful public page acquisitions with timestamps and hashes, reuses repository checkouts with commit receipts, and leaves every job's request history separate. Other arms' conclusions are not deliberately supplied. The initial live attempt exposed Git's ownership check on the shared filesystem. The corrected helper uses a per-command exception for the exact public cached checkout. V3 also checks extracted-text integrity and rejects dirty or changed pinned repositories. Its separate `cache/v3` starts with new acquisitions, shared by the paired arms. The initial helper, run and errors remain preserved. This is cooperative workspace separation, not a filesystem security boundary.

Use **`discovery_to_plan.py` for future runs**. The original `pilot.py` warmup and frozen `pilot_v4.py` paired experiment remain preserved historical protocols. Deeper studies have a time budget, then discovered leads enter technical and Plan review in batches sized by text volume. Reviews use a heading with the supplied lead ID and one `Review-status:` or `Disposition:` line. Missing lead outcomes remain pending; reports whose upstream evidence changes become stale. Aggregate notes remain unresolved intake until reviewed. Finished job outcomes can be reattached idempotently after interruption; unfinished attempts without outcomes require manual salvage. Unfinished deeper studies remain visible even after a lead has been compared. Later discoveries may require another pass. Delivery does not establish semantic correctness or complete coverage.

The stable entrypoint repairs observed child-note loss: complete eligible child artifacts travel with parent reports, shared bodies travel once, exact rendered size determines batching, and content/membership changes invalidate reviews. Source, retained copy and registered hashes must agree. Assigned IDs are explicit; embedded IDs remain evidence. Review reports also have an explicit pending-intake reference for possible unextracted directions. That reference is not automatic extraction or a new lead, and no intake-resolution command is implemented. [Implementation and checks](evaluator/post-pilot-workflow-change.md) include a real J8 handoff replay restoring both omitted corrections. This proves availability, not model comprehension. The fix was developed separately and is excluded from frozen participant scores.

If verified shared evidence alone already exceeds the normal grouping allowance, related assignments can reuse that exact context with one normal allowance for additional assignment text and metadata. Different source contexts still split; oversized bodies remain whole and the full size is recorded. An offline replay reduces the current terminal snapshot from 25 frozen batches to five stable batches. This is evidence of reduced repeated transport, with model quality, runtime and monetary savings still unmeasured.

Prepare a **new** user-supplied case with `python3 prepare_case.py my-case --brief /path/product-brief.md --plans-dir /path/Plans --include 00-plans-index.md --include Usage.md --include contracts/usage.schema.json`. Repeat `--include` for only the intended current owner/consumer documents and companions; paths are relative to the supplied Plans directory and remain under `Plans/` in the frozen copy. The application writes hashes, manifest, navigation and a brief-only external research stub; users and agents do not author hash metadata manually. Existing cases are never overwritten. Unreadable/missing selected files are recorded as unavailable with no historical fallback; at least one readable UTF-8 Plan file is required. Select inputs that contain no secrets or local machine state: this helper does not redact or detect secrets, and it excludes hidden paths and symlinks rather than copying a whole repository. Preparation does not launch research or modify existing frozen inputs. If writing is interrupted, the manifest is written last; retain the partial case and retry with a new name.

Typical commands:

```bash
python3 discovery_to_plan.py init CASE hybrid --name CASE-hybrid-followup --job-timeout-seconds 360
python3 discovery_to_plan.py campaign CASE-hybrid-followup --research-seconds 180 --workers 2
python3 discovery_to_plan.py status CASE-hybrid-followup
python3 collect.py CASE-hybrid-followup
python3 followup/workflow_transport_checks.py
```

These commands illustrate a future authorized run; replace CASE and use a fresh name. Initialization prepares inputs; campaign executes provider jobs. The final command is offline and makes no provider calls. Stable code rejects historical pilot state and existing-name collisions. This post-start operational deviation is not a predeclared matched resource limit or evidence of model failure. The original protocol files remain unchanged. Both Usage attempts are closed under their separately recorded common comparison budget, with unchanged model/input/job settings. The final aggregate distinguishes calendar envelope, native execution interval union and summed job durations.

Only one campaign holds `campaign.lock` at a time; up to two independent study jobs can run inside it. The timebox bounds study admissions and permits admitted jobs to finish. Discovery and review work have separate job limits; there is no hard total campaign deadline. Every job uses a fresh native Goal through the existing adapters. Reports, outcomes and frozen protocol/input hashes are preserved rather than overwritten for a retry. The matched settings and evaluation rules are in `EVALUATION_PROTOCOL.md`. V2 was reviewed before launch and superseded without participant jobs.

A Plan comparison must preserve every lead's outcome: covered, supported repair, product proposal, uncertain, deferred or rejected. New features and consequential choices stay pending until an explicit user decision. A finding is “landed” only after actual owner/consumer edits are verified; a report or decision-log row alone does not qualify. Benchmark fixture amendments and real canonical changes are counted separately. Production approval UI remains future integration work.

`measurements.json` records delivery and source-use data; semantic evaluation remains separate. The [four-attempt aggregate](evaluator/final-comparison-measurements.json) includes failed/interrupted captured work, imported research counted once and separate warmup/amendment overhead. Intake smokes and cache smokes are checks of the helper, not evidence of research quality. Pricing assumptions and unknown billing are in `PRICING_BASIS.md`.
