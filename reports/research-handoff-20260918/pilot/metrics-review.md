# Collector review

`collect.py` is ready for interim and final observed-job snapshots. It calls the existing, unchanged parent `valuation.codex(job)` and `valuation.omp(job)` and retains their full per-job evidence references, token records, assumptions and unavailable reasons in `native-valuations.json`. It does not rewrite native evidence, protocols, inputs or run configuration.

Run `python3 collect.py RUN_NAME ...` to refresh each run's `measurements.json`, `native-valuations.json` and `comparisons.md`. Run `python3 metrics-test.py` for the small regression check. `collect(run, write=False)` supports read-only inspection.

## Corrected accounting

- Active captured values no longer become completed totals. Each amount reports known subtotal, missing jobs, priced/eligible counts, and successful, other-terminal, and unfinished partitions. A subtotal with no available observations is null, including an arm with no jobs. Both native successful statuses (`complete` for Codex and `completed` for OMP) are recognized.
- `complete` means every observed eligible job succeeded and has a captured valuation; it never attests campaign completion, exhaustive billing coverage or semantic completion. Collection read errors suppress this flag. `completed_successful_captured_total` is null otherwise. Failed-attempt captured usage stays in its own partition and remains included in the known subtotal.
- Astra conditional API equivalent and Codex credits remain separate from DeepSeek Go allowance valuation and local runtime catalog estimate. No cross-unit grand total is invented. Native Codex input includes cache; native OMP input excludes cacheRead. The unchanged valuation functions apply those different bases. Pricing sources and verification date are in `PRICING_BASIS.md`.
- Actual billed cash, search/controller cash, uncaptured failed-request charges and setup/controller duration remain unknown. A native catalog zero does not establish free work.

## Delivery, timing and integrity

- Per-job phase, actual native outcome, interim notes, expected handoff IDs and present/missing handoff/report mentions are retained. Per-lead stage observations expose failed or unfinished studies even when a later comparison exists. Mentions are token-boundary matches, not substring matches.
- Unique IDs, duplicate IDs, original discovery leads, follow-up leads, unclassified origins and unique stored content hashes are distinct. None claims semantic uniqueness. Comparison delivery counts include terminal reports with notes and therefore must be read with per-job outcomes; interim reports do not count as delivered.
- Search/fetch receipt statuses and shared cache-hit counts are separate from model outcomes. Tool failures can coexist with a successful native Goal and are not silently relabeled successful source acquisition.
- Execution wall span uses the earliest observed execution start and latest finish, counting parallel jobs once. Terminal starts are reconstructed from recorded finish minus monotonic elapsed time. Native started_at is used for active jobs when available. Missing start coverage yields null, not an assumed zero or configuration creation time. An unfinished Codex job often lacks a start timestamp until its summary/outcome exists. The separately retained summed job duration can exceed wall time due to concurrency and is incomplete while elapsed fields are absent. Wall envelope includes gaps between observed jobs; future campaign work and setup time are outside it.
- Frozen Plan bytes, manifest/brief hashes, protocol hashes and each job's original input hashes get explicit expected/actual checks. Missing evidence stays unknown. Empty inputs do not vacuously pass.
- The original v1 run is labeled transport/prototype warmup; v2 runs are labeled paired-pilot observations. The collector does not pool these roles.

## Validation and limits

Three small regression checks pass: partial/missing/empty aggregation, overlapping jobs plus unfinished/missing timestamp cases, and lead-ID boundaries. A live refresh of the warmup plus all four v2 runs completed without collection errors; frozen Plan bytes were unchanged in all five. At that snapshot v2 jobs were not yet launched, so amounts correctly remained null. The warmup showed three successful jobs and one unfinished reconcile; its job input hashes were unchanged.

Reads are deliberately tolerant of missing/temporarily malformed live files, but sequential reads are not an atomic experiment snapshot. A newly created job with incomplete `job.json` is recorded as a collection error; refresh after stabilization. The underlying estimator can withhold a whole-job valuation for malformed/partial usage coverage even if some individual records are priced; those detailed native records remain available for audit and are not silently added as a complete job. Search retries, controller usage, manual setup failures outside run job directories, account-specific billing and semantic quality need separate evidence/review. Do not compare arm totals until matching stage coverage and final outcomes are established.

## V3 update (2026-09-08)

This supersedes the original role/delivery description where applicable: frozen v3 configurations are the paired pilot, and empty v2 configurations are labeled `unlaunched_v2_configuration`. `launch_state` separately distinguishes no observed participant jobs from observed jobs. Frozen navigation now has an expected/actual hash check; legacy configurations without an expected digest remain unknown.

For v3, `lead_stage_current_delivery` uses only the frozen protocol's read-only `delivered` and `ready` functions. It requires the selected job's valid per-ID delivery marker, unchanged receipt/report hash, current lead/upstream fingerprints and the current reconciliation prerequisite for comparison. `current_comparison_delivered_lead_ids` and its count exclude omitted or stale IDs. Delivery can include explicit uncertain/deferred sections from a timed-out job under v3 rules; native runtime outcome stays separate. Raw report-ID mentions and historical comparison-input counts remain explicitly labeled and do not attest delivery. Legacy runs report current delivery as null.

Before overwriting any existing derived `measurements.json`, `native-valuations.json` or `comparisons.md`, the collector copies them to `metrics-snapshots/<UTC timestamp>/<run>/`; the new report links the previous snapshot. Original raw/native evidence is never archived by copying over it or modified.

The fourth regression check uses a small temporary v3 fixture: a timed-out comparison with a valid uncertain section counts according to the protocol, an ID mentioned only in prose stays undelivered, and editing the upstream lead invalidates both reconciliation and comparison. All four checks pass. Refreshed the v1 warmup and all four unlaunched v3 configurations without collection errors; all four v3 navigation hashes match. The previous `metrics-live-snapshot.json` remains, with the new summary in `metrics-v3-live-snapshot.json`. A read-only v2 smoke confirms the unlaunched role; its earlier derived outputs were left intact.

## V4 transport amendment (2026-09-08)

V4 now identifies the paired conditions; v3 is `pre_amendment_v3`, including its historical source view. V4 delivery/currentness reuses only frozen `pilot_v4.delivered/ready` reads. Imported jobs carry their **original v3 native execution path as identity**, the byte-preserved-import provenance label, and the import receipt's recorded 406-file match claim/digest. The collector does not treat copied raw artifacts as a second execution. Imported research is included once in the v4 condition; raw v3 measurements are a historical view that must not be summed again.

`native_execution_interval_union_seconds` measures the union of job invocation intervals, counting concurrent execution once and excluding between-job gaps. It includes adapter startup/cleanup and is **not pure model-inference time**. `known_execution_interval_union_seconds` remains a partial observation when active jobs lack start timestamps; the full union stays null until coverage suffices. The wall envelope still includes amendment delays. Its earliest start can be established from imported completed jobs and the creation-time lower bounds of later jobs even when those jobs have no recorded execution start yet. All merged intervals and known gaps are explicit; partial gaps may overlap unmeasured execution and are not automatically classified as pure idle/model-free time.

`metrics-amendment-overhead.json` contains only the two explicitly excluded v3 reviews J0004/J0005. It excludes all three imported research jobs, retains interrupted runtime states, full native valuation records, captured partial subtotals, cleanup `clear/get` receipts, thread IDs and receipt digests. Both recorded cleanup receipts show cleared=true and goal=null. These controller transport-amendment interruptions are not labeled model-quality failures. At collection, their captured Astra API-equivalent subtotal is **$0.81483**, Codex credit estimate **20.37075**, invocation union **89.592 seconds**, and envelope **89.83959 seconds**; actual cash, uncaptured charges and search/controller costs remain unknown.

The added compact test distinguishes a 70-second envelope, 30 summed job-seconds, 25-second interval union and 45-second gap, verifies partial active coverage, and verifies imported/original execution identity plus exclusion from amendment overhead. All five regression checks pass. Refreshed four v4 conditions plus v1 warmup with prior derived snapshots preserved. No frozen protocol, configuration, fixture or native evidence was changed.
