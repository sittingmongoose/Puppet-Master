# C-01/control/critic-v1 — independent assessment and integrated proposal

## Assessment in brief

The researcher proposal is directionally sound: preserve original bytes, separate stable record identity from content digest, keep processed images as versions, pin annotations to the exact displayed rendition, require human review, and export a selected portable packet. The evidence supports these as planning choices, not tested guarantees.

Adopt a **provisional central publication service with a private local intake queue** only if the club names a volunteer willing to operate a host, accounts, backups, access rules and deletion. This supports disconnected session entry and delayed upload; it does **not** provide shared offline review or automatic peer collaboration. If no maintainer and reachable host are acceptable, start with a local packet workflow and defer multi-member live collaboration. Do not call either option affordable or low-maintenance until the club checks its devices, file sizes, connectivity and hosting arrangements.

Keep the workflow deliberately small: prepare a session; copy files and notes into a recoverable local batch; preserve originals; report per-file progress; upload when connected; inspect supplied metadata and generated previews; attach comments and rectangles to an immutable preview version; review and explicitly publish chosen material; withdraw or erase under a declared policy; export an independently verifiable, selected packet. Do not add telescope control, scientific reduction, sky-coordinate inference, event prediction or public social features. Neither a file nor its member-supplied metadata is validated astronomy evidence.

## Integrated planning proposal

### Records and provenance

Use independent stable IDs for sessions, import batches, source files/assets, immutable file versions, derivatives/previews, annotations, members and publication events. Keep original name and relative source path as submitted metadata, never a key. A SHA-256 digest and byte length identify a byte sequence and help check transfers; they do not identify an observation. Do not auto-merge byte-identical files or treat a changed digest as a new observation. Preserve duplicate-looking files as separate records until a member relates them. Represent original → derivative relationships explicitly, with parent version, tool/version, parameters, operator, time, and a reviewable failure state. Preserve source bytes unchanged.

Store raw supplied metadata and parsed interpretations separately. Attribute each parsed value to source, parser/version, status, precision, unit and time scale; retain unsupported values as opaque text and mark missing or ambiguous values for review. FITS Standard v4.0 defines `DATE-OBS`/time conventions and `TIMESYS` context within its scope; it cannot establish correctness of a supplied header or cover the club’s mixed formats. Do not normalize absent or ambiguous time scales as a scientific fact. Require representative files before choosing decoders, conversion code, quotas or a common field set. [D10]

### Ingest and recovery

A local intake queue keeps source files and a manifest until the server has acknowledged and verified them. Assign batch/item IDs before transfer; show per-file states, error cause and retry/resume action. Keep the removable-media copy until the club copy is checked. Treat a lost response as retryable and idempotent by item ID. Mark a file reviewable only after complete transfer, server-side digest comparison and metadata capture; upload completion alone does not mean application import completed.

The tus 1.0.0 protocol’s `Upload-Length` and `Upload-Offset` are byte counts; `HEAD` discovers the offset, `PATCH` continues, and a mismatched offset is a conflict. The protocol specifies transfer semantics, not record selection, application idempotency, atomic publication or total storage quota. [D05] The researcher’s tusd v2.10.1 pin resolves to commit `388a27cb81c33b2349e0308b5e97e23797e86fd9`; the captured handler implements upload creation/offset and size checks. Release 2.10.1 (2026-09-16) lists PR #1397 enforcing MaxSize on the experimental IETF draft create path, PR #1396 for deferred uploads with Content-Length, and PR #1385 for silent S3 truncation of deferred-length uploads. Issue #1386 reports the first defect against an earlier commit with `-enable-experimental-protocol`; that flag defaults off. Thus it is a real, release-addressed edge case for an opted-in path, not evidence of a default tusd bypass. Do not enable that experimental path for this proposal. Even a fixed per-upload limit is not a total quota, authentication or authorization system. Test the selected tusd release, storage adapter, transfer mode and limits before relying on them. [D06–D09]

### Annotation, identity and collaboration

Model a note/comment as a member-authored record that targets a stable session or asset/version. A rectangular selection targets the **exact immutable preview version**, records its digest/width/height, and stores `xywh=pixel:x,y,w,h` in that rendition’s pixel frame (top-left origin; x right, y down). The preview bytes and any crop/rotation/orientation transform must be reproducible or retained. Do not use browser CSS pixels or silently rebase a region when a preview changes. Keep the old annotation and show “review against new preview”; allow remapping only after a member confirms it. W3C Web Annotation provides a target/selector data model, and Media Fragments defines pixel/percentage spatial fragments; neither guarantees this app’s client renders them correctly. [D03–D04]

Use invite-only member identities and explicit coordinator/member permissions. Keep drafts private until a deliberate publication event selects records and files. Enforce authorization for lists, metadata, originals, previews, derivatives, annotations, downloads and exports. Local queue data on shared devices needs a stated lock/log-out and protection policy. A central revision token or strong ETag can reject stale edits (`If-Match`/412); the application must retain the losing local draft and present a compare/merge or explicit member choice. Independent comments should be separate records; editing a comment/annotation should create a history revision. Do not describe HTTP conditional requests as automatic three-way merge. [RFC 9110 §13.1.1 and §15.5.13: https://www.rfc-editor.org/rfc/rfc9110.txt]

### Visibility, retention, handoff

Define **withdraw** as immediately denying future club reads and exports. Define **erase** as an operational process covering primary files, derivatives/previews, annotation history, local pending copies and backup expiry. State who can authorize it and the retention window before real member data is imported. Keep only a non-sensitive deletion marker if needed. Neither central deletion nor account revocation can recall packets already downloaded to members’ devices; say so plainly and minimize what each packet contains.

Export a selected snapshot as a directory or archive with a readable README, versioned application `manifest.json`, stable IDs/relative paths, included originals and chosen derivatives, exact preview targets, annotation revisions, provenance links, privacy/publication selection, and SHA-256 payload manifest. Verify the packet offline after export and re-import. BagIt v1.0 can validate that payload files match the manifest, but leaves their meaning to the application. RO-Crate or OpenAstronomyLog may be investigated later if a real partner or import/export need appears; neither is needed to start, and no OAL schema compatibility was audited here. [D11]

## Researcher-claim review: checked, repaired, objected, unresolved

| Claim or choice | Assessment |
|---|---|
| Originals and derivatives are distinct; SHA-256 is not observation identity. | **Checked and keep.** Clarify that digest identifies bytes and detects transfer mismatch; it cannot establish same observation, authorship, validity or a non-collision proof for an uncontrolled source. No automatic merge. |
| Resumable upload supports retry/recovery. | **Checked with boundary.** tus offsets are bytes. tusd’s issue #1386 is conditional on the opt-in draft protocol, disabled by default; PR #1397 and release v2.10.1 address it. The cited test history is not a runtime test performed here. Size cap is per upload and backend/mode applicability remains open. |
| A local spool plus central service is the practical minimum. | **Objected as unconditional.** It fits delayed upload and later review, but adds a reachable host/operator, backups, identity, security and retention work. It does not support collaborative review without connectivity. Make the host/maintainer decision a gate; packet-only pilot is fallback if that burden is rejected. Affordability is unverified. |
| Web Annotation / Media Fragments support durable regions. | **Checked as a representation, not an app guarantee.** Pin the selector to exact immutable preview bytes and pixel dimensions; include orientation/crop transforms and test browser coordinate conversion. These specs do not provide annotation storage, permissions, robust remapping or UI behavior. |
| Revision token / `If-Match` makes edits predictable. | **Keep with repair.** HTTP can reject a stale write; the app must preserve the submitted draft and implement its own comparison, resolution, audit/history and retry. A 412 is not an automatic merge. |
| FITS fields can represent submitted observation time. | **Keep narrowly.** The standard’s conventions and time-scale context are useful only for supported FITS inputs. Do not assume JPEG/RAW or all camera headers share them, or that parsing verifies astronomy. |
| BagIt provides portable validated export. | **Keep narrowly.** It validates checksums of package payload, not the semantic manifest, target relationships, authorization, or scientific claims. |
| Yjs issue #768 was fixed by v13.6.33. | **Checked independently at exact tag/commit.** Issue reports deep observer `currentTarget`/path behavior against v13.6.29; fix commit `713a2895e78d13dd6cc257fdd4d46dbdec6d4fa7`, source and named regression test occur in v13.6.33 at `9ea3a4fb57b814292ce18dfd13c4f422e44e6c5c`. This narrow regression neither selects Yjs nor validates persistence, permissions, binary sync or deletion. Test was inspected, not run. [D12–D18] |
| Full RO-Crate/OAL, automatic region remapping, CRDT, astronomy correctness. | **Defer or exclude.** Useful leads only when a concrete interoperability need or validated registration workflow exists. No ground-truth source or real sample data was available. |

## Observable validation proposal — NOT executed

1. Survey volunteers’ operating systems, connectivity, removable media and representative images/notes. Build a format and size matrix; retain unsupported originals with “preview unavailable”. Compare candidate hosting/admin workload and cost with the packet-only path before selecting a host.
2. Import byte-identical files with different names, renamed duplicates and different processed versions from the same session. Confirm stable records, correct byte digests, no automatic observation merge, and visible raw versus parsed fields. For FITS, exercise missing/ambiguous `DATE-OBS`/`TIMESYS`; confirm values are source-attributed and uncertain entries are reviewable.
3. Interrupt local copy and network transfer, restart, retry after lost response and submit a stale offset. Confirm removable media unchanged, no duplicate records, resume offset is byte-accurate, digest matches before review, limits apply to the selected server/storage mode, and disk-full/retry failures are understandable. Include experimental tus protocol disabled.
4. Place annotations at preview corners/interior; test CSS scaling, EXIF orientation, crop/rotation, resize and reprocessing. Confirm pixel-to-display mapping against exact preview bytes/dimensions and old annotations remain anchored with review status after new previews.
5. Two members edit one record from the same revision while disconnected, then reconnect. Confirm one stale edit is retained, both can be reviewed without silent loss, independent comments remain separate, and drafts remain private until selected publication. Test every read path (list, metadata, source, preview, derivative, annotation, packet) using authorized, unauthorized, removed and offline members.
6. Withdraw and erase a published and a private item. Confirm future reads/exports are denied, configured primary and backup copies expire, local pending copies are addressed, and the documented limit on downloaded packets is accurate. Export a selected packet, verify hashes offline, re-import, and confirm provenance, relationships, exact annotation targets and privacy selection.

These are proposals. Executed: public-source retrieval and manual inspection of captured specifications, release/issue metadata, pinned source/patch/test files, and static text/PDF extraction for this assessment. No tests, builds, uploads, image conversion, UI, storage adapter, host, or account were run or selected. No astronomy truth was checked.

## Conditions, unresolved questions and preservation

Before implementation planning advances, the club must decide who operates the service, whether members can reach it after sessions, how private drafts are protected on shared devices, membership/revocation rules, retention and backup expiry, who authorizes erasure, and what happens to exported copies. Obtain representative files and decide only the first supported preview formats. Select a resumable server/storage combination and verify its exact version, license, quota, authentication integration and recovery behavior. Do not add dates/units/sky coordinates that are not explicitly established by source material. Keep processing reversible, human-reviewed, and visibly distinct from source data. Keep all tests proposed until actually run and reported with result and scope.
