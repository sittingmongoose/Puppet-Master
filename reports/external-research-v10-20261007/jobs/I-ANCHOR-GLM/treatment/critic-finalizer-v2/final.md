## 2. Architecture (complete proposal)

1. **Bundle format**: ZIP of `pages/*.html`, `assets/*`, `manifest.json`; manifest carries monotonic `edition`, per-file SHA-256 + whole-tree `content_hash`, `min_reader_version`, Ed25519 signature over the canonical manifest (SRC-04 targets/snapshot roles at kiosk scale).
2. **Key lifecycle (correction adopted from critique §1)**: offline museum signing key with key-escrow + scheduled rotation procedure recorded as an explicit operational requirement now; threshold signing optional if a second curator exists; full TUF root rotation (SRC-04) as the fleet-scale upgrade path. Without this, a compromised curator key forces re-flash of every kiosk.
3. **Atomic update protocol**: extract into `editions/<edition-hash>/` with a vetted safe extractor; verify every file hash + manifest signature; fsync files **and the directory**; atomically replace the `current` symlink via symlink+rename (OSTree model at content scale, SRC-08; A/B fallback semantics, SRC-06/SRC-07). Never write inside a served edition; keep the previous edition until a grace window passes; boot-time GC only of unreferenced, non-in-progress directories (race note adopted from critique).
4. **Rollback**: `current.previous` pointer; on reader-start self-check failure serve `previous` and log; interrupted extractions are idempotent and GC'd (update_engine checkpoint-resume reduced to content scale, SRC-06).
5. **Metadata freshness**: signed manifest `expires` (anti-freeze), refusal below highest installed `edition` (anti-rollback), persisted `last_seen_edition` (SRC-04). Full TUF only if kiosks become network-exposed.
6. **Editor flow**: staging → sandboxed preview of the extracted bundle → approve → sign → release; kiosks poll opportunistically.
7. **Search (corrected per critique §4)**: per-edition SQLite FTS5 index at activation — `unicode61 remove_diacritics 2` for Latin fields (mode 2 pinned: mode 1 has the documented U+1ED9 multi-diacritic bug; the disposition stands on the shipping build's demonstrated mode 2, CHK-2/CF-02, even though the landing version was not pinned) plus a trigram column for CJK/substring (SRC-02, SRC-03). **Boundary: trigram cannot answer sub-3-char CJK queries (CF-02 [executed]: `美术` no match, `美术馆` match)** — short-CJK queries fall back to bounded `LIKE` scan on the per-edition corpus or prefix-expansion at index time; the §6 relevance matrix must include a 2-char CJK class. Per-page `lang` from the manifest; per-edition indexes keep activation atomic.
8. **Untrusted rendering**: loopback-only origin `http://127.0.0.1:<port>/editions/<hash>/`, strict CSP, no `file://`, no privileged bridges, no remote fetch; optional DOMPurify pass (SRC-09, v3.4.16) as preview-surface defense-in-depth. Condition: same-origin scripting remains possible, so the audit boundary is the absence of privileged bindings — covered by the renderer-confinement test.
9. **Accessibility gate**: WCAG 2.2 AA in CI on chrome + fixture pages: 1.4.3/1.4.11 contrast, 1.4.12 spacing, 2.4.7 focus, 2.5.1/2.5.7 gesture/drag alternatives, 2.5.8 ≥24px (44px editorial buttons recommended), 1.3.4 orientation with the museum's essential-justification on record (SRC-10). Large-text/high-contrast mode shipped.
10. **Web view baseline (correction adopted)**: track WebKitGTK 2.54.x for security releases (SRC-11); pin the exact release page + `.asc`/`.sums` at packaging time — the directory listing alone is observation, not pinning.
