## 1. Resolved product decisions (the four the draft left open)

1. **Container: hardened ZIP+manifest, not ZIM** (S1 vs S5/S6/S7). The draft's own framing is the supported default and the critic's F6 notes the ZIM variant's integration costs (search indexing against a ZIM container, libzim/toolchain adoption, fit with the editors' preview-and-approve workflow) are unexamined in bounded evidence. ZIM stays a preserved alternative (§6); flipping to it would require new bounded verification first.
2. **Trust: minisign-style single content signature + version monotonicity, not full TUF, as the shipped baseline** (S7). The museum's operational cost of TUF role ceremonies is real (a product choice the draft and critique both flag). The lighter scheme explicitly **loses** TUF's indefinite-freeze and mix-and-match defenses (S7); full TUF is kept as the named upgrade path if the threat model grows. Every other S7 property the baseline keeps: pinned trust root at the kiosk, editor-held signing key, expiry check, size limits, freshness floor (reject any version older than the highest previously activated).
3. **Sanitization: import-time and render-time (double)** (S3). One sentence of rationale: the kiosk web view is the last line of defense for untrusted contributed content, so the render-time pass stays even though import-time sanitization happens before signing.
4. **Search defaults: unicode61 `remove_diacritics=2` for Latin-script collections, trigram index added per bundle when CJK content is detected**, chosen per bundle via a manifest field, with O1 (custom tokenizer/`fts5_locale`) remaining an optional lead (S2). One sentence of rationale: it makes the multi-language requirement a per-bundle configuration instead of a global re-architecture.

## 2. Correction spine C1–C6 in final form

- **C1 (final) — extract-then-activate, never unzip over the active directory** (S5, S6). Import pipeline: extract each arriving bundle into a fresh staging directory under the content root; enforce path containment (`abspath` + `commonpath`) and per-member plus total size caps against traversal members and ZIP bombs (S6-documented pitfalls); verify contents; **fsync the staging tree and the content-root parent directory** (F8 — an explicit step, honestly marked as an engineering durability requirement beyond what the fetched S5 page documents: rename-atomicity is an in-memory ordering guarantee and without fsync a power cut can still surface an empty or partial edition); then activate.
- **C1 activation layout (F3 resolved): `active`-symlink flip.** The bounded S5 evidence establishes atomic replacement of an existing *path* ("there is no point at which another process attempting to access newpath will find it missing"; on failure "an instance of newpath" is left in place) and documents `RENAME_EXCHANGE`; it does **not** establish that a plain `rename()` replaces a non-empty target *directory*. The proposal therefore never relies on directory-over-directory replacement: the active content path is a **symlink** `active → editions/<n>`, and activation is a plain `rename()` of a freshly created symlink over it — exactly the documented path-replacement case, crash-atomic, with the previous edition directory left untouched for instant rollback. Kiosks perform the swap on local disk only (S5 NFS caveat). `RENAME_EXCHANGE` (S5-documented) is preserved as the equivalent layout for deployments that prefer real directories; validation V1 exercises both.
- **C2 (final) — never trust a bare manifest** (S7). The manifest carries a content signature (editor key), a size manifest, an expiry timestamp, and a **monotonically increasing integer edition number** (F7 resolved: the version format is defined as a plain integer compared with the recorded freshness floor, per S7's never-accept-older-than-seen rule — no string comparison). Activation requires: signature verifies, edition strictly newer than the last activated, sizes match, not expired.
- **C3 (final) — sanitize untrusted HTML at import and at render** (S3). Import-time sanitization happens server-side *before* signing; render-time sanitization runs in the kiosk. The sanitizer is pinned with a routine upgrade cadence — S3 shows several releases per month, so pin-and-forget is unsafe (§4).
- **C4 (final) — FTS5 index built at bundle import, replacing page-text scanning** (S2). Index title+body per page; `unicode61` with `remove_diacritics=2` for Latin-script languages; `trigram` added for CJK subset matching. Documented conditions carried: FTS5 requires `SQLITE_ENABLE_FTS5` at build time; **trigram substrings of fewer than 3 characters never match** (a user-facing documented condition, not a defect); unicode61 has no segmentation for space-less scripts (CJK runs become single tokens) — mitigated by the trigram index and, optionally, O1. The introducing version of trigram is now bounded: **3.34.0** per S8 (U1 resolved; pins must still be checked against the deployed SQLite build).
- **C5 (final) — WCAG 2.2 AA baseline** (S4). Target AA for the kiosk chrome and require or systematically repair contributed pages at import. Kiosk-specific notes preserved: 2.5.8 target size (24×24 CSS px) for touch, 2.2.1 timing adjustability for timed exhibit rotation, 2.4.11 focus-not-obscured because update banners commonly obscure focus; **SC 4.1.1 was removed in WCAG 2.2 and is not cited**; 2.4.13 Focus Appearance is AAA, not AA.
- **C6 (final) — keep the previous edition for instant rollback** (S5 `RENAME_EXCHANGE`; S1 whole-archive MD5 as a secondary integrity gate). Under the symlink layout, rollback is flipping `active` back one edition — a single rename — which is the direct answer to the brief's power-loss coherence requirement and is now consistent with C1 (F3 resolved). F5 honored: the plan's missing sanitization was called the *highest-severity gap* as a priority judgment about the plan, not a CVE-sourced rating — S3's page shows no CVE numbers, and this proposal makes no severity claim beyond that judgment.

## 5. Architecture summary (proposed)

One kiosk service: bundle receiver → verifier (signature, integer edition, sizes, expiry, freshness floor) → stager (contained, size-capped extraction, fsync) → activator (symlink flip; `RENAME_EXCHANGE` alternative) → renderer (restricted web view: no network, no file:// or external navigation; render-time sanitization) → search (FTS5 index rebuilt at import) → accessibility layer per C5. Central editor service: upload → import-time sanitization → preview → sign → publish. Previous editions retained on device for one-flip rollback. ZIM-per-edition remains the documented alternative container (S1) with whole-file MD5 integrity and simpler single-file activation, at the cost of the libzim toolchain and unexamined integration costs (F6).
