# D-M14-A — bounded decision for class downsampling and valid-area summaries

**Decision.** Select the coarse-cell meaning before processing. Both alternatives require a declared target grid (CRS, transform, shape) and an explicit validity policy. No universal resampler follows from the supplied sources.

## Findings

**F1 — Two alternatives for the same inputs.** **A. Representative label:** use nearest-neighbor on the class-ID band and carry validity independently, sampling the selected validity mask at the same source location/grid. This preserves an input class ID and fits display or lookup products that need one representative label; it can miss rare classes and does not mean “majority.” Keep source-valid totals separate, and report per-target coverage only if that is requested. **B. Composition:** accumulate valid source-cell area by class and total valid area within each target cell; return class fractions/coverage, or produce a dominant label only under explicit winner, tie, and mixed-cell rules. Aligned nested grids with equal-area cells permit exact area-by-count aggregation; otherwise use footprint overlap weights and the chosen area model. B answers a different question and costs more. Rasterio says grid changes require recalculating values and no method is universally correct [S2, “Up and downsampling”; “Resampling Methods”]. Choose by product meaning, not a library default.

**F2 — Keep validity, nodata, and labels distinct.** A GDAL/Rasterio valid-data mask is nonzero (typically 255) for valid; a NumPy masked-array mask is True for invalid. `read_masks(band)` is per-band; `read(band, masked=True).mask` has the inverse sense [S1, “Reading dataset masks”; “NumPy masked arrays”]. For a class band, default to its band validity unless product requirements say otherwise. For multiband products choose selected-band, all-bands-valid (AND), any-band-valid (OR), or dataset-wide semantics explicitly: Rasterio’s `dataset_mask()` prioritizes a .msk, dataset-wide alpha, or internal mask; otherwise it uses RGBA alpha, OR of nodata-derived band masks, or all-valid when nodata is absent [S1, “Dataset masks”]. A .msk can make a pixel valid even when its value equals declared nodata; it overrides nodata for returned masks without changing pixels or nodata metadata [S1, “Writing masks”; “Nodata representations in raster files”]. Thus class ID 0 is valid when the chosen mask says valid; do not infer validity from class/nodata equality. If “external mask” means a separate raster rather than a .msk sidecar, declare it authoritative or not, verify its grid alignment, and define how it is aligned/aggregated; the supplied docs do not specify that product policy.

**F3 — Limits and negative leads.** Do not bilinearly or cubically interpolate class IDs. The resampling guide only says nearest may be unsuitable for continuous data and identifies bilinear/cubic, and sometimes average, for continuous values; it does not prescribe categorical majority resampling [S2, “Resampling Methods”]. The mask tutorial’s sieve size was selected empirically for its example and is not a general mask-repair rule [S1, “Writing masks”]. The supplied GDAL affine tutorial does not prescribe CRS area methods or overlap aggregation [S4].

**F4 — Define “area.”** Always retain valid-pixel counts and the selected validity policy. For a constant affine cell footprint, planar area is `abs(GT(1)*GT(5) - GT(2)*GT(4))` in squared coordinate units, from the affine basis determinant [S4, “Transformation from image coordinate space to georeferenced coordinate space”]. Count × cell area is meaningful only when the grid and area model make that area constant and appropriate. Geographic degrees are not a physical area unit: choose a suitable projected or geodesic method and name it. Do not label a pixel count “area” without that choice.

**F5 — Preserve grid geometry and bounded processing.** Reading to a different `out_shape` resamples; update the transform for the new shape [S2, “Up and downsampling”]. GDAL pixel/line coordinates run from pixel corners (0,0) to (width,height); the first center is (0.5,0.5) [S4, “Transformation…”]. For large rasters, windows/blocks can bound memory; propagate the matching window transform and validity data. A small window may read whole storage blocks, unchunked inputs may require whole-dataset reads, and bands can have different block shapes, so check shared-window assumptions [S3, “Reading”; “Window transforms”; “Blocks”].

**F6 — Optional continuous-band lead.** An opt-in continuous path may use bilinear/cubic when interpolation is intended, or average when retaining numerical properties is desired [S2, “Resampling Methods”]. Keep it separate from class labels and validity summaries. The supplied source does not define nodata-kernel behavior or promise conservation; decide those semantics and validate them before adoption.

**F7 — Proposed validation and open choices.** These checks are **proposals, not executed tests**: (1) declared nodata 0 plus a .msk marking zero-valued class valid; assert unchanged values and validity follows the selected mask; (2) disagreeing band masks; compare selected-band, AND, OR and `dataset_mask()`, including NumPy-mask inversion; (3) nearest outputs only valid input IDs, while aggregation checks class-area sums, invalid exclusion, ties, no-valid cells and mixed-cell policy; (4) hand-computed aligned nested-grid counts/areas, plus rotated affine, partial-edge and window-transform cases; (5) continuous data under chosen resampling and nodata policy. Product choices still open: validity scope and whether an external mask is authoritative; target grid; source-total versus per-cell summaries; representative label versus fractions/dominant class and its tie/threshold rules; area units/CRS method; and class/nodata collisions. Sources establish mechanics, not these choices.
