## Topic and cross-topic findings to carry forward

1. **Shared buffer / recovery / disk changes (topic A):** Keep the resource-versus-view distinction as a compatible analogy, not a product API. Keep separate save/recovery truth and the remote-success boundary. Keep direct write versus same-directory replacement, metadata/link behavior, durability, TOCTOU, watcher loss/replacement, and timestamp granularity as conditional implementation questions. The strongest addition is the dirty→outside-write→undo-to-clean acceptance edge. It is optional coverage of F-026's current state machine; no evidence says the current combined prompt is wrong.
2. **Text / size / line endings (topic B):** Keep Ropey as one candidate, not selected product. Its default line features recognize CR; its CRLF seam helper is lower-level than F-082's nearest-surviving-boundary insertion rule. Keep exact-byte fixtures, index-unit adapters, malformed/BOM tests and 10k/5 MB boundary measurements as proposed validation. Keep preview byte bounds and F-082 tie/no-neighbor semantics as unresolved owner decisions.
3. **Intersections:** Save/recovery must operate on the same shared buffer; text offset conversions cannot fork save or undo authority; F-082 no-op/edit fidelity must survive Rope serialization; F-028 truncation/read-only reasons cannot be overridden by Rope capability; external-change prompts cannot silently overwrite recovery memory; and a failed writer can expose partial target output unless the selected save layer provides a documented guarantee. Preserve all of these as cross-topic test seams, not claims of implementation failure.
4. **Useful negative/rejected findings:** Keep “watch event is not current disk truth,” “mtime is conditional,” “atomic replace is not durability,” “Rope CRLF seam is not nearest-ending behavior,” and “Rope size capability does not prove Slint responsiveness.” Reject raising or bypassing 5 MB/10,000 lines, enabling virtualized editing, choosing mtime-only conflict checks, selecting Ropey/crop by description, and using a read-only metadata bit as sole write authority.
5. **Uncertainty and discovery limits:** Keep filesystem/platform/remote semantics, backup lifecycle, path aliases, exact Slint version/control, encoding classification, F-082 tie behavior, F-028 threshold precedence and preview budget unresolved. Discovery is useful beyond the frozen defects and non-exhaustive; do not turn it into an exhaustive recall claim or a benchmark conclusion.
