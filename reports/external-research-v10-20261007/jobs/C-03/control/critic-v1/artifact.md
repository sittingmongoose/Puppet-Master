## Critic’s claim check

The central recommendation is sound: retain the exact supplied page/document as the human reference; keep any render, OMR output, or parsed structure as a separately versioned derivative; require a person to review interpreted score data; and use explicit edition/part links and publication revisions. The researcher correctly treats OMR as fallible, source hashes as byte identity rather than work identity, visual and logical anchors as different mechanisms, and future validation as proposed rather than executed.

Corrections and limits carried into this integrated proposal:

- MusicXML 4.0 says a measure `id`, when present, is unique **within that document**; it does not provide a global cross-file identity. The `number` attribute identifies/group-matches measures and is often numeric but need not be. Displayed `text` may differ, implicit measures suppress it, and `non-controlling="yes"` means part barlines need not coincide. Do not summarize all these semantics as “measure IDs are only file-local” without distinguishing the separate attributes. Keep both the parsed file digest and part identity in any logical locator; never auto-link editions from a measure label. [C09, C10]
- The W3C spatial selector conventions support a region-based analogy, not a score-specific anchor schema. The proposed normalized-raster coordinate frame, zero-based page index, half-open rectangle bounds, page-preview digest, and transform metadata are product choices. Media Fragments’ `xywh` pixel/percentage semantics do not themselves define our preview renderer, rotation handling, or reattachment algorithm. [C11, C12]
- Audiveris 5.11.0 is pinned at commit `9e1e55cd2746037d059345881c53e6a6754bffbd`. Its README says recognition is not 100% and describes export of a subset of OMR data to MusicXML. The exact `RunTable.afterUnmarshal` → `afterMarshal` path has no null guard before reading `sequences.length`; issue #971 reports that failure on this exact build and the fallback `ZipFileSystem.open` failure. The report is open and detailed, but remains a user report: neither defect was reproduced here, and the issue’s score was not downloaded. Treat the source match as corroboration, not proof of incidence or prevalence. [C02–C04, C07]
- The prior fixed path is correctly bounded: issue #953 reports two batch-export NPEs on 5.10.2; PR #954 changed two implementation files, was merged to development on 2026-06-21, and is present in 5.11.0, whose release notes list an imperfect-scan export fix. The PR author reports recompiling the changed classes and manually running photographed multi-meter parts; no automated regression test file was added. This supports “these reported failure paths were addressed,” not “imperfect scans now export reliably.” [C01, C05, C06, C08]
- Audiveris’ pinned license is AGPL-3.0. A volunteer pilot should make a distribution/linking choice only after license review; this report is not legal advice and makes no compatibility finding. [C15]
- PDF.js is a discovery lead for viewing PDFs, not a selected renderer: only its living API documentation was examined, not pinned code, release behavior, native-platform fit, page transforms, or annotation round-tripping. Likewise Yjs and Automerge are collaboration leads supported here by living documentation, not pinned implementation audits. The first plan should avoid depending on any of them until a small comparative pilot closes those gaps. [C14, C16, C17]

A PDF viewer such as PDF.js may be compared later with a native/local page-rendering option. It is not endorsed on current evidence. Semantic MusicXML event anchors and raster regions are complementary, not substitutes: show each with its provenance and let a person confirm any relation between them.

## Integrated proposal

1. **Intake, identity, and provenance.** Let a librarian create a local work, edition, and part record. Keep stable local IDs distinct from supplied titles, composer/arranger, publisher/edition statement, year, instrument label, and catalog text. Each upload is a new versioned asset with original bytes, media type, size/hash, contributor, receipt time, permission/provenance note, and correction history. Hash equality means identical bytes, not same work, rights, contributor, or edition. Record authorization for named internal use and packet recipients; do not infer it. A replacement is a new version linked by a librarian, never an overwrite or title-based merge. Keep an unresolved equivalence state.
2. **Preview and interpretation.** Create a preview linked to its source asset, page index, renderer/build, settings, orientation/crop transform, and output digest. Preserve the source exactly. Accept an editable score file as another source, not as a substitute for an uploaded print page. OMR/parsed output is a derivative linked to the exact source/version and tool/settings. States should distinguish `unreviewed`, `reviewed`, `reviewed-with-known-errors`, `rejected`, and `stale`; each review records exact source/output digests, reviewer, time, and notes. Source replacement or reprocessing invalidates review. A successful pipeline stage is not musical correctness.
3. **Passage identity and annotation.** Make each note target a source asset plus preview version, explicit zero-based page index, normalized-preview pixel frame, dimensions, and region/stroke geometry. Record positive `x,y,width,height`, origin, unit, rotation/crop normalization, and renderer version; if half-open bounds are chosen, document that as our convention. Store pencil-like marks as sidecar vectors with point order, width/style in the declared coordinate frame, author, timestamps, and visibility. Add optional file-digest + part + measure `id`/`number`/display `text` + parser event locator as a **hint**, never as proof of cross-part correspondence. A changed page-preview digest makes the old anchor visibly stale; preserve the old source and mark, then let a person reattach or decline. A shared rehearsal note can target separate pages in differently paginated parts only after a librarian/director confirms the relationship.
4. **Collaboration and offline use.** Use director-published, immutable shared-note revisions. Members download an identified revision for offline reading. Personal marks stay private by default and may be edited locally offline. A member’s proposed shared change is a separate pending suggestion carrying its base publication revision; if the director publishes after that base, require a human to review the stale suggestion. Same-note edits must not silently overwrite: retain both, expose a conflict, and let an authorized person resolve. Show last-sync/publication identity and pending state. Do not promise cross-device synchronization until a transport and conflict/retry rules are selected and tested.
5. **Access and retention.** Separate librarian intake/identity/rights duties, director rehearsal/publication duties, and member assigned-read/private-mark duties; roles may overlap. Enforce checks on view, cache sync, packet generation, and export. Default packets exclude personal marks. Decide before real ingestion how originals, derivatives, annotations, audit/provenance records, backups, and offline replicas expire or are deleted; document who can withdraw a shared note or source. A deletion tombstone can coordinate online replicas but cannot recall a downloaded or printed copy. Provide visible local-copy clearing and disclose residual offline/backup windows. Do not promise complete deletion until those paths have been specified and validated.
6. **Rehearsal and handoff.** The director selects ordered works/passages against exact edition/part versions and publishes a packet revision. Export a portable bundle containing authorized source or print-ready files, a UTF-8 manifest, and sidecar shared notes/anchors. Include local work/edition/part/version IDs and labels, hashes, packet/publication revision, generation time, reviewer state, contributor/provenance/permission text, coordinate/index conventions, and tool versions for derivatives. Default exclude private marks; any flattened shared-note rendition is another derivative retaining sidecar/manifest. Reopen the bundle without account access in a clean environment. A packet convention is still a proposal: choose a schema and verify that a plain reader can understand it before relying on portability.

## Observable validation plan — proposed, not run

Use only a small score set with documented permission: one born-digital PDF, a clean scan, a skewed phone photograph, a supplied editable score, and two differently paginated/revised parts. Do not use the issue reporter’s IMSLP score unless its permitted use is independently established.

- **Ingest/provenance:** compare uploaded bytes/hash to source; verify every preview and interpretation is a distinct derivative linked to source, uploader, permission note, tool/version/settings, and output hash; ensure identical bytes do not collapse distinct provenance/edition records.
- **Interpretation/recovery:** show unchecked/rejected/reviewed/stale state and invalidate it on replacement/re-run. If Audiveris is licensed for the chosen distribution and used in isolation, pin release/build/settings and include clean/skewed and multi-page cases. Record symbol/measure errors against authorized ground truth; include a test intended to exercise #953’s historical path and a separate reproduction attempt for #971. Report reproduction outcome, not presumed failure. Test interrupted import and failed export; original must remain readable and missing derivatives visible.
- **Anchors:** mark regions at corners/staff lines, zoom/pan/reopen at varied scales, and check identical target pixels in the recorded preview frame. Exercise rotation, crop, orientation, page-index base, stroke width, and preview-hash change. Confirm stale anchor cannot move silently.
- **Cross-part:** use nonnumeric/display measure labels, implicit measures and non-controlling measures; verify labels never auto-relate notes. Confirm one shared instruction may have distinct human-confirmed anchors on differently paginated parts.
- **Offline/collaboration/access:** download a specific publication, disconnect, read it and create private marks plus a queued suggestion; publish a newer revision before reconnect; verify stale-base review, no silent overwrite, no leakage of private marks through UI/cache/sync/packet, and unauthorized access fails at both read and export paths.
- **Deletion/handoff:** exercise role removal, personal/shared mark deletion, rights withdrawal, an offline replica, and backup expiry. Verify tombstones and the stated residual limits. Export and reopen without account access; inspect bundle contents, manifest hashes, identities, permission text, review state, anchor units/index base, and absence of private marks.

Set accuracy, storage/retention, cache expiry, and recovery thresholds with volunteers using their authorized material. Import/render/export success does not establish musical correctness.

## Open decisions and uncertainty

- No renderer, PDF/notation parser, persistent store, sync transport, packet schema, annotation format, or OMR component has been selected. PDF.js is one unpinned discovery lead; compare its actual page/annotation semantics with a local alternative before choosing.
- Audiveris 5.11.0 has pinned code and one relevant fixed history path, but issue #971 remains open and untested here. Its license/distribution consequences need qualified review.
- Measure/event correspondence across parts and editions has no established general solution in the evidence. Require human confirmation and preserve unmatched annotations.
- The exact retention and deletion policy is a product/user decision. Local and printed copies cannot be remotely recalled; backup and offline synchronization semantics remain to be designed.
- The portability of the proposed manifest and sidecars is unvalidated. Keep the packet self-describing and test an account-free reopen before calling it portable.
- Yjs/Automerge evidence is current documentation only, not a pinned release/code audit. Do not infer secure sharing or deletion semantics from their merge behavior.
