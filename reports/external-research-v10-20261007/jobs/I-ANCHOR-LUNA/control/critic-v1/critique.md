## Verdict

The researcher draft answers the integrated brief unusually broadly and is a sound conditional proposal, not a deployment design. Preserve its central correction to the frozen plan: do not let a client timestamp select the current record. Preserve the event history, receipt workflow, explicit domain conflict review, conditional PouchDB/CouchDB prototype, native SQLite/PostgreSQL fallback, CRDT comparison, ODK workflow analogy, open choices, and proposed-only validation status. The changes below are specific points for the final reviser to tighten; they are not a replacement proposal or an adoption list.

## Actionable revisions

1. **Keep the component recommendation conditional and make the gate concrete.** PouchDB’s default browser adapter is IndexedDB; its guide says the native SQLite adapter is a separate plugin and describes browser/storage conditions that may justify going native [S14, C09]. PouchDB docs report CouchDB 3.x tested in CI, not certification of this exact PouchDB 9.0.0 / CouchDB 3.5.2 pair [S14]. Retain the prototype recommendation only after a matrix names the actual managed OS, browser, app lifecycle, database build, storage quota, and Couch server version. Specifically test foreground recovery after process/device restart and prolonged offline capture; do not imply a PWA guarantees background sync or durable storage without that evidence. The draft already asks for a device/storage spike; make that a decision gate before choosing the stack.

2. **Specify idempotency in terms of the operation, not Couch revision identity.** The stable event ID and content hash are good. Define the server rule: same event ID plus the same canonical event/attachment hashes is an idempotent duplicate even after a retry, worker restart, or a different delivery path; same ID with different content is quarantined and shown. Define canonicalization/hash inputs and have the server recompute attachment hashes before issuing a receipt. Test concurrent duplicate delivery and worker crash after accepting an event but before returning its receipt. Keep transport retry distinct from receipt: Pouch’s `live:true, retry:true` events report pause/reconnect, not durable application acknowledgment [S13, C10].

3. **Separate arrival order from causality.** A per-device sequence orders one device’s events; a server sequence records arrival order. Neither establishes a total causal order across crews. Preserve parent/superseded links and explicit concurrent status in the projection. Add a proposed assertion that reordering later causal events does not make the projection silently choose a conflicting state. The current proposal’s timestamp rejection is well supported by the offline-clock problem and should remain [S01–S02].

4. **Resolve the tension between immutable photo-bearing events and deletion.** The draft recommends putting attachments in immutable event documents where feasible, while also promising central photo/record deletion and tombstones. Couch attachments are changed through document revisions; deletion/compaction is not equivalent to immediately erasing every retained revision, backup, or disconnected copy [S06–S07, C04]. Tell the reviser to select the attachment model after retention and redaction policy is decided: if per-photo redaction is required, prefer separately addressable photo records or state another tested erasure mechanism; make the redaction event, server tombstone/deny-reupload rule, backup expiry, and disconnected-device behavior explicit. Add a test where a stale device reconnects and retries a deleted attachment. Do not state physical deletion is complete based only on a server tombstone.

5. **Clarify what “server-only receipt” means under CouchDB permissions.** Database members can read and modify all ordinary documents in their database; design-document validation can reject writes using user context, but it cannot hide receipt documents from members [S05, S19, C02–C03]. If receipts or principal/device details are private, do not store them in the same client-readable database and call them server-only: place them behind an authorized gateway/separate database and return only the receipt status the caller may see. If all members in a scope may read them, say so. Add direct and replicated-write tests for crew attempts to change receipts, supervisor read-only behavior, cross-scope reads, and the authenticated context on replication. The draft’s open access-scope question is appropriate and should remain a decision gate.

6. **Correct and sharpen the issue/fix/regression/release trail.** The #8456 → #8460 path is real: the PR description explains the conflicting attachment reference; it adds a regression and fix commit and merged 2022-03-29 [S09–S11, C06–C07]. The exact PouchDB 9.0.0 IndexedDB bundle at the pinned commit contains `revHasAttachment` and adds the digest-to-revision association only when that revision body lists it [S08, C05]. The upstream test constructs the divergence, removes the attachment-bearing leaf, compacts, then expects a missing-stub 412; it was inspected, not run here [S11, C06]. Two source corrections: (a) inherited S11’s `#L3899` fragment is wrong for this pinned file; the test begins at line 3729 and ends at 3795; preserve S11’s ID and correct its locator in the final presentation. (b) The visible Pouch 8.0.0 release page inspected here does not itself list `#8460`; do not say its release notes list the issue unless the full changelog is separately verified. Pouch 9.0.0’s exact pinned bundle is the stronger release-applicability evidence. CouchDB #5422 is marked closed, uses 3.4.2, and still shows no linked branch or PR; describe it as an unresolved applicability question, not as proof that 3.5.2 is affected or fixed [S15, C08].

7. **Retain the mechanism distinctions.** The alternatives are materially different: Couch/Pouch provides revision-based replication and conflict leaves; the SQLite/PostgreSQL path retains the local database but must implement outbox, replay, authorization, and attachment transfer; Automerge merges independent edits but same-property values still have a deterministic default and need a domain rule; ODK is a capture/finalize/send analogy, not shared-asset conflict resolution [S03–S04, S13–S18, C10–C13]. Keep their scope and caveats explicit. Don’t present CRDT convergence as a resolution of operational status conflicts or ODK as a direct replacement without separate product evidence.

8. **Preserve the proposed/executed boundary and validation breadth.** Keep the eight validation proposals as proposed. Make the duplicate/worker-recovery, stale deletion replay, receipt privacy, exact component matrix, and server-side byte-hash checks explicit tests. The inspected upstream regression test was not executed; neither it nor the researcher’s test plan demonstrates the selected pair on target devices. Keep the other useful tests for concurrent edits, attachment amplification, access control, restore, and operator history. The Pouch/Couch retry evidence is transport behavior, while exactly-once delivery is not established; continue to describe idempotent outcome rather than exactly-once delivery.
