## Topic 1 — acquisition (accepted, bounded per-tile skip-existing + capped backoff retry; bulk and byte-range-default rejected)

Independently checked: every captured client acquires per tile — leaflet.offline downloadTile→saveTile keyed by URL **[LO-TM:84,97]** with `hasTile` skip **[LO-TM:206]** (locator re-verified this stage); osmdroid saveFile keyed by tilesource+index **[OSQ:128]**; libshumate store_tile_async **[SHU:957]**. Resume granularity is per tile, not byte-range: **[MTD:154,172,197]** shows the download path is redirect-aware (`redirectCount`, `CantContinueException`) yet contains no retry/backoff — my check, extending the predecessor's NetworkAvailabliltyCheck **[OSN:33]** negative lead to the downloader itself. Resumability therefore = skip-existing on restart + viewer-owned retry, and the retry shape exists as public primary semantics: curl retries transient errors with exponential backoff (1 s doubling to a 10-minute cap), honors server `Retry-After`, bounded by `--retry-max-time` **[CURL:2764-2765,1884]**. Boundedness: OSMF policy names bulk downloading ("scraping") and offline mass use as prohibited **[OSMP]**; ControlSaveTiles' computed viewport list per action **[LO-CS:139]** is the compliant bounded pattern. Byte-range resume is rejected as the default — `accept-ranges: bytes` **is** advertised on OSM tiles **[OSMH:12]**, but small tiles make per-tile resume cheaper than range bookkeeping; kept as an optional lead for large rasters.

## Topic 1 — refresh (accepted conditional revalidation; amended: per-source header capability now partially verified)

Mechanism: conditional GET with If-None-Match/If-Modified-Since against stored validators **[R9110 §13.1.2–13.1.3]**, scheduled by stored freshness (max-age) **[R9111 §4.2]**. The predecessor left "does a tile source actually emit validators/max-age?" unresolved. My single bounded probe captured the canonical OSM endpoint returning `etag`, `cache-control: max-age=526616, stale-while-revalidate=604800, stale-if-error=604800`, `expires`, served with `age: 11504` via varnish **[OSMH:3,4,6,15]**. Amended disposition: refresh can be conditional for OSM-class sources today; the residual uncertainty is per-source variation (one URL, one time, dynamic CDN response — not a survey), so the viewer must still fall back to time-based re-download when headers are absent. Under intermittent links, stale-if-error is the documented offline fallback **[R5861 §4]** and is in live production use on OSM **[OSMH:3]**. Connectivity gating **[OSN:33]** remains backoff-free in captured code; backoff is viewer-owned per **[CURL]**.

## Topic 2 — stale display and retention (dispositions from the shared inventory, spot-checked)

Display: accepted serve-stale then background revalidate within a declared window **[R5861 §3]**; rejected blocking refresh on the display path. Stored-first with no age check goes unboundedly stale **[LO-TL:20]** (locator re-verified: `createTile` serves stored without staleness); a freshness field beside the blob is required, `mark_up_to_date` **[SHU:543]** (re-verified) the recorded update counterpart. MBTiles 1.3 carries no freshness/retention fields **[MBT]**, so expiry authority (server header vs heuristic) stays a viewer decision. ## Shared substrate (identity / freshness / reuse invalidation)

All captured stores key tiles flatly by (source, z, x, y) or URL **[MBT; LO-TM:97; OSQ:128; SHU:378]**; freshness is out-of-band metadata. Automatic reuse invalidation **[R9111 §4.4]** (locator re-verified) fires only on unsafe methods/explicit directives, so a GET-only viewer must re-key identities manually on source/version change. Both topics consume one freshness record: acquisition/refresh spends it to decide network work; display/retention spends it to decide what is shown and evicted — one substrate, two independent policies.

## Material findings (eight, distinct)

1. Per-tile skip-existing + retry is the resumability unit in every captured client; none byte-ranges small tiles **[LO-TM:206][MTD][OSQ][SHU]**.
2. Bulk acquisition is prohibited by OSMF policy; viewport/session-bounded saving **[LO-CS:139]** is the compliant bound **[OSMP]**.
3. Captured clients ship no backoff **[MTD][OSN]**; standard retry semantics are public: exponential backoff capped at 10 min, `Retry-After` honored, total time bounded **[CURL]**.
4. Canonical OSM emits ETag + max-age + RFC 5861 directives live **[OSMH]** — conditional refresh and serve-stale windows are header-supported for this source class; per-source variation unverified (amends the predecessor uncertainty).
5. Refresh disposition: conditional revalidation **[R9110 §13]** with stale-if-error offline fallback **[R5861 §4]**, degrading to time-based re-download when headers are absent.
6. Stored-first display without an age check is unboundedly stale **[LO-TL:20]**; serve-stale + bounded background revalidate **[R5861 §3]** is the accepted alternative.
7. Bounded retention exists in captured code (size-cap **[SHU]** / expiry **[OSQ]**); MBTiles 1.3 forces a viewer-owned retention schema **[MBT]**.
8. GET-only viewers receive no automatic reuse invalidation **[R9111 §4.4]**; source/version changes must re-key (source,z,x,y) identities.

## Topic comparison and discriminating checks

Shared identity+freshness, different binding point: topic 1 binds on network work (skip/validate/retry — bounded by policy **[OSMP]** and backoff **[CURL]**); topic 2 binds on user-visible truth (what may be shown stale, what is evicted). Proposed, not executed: (1) probe further candidate endpoints for validators/max-age to size the refresh fallback; (2) measure tile-size distribution to keep byte-range rejected; (3) topic-1 — kill/restart mid-acquisition, skip-existing must complete without duplicates; (4) topic-1 — inject failures, retry must back off exponentially and stop at a total-time bound; (5) topic-2 — serve stale with revalidate window = max-age, staleness must stay bounded. Checks 1–2 test the shared substrate; 3–4 are topic-1-specific; 5 is topic-2-specific. Executed this stage: 12/12 shared bytes hash-re-verified; three new captures indexed; one single-URL header probe; five locator spot-checks (LO-TM:206, LO-TL:20, SHU:543, R9111 §4.4, R5861 §3.1). Not executed: multi-endpoint header surveys, live resume/failure runs — no code executed, no bulk requests.

## Disposition ledger

Accepted: bounded per-tile skip-existing acquisition with capped exponential-backoff retry (T1); conditional revalidation scheduled by max-age with stale-if-error fallback (T1 refresh); serve-stale + bounded background revalidate (T2 display); size/expiry-bounded retention (T2). Amended: T1 refresh no longer carries blanket "header emission unverified" — narrowed to per-source variation after **[OSMH]**. Rejected: bulk/mirror acquisition; byte-range resume as default (optional lead retained); blocking display-path refresh; unbounded retention. Unresolved: header emission across other sources; acquisition-queue persistence across restarts (no captured implementation); expiry authority (server vs heuristic); RFC 5861 window normativity (informational); eviction order (rank/size vs expiry).
