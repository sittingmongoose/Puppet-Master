### Substantive criticism, corrections, and dispositions

1. **The duplicate-header recommendation needed a concrete safe path.** The v3.0.6 `_read` caller invokes `_validate_names` before constructing `TextFileReader`; duplicate caller-supplied `names` raise `ValueError`. File-header mangling tests cover repeated two-row/MultiIndex headers, not exact GH-7160 regression. Corrected P1/P5: inspect the first logical CSV record by position, then parse records using positional columns (`header=None` or a row-oriented CSV reader), preserve the raw header cells and assign internal IDs from positions. Never pass repeated source headers as pandas `names`, and never persist generated `.1` suffixes as identities. GH-7160's v0.19.0 helper adds numeric suffixes; its release note explicitly ties the before/after data-loss example to GH-7160/GH-9424. The current release note and test do not establish every parser edge case; retain parity fixtures.
2. **The parallel-parser caution was too loosely applied.** Issue #66259 is now shown closed, milestone 3.1, with no linked branch/PR or closure explanation in the issue view. It reports >50 MB local-file divergence on non-Windows and says the parallel path ignores `low_memory=False`; the proposed fix is a gate and the issue's described verification is not release evidence. The inspected pandas v3.0.6 `readers.py` has no parallel-read path. Thus this issue does not establish a defect in the pinned v3.0.6 candidate. Retain it as a version-upgrade gate only: recheck code and issue/release applicability on every upgrade; for a later release with parallel reading, require serial/parallel parity fixtures or explicitly disable that path using that release's documented mechanism. No file-size or speed claim is made.
3. **The Emoncms evidence is analogy, not component selection.** The cited live docs describe feed-based server architecture and graph behavior; they are not pinned implementation code for this local batch-import product. Issue #142 is a user-reported missing-day symptom with no verified fix or release link. Keep gaps/coverage and sparse-cumulative test ideas, but infer no product architecture or shipped correction.
4. **Timestamp rules need to distinguish ambiguous from nonexistent times.** `fold` documents the two occurrences of an ambiguous time; it does not by itself validate nonexistent wall times. Corrected P1/P3/P6: preserve raw text and flag both cases, using a tested round-trip/offset validation or equivalent; never silently choose, shift, or collapse. Offsetless repeated local times remain unresolved unless the file or user supplies enough information.
5. **CSV and export details were under-specified.** Python's standard `csv` reader is a viable small-scope alternative, but its `strict` option defaults false. If chosen, open with `newline=''`, set explicit dialect/encoding and strict parsing, and validate every row width. In any parser, preserve original bytes/hash separately from decoded fields; disable implicit NA/date/numeric conversion until review. Coverage must count expected intervals from an explicit calendar and interval convention, not from observed rows alone.
6. **Unjustified implementation choices remain choices.** A relational database, pandas, chart library, Python runtime, estimated/fill view, and portable review bundle were proposals, not evidence-backed user requirements. Keep runtime, store, and chart choices open behind stated acceptance checks; keep fill and extrapolation out of the MVP. Author event ranges/labels only; do not require author identity. No criticism changes the brief's privacy, locality, one-building/three-meter scope, or non-claims.

## Proposed replacement sandbox plan

### P1 — Import, preview, and immutable evidence

Accept CSV exports for one building, three meters, and at most one year per meter. Keep each selected original byte-for-byte; record a content hash, size, and import-run identity. Before normalization, preview and confirm encoding/BOM policy, delimiter, quoting/escape convention, header record, source-position-to-field mapping, meter alias, timestamp syntax, start/end/register-instant meaning, time-zone/offset convention, explicit interval duration, unit, decimal convention, and value kind (interval energy, average/instantaneous power, or cumulative register). Preserve decoded raw field strings, logical source row number, original header cell and position, and every interpretation revision.

For pandas v3.0.6, read the header and data positionally (for example, `header=None`, string dtype, `keep_default_na=False`, `na_filter=False`, and no date parsing); validate row widths and only then apply reviewed mappings and conversions. Do not supply duplicate names. For Python `csv`, use `csv.reader` with `newline=''`, explicit encoding/dialect, strict mode, and row-width validation. Parser-specific tests must prove equivalent reviewed records or a clear row-and-column error. Never silently skip a malformed row, turn unknown text into zero/NA, or treat a parser-generated suffix as a field identity. Parser/runtime remains a product choice: prefer the standard-library path for this bounded workload unless a later measured requirement justifies pandas; if pandas is selected, pin a tested release and adapter.

### P2 — Local storage and review

Keep a local-only store with distinct source-file, raw-row, mapping/interpretation-revision, normalized-interval, review/exclusion, event, and export-run records. Store choice remains open: a local relational database is the default proposal if transactional review and repeatable queries are needed; a portable project-file store is an alternative if portability is more important. Decide after confirming single-user use, backup needs, and whether project portability is required. Every normalized value links to source hash, row, and interpretation revision. Classify exact duplicate rows, identical intervals with conflicting values, partial overlaps, and duplicate timestamps separately. Show originals and provenance; never overwrite with a newer export. Exclusions are scenario decisions and never mutate raw records.

### P3 — Dashboard and comparison semantics

Show daily/monthly totals, time-of-day profiles, and user-selected period comparisons. Label meter, period, local zone, interpretation revision, value kind, and units. For each period show calendar-expected and observed intervals, coverage, missing intervals, and excluded/suspect counts. Missing data appear as gaps. Filled or estimated views are outside the MVP; any later option must be separately approved, labeled, and excluded from observed totals and defaults. Do not extrapolate partial coverage.

Sum only valid, non-overlapping interval-energy records. Exclude a boundary interval or use an explicitly approved allocation rule; never silently prorate. Convert power to energy only when duration and interval-average/hold semantics are justified and shown; point samples without a justified integration rule do not yield totals. Difference cumulative readings only across valid adjacent intervals; negative jumps are review cases for reset, rollover, correction, or error. Rollover requires explicit meter range/behavior. Use exact decimal or integer-scaled arithmetic with a documented unit conversion and rounding point; verify by hand-calculated fixtures.

Use building-local calendar periods after retaining an unambiguous instant (UTC plus original zone/offset where available). Preserve both fall-back occurrences as distinct instants. A nonexistent spring-forward wall time and an ambiguous offsetless fall-back time stay in review until resolved; no automatic shift or row-order guess. Define and test how intervals crossing local midnight are allocated; absent an approved rule, exclude them from daily totals and disclose the exclusion. Comparisons expose coverage differences and are descriptive, not verified savings or causal estimates. Chart library remains open pending checks for visible null gaps, DST labels, multi-unit overlays, offline operation, accessible table alternative, export, and packaging.

### P4 — Interpretations, events, and boundaries

Allow competing export interpretations to be saved and compared side by side. Operator events such as closures are optional time-range annotations; they never change readings or establish cause. Keep the explicit limits: one building, three meters, one year; no bill certification, tariff conclusions, automated controls, equipment-purchase advice, or verified-savings claims.

### P5 — Components, privacy, and local operation

Choose runtime and parser only after normal-laptop packaging/startup and representative-file checks. Candidate parser path: positional standard-library CSV reader by default; pandas v3.0.6 behind a product-owned adapter only if measured needs justify the dependency. An upgrade requires renewed pinned-code, issue/release, header, NA, and serial/parallel applicability review. Aggregation belongs in a deterministic domain layer separate from charts. Storage and charts remain unresolved as specified in P2/P3. Process locally by default; no cloud account or third-party service. Default exports omit account identifiers and raw file paths. A user may opt into a review package containing selected source hashes, aliases, row references, interpretations, coverage, exclusions, and uncertainty; ask before including filenames or identifiers.

### P6 — Comparison export and proposed validation

Export scenario-specific meter alias, period boundaries and zone, units/value semantics, observed total, expected/observed coverage, included/excluded counts, interpretation revision, and a manifest of selected source hashes/import choices. Include row references for reviewed exceptions. State that output is not billing certification or verified savings.

Proposed checks for the later authorized sandbox (none executed here):

1. CSV: quoted delimiter/newline, BOM and supported encodings, alternate delimiter/decimal settings, duplicate/blank headers, quoted duplicate labels, missing/extra fields, empty file, malformed quoting, unknown tokens, inconsistent widths, repeated identical file, duplicate timestamps, and large-file fixture. Assert raw evidence/positions survive; parser choices yield equivalent reviewed records or explicit errors.
2. Time: UTC/offset inputs, interval start/end, repeated fall-back hour with both offsets, offsetless ambiguity, nonexistent spring-forward time, leap day, range boundaries, local midnight crossing, and 23/25-hour days. Assert ambiguity classification, coverage, and visible review; no collapse/shift.
3. Values: unit multiples, decimal separators, interval energy, power with known duration and explicit integration assumption, cumulative readings, missing values, reset/rollover candidates, precision, and rounding. Compare every total to hand-calculated fixtures.
4. Review/storage: exact duplicate, conflict, partial overlap, exclusion, alternate interpretation, event annotation, repeated import, and recovery. Assert raw immutability, provenance, and scenario-specific results.
5. Aggregation/comparison: gap reduces coverage; totals recompute from included rows; unequal coverage is explicit; repeated DST bins remain distinct; boundary policy is applied; no imputation or extrapolation by default. If a parser release includes parallel reads, compare against its serial path and pin/disable as justified.
6. Export/privacy: recompute selected scenario from manifest/source identity; check aliases, units, coverage, exclusions, and interpretation; default omits account identifiers and file paths; optional provenance fields require explicit selection.
7. Packaging: chosen runtime and timezone data availability on target normal laptops, startup, offline operation, and representative file sizes. Do not claim performance until measured.
