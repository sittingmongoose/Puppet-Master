# Legitimate test input — untrusted candidate preliminary proposal

This is a preliminary bounded recommendation. The allowlisted inputs include no candidate-authored critique or earlier draft, so I cannot adjudicate critique-specific findings; the points below address the brief and identify that gap.

1. **Treat category IDs as labels.** Use nearest-neighbor as the conservative categorical baseline so output values remain sampled source values. Resampling changes cell values and has no universally correct method; Rasterio 1.3.10 specifically warns nearest may be unsuitable for continuous data [R1]. If the product requires a representative aggregate, investigate a categorical mode rule separately, including ties and invalid contributors; the frozen sources do not establish that method's availability or semantics for this release.

2. **Bind the class domain.** Record the input class-ID-to-label table, output dtype, and permitted IDs. Reserve a representable value outside that domain for nodata only when one exists; otherwise preserve invalidity with a mask. Validate that output IDs belong to the declared domain. These are proposal constraints for the categorical input described in the brief, not behavior guaranteed by the cited docs.

3. **Choose validity deliberately.** Read and document the effective per-band validity mask (read_masks: nonzero means valid); NumPy masked-array masks use the opposite sense [R2]. Check for sidecar/internal masks and alpha. Rasterio's dataset-mask precedence can select those masks ahead of nodata; with nodata it combines band masks by binary OR. Do not silently substitute that dataset-wide OR for a product rule that requires all bands valid or a particular band's validity [R2].

4. **Keep output values and validity separate.** Apply the chosen validity rule when building the output mask and nodata metadata. A .msk mask may override nodata metadata on later reads, and write_mask can set validity without changing pixel values or nodata metadata [R2]. Reopen the output and verify both the stored class values and the effective mask, especially when a valid class could equal the proposed nodata sentinel.

5. **Recheck validity after resampling.** Specify how an output cell is considered valid when its selected source sample is invalid or its footprint intersects invalid pixels. The supplied docs do not define the desired categorical mask aggregation rule, so do not infer validity solely from the output class value. Make the chosen edge behavior explicit and test it against the mask policy [R1, R2].

6. **Keep grid geometry coherent.** Set the requested output width and height, then scale the affine transform by source-width/output-width and source-height/output-height, as Rasterio's out_shape example does [R1]. Preserve the intended origin/extent; the GDAL affine coefficients encode origin, pixel width/height, and possible rotation, with north-up pixel height commonly negative [G1]. Check transformed corners and pixel size against the requested grid.

7. **Keep continuous advice optional and distinct.** For a separate continuous band, bilinear or cubic may be preferable to nearest; average may help retain selected numerical properties [R1]. Do not apply that recommendation to class IDs. Proposed checks (not performed): class-domain preservation, nodata collision, mask precedence/edge behavior, and output dimensions/transform/corners. The frozen sources do not settle the categorical aggregate or mask policy, and no tests were run.
