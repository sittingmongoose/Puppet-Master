## Claim and dependency results

1. **Categorical resampling policy (amendment 1; S1).** Rasterio says changing the grid entails recalculating values, there is no universally correct interpolation method, nearest is the default, and it may be unsuitable for continuous data. It does not say nearest is categorically correct, define class semantics, or define dominant-class aggregation. The amendment properly presents nearest only as a product-selected sampling baseline/inference; class-owner choice, domain, footprint aggregation, and tie rule remain dependencies, not source facts.

2. **Class domain and nodata collision (amendment 2; S2).** The mask guide demonstrates that declaring zero nodata can mask some otherwise meaningful zero-valued pixels and explains that a .msk can override nodata metadata. This supports separating validity from class identity and resolving collisions from authoritative metadata/mask policy. It does not provide this product's class mapping, valid-code set, sentinel, or prove that a resampling operation cannot emit the sentinel. Those are correctly left unresolved; checking output codes/validity is proposed, not performed.

3. **Input mask polarity and precedence (amendment 3; S2).** The guide states GDAL valid-data masks are nonzero for valid pixels and NumPy masked-array masks use True for invalid pixels. It documents dataset_mask() precedence: .msk, dataset-wide alpha, or internal mask; RGBA shadow nodata uses band 4; otherwise nodata uses binary OR of band masks; absent nodata yields all-valid. Thus the amendment's conditions are supported. Its warning that dataset_mask() is not an all-bands-valid rule follows directly from the OR condition; per-band read_masks() is the applicable documented interface when validity is per band.

4. **Output validity and operation behavior (amendment 4; S1/S2).** The captures document source-mask interpretation and general resampling, but do not specify downsampled-mask semantics or guarantee how a selected Rasterio operation propagates nodata/external masks. The amendment correctly labels same-location, any-contributor, and all-contributors as policy alternatives and requires product selection plus operation-specific validation. This remains unresolved until a policy is supplied and an actual check is run.

5. **Output shape, transform, and grid dependency (amendment 5; S1/S3).** S1's out_shape example scales the existing transform by source width/output width and source height/output height. S3 defines the affine transform (including pixel vectors/rotation) and maps pixel corners from (0,0) through (width,height). Together they support scaling the existing same-CRS grid and checking corners/footprint. The preservation of the existing footprint is the geometric consequence of scaling those vectors about the existing origin, not a separate guarantee about arbitrary bounds/alignment. If bounds/alignment differ, destination transform and shape must be deliberately set together. S1 points CRS changes to reprojection guidance but that guide is not in this frozen corpus; the recommendation is therefore limited to saying the same-CRS resize formula is insufficient for CRS change and a reprojection/destination-grid workflow is needed.

6. **Optional continuous-band method (amendment 6; S1).** S1 supports bilinear/cubic as better suited than nearest for continuous data and average as potentially useful for retaining certain numerical properties. It does not make any method universally best or decide per-product goals. The per-band, conditional, separate optional lead is supported and qualified.

7. **Verification claims (amendment 7; S1-S3).** Proposed checks are recommendations, not source-reported or executed results. No raster data, application code, or tests were run. The proposed checks are allowed to test the unresolved class-domain, validity, transform/footprint, and continuous-band conditions; they must not be reported as completed.
