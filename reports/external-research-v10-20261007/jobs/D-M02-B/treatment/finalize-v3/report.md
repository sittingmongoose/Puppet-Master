## Recommendation and dispositions

1. **Q1 — accepted:** For a whole-pixel crop, construct `Window(col_off=c, row_off=r, width=w, height=h)` in source pixel coordinates and read it with `src.read(..., window=win)`. Keep the crop’s spatial reference with `src.window_transform(win)`. If writing a cropped dataset, copy source metadata and update `height`, `width`, and `transform` to the window dimensions and window transform. Rasterio documents integer and floating window offsets/sizes, but integer, nonempty, in-bounds windows avoid leaving fractional-window rounding and edge policy implicit. [Rasterio windowed I/O 1.3.10, lines 13–24, 119–164](https://raw.githubusercontent.com/rasterio/rasterio/1.3.10/docs/topics/windowed-rw.rst)

2. **Q2 — accepted with a condition:** Reading into a different `out_shape` is resampling: it changes the grid and recalculates values. For a crop of `w × h` source pixels written to `W × H`, use the crop transform as the base, then scale its pixel axes by `w/W` and `h/H` (e.g. `src.window_transform(win) * Affine.scale(w / W, h / H)`). This retains the cropped upper-left origin while representing the larger or smaller output cells; use the actual returned array dimensions. Rasterio’s example applies this rule to a full dataset; combining it with its documented window transform for a crop is an affine-coordinate inference, not an executed Rasterio check. [Rasterio resampling 1.3.10, lines 10–20, 34–48; windowed I/O, lines 142–164](https://raw.githubusercontent.com/rasterio/rasterio/1.3.10/docs/topics/resampling.rst)

3. **Pixel count versus I/O — rejected:** Do not equate `w × h` logical crop pixels (per band) with physical bytes or blocks read. Rasterio may read full touched chunks; its example warns a 1×1 request can require a 512×512 chunk, or the entire dataset for an unchunked source. The actual layout is unknown here. Inspect per-band `src.block_shapes`; consider block-aligned reads only if workload and measurements justify them. Rasterio also cautions that bands need not share block layouts. [Rasterio windowed I/O 1.3.10, lines 57–66, 188–203, 233–251](https://raw.githubusercontent.com/rasterio/rasterio/1.3.10/docs/topics/windowed-rw.rst)

4. **Coordinate relationship — accepted:** Cropping changes the affine origin to the crop’s upper-left corner but keeps the source grid spacing. Resampling changes pixel spacing and cell values. Use the crop transform before applying output-shape scaling; do not scale the full-dataset transform for a crop. GDAL defines affine image coordinates from pixel corners: `(0,0)` is the upper-left corner and `(0.5,0.5)` is that pixel’s center. Do not add a half-pixel shift to the corner-anchored transform. The full affine also carries rotation/skew terms, so validate coefficients rather than assuming north-up rasters. [GDAL geotransform tutorial 3.9.0, lines 9–32; Rasterio windowed I/O, lines 142–164; resampling, lines 44–48](https://raw.githubusercontent.com/OSGeo/gdal/v3.9.0/doc/source/tutorials/geotransforms_tut.rst)

5. **Resampling choice — amended:** For continuous fields, bilinear or cubic are documented alternatives to the default nearest; `average` may suit a numerical aggregation goal. No method is universally correct. For categorical labels, nearest is a conservative candidate when the requirement is to retain an existing class code; bilinear/cubic interpolation of class numbers would create values with no label meaning. If downsampling is meant to represent dominant area, nearest may not answer that question: define a majority/other aggregation rule, nodata and tie behavior, and verify support in the selected released API first. The supplied source neither names the class labels nor establishes their semantics, so this choice remains conditional. [Rasterio resampling 1.3.10, lines 53–68](https://raw.githubusercontent.com/rasterio/rasterio/1.3.10/docs/topics/resampling.rst)

6. **Fixtures and unresolved conditions:** Proposed, not run: (a) a 1024×1024 synthetic raster with a nonsymmetric affine and row/column-coded values; check a non-origin crop’s shape and that `window_transform` maps its corners to the matching source coordinates; (b) resample that crop to noninteger scale ratios and compare output shape, scaled affine coefficients, and footprint; (c) use a known tiled fixture with an interior 1×1 read and a block-crossing crop, then measure driver/storage reads if physical I/O must be asserted; also include an unchunked fixture if that case is supported; (d) use continuous ramps and a labeled categorical fixture to test each configured resampler, nodata edges, and any declared majority/tie rule. At runtime, inspect every band’s block shape rather than assuming equality. Actual source block layout, class meanings, preferred aggregation semantics, and I/O costs remain unresolved.
