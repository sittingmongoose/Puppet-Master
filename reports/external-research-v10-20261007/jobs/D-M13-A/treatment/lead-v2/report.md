3. **Regression coverage (executed check: read-only grep/read of frozen `taroldtest.py`; proposed check below is not executed).** Class `TestExtractionFilters` (~3404) is the PEP 706 suite: `test_fully_trusted_filter` (~3908, identity), `test_tar_filter` (~3915), `test_data_filter` (~3925); absolute-path rejection (~3513 expects `AbsolutePathError`), outside-destination/link-outside (~3548/3626/3639/3646 expects `OutsideDestinationError`/`LinkOutsideDestinationError`), `test_default_filter_warns` (~3937), `test_change_default_filter_*` (~3946–3981), `test_custom_filter` (~3987), `test_bad_filter_name` (~4004), `test_stateful_filter` (~4010). Demonstrates: named filters reject absolute/outside paths and constrain metadata, default-without-filter warns in 3.12, string names resolve and bad names fail, custom/stateful filters compose. Pre-existing extraction tests also pin `filter='data'`/`'fully_trusted'` explicitly (e.g. lines 118, 478, 658–737). What it does not demonstrate: safety of arbitrary archives, non-tar formats, or importer-specific destination handling.
4. **Importer-policy amendment (applicable to 3.12.3).** Pass an explicit filter on every extraction call: `tar.extractall(dest, filter='data')` / `tar.extract(m, dest, filter='data')`, or `shutil.unpack_archive(path, dest, filter='data')` for tar archives; alternatively set `TarFile.extraction_filter = tarfile.data_filter` (function, not string — strings raise `TypeError` for that attribute) on the importer-owned class/instance. Catch `tarfile.FilterError` (incl. `AbsolutePathError`, `OutsideDestinationError`, `LinkOutsideDestinationError`) and fail closed (abort import, do not fall back to `fully_trusted`). Do not rely on the 3.12 default: it warns and behaves as `fully_trusted`. Pin this in code review/lint (no `extract(all)` without `filter=`), not only docs.
5. **Residual limitations; no universal safety claim.** `data` filter reduces "surprising/dangerous" behaviors but does not make extraction universally safe: fully-trusted archives can still be malicious in content; custom filters can reintroduce risk; `tar` filter is weaker than `data` by design; error handling differs (fatal vs nonfatal vs skip-None) so callers must handle all three; default changes in 3.14 — behavior pinned here is 3.12.3 only. Frozen PEP text is context, not runtime truth. No claim about CVEs beyond this lead, other Python versions/branches, or backports (issue lists follow-ups gh-103832…gh-104583 and an unofficial backport — not traced; recorded as negative/optional leads, stopped per bounded scope).
6. **Bounded additional regression (proposed, not executed; stop rule met).** Add one test in importer's suite (not CPython): build a minimal in-memory tar with one member `../evil.txt` and one absolute-path member, call importer's extract helper with its default policy, assert it raises `tarfile.OutsideDestinationError`/`AbsolutePathError` (or importer's wrapped error) and writes nothing outside dest; repeat with `filter='fully_trusted'` only to assert the test would fail-open (documents why explicit `data` is required). Stop: decision (explicit `data` + fail-closed) is supported by (1)–(3); no further archive corpus needed.
