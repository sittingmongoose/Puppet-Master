3. **Regression coverage (frozen `taroldtest.py`; states what it demonstrates).** Class `TestExtractionFilters` (~3404): `test_absolute` (~3491, `AbsolutePathError`), `test_parent_symlink*` (~3517+, `OutsideDestinationError`/`LinkOutsideDestinationError`), `test_fully_trusted_filter` (~3908, identity), `test_tar_filter` (~3915), `test_data_filter` (~3925), `test_default_filter_warns` (~3937, `DeprecationWarning` "Python 3.14"), `test_change_default_filter_*` (instance/class/subclass accept callables; string→`TypeError`), `test_custom_filter` (~3987, rename/skip), `test_bad_filter_name` (~4004, `ValueError`), `test_stateful_filter` (~4010). Pre-existing extraction tests pin `filter='data'`/`'fully_trusted'` explicitly. Demonstrates: named filters reject absolute/outside paths and constrain metadata, 3.12 default-without-filter warns, string names resolve and bad names fail, custom/stateful filters compose. Does not demonstrate: safety of arbitrary archives, non-tar formats, or importer-specific destination handling.
4. **Importer-policy amendment (applicable to 3.12.3).** Pass an explicit filter on every extraction: `tar.extractall(dest, filter='data')` / `tar.extract(m, dest, filter='data')`, or `shutil.unpack_archive(path, dest, filter='data')` for tar archives; alternatively set `TarFile.extraction_filter = tarfile.data_filter` (function, not string — strings raise `TypeError` for that attribute) on the importer-owned class/instance. Catch `tarfile.FilterError` (incl. `AbsolutePathError`, `OutsideDestinationError`, `LinkOutsideDestinationError`) and fail closed (abort import; no fallback to `fully_trusted`). Do not rely on the 3.12 default: it warns and behaves as `fully_trusted`. Enforce in code review/lint (no `extract(all)` without `filter=`), not docs alone.
5. **Residual limitations; no universal safety claim.** `data` reduces "surprising/dangerous" behaviors but does not make extraction universally safe: file content can still be malicious; custom filters can reintroduce risk; `tar` filter is weaker than `data` by design; three outcomes (fatal vs nonfatal vs skip-`None`) must all be handled; 3.14 default-switch text is 3.12.3-docs/PEP context, behavior pinned here is 3.12.3 only. No claim about CVEs beyond this lead, other versions/branches, or backports.
6. **Bounded additional regression (proposed, not executed; stop rule met).** Add one test in the importer's suite (not CPython): build a minimal in-memory tar with one `../evil.txt` member and one absolute-path member, call the importer's extract helper under its default policy, assert it raises `OutsideDestinationError`/`AbsolutePathError` (or the importer's wrapped error) and writes nothing outside dest; repeat with `filter='fully_trusted'` only to assert the test would fail-open (documents why explicit `data` is required). Stop: decision (explicit `data` + fail-closed) is supported by (1)–(3); no further archive corpus needed.
