# D-M13-A / control / finalize-v2 — Explicit extraction filter for a CPython 3.12.3 importer (final)

Question: should a package importer targeting CPython 3.12.3 pass an explicit extraction filter? Investigate the PEP 706 lead (issue 102950 / PR 102953), trace the implementation branch, regression coverage, and release boundary, and propose a small importer-policy amendment. Do not audit every tarfile vulnerability.

Recommendation: **require `filter='data'` on every `extract`/`extractall` call; treat `FilterError` as fatal at default errorlevel; clean up the destination on abort.** Target is pinned CPython 3.12.3 where the feature exists but the default is still legacy.

## Findings (6 obligations)

1. **Issue, merge, and 3.12.3 availability are distinct (Obl. 1).** Issue 102950 ("Implement PEP 706 – Filter for tarfile.extractall", created 2023-03-23, closed 2023-05-30) tracks the work; it ships no code. PR 102953 ("gh-102950: Implement PEP 706", base `main`) merged 2023-04-24T08:58:06Z, merge SHA `af530469954e8ad49f1e071ef31c844b9bfda414` (8 files: `Lib/tarfile.py`, `Lib/shutil.py`, both test files, `Doc/library/tarfile.rst`, `Doc/library/shutil.rst`, `Doc/whatsnew/3.12.rst`, 1 NEWS fragment). PEP 706 targets Python 3.12; frozen `v3.12.3` `Lib/tarfile.py` contains `_get_filtered_attrs`, `fully_trusted_filter`, `tar_filter`, `data_filter`, `_NAMED_FILTERS`, `TarFile.extraction_filter`, and `filter` params — so 3.12.3 **has** the feature. With `filter=None` and `extraction_filter=None`, 3.12.3 warns (`DeprecationWarning`: "Python 3.14 will, by default, filter…") and falls back to `fully_trusted_filter`; the `'data'` default arrives in 3.14 only. An importer omitting `filter` on 3.12.3 gets legacy behavior plus a warning, so the filter must be explicit.
2. **Consequential branch: outside-destination gate (Obl. 2).** In `_get_filtered_attrs(member, dest_path, for_data)` (`tarold.py:755+`, shared by `tar_filter`/`data_filter`): strip leading `/`/`os.sep`; if still absolute raise `AbsolutePathError` (e.g. `C:/foo` on Windows); `target=realpath(join(dest,name))`, and if `commonpath([target,dest]) != dest` raise `OutsideDestinationError`. `data_filter` (`for_data=True`) adds absolute/outside-link refusal (`AbsoluteLinkError`/`LinkOutsideDestinationError`), device refusal (`SpecialFileError`), mode sanitization (`& 0o755`, exec-bit/owner read-write rules) and ownership stripping. Callers: `extractall`/`extract(..., filter=...)` → `_get_filter_function` (None→`extraction_filter`→warn+`fully_trusted`; callable passthrough; string via `_NAMED_FILTERS`; unknown→`ValueError`) → `_get_extract_tarinfo` (calls filter; `None` skips member) → `_extract_one` → `_extract_member`; CLI `--filter` passes through to `extractall`. `shutil.unpack_archive` was extended in the merge but not line-traced (bounded stop).
3. **Regression coverage (Obl. 3; static read, not executed).** Frozen `v3.12.3` `Lib/test/test_tarfile.py::TestExtractionFilters` (~line 3404) with `check_context`/`ArchiveMaker` hostile-archive harness: `test_benign_file` (all filters pass benign file); `test_absolute`/traversal/symlink tests (`fully_trusted` reproduces escape, `tar`/`data` raise `AbsolutePathError`/`OutsideDestinationError`/`LinkOutsideDestinationError`); device tests (`data` raises `SpecialFileError`, `tar`/`fully_trusted` allow); `test_tar_filter`/`test_data_filter`/`test_fully_trusted_filter` unit checks; `test_default_filter_warns` plus `extraction_filter` override tests. Demonstrates: the gate fires exactly on hostile members, `fully_trusted` preserves legacy behavior, `data` is strictest, and the omitted-filter warning exists. Not demonstrated: DoS limits, shadowing, caller cleanup.
4. **Importer-policy amendment (Obl. 4).** On pinned 3.12.3: pass string `filter='data'` at every `extract`/`extractall` (and `shutil.unpack_archive` where used); keep default `errorlevel>=1` so `FilterError` is fatal; on abort discard the destination (extract into fresh `tempfile.mkdtemp`). Optionally set `TarFile.extraction_filter = staticmethod(tarfile.data_filter)` as defense-in-depth where the importer owns the `TarFile` — a **function**, never a string (strings are rejected there by design and silently no-op on older Pythons). If tar-specific features are genuinely needed, standardize on `filter='tar'` explicitly and justified; never rely on the 3.12 default. No version fallback needed on pinned 3.12.3; shared <3.12 code must fail-or-warn per docs, never silently extract.
5. **Residual limitations; no universal safety (Obl. 5).** `filter='data'` does not make extraction universally safe. Docs: never extract untrusted archives "without prior inspection"; filters "do not prevent denial-of-service attacks"; on refusal the archive "may be partially extracted" and tarfile "does not attempt to clean up" — cleanup is the caller's duty; `errorlevel=0` downgrades refusals to skip-and-continue and must not be set silently. Uncovered: file-count/total-size/name-length caps, control characters/confusables/foreign separators, expected-extension allow-lists, case-insensitive shadowing, duplicate members (later overwrites earlier), symlink evaluation against live disk. Impose OS-level disk/memory/CPU limits where input may be untrusted.
6. **One bounded additional regression, then stop (Obl. 6; proposed, not executed).** Single archive with 5 members — benign `ok.txt`, absolute-path member, `../escape` member, symlink pointing outside dest, fifo/device member — asserting at default errorlevel: `filter='data'` raises the four expected errors (`AbsolutePathError`/`OutsideDestinationError`/`LinkOutsideDestinationError`/`SpecialFileError`) while extracting `ok.txt`; `filter='tar'` blocks absolute/escape but allows the fifo; omitted `filter` emits `DeprecationWarning` on 3.12.3. Stop rule: when `data` blocks all four hostile members and the benign member passes, the importer decision is supported; no further sweep.
