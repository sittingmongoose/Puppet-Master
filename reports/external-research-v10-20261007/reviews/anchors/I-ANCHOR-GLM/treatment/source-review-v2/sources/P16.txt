27: fsync() transfers ("flushes") all modified in-core data of (i.e.,
28: modified buffer cache pages for) the file referred to by the file
29: descriptor fd to the disk device (or other permanent storage
30: device) so that all changed information can be retrieved even if
31: the system crashes or is rebooted. This includes writing through
32: or flushing a disk cache if present. The call blocks until the
33: device reports that the transfer has completed.
34: As well as flushing the file data, fsync() also flushes the
35: metadata information associated with the file (see inode(7)).
36: Calling fsync() does not necessarily ensure that the entry in the
37: directory containing the file has also reached disk. For that an
38: explicit fsync() on a file descriptor for the directory is also
39: needed.
40: fdatasync() is similar to fsync(), but does not flush modified
41: metadata unless that metadata is needed in order to allow a
42: subsequent data retrieval to be correctly handled. For example,
43: changes to st_atime or st_mtime (respectively, time of last access
44: and time of last modification; see inode(7)) do not require
45: flushing because they are not necessary for a subsequent data read
