## Material defects

Candidate locations below refer to the frozen `jobs/I-ANCHOR-GLM/control/reviser-v2/final.md`, its `critique-dispositions.md`, or the supplied `critic-v2/critique.md`. ### M1 — unsupported durability guarantee (high)

Claim: activation is a plain `rename()` of a freshly created symlink over it — exactly the documented path-replacement case, crash-atomic.

Location: reviser-v2/final.md:20, reviser-v2/final.md:19, reviser-v2/final.md:25, reviser-v2/critique-dispositions.md:26.

Primary check: rename documents atomic namespace replacement; fsync documents separate persistence of directory entries. C1 fsyncs before activation and never specifies flushing the directory containing active after the rename. It also does not define durable publication of staging under editions/<n> or recovery. Evidence: sources/P09-fsync.txt:27-39, sources/P43-rename-description.txt:31-50.

Impact: The central power-loss requirement is asserted as solved without a complete persistence protocol or pinned filesystem/recovery assumptions. V1 is useful but only proposed. Limit: No crash test was run; this is an unsupported general guarantee and missing persistence step, not a demonstrated failure on a particular filesystem. A prior edition may survive, but that does not establish the promised always-valid active path.

### M2 — incorrect source governing condition (medium)

Claim: S5’s guarantees are Linux `rename(2)` with a brief both-resolve window and no NFS atomicity.

Location: reviser-v2/final.md:31, reviser-v2/final.md:20, critic-v2/critique.md:23.

Primary check: The NFS BUGS paragraph says a failed RPC can follow a rename that already happened after server crash/retransmission. It does not state that NFS makes replacement non-atomic. Evidence: sources/P43-rename-description.txt:233-239.

Impact: Misstates the source limitation and preserves an incorrect critic condition. Local storage remains a defensible product restriction. Limit: This does not certify all NFS deployments or their crash semantics; it rejects the blanket attribution to this primary page.

### M3 — incorrect release applicability (medium)

Claim: a pin below 3.4.16 misses the raw-text-root and XML-clobbering fixes.

Location: reviser-v2/final.md:29, reviser-v2/critique-dispositions.md:10, critic-v2/critique.md:10.

Primary check: 3.4.15 already contains XML-clobbering hardening. The rawtext-root guard and matching regression additions belong to 3.4.16. Version 3.4.15 is therefore a counterexample to the conjunctive blanket claim. Impact: The required affected/fixed release analysis is wrong even though the recommendation to keep the sanitizer current is useful. Limit: This does not claim 3.4.15 is generally safe; it distinguishes two different fixes and their applicable versions.

### M4 — unresolved multilingual behavior and overgeneralized condition (medium)

Claim: trigram substrings of fewer than 3 characters never match.

Location: reviser-v2/final.md:23, reviser-v2/final.md:15, reviser-v2/final.md:38, reviser-v2/final.md:40.

V4 can expose this but supplies no acceptance outcome. Limit: The candidate correctly discloses the MATCH limitation; no hidden runtime bug is alleged. ### M5 — underdefined security and approval contract (high)

Claim: Activation requires: signature verifies, edition strictly newer than the last activated, sizes match, not expired..

Location: reviser-v2/final.md:21, reviser-v2/final.md:13, reviser-v2/final.md:37, reviser-v2/final.md:44.

Primary check: TUF binds target content using hashes in authenticated metadata; minisign signs a selected file’s bytes. The proposal specifies a content signature in a manifest and sizes but no exact signed object, canonical encoding, detached signature or authenticated content-hash mapping. Highest previously activated differs from S7 highest previously seen. Persistence, rollback interaction, clock trust and preview-to-signed-byte identity are not defined. Evidence: sources/P07-tuf.txt:117-143, sources/P10-minisign.txt:20-35,113-121, sources/P17-tuf-spec.txt:759-798.

Impact: Cannot establish complete integrity, anti-rollback or remote approval semantics from this contract. If only the manifest plus sizes is authenticated, equal-length substituted files are not excluded; if the whole immutable bundle is signed, that case can be excluded, but the proposal does not choose the contract. Limit: This is a completeness gap, not a proven signature bypass. It does not require adopting all of TUF or rescind the legitimate lightweight-scheme choice.

### M6 — coherence claim exceeds single-path atomicity (high)

Claim: rollback is flipping `active` back one edition — a single rename — which is the direct answer to the brief’s power-loss coherence requirement.

Location: reviser-v2/final.md:25, reviser-v2/final.md:44.

Primary check: rename gives one-path atomicity and leaves already-open descriptors unchanged; it provides no multi-open document/image/index snapshot. FTS5 also requires consistency with external content when that mode is used. Proposal does not pin a reader/session, asset URLs and search index to one edition or define a recovery fallback. Evidence: sources/P43-rename-description.txt:31-50, sources/P41-fts5-conditions.txt:637-643.

Impact: A page opened through active before the flip and an image opened through active after it can use different editions. A pointer flip alone does not establish the museum’s coherent-edition requirement. Limit: The mixed-open example is a static interleaving inference, not an executed reproduction. An edition-qualified routing policy could prevent it, but none is supplied.
