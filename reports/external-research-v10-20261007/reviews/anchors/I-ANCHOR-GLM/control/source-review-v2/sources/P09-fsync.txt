L26: DESCRIPTION top
L27: fsync() transfers ("flushes") all modified in-core data of (i.e.,
L28: modified buffer cache pages for) the file referred to by the file
L29: descriptor fd to the disk device (or other permanent storage
L30: device) so that all changed information can be retrieved even if
L31: the system crashes or is rebooted. This includes writing through
L32: or flushing a disk cache if present. The call blocks until the
L33: device reports that the transfer has completed.
L34: As well as flushing the file data, fsync() also flushes the
L35: metadata information associated with the file (see inode(7)).
L36: Calling fsync() does not necessarily ensure that the entry in the
L37: directory containing the file has also reached disk. For that an
L38: explicit fsync() on a file descriptor for the directory is also
L39: needed.
L40: fdatasync() is similar to fsync(), but does not flush modified
L41: metadata unless that metadata is needed in order to allow a
L42: subsequent data retrieval to be correctly handled. For example,
L43: changes to st_atime or st_mtime (respectively, time of last access
L44: and time of last modification; see inode(7)) do not require
L45: flushing because they are not necessary for a subsequent data read
L46: to be handled correctly. On the other hand, a change to the file
L47: size (st_size, as made by say ftruncate(2)), would require a
L48: metadata flush.
L49: The aim of fdatasync() is to reduce disk activity for applications
L50: that do not require all metadata to be synchronized with the disk.
L51: RETURN VALUE top
L52: On success, these system calls return zero. On error, -1 is
L53: returned, and errno is set to indicate the error.
L54: ERRORS top
L55: EBADF fd is not a valid open file descriptor.
L56: EINTR The function was interrupted by a signal; see signal(7).
L57: EIO An error occurred during synchronization. This error may
L58: relate to data written to some other file descriptor on the
L64: Other filesystems (e.g., most local filesystems) will
L65: report errors to all file descriptors that were open on the
L66: file when the error was recorded.
L67: ENOSPC Disk space was exhausted while synchronizing.
L68: EROFS
L69: EINVAL fd is bound to a special file (e.g., a pipe, FIFO, or
L70: socket) which does not support synchronization.
L71: ENOSPC
L72: EDQUOT fd is bound to a file on NFS or another filesystem which
L73: does not allocate space at the time of a write(2) system
L74: call, and some previous write failed due to insufficient
L75: storage space.

L82: HISTORY top
L83: fsync()
L84: 4.2BSD, SUSv1, POSIX.1-1996.
L85: fdatasync()
L86: POSIX.1-1996.
L87: In Linux 2.2 and earlier, fdatasync() is equivalent to fsync(),
L88: and so has no performance advantage.
L89: The fsync() implementations in older kernels and lesser used
L90: filesystems do not know how to flush disk caches. In these cases
L91: disk caches need to be disabled using hdparm(8) or sdparm(8) to
L92: guarantee safe operation.
L93: Under AT&T UNIX System V Release 4 fd needs to be opened for
L94: writing. This is by itself incompatible with the original BSD
L95: interface and forbidden by POSIX, but nevertheless survives in HP-
L96: UX and AIX.
