## Consequential findings

### C-F1 — X, Y: material missing condition

The claim that each step holds the source read lock only for that call needs the condition that the backup owns the source read transaction. If S already has an explicit read transaction, the code does not set bCloseTrans and leaves it open between steps. In rollback-journal operation that reader can block the active writer at commit; under a pinned read snapshot, later committed external changes are not necessarily visible to this S. Distinct handles and a prohibition on source write transactions do not exclude this legal state. X recommends a dedicated S, but does not explicitly require a fresh transaction-free S; Y allows existing-handle use. Completed-copy consistency is not refuted; the unconditional concurrency/freshness description is incomplete.

Locations: X/final.md:7, Y/final.md:9. Evidence: E04, E12. Static diagnostic: CE2.

### X-F1 — X: decisive local policy contradiction

The success-path instruction says to finish, close both handles, then remove the unique staging database and sidecars after success or abandonment. The publication gate instead requires the closed staging copy to be reopened and validated before publication. Literal execution of the cleanup sequence removes a successful candidate before that gate. Reading success as already-published success does not establish the missing ordering: finish and close are themselves prerequisites of publication. A safe implementation requires resolving the text, which this review does not do. This regression is absent from the draft, where deletion was on exhaustion or fatal error.

Locations: X/final.md:3, X/final.md:9, X/final.md:17. Evidence: E08. Static diagnostic: CE1.

### X-F2 — X: conditional technical overstatement

The release-code correction about finish preserving a current BUSY/LOCKED status is valid. Calling p->rc the last stored step result is too narrow: backupUpdate can set a fatal p->rc between step calls when a same-handle copied-page update fails. Finish then returns that status rather than the last step result. The DONE-plus-finish-OK publication gate remains conservative.

Locations: X/final.md:11. Evidence: E06, E08. Static diagnostic: CE3.
