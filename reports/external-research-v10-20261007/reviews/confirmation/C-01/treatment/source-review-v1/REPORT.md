## Material finding

**D-SRC-01 — The claimed current-state inverse coordinate conversion is false during TiledImage scale animation at the pinned version.** Final artifact line 38 says `current=true` uses the currently drawn location and recommends that conversion while an image animates; line 94 and A-P4's disposition carry the recommendation into validation/design. The documentation comment supports the intended meaning, but the implementation does not fully implement it.

At OpenSeadragon commit `7842cd92e6799d97c18227a79cb69af4f706b023` (verified annotated `v6.0.2` tag), `src/tiledimage.js:564–567` selects current or target scale inside `_viewportToImageDelta`. Its inverse caller at lines 588–595 uses current rotation/translation when requested **but omits the third argument to that helper**, which consequently uses target scale. The forward conversion passes the flag at line 621. Animated `setWidth` and `_setScale` at lines 824–830 and 1388–1408 allow unequal scales; rendering uses current scale at lines 1932–1943. This is a source-level inconsistency, not an inference from a similarly titled issue. [Pinned implementation](https://github.com/openseadragon/openseadragon/blob/7842cd92e6799d97c18227a79cb69af4f706b023/src/tiledimage.js).

An isolated reviewer check executed the four verbatim captured conversion methods with a synthetic 1000×500 image, zero translation/rotation, current scale 1 and target scale 2. A current-state forward conversion of `(500,250)` yielded `(0.5,0.25)`; inverse conversion with `true` yielded `(250,125)`. The equal-scale control returned `(500,250)`. Thus the flag alone can save a rectangle against the wrong intrinsic pixels while this image-scale condition holds. This does **not** establish a failure for a fixed TiledImage during viewer-only pan/zoom, after settlement, or for the ordinary-preview minimum. The final's alternative of waiting for settlement remains defensible; it does not make the other API claim true.
