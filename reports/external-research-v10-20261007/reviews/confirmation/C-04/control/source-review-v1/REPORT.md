**D01 — Required competing-component comparison is absent (O2; axes S1 and S3).** Final artifact lines 15–22 compare several useful mechanisms: page regions, OMR/structured notation, curated facsimile encoding, returned packets, replication, and a service. However, the proposal offers one implementation at each complementary layer—PDF.js for PDF viewing/coordinates, Audiveris for OMR, Verovio for notation rendering, and an explicitly unselected PouchDB replication lead. It contains no evidence-based comparison between competing implementations for any consequential component job, nor a reasoned abstention explaining why such comparison could not be made. Its preservation check labels O2 satisfied without addressing that missing part.

The governing review instruction expressly includes **competing components** in O2; BRIEF lines 15–17 additionally require useful competing mechanisms, component options, and consequential source investigation. This finding does not impose a named library or a source-count target. To establish that the omission matters rather than demanding an arbitrary catalog, reviewer open discovery found [OpenSheetMusicDisplay](https://github.com/opensheetmusicdisplay/opensheetmusicdisplay), another public MusicXML renderer. Its pinned README and package at `ea3ff982e2e5a4df010cef7871f69376a662d3fe` identify version 2.2.0, TypeScript/VexFlow, SVG/PNG output and feature limits (`DISC-OSMD-README`, lines 35–40, 52–80; `DISC-OSMD-PACKAGE`). Verovio's pinned README identifies C++20, multiple bindings and LGPL licensing (`CHECK-VRV-01`, lines 11–29). These expose consequential maintenance, deployment and supported-input questions that cannot be resolved by comparing a renderer with an OMR engine. The reviewer did not qualify OSMD, select it, or provide a repaired proposal. The missing comparison is material to the declared full research scope even though all advanced notation components remain optional.
