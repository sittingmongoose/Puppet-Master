# Frozen sandbox plan — Museum object-image annotation desk

This is a fresh product-planning input, not researched conclusions. All choices below are initial proposals for comparison.

## P1 — Sources

The browser desk opens local image uploads and user-supplied IIIF presentation/image-service links. One session contains up to fifty museum objects with multiple image views; each source retains its original identifier and rights statement.

## P2 — Inspection

Curators zoom and pan, compare two views and create rectangular or polygonal region notes. A note records the view identity, region coordinates, author-entered text and review status; the MVP does not run visual recognition.

## P3 — Exchange

A portable review package contains object/view references, annotations and selected locally owned thumbnails. Partner image pixels are not bundled by default. Reopening should explain unavailable, changed or denied sources and leave annotations intact.

## P4 — Storage and revisions

A small institutional service stores packages and annotation revisions. Curators work independently and exchange a package for review; live simultaneous editing is deferred, but conflicting imported revisions must be surfaced.

## P5 — Components and usability

The image viewer, manifest parser and annotation serialization components are undecided. Keyboard inspection, usable focus order, readable rights information and low-bandwidth behavior are MVP concerns; coordinate interpretation must be explicit in the proposed design.

## P6 — Acceptance

Proposed validation covers multi-view objects, source replacement, package reopen, region geometry, missing images and rights-dependent export. The plan has no pinned component version or executed interoperability test.
