# Additive interface v1.1 — terminal missing partner

Original v1 mechanics and protocol remain preserved. A two-final packet can still use v1. The v1.1 builder also admits exactly one actual designated frozen final plus one positively terminal missing designated final. It does not admit unfinished research/critique as a final, or a merely pending partner as failed.

Ops runs `build_blind_packet_v1_1.py` coordinator-only with the same CLI flags. The binding retains the original brief, common criteria, 12-obligation map, important checks and I01 evaluation budget (1200-second decisive-screen target, 1800 seconds total, first actual-output assessment starts the clock). `final_freezes` contains the one real final. Add `terminal_missing_outputs: [{"terminal_record": {"path": "…", "sha256": "…"}}]`.

The pinned terminal record is coordinator-only and uses `schema: er9.terminal-missing-final.v1`, the same `pair_id`, `pipeline_terminal: true`, `designated_final_present: false`, and positive `terminal_evidence_refs` path/SHA-256 bindings. Ops may include cause/arm/native details there for later operational diagnosis; none enter Phase 1. The evaluator sees only an anonymous terminal-missing artifact notice, operational `FAIL`, and quality `UNASSESSED`. The original failed attempt remains preserved and charged separately.

Evaluate every original actual task obligation and consequential current claim in the available current final. Apply the same declared important checks; for the missing partner, those checks are UNASSESSED because no designated current artifact exists. A present final can receive its own fully covered PASS/FAIL/HOLD. A missing partner never receives a semantic FAIL grade based on another arm or on unfinished research. Mark the pair `INCOMPLETE_PAIR`; there is no complete matched semantic comparison, two-FAIL equivalence or paired winner.

Do not include failure cause, native history or economics in the anonymous packet. Save the current-output judgment before opening operational history. Disclose any labels or model facts already known from assignment context; mechanical aliases do not restore information the evaluator has already learned.

If a later authorized successor runs, it receives a new explicit versioned reservation and preserves the original result/cost. Do not silently expand/restart the original I01 evaluation budget.
