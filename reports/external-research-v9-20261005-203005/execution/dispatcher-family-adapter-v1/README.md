# Dispatcher declared-family adapter v1

This fixes one confirmed prelaunch schema mismatch. Dispatcher source SHA 991cea7b2983aec4725b534188f02f57816d2b5648282f02cfa3073ef7197776 directly indexes requested_family. The frozen confirmation and recovery cards instead use candidate_family. Auditor metadata records 73 owner-registered rows across 16 card groups, including 29 SEALED_READY rows affected by this KeyError.

family_adapter.declared_family(card) reads only the explicit requested_family and candidate_family fields. It returns Z for GLM or L for Luna. Both fields may be present only when they agree. Missing, invalid, unsupported or conflicting declarations raise FamilyBindingError. It never uses a case label, filename, suffix, requested-model string or absent runtime selector to infer family. Muse is outside this adapter's supported current dispatcher scope and is rejected.

Ops owns live integration. Pin/import the exact module and replace only the failing expected_family expression with declared_family(card). Keep the existing frozen-owner registration SHA check, registered queue family, owner family/model/effort checks, stage/runtime/source pin checks, response-bound checks and actual native model/effort verification before Goal activation. Existing clocks, resource gates, tools, stage descriptors and frozen cards are unchanged. Add the module to the prospective dispatcher source pin set before resuming admission.

registered_family(card, owner_request, registered_queue_family) is a pure stricter identity guard using the existing declared model/effort fields. validate_launch_binding(card, owner_request, registered_queue_family, verified_runtime_identity) additionally checks an explicitly verified pinned runtime identity containing family, model, effort and verified=true. The caller must establish that identity from its existing verified runtime pins/native configuration. An unbound template, a missing luna_runtime field or a route label is not proof and is rejected. This helper creates no new runtime metadata requirement for the narrow existing-schema integration; the existing runtime guards remain required.

Seventeen local tests use only structural declaration metadata and synthetic runtime identity fixtures. The actual-schema test covers all 73 audited owner rows and 16 actual frozen card groups; every source card and owner request was byte/SHA verified before creating the positive vectors. Synthetic tests cover legacy requested-only declarations, agreement, conflict, missing/invalid values, label-only data, queue/owner/model/effort mismatches and unbound or mismatched runtime identities. Tests start zero Goals, model requests or native processes.

PIN.json and INTEGRATION_OUTBOX.json identify the module, tests, actual vectors, verification and exact source defect. REPORT.json records the bounded diagnosis and limits. PUBLIC_SELECTION.json contains only source/control identity metadata; no candidate prompt, answer, source interpretation, private HOME, auth, raw native log or runtime edit is included. Earlier exports and live jobs remain untouched.
