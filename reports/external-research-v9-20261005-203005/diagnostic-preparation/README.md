# ER9 diagnostic packet preparer

This directory prepares immutable inputs and mechanical exposure graphs. It launches no native process, admits no job and writes no campaign state. Sole admission remains `codex-er9-ops`. Candidate source interpretation, criticism, integration, repair and check code stay on affordable native Goals. `cases/` remains unchanged.

Use `prepared/LIVE_OUTBOX_R002.json` for the four seed-free V14/V15 pairs: eight complete neutral arm workspaces. Each request supplies exact source card/task/brief hashes, finite stage allowance, `execution_enabled` and `public_get`, and designated artifacts. Original r001 packets remain history. The r002 metadata applies `ADMISSION_OVERLAY_01.json`: requested Luna response100 defaults are explicitly unsupported and replaced prospectively with null enforcement, while the original wall/occupied limits remain authoritative. No input bytes or criteria changed. Do not admit both request versions with the same job IDs.

All packets remain `PREPARED_NOT_ADMITTED`. Their `prepared-stage.json` or runtime template deliberately has no accepted tool configuration. Ops copies the exact neutral task/input bytes into its own stage workspace, binds the accepted family-specific native runner and tool/config pins, seals the actual matched pair before outputs, and records actual identity. Never run a Luna packet through the GLM worker or infer route acceptance from preparation.

Four live alternative pairs already have eight exact packets in `alternatives/prepared/LIVE_STANDBY_OUTBOX.json`. These are conditional options, not thirty extra comparisons. Root selects one identity for each original slot before outputs and ops prevents concurrent original/replacement admission. No family substitution is attributed as Luna work or same-model replication.

`bind_seeded.py` binds a stage only from a pinned plan, a legitimate candidate seed manifest, a private fixture-suitability receipt and the exact listed same-arm completed predecessor freezes. Versions and full-context suitability still require independent semantic evaluation; a hash is no proof of source meaning.

For V06, `exact_assembly.py` applies an affordable candidate's frozen unified diff to the exact frozen original. It accepts only `proposal.md`, zero fuzz and zero offsets, preserves untouched text and copies candidate catalogs. Its receipt records zero new native starts and `PENDING_INDEPENDENT_EVALUATION`. It never supplies semantic repair. Ops treats this as a separate mechanical assembly after the actual patch Goal freeze and evaluates the complete assembled current final.

The existing GLM `dev/execution/stage_worker.py` stage schema remains unchanged. Luna's accepted owner runner/wrapper is bound by ops; preparation does not claim an unavailable response cap or output-freeze adapter is installed. Native route qualification, actual Goal identity, process quiescence and tool isolation remain the runtime owners' responsibilities.
