# Jujutsu Integration — frozen product brief

Puppet Master is planned as a Rust and Slint workbench. Jujutsu is a first-class local source-control choice alongside Git. A person can keep local history without an online service, or separately connect a hosted repository. Jujutsu itself has no service account. Selecting a hosting service does not replace the local history backend. This brief describes promises in the frozen Plans, not an implemented or certified adapter. [Plans/Jujutsu_Integration.md §0; Plans/Source_Control_System.md SCS-001, SCS-010, SCS-011; Plans/00-plans-index.md]

People use the existing Source Control surface for their repository, changes, workspaces and history. Jujutsu shows Bookmarks and Operation Log; Git-only staging and stash do not appear. The source graph preserves Jujutsu changes, current commits, rewrites, abandonment and conflicts. Source history, operation history and Backup history remain separate views with separate actions. The source graph is bounded and paginated, and preserves selection while displaying stale or partial information honestly. Ordinary UI uses understandable labels; raw identifiers and adapter details belong in Technical Details. Jujutsu does not gain a separate backend-specific panel. [Plans/Jujutsu_Integration.md JJI-006; Plans/Source_Control_System.md SCS-005, SCS-015, SCS-017; Plans/FinalGUISpec.md F3-529, F3-530]

The integration covers creating, describing, editing, splitting, squashing, rebasing, abandoning and restoring changes; creating, moving, renaming, deleting, tracking and untracking bookmarks; listing and managing workspaces; viewing status, diffs and history; inspecting, undoing and restoring operations; and Git transport/interchange through the Jujutsu adapter. Jujutsu clone remains its own route and returns to the exact caller through success or cancellation. The current owner defines 31 canonical commands. Older command aliases normalize before policy and do not receive their own handlers or receipts. Consumers do not issue direct Jujutsu subprocesses outside the adapter. [Plans/Jujutsu_Integration.md §§1, 3.1; JJI-003, JJI-007; Plans/Commands_System.md; Plans/UI_Command_Catalog.md; Plans/Wiring_Matrix.md]

Jujutsu change identity, immutable commit identity, operation identity, workspace identity and bookmarks stay distinct. A workspace is not inferred from a path or focused folder, and a bookmark is not a Git branch. Mutations bind the exact repository, execution computer and environment, expected native revision, one current writer lease, separate permission and filesystem-safety decisions, and an idempotent command instance. Results preserve before/after operation identity. Stale identity, lost authority or an unknown effect blocks automatic retry. Multi-step work reports actual progress, waits, cancellation and terminal outcome through the shared work mechanism; a spinner or accepted dispatch is not completion. Credential leases use non-secret references. [Plans/Jujutsu_Integration.md JJI-001–003; Plans/Source_Control_System.md SCS-002–003; Plans/Shared_Integration_Runtime.md §§2, 8 and successor Full-Thread addendum; Plans/Permissions_System.md; Plans/FileSafe.md]

When Git and an active Jujutsu store coexist, Jujutsu is the default sole mutation authority. Git inspection may remain available, but Git writes require explicit compatibility checks, the same writer lease, exact before/after Jujutsu operation identities and an independently certified reconciliation path. A late or unmatched mutation quarantines the workspace. The frozen Plans explicitly keep colocated import/export effectively disabled by default in the 0.44.0 profile; only exact certified adapter and live-environment evidence may enable those capabilities. The version is a snapshot-specific input rather than a timeless minimum. There is no implicit reconciliation or fallback Git write. [Plans/Jujutsu_Integration.md JJI-004, JJI-006; Plans/Source_Control_System.md SCS-004; Plans/WorktreeGitImprovement.md]

Setup binds the exact computer and environment and separately discloses installation, ownership, version, adapter, authentication, eligibility and mutation certification. Requested and effective capabilities remain distinct. Ambiguous or unsupported colocation blocks mutations and exposes typed reasons and recovery actions. Settings, Onboarding and Doctor use the owners' commands, current projections and receipts; they do not supply private installers or source-control runtimes. Assistant Chat, Orchestrator, Executor, File Manager, LSP and Runtime Artifacts consume the same identities and owner boundaries. [Plans/Jujutsu_Integration.md §§1.2, 3; JJI-006; Plans/Source_Control_System.md SCS-004–005; Plans/Settings_System.md; Plans/Planning_Wizard.md; Plans/newtools.md]

Native undo and operation restore target exact operation-log identities. FileSafe safe points complement these actions and keep separate decisions and receipts; they do not replace native recovery. Conflict recovery proves the current snapshot and conflict identity, rather than assuming that clean-looking files prove a resolved Jujutsu conflict. [Plans/Jujutsu_Integration.md JJI-005; Plans/FileSafe.md]

A source-inclusive backup must preserve recoverable Jujutsu operation, object and workspace closure across colocated, non-colocated and shared-workspace layouts. It includes retained historical and non-current objects, required backing/shared stores and captured dirty files under a capture barrier and garbage-collection fence. Capture does not manufacture an operation to align those files. Operation-log text, a Git push, bundle, mirror or current bookmarks alone cannot prove complete recovery. Restoration is verified in an isolated disposable repository, including inspection and restoration of a selected historical operation, before Backup can activate it. Conflicts, collisions, missing objects and stale state remain distinct blockers. Mutable configuration is sanitized and inactive; credentials and owner bindings require revalidation. The original repository is untouched by the drill, and no drill pushes, activates hooks or resumes Goals. Existing Backup, Source Control, Project and Forge routes retain their separate ownership. [Plans/Jujutsu_Integration.md JJI-008; Plans/Source_Control_System.md SCS-014; Plans/Backup_Restore_System.md BRS-002, BRS-003, BRS-006, BRS-014]

They do not establish native handlers, event admission, real recovery, security, performance, visual acceptance or readiness.
