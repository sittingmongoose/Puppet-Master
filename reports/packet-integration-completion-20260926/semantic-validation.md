# Computed contract joins

Project recovery compares the candidate attempt to the retained owner context, immutable original terminal result and canonical RFC 8785 digest. It checks recovery/operation/draft/repository/effect identities, composition fences and both halves of the active claim. Onboarding consumes that same context and resolves original result bytes for unknown and failed-before-effect cases; route selection does not override owner availability.

Commands import retains the entire reviewed plan, computes its hash and compares every ordered import entry, actor, Project, picked-file hash and generation across preview and commit. Missing or duplicate plans fail closed. Mutation staleness uses an explicit pre-dispatch generation witness; a newer result does not authorize a stale request. Source/destination root identity, FileSafe evidence, exact confirmation and owner-local action routing remain separately checked. Favorable client assertions never replace these comparisons.

Forge checks actual request/result/receipt/binding/run/artifact/capability/admin/permission witnesses and schema-valid counterexamples. See forge-semantic-validation.md for the exact witness and provider boundaries.

The central contract verifier now admits the Commands pair explicitly. Closed action-family discriminators must be disjoint; per-definition primary identity annotations use actual request/projection IDs or complete control-route tuples. Repeated session IDs and shared Settings writer destinations are not record identities. True duplicates still fail. Previously reused onboarding fixture request IDs were assigned distinct fixture identities without changing their actions.

Independent GPT-6 Sol high reviews passed the Commands joins, Project/Onboarding mutation probe, Forge joins and identity rules. Tests and aggregate counts are recorded in validation.md. No static result certifies native enforcement or creates a handler, storage family or governance lock.
