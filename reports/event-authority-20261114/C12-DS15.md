## What was short, and what closes it

The scope row asked for the seven still-short deck-2 families: catalog update/remove, context sharing/revocation and custom-headless skipped, with eager schema closure, the actual original store and explicit `--family` runs. At base each family reached 176–191 guard rows, and 93–119 of them were proved only by another family's negative. The lane-wide gated run samples at most ten negatives per row across all 23 families, so a deck-2 family's own witness often never reached the tool.

- **Own-family witnesses.** `scripts/pm_ds15_c12_cases.py` writes `Plans/ds15_c12_cases.json`: **837 witnesses** (726 one changed path, 111 one fact held in two to four copies). Each starts from a named valid deck-2 base of its own family (or its own policy case). Its target row is declared before it runs. Run through the complete deck-2 checker, it must be refused first at exactly that row, its observation must refuse at no other row of that table, and its parent must evaluate with no refusal recorded. The 245 attempts that failed any of these are listed as INVALID in `c12-derivation.json`; none is kept. Derivation is deterministic: the final rerun leaves the fixture byte-identical.
- **Per-family gated proof.** `scripts/pm-c12-ds15-closure.py --mode gated --family F` runs the unchanged tool `004bdedd63` (source SHA-256 `e8038992…c0b8`) from the pinned collection. Each table runs with only that family's own controls and negatives. A row the family cannot refuse first is the one exception: another family's negative of that row is added and marked assisting, so the table can certify and the family's other rows keep their credit. An assisting negative is never credited to the family. The matrix counts a row as the family's own only when every negative the tool cut for it names that family.
- **Actual original store.** Retained reads select their recipe from the one sealed receipt of the exact original in `Plans/ds15_original_custody.json` (SP-1101). The custody was re-recorded once at composition with 56 deliberate seals: SX09 twice-sealed, SX02 older recipe, SX05 wrong family, a float original for the number domain, and the CR02 sequence join. The 225 existing seals are byte-identical. No read creates or changes a receipt.
- **Eager schema closure.** Every schema occurrence each family's complete boundaries evaluate compiles through `cached_validator`, which runs `check_reference_closure` over the whole resource (unused branches included) behind SR01 before any instance. The 2 reference-closure cases per family still refuse. `schema-reference-closure.json` lists each occurrence and its recipe.
- **Explicit `--family` runs.** `python3 scripts/pm-ds15-deck2-contracts.py --family F` passes for all seven: 121, 126, 180, 180, 197, 197 and 129 cases.
