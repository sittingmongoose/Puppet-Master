### Retained reads (batch 2 fix 1, built in from the start)

- **Selection only from the sealed receipt for that exact original** (`W3FOriginalOwner`, `:525`): receipts are looked up by Store, scope, event type and event id, and the receipt must bind the bytes Storage holds (`source_commitment`). The recipe comes only from that receipt; there is no Store default, no fallback and no probing.
- **Missing or ambiguous receipts** keep the bytes untouched and return unavailable or unsupported: no receipt for the original → `original_unavailable` (`recipe_custody`); a receipt for the same id that binds other bytes (a receipt for another original) → `original_unavailable` (`recipe_receipt_binding`); two receipts → `recipe_unsupported` (`recipe_unique`); a receipt naming an unknown recipe → `recipe_installed`; a receipt without the family's at-write admission → `original_admission`; an original Storage cannot hand out as canonical bytes → `original_resolved`; a caller-supplied recipe selector → `recipe_override` (the shared dispatcher's `caller_recipe_override`).
- **No receipt is created while reading:** the owner only reads the static catalogue.
- **New-write selection stays separate:** a fresh append reads no receipt; its recipe is the writer's own (`append` path rows).
- **Negatives:** for every family and supported scope, on both the retry and the history path: unsealed (missing), other-original receipt, ambiguous, no admission, unknown recipe, caller recipe, unencodable original, and nine frozen-verifier component defects (envelope, payload, Storage times, operation, event identity, key, full-value commitment, producer commitment, custody event; the three that change the binding fields run on the history path only).
- **History in both directions** (standing check 10): every history positive reads after the live writer grant is gone and the writer is withdrawn (`admission.writer_granted=false`, `writer_withdrawn=true`), and no history row reads current admission or live owner state. Forged (`history-forged-record`), withdrawn (`original_withdrawn`) and foreign (`history-foreign-family`) records are refused.

### What Astra keeps finding: how each was ruled out

1. **Forged or contradictory inputs:** every identity is recomputed from captured owner authority (`event_identity`, key recipes, `operation_field`, `source_identity`); supplied digests are compared with recomputed ones (`custody_producer`, `custody_full_value`); joined copies must agree field by field (scope copies, context, receipts).
2. **Storage-assigned metadata:** append rows compare the candidate's `sequence_id` and times with Storage's issued values; the retry comparison uses the producer projection, which excludes them (a retry positive carries different Storage values and still returns the original).
3. **Historical readers:** valid history reads after live changes; withdrawn, forged and foreign records are refused; no current-writer row reaches a retained original.
4. **One field read two ways:** strict typed equality everywhere (`strict_equal`: bool is not int, int is not float); uppercase uuid and a trailing LF are refused by the full-match rows.
5. **Unresolved references:** eager `$ref` resolution, including unvisited branches, at load and on the `install` path (a dangling reference per family).
6. **Size limits:** the whole canonical payload against 16 KiB (exact 16,384-byte positive, 16,385-byte negative, genuine SP-337 pack positive), and the whole checkpoint root including history and hold refs.
7. **Custody on every path:** first-receipt custody on append, the original receipt on retry, the sealed original on every retained read and retry.
8. **Masked negatives:** the judge refuses any negative that refuses anywhere but its own row (except entailed rows), and the tool's matrix and cut/restore runs re-check every table.
9. **Grades:** see below; criterion 12 claims only what the tool credits.
10. **Numbers written two ways:** one canonical recipe per identity and digest (`qualified_jcs`, producer route); `1.0`/`1e0` refused at integer slots; `-0`/`01` refused at ingress.
11. **Types confused:** string booleans, string numbers, booleans, null, arrays and objects at every typed field (schema negatives); a string `"true"` grant and a boolean retry count are refused.
12. **Formats skipped by the validator:** date-time through the shared checker; uuid and patterns through explicit full-match rows.
10a. **Tightened rules and history:** retained originals verify under their sealed `w3f@1` recipe; a caller cannot select a weaker recipe. W3F has a single edition (no deployed predecessor), so there is no older-recipe positive to build.
